## Next patch release

**Security**

- Windows installation hardening. `install.ps1` runs Node.js only after `node.exe` matches the pinned SHA-256 and otherwise installs a freshly verified runtime. Setup, `install.ps1` and service repair leave the program folders of the root (`runtime\`, `releases\`, `config\`, `modules\`) owned by Administrators with permissions only they can change, remove permissions that were granted on the root or these folders before, and stop with an error when one of them is a junction or a symbolic link. An existing release folder is used only after it matches its verified archive. Remote Setup creates its temporary folder already protected and checks the installer inside it before running it. Run Setup of the installed version again on Windows to apply the new permissions. See [Windows](https://github.com/ProAnima/Arkvory/blob/main/wiki/install/windows.md) and [ADR 0031](docs/adr/0031-release-installation-and-supervision.md#windows-installation).
- Every Arkvory process — the services, `arkvory`, the installers, `arkvoryctl` and Remote Setup — now loads code only from its own release directory and from the built-in modules of Node.js. Module resolution no longer reaches `node_modules` folders of parent directories, the home directory of the account or `NODE_PATH`, and the service definitions clear `NODE_PATH`. On Windows, Setup makes `%ProgramData%\ProAnima` writable only by administrators when it installs Arkvory or repairs the services. Updating is recommended for every installation; run Setup of the installed version again on Windows to apply the new permissions and service definitions. See [Security](https://github.com/ProAnima/Arkvory/blob/main/wiki/operate/security.md#code-loading) and [ADR 0031](docs/adr/0031-release-installation-and-supervision.md#confinement).
