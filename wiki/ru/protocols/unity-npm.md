# Пакеты Unity и npm

Каждый репозиторий Arkvory — это npm-совместимый реестр по адресу `https://<хост>/npm/<репозиторий>/`. Unity Package Manager читает его как scoped-реестр (scoped registry), а `npm` публикует в него пакеты и устанавливает их оттуда. Студии используют его для SDK, инструментов и модулей, общих для нескольких проектов Unity; у каждого пакета своя версия.

Архивы пакетов (tarball) — обычные артефакты, поэтому на них действуют права на репозиторий, квоты, проверки SHA-256, резервные копии и зеркала.

## Прежде чем начать {#before-you-start}

Вам понадобятся:

- Адрес сервера с HTTPS (см. [HTTPS](../install/https)).
- Репозиторий, например `games`. Адрес его реестра — `https://arkvory.example/npm/games/`.
- Ключ. Разработчики используют персональный токен доступа с областью `read`. Сборочные агенты, которые публикуют, используют персональный токен с областью `read-write` или ключ сервиса. См. [Учётные записи и ключи](../use/accounts).

Arkvory передаёт клиенту адрес каждого архива в данных пакета. Адрес строится из имени хоста, по которому пришёл клиент. Когда HTTPS завершается на обратном прокси-сервере, он должен передавать заголовок `Host` и отправлять `X-Forwarded-Proto: https`, как в примере nginx из раздела установки. Иначе клиент получит адреса архивов с `http://`.

## Добавление реестра в проект Unity {#unity-manifest}

1. Откройте `Packages/manifest.json` проекта и добавьте scoped-реестр:

```json
{
  "scopedRegistries": [
    {
      "name": "Arkvory",
      "url": "https://arkvory.example/npm/games/",
      "scopes": ["com.proanima"]
    }
  ],
  "dependencies": {
    "com.proanima.tools": "1.2.0"
  }
}
```

2. Передайте Unity ключ. Не помещайте его в проект. Создайте файл `.upmconfig.toml` в папке пользователя (`%USERPROFILE%\.upmconfig.toml` в Windows, `~/.upmconfig.toml` в macOS и Linux):

```toml
[npmAuth."https://arkvory.example/npm/games/"]
token = "<ваш ключ Arkvory>"
alwaysAuth = true
```

3. Перезапустите Unity. В окне Package Manager откройте **My Registries**, чтобы увидеть пакеты реестра.

Примечания:

- `scopes` — это префиксы имён пакетов. Unity берёт из Arkvory пакеты, имена которых начинаются с одного из scope, а все остальные — из реестра Unity.
- Адрес в `.upmconfig.toml` должен совпадать с `url` в манифесте, включая завершающую косую черту.
- `alwaysAuth = true` обязателен. Реестр не отправляет запрос на вход (login challenge), поэтому Unity должен передавать токен с каждым запросом.
- Имена пакетов Unity — это доменные имена в обратном порядке в нижнем регистре, например `com.company.package`. Unity не поддерживает имена с `@scope/`.

Закоммитьте `Packages/manifest.json` вместе с проектом. У каждого разработчика свой `.upmconfig.toml`.

## Публикация пакета {#publish}

Пакет — это папка с файлом `package.json` в корне. Публикуйте его через `npm`.

1. В папке пакета создайте файл `.npmrc`:

```ini
registry=https://arkvory.example/npm/games/
//arkvory.example/npm/games/:_authToken=${ARKVORY_TOKEN}
```

2. Задайте ключ в окружении и опубликуйте:

```bash
export ARKVORY_TOKEN="$(cat ~/.arkvory/key)"
npm publish
```

```powershell
$env:ARKVORY_TOKEN = (Get-Content C:\Private\arkvory.key -Raw).Trim()
npm publish
```

Строка с `_authToken` должна начинаться с адреса реестра без `https:`. Не храните ключ в `.npmrc`: npm подставляет `${ARKVORY_TOKEN}` из окружения.

Вместо строки `registry` в `.npmrc` можно задать реестр в `package.json` пакета:

```json
{
  "name": "com.proanima.tools",
  "version": "1.2.0",
  "publishConfig": { "registry": "https://arkvory.example/npm/games/" }
}
```

Что проверяет реестр:

- **Имя и версия.** `name` и `version` в `package.json` внутри архива должны совпадать с публикуемыми. Версия соответствует SemVer 2.0.0, например `1.2.0` или `2.0.0-beta.1`. Реестр читает данные версии из этого файла, а не из JSON, который отправляет клиент.
- **Контрольные суммы.** Длина, `shasum` и `integrity`, объявленные клиентом, должны соответствовать байтам. Несовпадение возвращает `422 integrity_mismatch`.
- **Архив.** Он должен содержать `<папка>/package.json`, как его создаёт `npm pack`. Второй `package.json` в архиве отклоняется, потому что npm и реестр могли бы прочитать разные файлы.
- **Версия неизменяема.** Тот же архив, опубликованный повторно, принимается и ничего не меняет (`200`). Другое содержимое для существующей версии возвращает `409` с причиной `version_exists`. Публикуйте исправление как следующую версию.

`npm publish` читает пакет из реестра перед публикацией, поэтому публикующему ключу нужны также `content.read` и `artifact.list`, помимо `upload.create`. См. [Права](#permissions).

Версия доступна, как только `npm publish` завершается. Архив версии хранится как артефакт `<имя>-<версия>.tgz` с меткой `npm`. Для имени с scope `@team/util` становится `util-<версия>.tgz`.

## Установка пакетов {#install}

В Unity добавьте зависимость в манифест или выберите пакет в окне Package Manager в разделе **My Registries**.

Для npm задайте реестр в `.npmrc` проекта или пользователя. Обычно выбирают реестр для одного scope, потому что Arkvory не перенаправляет запросы в публичный реестр npm:

```ini
@team:registry=https://arkvory.example/npm/games/
//arkvory.example/npm/games/:_authToken=${ARKVORY_TOKEN}
```

```bash
npm install @team/util
npm view @team/util versions
npm search tools
```

Если задать `registry=` на Arkvory для всего проекта, npm будет искать там все пакеты, в том числе публичные, например `lodash`, и получит `404`. Используйте реестр для scope или проект, в котором только ваши собственные пакеты.

npm проверяет `dist.integrity` во время установки и записывает адрес реестра в `package-lock.json`.

## Версии и dist-теги {#versions-and-tags}

Dist-тег — это подвижное имя версии. `npm publish` назначает `latest` на новую версию. Другие теги помогают разделять каналы выпуска.

```bash
npm publish --tag beta
npm dist-tag add com.proanima.tools@1.3.0 latest
npm dist-tag ls com.proanima.tools
npm dist-tag rm com.proanima.tools beta
```

```bash
npm install com.proanima.tools@beta
```

| Правило          | Значение                                                                       |
| ---------------- | ------------------------------------------------------------------------------ |
| Имя тега         | Начинается с буквы. Буквы, цифры, `.`, `_` и `-`. До 64 символов.              |
| Запрещённые теги | Имя, похожее на версию (`v1`, `v2.0`), а также `x` и `X`                       |
| `latest`         | Всегда указывает на версию. Его можно переместить, но нельзя удалить (`409`).  |
| Перемещение тега | `npm dist-tag add` или публикация с `--tag`. Новая версия должна существовать. |

Тег — это только имя: он не удаляет и не скрывает другие версии.

Удалить опубликованную версию нельзя. См. [Что не поддерживается](#not-supported).

## Поиск {#search}

Список **My Registries** в Unity и `npm search` используют адрес поиска `/-/v1/search`. Поиск находит пакеты, в имени или описании которых есть этот текст (регистр не важен), и пакеты, у которых этот текст — целое ключевое слово. Без текста он перечисляет все пакеты.

- Он возвращает по одной строке на пакет: версию с тегом `latest`, а если его нет — самую новую версию.
- Результаты отсортированы по имени. Ранжирования по популярности нет.
- `size` по умолчанию равен 20, максимум — 250. `from` — смещение.

```bash
curl -fsS -H "Authorization: Bearer $ARKVORY_TOKEN" \
  "https://arkvory.example/npm/games/-/v1/search?text=tools&from=0&size=20"
```

Чтобы прочитать пакет напрямую, запросите его имя. `@scope/name` можно отправить как `@scope%2fname`:

```bash
curl -fsS -H "Authorization: Bearer $ARKVORY_TOKEN" https://arkvory.example/npm/games/com.proanima.tools
```

Ответ перечисляет каждую версию вместе с содержимым её `package.json` (включая поля `unity` и `displayName`, которые читает Unity), dist-теги и время публикации. В `dist` есть `tarball`, `shasum` (SHA-1) и `integrity` (SHA-512).

## Имена и ограничения {#limits}

| Параметр                           | Правило                                                                                                                                                                                                |
| ---------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Имя пакета                         | Строчные буквы, цифры, `.`, `_`, `~` и `-`; начинается с буквы или цифры. До 214 символов. Для npm допустимо `@scope/name`.                                                                            |
| Версия                             | SemVer 2.0.0, до 256 символов                                                                                                                                                                          |
| `package.json` в архиве            | До 256 КиБ. Данные всех версий приходят одним ответом, поэтому делайте его небольшим.                                                                                                                  |
| Архив                              | Не больше максимального размера объекта в установке, `ARKVORY_MAX_OBJECT_BYTES` (по умолчанию около 10 ТиБ). Отклоняется архив, который при распаковке увеличивается больше чем в 100 раз плюс 64 МиБ. |
| Остальная часть запроса публикации | До 8 МиБ JSON с вложенностью не более 64 уровней. Архив читается потоком и не хранится в памяти.                                                                                                       |
| Один запрос публикации             | Должен завершиться в течение 30 минут и не должен простаивать дольше 30 секунд (`ARKVORY_UPLOAD_DEADLINE_MS`, `ARKVORY_UPLOAD_IDLE_TIMEOUT_MS`)                                                        |
| Одновременные загрузки             | По умолчанию 2 на сервер и 1 на ключ. Ожидающий запрос сдаётся через 20 секунд.                                                                                                                        |
| Текст поиска                       | До 256 символов                                                                                                                                                                                        |

`npm publish` — это один запрос, и после сбоя он начинается с первого байта. Для пакетов в много гигабайт загружайте файл через [`arkvoryctl`](./cli) как артефакт или [обычный файл](./raw-files). Крупные бинарные ресурсы, которые часто меняются, лучше размещать в [Git LFS](./git-lfs); в пакетах держите код и стабильные ресурсы.

Лимиты сервера описаны в разделе [Переменные окружения](../reference/environment#transfers-and-bandwidth).

## Права {#permissions}

Персональные токены и файловые ключи получают доступ на чтение или запись к репозиторию. Ключи сервиса получают точные действия.

| Операция                                     | Действия ключа сервиса | Персональный токен или файловый ключ          |
| -------------------------------------------- | ---------------------- | --------------------------------------------- |
| Установка: чтение пакета и скачивание архива | `content.read`         | Доступ на чтение                              |
| Поиск, список dist-тегов                     | `artifact.list`        | Доступ на чтение                              |
| Публикация, добавление и удаление dist-тегов | `upload.create`        | Доступ на запись, область токена `read-write` |

Разработчику, который только устанавливает пакеты, нужен токен с областью `read`. Сборочному агенту, который публикует, нужны `upload.create`, `content.read` и `artifact.list`. Удалить опубликованную версию не может никто.

## Шлюзы чтения и зеркала {#read-gateways-and-mirrors}

- [Шлюз чтения](../operate/read-gateways) обслуживает установку и поиск, потому что это запросы `GET`. Публикация получает `405`.
- [Зеркало](../operate/mirrors) хранит версии и теги своего источника. Установка и поиск работают. Публикация отклоняется с `409` и причиной `mirror_read_only`. Адреса архивов в данных зеркала указывают на зеркало.

Чтобы использовать зеркало в Unity, укажите адрес зеркала в `url` и его ключ в `.upmconfig.toml`.

## Что не поддерживается {#not-supported}

- Удаление версии (`npm unpublish`). Проекты фиксируют версии, и удаление сломало бы их сборки. Вместо этого опубликуйте исправленную версию и переместите тег.
- `npm deprecate`, `npm login`, `npm owner`, `npm access` и другие команды управления. Запросы, изменяющие данные по другим путям, получают `405` с сообщением «This registry supports publish, install and dist-tags». Вместо `npm login` создайте токен в консоли и поместите его в `.npmrc`.
- Список всех пакетов по адресу `/-/all` и `npm audit`.
- Прокси к публичным реестрам. Arkvory хранит ваши собственные пакеты. Пакеты из npmjs.com или реестра Unity берутся оттуда.
- Ранжирование результатов поиска.
- Раздел для пакетов в консоли. Архивы отображаются в разделе [[ui:catalog]] как артефакты с меткой `npm`.

## Устранение неполадок {#troubleshooting}

Ошибки имеют вид `{"error": "...", "code": "...", "request_id": "..."}`. `npm` выводит `error`. Передайте `request_id` администратору, чтобы он нашёл запрос в журнале сервера.

| Симптом                                               | Причина                                                                 | Что делать                                                                                                                                                                                              |
| ----------------------------------------------------- | ----------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `401` в Unity или npm                                 | Клиент не отправил ключ, либо ключ неверен, истёк или отозван           | В Unity проверьте, что адрес в `.upmconfig.toml` совпадает с `url` в манифесте и что `alwaysAuth = true`. В npm проверьте, что строка `_authToken` начинается с того же хоста и пути, что и `registry`. |
| `403` при публикации                                  | У токена область `read` или у ключа нет `upload.create`                 | Используйте ключ с доступом на запись                                                                                                                                                                   |
| `404` для пакета                                      | В этом репозитории нет такого пакета, или ключ не видит репозиторий     | Проверьте репозиторий в адресе и имя. Для пакета Unity проверьте, что его имя начинается с одного из scope из `scopes`.                                                                                 |
| `404` для публичного пакета                           | `registry=` указывает на Arkvory для всех пакетов                       | Используйте `@scope:registry=`                                                                                                                                                                          |
| `409` с `version_exists`                              | Версия существует с другим содержимым                                   | Опубликуйте новую версию                                                                                                                                                                                |
| `409` с `state_conflict`                              | Вы пытались удалить `latest`                                            | Вместо этого переместите `latest` на другую версию                                                                                                                                                      |
| `409` с `mirror_read_only`                            | Репозиторий — зеркало                                                   | Публикуйте на основной сервер                                                                                                                                                                           |
| `422` с `integrity_mismatch`                          | Байты отличаются от объявленных `shasum` или `integrity`                | Упакуйте и опубликуйте заново. Проверьте, что никакой прокси-сервер не меняет тело запроса.                                                                                                             |
| `400` «package.json names another package or version» | `package.json` внутри архива отличается от публикуемых имени или версии | Выполните `npm publish` из чистой сборки пакета                                                                                                                                                         |
| `400` «Only publishing a new version is supported»    | Команда отправила изменённый пакет, например `npm deprecate`            | Эти команды не поддерживаются                                                                                                                                                                           |
| `405`                                                 | Команда не поддерживается этим реестром                                 | См. [Что не поддерживается](#not-supported)                                                                                                                                                             |
| `507`                                                 | Достигнута квота репозитория или ёмкость установки                      | Освободите место или запросите большую квоту                                                                                                                                                            |
| `503`                                                 | Слишком много одновременных загрузок                                    | Подождите и повторите                                                                                                                                                                                   |
| Архив скачивается по `http://` и завершается ошибкой  | Прокси-сервер не отправляет `X-Forwarded-Proto: https`                  | Исправьте прокси-сервер, как описано в разделе [Прежде чем начать](#before-you-start)                                                                                                                   |
