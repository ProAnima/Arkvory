# Репозитории

Репозиторий — это именованное место в Arkvory, где хранятся файлы и где определяется доступ. Всё, что вы публикуете, попадает в один репозиторий, и каждый запрос называет его.

## Что такое репозиторий {#what-it-is}

У репозитория есть ID: строчные латинские буквы, цифры, `-` и `_`; он начинается с буквы или цифры и не длиннее 64 символов. Примеры: `releases`, `builds` и `game-prod`. ID входит в каждый адрес:

| Что                                         | Адрес                                  |
| ------------------------------------------- | -------------------------------------- |
| Артефакты, пакеты, файлы по пути (HTTP API) | `/api/v1/repositories/<репозиторий>/…` |
| Образы контейнеров                          | `/v2/<репозиторий>/<образ>/…`          |
| Git LFS                                     | `/lfs/<репозиторий>`                   |
| Пакеты npm и Unity                          | `/npm/<репозиторий>/…`                 |

См. [Образы контейнеров](../protocols/containers), [Git LFS](../protocols/git-lfs) и [Пакеты Unity и npm](../protocols/unity-npm).

В репозитории хранятся неизменяемые артефакты. Их можно увидеть в двух видах: пакеты UPack с версией ([Пакеты](./packages)) и файлы по пути с историей ([Файлы по пути](./files)). Стадии и продвижение переносят сборки между репозиториями ([Стадии и продвижение](./promotion)).

Сейчас у репозитория нет ни отображаемого имени, ни описания, ни собственных настроек, кроме доступа, [настроек хранения](#settings) и — для копии другого сервера — [состояния зеркала](#read-only). Переименовать репозиторий нельзя. Удалить его тоже нельзя: отнимите доступ, и файлы останутся на диске.

## Создание репозитория {#create}

Команды для создания репозитория нет. Репозиторий появляется, как только на него выдан доступ. До первой загрузки он пуст.

Администратор делает одно из двух:

- Выдаёт группе доступ к новому имени. В консоли откройте [[ui:administration]], разверните [[ui:manageGrants]], выберите группу, введите имя в поле [[ui:repository]], выберите [[ui:read]] или [[ui:write]] и нажмите [[ui:saveGrant]]. Для первого доступа удобна группа `arkvory-owners`, в которую входит владелец. См. [Группы и доступ к репозиториям](./accounts#groups).
- Указывает репозиторий в политике сервисной учётной записи. См. [Сервисные учётные записи и ключи для CI](./accounts#service-accounts).

В API то же делают `setGroupGrant` и `setServicePolicy`. Опечатка создаёт новое, неверное имя: проверяйте написание. Репозиторий `releases` существует после установки, с доступом на запись для группы `arkvory-owners`.

## Просмотр доступных репозиториев {#list}

Вы видите только те репозитории, на которые у ваших учётных данных есть право. Репозиторий, на который у вас нет права, в списке не появляется, а прямой запрос к нему возвращает `404`. Пустой репозиторий, к которому у вас есть доступ, тоже отображается.

В консоли откройте [[ui:repositories]]. Каждая карточка показывает имя репозитория и, под заголовком [[ui:repositoryRights]], действия, которые у вас там есть. Кнопки:

- Кнопка [[ui:repositoryOpen]] открывает каталог репозитория. Она появляется, если вы можете просматривать список артефактов.
- Кнопка [[ui:repositoryStorage]] открывает каталог с настройками хранения. Она появляется, если вы можете читать политику хранения или диагностику.
- Кнопка [[ui:repositoryAccess]] ведёт к управлению пользователями и сервисами. Она появляется для администраторов и администраторов сервисов.

Список показывает по 50 репозиториев за раз; кнопка [[ui:managementMore]] загружает следующую страницу, а [[ui:managementReload]] обновляет список. Зеркало отмечено значком [[ui:mirrorBadge]].

С `arkvoryctl`:

```bash
arkvoryctl repositories
arkvoryctl doctor
```

`repositories` выводит каждый репозиторий с его `formats` и вашими `permissions`. Если в ответе есть значение `next`, передайте его в `--after`. `doctor` показывает сервер, возможности и права текущего ключа.

В API `listRepositories` принимает `limit` (от 1 до 100, по умолчанию 50) и `after` — последний ID предыдущей страницы. `getRepository` возвращает одну карточку.

```bash
curl -H "Authorization: Bearer $ARKVORY_KEY" "$ARKVORY/api/v1/repositories?limit=100"
```

```typescript
const page = await client.repositories({ limit: 50 });
const card = await client.repository('releases');
```

Карточка состоит из `id`, `formats` (всегда `upack` и `assets`) и `permissions`. О размере и числе файлов она ничего не сообщает. Названия действий см. в разделе [Права](./accounts#permissions).

## Выбор репозитория в консоли {#choose}

На карточке [[ui:connection]] есть поле [[ui:repository]] со списком репозиториев, которые вы можете читать. Сначала в поле стоит `releases`. После входа консоль оставляет его, если вы можете его читать, а иначе выбирает первый репозиторий, доступный вам для чтения. Чтобы работать в другом, введите его имя или выберите из списка. Каталог, пакеты, загрузки и сведения об артефакте затем используют этот репозиторий. Кнопка [[ui:repositoryOpen]] на карточке заполняет поле за вас.

Адрес артефакта в консоли содержит его репозиторий: `#/artifact/<репозиторий>/<id>`. Ссылка на артефакт из репозитория, который вы не можете читать, показывает сообщение и каталог.

`arkvoryctl` использует репозиторий профиля — `releases`, если при добавлении профиля вы не указали другой. Для одной команды его можно заменить параметром `--repository`:

```bash
arkvoryctl profile add production --server https://arkvory.example --token-file ~/.arkvory/key --repository builds
arkvoryctl list --repository releases
```

В SDK `client.inRepository('builds')` возвращает клиент, привязанный к одному репозиторию. В HTTP репозиторий указан в пути.

## Настройки репозитория {#settings}

Что можно задать для репозитория сейчас:

- **Доступ.** Кто может читать и записывать. См. [Учётные записи и доступ](./accounts).
- **Хранение.** Квота в ГиБ, предупреждающий и критический пороги, правила хранения (хранить последние N сборок каждого пакета и канала, защищённые метки, минимальный возраст), автоматическая очистка и физическая очистка. Для просмотра настроек нужно действие `storage.read`, для изменения — `storage.manage`; уровень группы человека их не даёт, а ключ сервиса даёт. В консоли они находятся в разделе [[ui:storageTitle]], который открывается кнопкой [[ui:repositoryStorage]]. В `arkvoryctl` их читают `storage usage` и `storage policy`. Новая загрузка, которая превысила бы квоту, отклоняется с ошибкой `507 storage_quota`. См. [Хранение](../operate/storage).
- **Зеркало.** Администратор сервера может сделать репозиторий копией репозитория другого сервера. См. следующий раздел.

## Репозитории только для чтения {#read-only}

**Зеркало** — это копия репозитория другого сервера Arkvory только для чтения. Сервер синхронизирует её сам. Все, у кого есть право чтения, могут просматривать список и скачивать. Менять её нельзя никому: загрузка, публикация, изменение меток, добавление стадий, назначение путей и удаление отклоняются с ошибкой `409 mirror_read_only`, какими бы ни были уровень группы человека или действия ключа. Чтобы изменить содержимое, используйте основной сервер.

Консоль показывает зеркало со значком над каталогом и скрывает кнопку загрузки:

| Значок               | Значение                                                           |
| -------------------- | ------------------------------------------------------------------ |
| [[ui:mirrorBadge]]   | Копия актуальна                                                    |
| [[ui:mirrorBehind]]  | Сервер ещё догоняет источник                                       |
| [[ui:mirrorFailing]] | Последняя синхронизация не удалась; скачивание продолжает работать |

Нажмите [[ui:mirrorHelpLabel]] рядом со значком, чтобы увидеть источник, время последней синхронизации и код ошибки.

Второй вид — **импорт**. Это обычный репозиторий, который автоматически забирает версии с определёнными стадиями из репозитория другого сервера (например, из `dev` в `prod`). Его значок — [[ui:mirrorImport]]. Загружать в него можно по-прежнему, а последующие изменения или удаления в источнике не влияют на то, что уже скопировано.

В API `getRepositoryMirror` возвращает состояние: `mode` (`mirror` или `import`), `phase` (`pending`, `seeding` или `following`), `caughtUp`, `syncedAt` и `errorCode`. Для обычного репозитория он отвечает `404`.

Зеркала настраивает администратор сервера. См. [Зеркала](../operate/mirrors). **Шлюз чтения** — это другое: адрес, который только отдаёт скачивания тех же репозиториев. Изменения через него отклоняются с ошибкой `405 read_only`. См. [Шлюзы чтения](../operate/read-gateways).
