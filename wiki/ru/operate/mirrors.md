# Зеркала и вторая площадка

**Зеркало** — это репозиторий одной установки Arkvory, который служит копией другого репозитория (**источника**) на другой установке, доступной только для чтения. Установка с зеркалом забирает изменения из источника по HTTPS. У неё своя база данных, своё хранилище файлов, свои учётные записи и свои ключи.

Зеркало нужно, чтобы отдавать скачивания из второго места и держать вторую площадку, которая может заменить источник, если он потерян. Зеркало не заменяет резервную копию источника и не даёт автоматической высокой доступности. Переключение вы выполняете сами. Другие способы защиты описаны в разделах [Резервные копии](./backups) и [Шлюзы чтения](./read-gateways).

## Что такое зеркало {#what-a-mirror-is}

Для зеркалируемого репозитория установка-зеркало копирует:

- Опубликованные файлы: их байты и те же **идентификаторы артефактов**, что и на источнике.
- Метки, метаданные и коллекции.
- Регистрацию UPack, стадии и текущие пути к файлам.
- Образы контейнеров, объекты Git LFS и пакеты npm репозитория.
- Удаления. Файл, удалённый на источнике, удаляется и на зеркале.

Скачивания по ID, по пакету (версия, диапазон, стадия) и по пути к файлу на зеркале отвечают так же, как отвечал источник при последней синхронизации. Они продолжают работать, когда источник недоступен.

Зеркало не копирует:

- Учётные записи, группы, ключи и права доступа. У зеркала свои, и они независимы: отзыв ключа на источнике не влияет на зеркало.
- Ссылки, которые защищают файлы от очистки, вложения сборок, журналы аудита и политики хранения.
- Историю путей к файлам до первой синхронизации. Номера версий меток и путей на зеркале собственные.

Клиенты не могут писать в зеркалируемый репозиторий. Загрузки, изменения меток, пути к файлам, стадии, удаление и продвижение в него возвращают HTTP 409 с причиной `mirror_read_only`. Другие репозитории установки-зеркала работают как обычно. Политики хранения в зеркалируемом репозитории не выполняются, а удаляет там только синхронизация.

## Настройте зеркало {#set-up}

Вам понадобятся ключ на источнике и одна команда на зеркале.

### Создайте ключ на источнике {#source-key}

Зеркалу нужен ключ, который может только читать репозиторий источника. Ключ с правом записи не нужен.

1. На источнике откройте [[ui:services]] с ключом восстановления или ключом оператора.
2. Нажмите [[ui:serviceCreate]] и в [[ui:servicePolicy]] добавьте репозиторий. Нажмите [[ui:bindingRead]], чтобы заполнить права, которые нужны зеркалу. Среди них `artifact.list`, `artifact.read`, `content.read`, `annotation.read`, `asset.read` и `package.read`.
3. Нажмите [[ui:keyIssue]], скопируйте секрет, подтвердите [[ui:keySaved]] и нажмите [[ui:keyActivate]]. Ключ, который не активирован, истекает через 15 минут.
4. Сохраните секрет в файле на сервере-зеркале. В файле только ключ, одной строкой, от 16 до 4000 печатаемых символов. Читать файл могут только root или группа «Администраторы».

Источник должен быть выпуском с потоком изменений. Команда на следующем шаге это проверяет.

### Подключите репозиторий на зеркале {#attach}

Используйте для зеркала **новое пустое** имя репозитория. Синхронизация делает репозиторий равным источнику, но никогда не удаляет то, чего на источнике никогда не было.

```bash
sudo arkvory configure --root /opt/proanima-arkvory \
  --mirror releases \
  --mirror-upstream https://arkvory.example \
  --mirror-token-file /root/mirror-releases.key
```

```powershell
$root = 'C:\ProgramData\ProAnima\Arkvory'
& 'C:\Program Files\ProAnima\Arkvory\arkvory.ps1' configure --root $root `
  --mirror releases --mirror-upstream https://arkvory.example `
  --mirror-token-file C:\secure\mirror-releases.key
```

| Параметр                   | Значение                                                                                                                                         |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| `--mirror NAME`            | Репозиторий на этой установке. От 1 до 64 символов: строчные буквы, цифры, `_` и `-`, первый символ — буква или цифра                            |
| `--mirror-upstream URL`    | Origin источника: `https://host` без пути, учётных данных и запроса. Обычный `http://` принимается только для `localhost`, `127.0.0.1` и `[::1]` |
| `--mirror-token-file FILE` | Абсолютный путь к файлу ключа                                                                                                                    |
| `--mirror-source NAME`     | Репозиторий на источнике. По умолчанию — то же имя, что в `--mirror`                                                                             |
| `--mirror-ca-file FILE`    | Файл PEM с центром сертификации источника. См. [HTTPS со своим центром сертификации](#ca-file)                                                   |

Передавайте одной команде один репозиторий. Нельзя объединять изменение зеркала с изменением HTTPS, хранилища копий или обновлений в одном вызове.

1. Команда проверяет источник с ключом, прежде чем что-либо изменить. Источник должен сообщать о потоке изменений для зеркал, а поток изменений репозитория источника должен отвечать.
2. Она сохраняет ключ в `config/mirrors/NAME.token`, записывает `config/mirrors/mirrors.json` и задаёт `ARKVORY_MIRRORS_FILE` в `config/runtime.json`.
3. Она перезапускает API и обработчик и ждёт, пока они будут готовы. Если что-то не получилось, она возвращает прежние файлы и перезапускает службы снова.

В Docker Compose команда дополнительно записывает `config/compose.mirrors.yml`, который подключает файлы зеркал к контейнерам API и обработчика. Добавляйте его в команды Compose, которые вы запускаете сами.

Чтобы заменить ключ репозитория, повторите команду с новым `--mirror-token-file`. Обработчик заново читает файл ключа после каждого сбоя, поэтому новый ключ работает без перезапуска. Репозиторий, который уже зеркалирует один источник, отклоняет другой источник с сообщением `NAME mirrors another source; detach it first`.

На установке-зеркале дайте людям и инструментам доступ к репозиторию. Репозиторий появляется, как только его имя указано в выданном доступе или в политике сервисной учётной записи. Для людей используйте [[ui:manageGrants]] в разделе [[ui:administration]], для инструментов — политику сервисной учётной записи. Права источника не переносятся.

### HTTPS со своим центром сертификации {#ca-file}

Если источник использует сертификат корпоративного или самоподписанного центра сертификации, добавьте `--mirror-ca-file /path/ca.pem` в команду `--mirror`. Команда проверяет, что каждый сертификат читается и не просрочен, и сохраняет от 1 до 64 сертификатов в `config/mirrors/ca.pem` (размер файла не должен превышать 1 МиБ). После этого обработчик доверяет им в дополнение к стандартным.

- Файл обслуживает все зеркала установки. Новый `--mirror-ca-file` дополняет его, а уже имеющийся сертификат хранится один раз. Отключение последнего зеркала удаляет файл.
- Обработчик доверяет всему набору для всех своих соединений, а не только для одного зеркала.
- Проверка сертификатов никогда не отключается.

## Что копируется и как часто {#sync}

Синхронизацию выполняет обработчик установки-зеркала. Отдельной службы нет. Для каждого зеркалируемого репозитория он выполняет такие шаги:

1. **Первичное заполнение.** Обработчик запоминает текущую позицию в потоке изменений источника. Затем он постранично читает список артефактов, пакетов и путей к файлам и делает зеркало равным источнику.
2. **Отслеживание.** Обработчик читает поток изменений источника. Когда он догнал источник, он проверяет поток заново каждые 10 секунд. Позицию он сохраняет после каждого применённого изменения.
3. **Копирование файлов.** Файл копируется по частям. Обработчик проверяет SHA-256 каждой части и всего файла. После прерывания он продолжает с первой недостающей части. Часть ждёт в `mirror-staging` внутри каталога хранилища файлов зеркала.
4. **После ошибки.** Обработчик повторяет шаг после паузы, которая начинается с 2 секунд и удваивается до 5 минут. Один зеркалируемый репозиторий с ошибкой не останавливает остальные.

В установке может быть до 64 зеркалируемых репозиториев. Копии учитываются в пределе ёмкости и на диске зеркала, поэтому планируйте столько же места, сколько нужно репозиторию-источнику. См. [Хранение](./storage).

Если ключ источника отозван или источник недоступен, зеркало продолжает отдавать то, что у него уже есть, и показывает ошибку в своём состоянии.

## Проверьте состояние синхронизации {#status}

### В консоли {#status-console}

Подключите консоль установки-зеркала к зеркалируемому репозиторию. Над каталогом значок показывает состояние:

- [[ui:mirrorBadge]] означает, что зеркало догнало источник.
- [[ui:mirrorBehind]] означает, что зеркало ещё копирует или ещё не начало.
- [[ui:mirrorFailing]] означает, что последняя попытка не удалась. Скачивания продолжают работать.

Откройте справку значка ([[ui:mirrorHelpLabel]]), чтобы увидеть источник, время последней синхронизации и код ошибки. В зеркалируемом репозитории консоль скрывает кнопки загрузки и изменения.

### В API {#status-api}

[getRepositoryMirror](../api/reference/mirrors#getRepositoryMirror) возвращает состояние репозитория. Для него нужно право читать репозиторий. Для обычного репозитория ответ — 404.

| Поле                             | Значение                                                                                                    |
| -------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| `mode`                           | `mirror` или `import`                                                                                       |
| `phase`                          | `pending` (обработчик не начал), `seeding` (первичное заполнение) или `following`                           |
| `caughtUp`                       | `true`, если сохранённая позиция равна самой новой позиции источника. `null` до конца первичного заполнения |
| `checkedAt`, `syncedAt`          | Когда обработчик последний раз читал поток изменений и когда он последний раз догнал источник               |
| `copiedArtifacts`, `copiedBytes` | Итоги копирования на сейчас (`copiedBytes` — десятичная строка)                                             |
| `errorCode`, `errorAt`           | Последний сбой шага или `null`                                                                              |

### Коды ошибок {#error-codes}

| `errorCode`             | Значение и что делать                                                                                                                                                                                                         |
| ----------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `mirror_mismatch`       | У одного и того же ID артефакта на источнике другое содержимое. Зеркало оставляет свой файл. Изучите артефакт; не удаляйте ни одну из копий, пока не узнаете причину                                                          |
| `mirror_source_changed` | В репозитории уже есть копия другого источника. Отключите его или зеркалируйте новый источник в новый репозиторий                                                                                                             |
| `mirror_source_behind`  | Источник восстановлен или установлен заново, и его поток изменений отстаёт от зеркала. Зеркало читает его заново, и код сбрасывается, когда оно догонит. Файлы, которых нет на восстановленном источнике, остаются на зеркале |
| `mirror_delete_blocked` | Источник удалил файл, который зеркало удалить не может, потому что здесь его ещё что-то использует, например ссылка или история пути к файлу                                                                                  |
| `mirror_failed`         | Сбой без более точного кода. Прочитайте журнал обработчика                                                                                                                                                                    |
| другие коды             | Код неудавшегося запроса, например `unauthorized`, когда ключ отозван, или `capacity_exceeded`, когда зеркало заполнено                                                                                                       |

В журнале обработчика (`component` равен `mirror`) бывают строки `mirror.started`, `mirror.step_failed` с `errorCode` и `attempts`, `mirror.recovered` и `mirror.stopped`.

## Мониторинг зеркал {#monitoring}

API установки-зеркала предоставляет три метрики для каждого зеркалируемого репозитория с метками `repository` и `mode`:

- `arkvory_mirror_last_sync_timestamp_seconds`: время, когда зеркало последний раз догнало источник.
- `arkvory_mirror_last_check_timestamp_seconds`: время, когда оно последний раз читало поток изменений.
- `arkvory_mirror_failing`: 1, пока последняя попытка не удалась.

Готовые правила Prometheus — `ArkvoryMirrorStale` (зеркало не догоняло источник больше часа) и `ArkvoryMirrorFailing` (сбой длится 15 минут). См. [Мониторинг](./monitoring). У зеркала, до которого обработчик ещё не добрался, времени синхронизации нет, поэтому правило устаревания не срабатывает до первой синхронизации.

## Импорт по стадии {#import}

С параметром `--mirror-stages` репозиторий на второй установке **не** зеркало. Это обычный репозиторий с правом записи, который принимает версии, имеющие на источнике одну из указанных стадий. Так можно переносить сборки с сервера разработки на рабочий сервер.

```bash
sudo arkvory configure --root /opt/proanima-arkvory \
  --mirror releases --mirror-upstream https://dev.example \
  --mirror-token-file /root/dev.key --mirror-stages release
```

- Укажите от 1 до 16 разных имён стадий через запятую.
- Версия копируется один раз, с тем же ID, теми же байтами, метками и регистрацией UPack и с соответствующими стадиями.
- После этого она принадлежит этой установке. Изменения, снятие стадий и удаление на источнике до неё не доходят. Версия, которую вы удалили здесь, больше не импортируется.
- Загрузки и политика хранения репозитория работают как обычно.
- Данные реестров образов контейнеров, Git LFS и npm не переносятся.
- Изменение стадий запускает новое первичное заполнение. Оно только добавляет и пропускает то, что уже есть.

Консоль показывает значок [[ui:mirrorImport]] или [[ui:mirrorImportFailing]], если последняя попытка не удалась. Ключу на источнике нужны те же права только на чтение, что и для зеркала.

## Переключение на зеркало при потере источника {#failover}

Это ручное переключение для двух независимых установок на двух площадках. Автоматического переключения нет. Изменения, которые зеркало ещё не забрало, теряются.

### Подготовьтесь заранее {#failover-prepare}

1. Установите вторую площадку, по возможности того же выпуска, что и источник, со своим PostgreSQL и своим диском. У двух площадок нет общих ресурсов.
2. Создайте на источнике ключ только для чтения и подключите каждый репозиторий как зеркало. Репозиторий, созданный на источнике позже, сам на зеркале не появится, поэтому подключите его так же.
3. На зеркале выпустите ключи, которые будут использовать ваши потребители, в том числе ключи с правом записи на случай переключения. Права источника не переносятся, поэтому скомпрометированный источник не даёт доступа к зеркалу.
4. Настройте потребителей (CI, агенты развёртывания) так, чтобы адрес зеркала был у них запасным для скачивания. Это заодно снимает нагрузку с канала к источнику.
5. Делайте резервные копии источника в хранилище копий вне его площадки. См. [Резервные копии](./backups). Зеркало их не заменяет.
6. Следите за зеркалом по правилам выше.

### Переключение {#failover-switch}

1. Убедитесь, что источник действительно недоступен для клиентов и сам не вернётся. Две площадки, обе принимающие запись в один логический репозиторий, потом нельзя слить. Если источник доступен частично, остановите его службы или закройте его порт.
2. На зеркале прочитайте `syncedAt` каждого репозитория. Изменений на источнике после этого времени на зеркале нет.
3. Отключите каждый зеркалируемый репозиторий на зеркале. Он станет обычным репозиторием с правом записи, с теми же ID артефактов и всеми данными.

   ```bash
   sudo arkvory configure --root /opt/proanima-arkvory --mirror-detach releases
   ```

   Команда перезапускает API и обработчик, поэтому ожидайте короткого перерыва.

4. Направьте клиентов, которые пишут, на зеркало через DNS или настройки вашего CI.
5. Загрузите на зеркало контрольный файл и скачайте его.

Что видят клиенты:

- До переключения скачивания с зеркала работают, а запись возвращает 409 `mirror_read_only`.
- После отключения запись работает. Значок исчезает.
- Ключи и пароли источника на зеркале не действуют, если вы не создали там те же учётные записи.

Пути назад нет. Не подключайте отключённый репозиторий как зеркало снова. Чтобы вернуть старый источник, очистите его или установите заново и подключите репозитории нового основного сервера как зеркала. Никогда не запускайте старый источник и новый основной сервер одновременно с включённой записью.

### Репетиция {#failover-rehearse}

Репетируйте переключение каждый квартал и после обновлений. Отключите один репозиторий на запасной копии, проверьте `syncedAt`, скачивание и загрузку и запишите дату и результат. Восстановление резервной копии источника в пустую установку проверяйте отдельно. См. [Регулярно проверяйте восстановление](./backups#test-restore).

## Ограничения {#limits}

- Зеркало доступно только для чтения, пока вы его не отключите. Отключённый репозиторий нельзя снова сделать зеркалом.
- Зеркало — не резервная копия. У него нет копии учётных записей, ключей и прав доступа, и оно не копирует ссылки, вложения, журналы аудита и политики хранения.
- Режим импорта не копирует образы контейнеров и данные Git LFS и npm.
- Синхронизация только добавляет и обновляет. После восстановления источника файлы, которые источник потерял, остаются на зеркале.
- Обе установки обновляются независимо друг от друга. Источник должен поддерживать поток изменений для зеркал.
- Набор доверенных центров сертификации источника действует для всего обработчика.
- Нет автоматического переключения, изоляции старого источника и обратной синхронизации.
