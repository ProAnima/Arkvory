# Модули

Пакет модуля добавляет в Arkvory новую функцию. Arkvory устанавливает только пакеты, подпись которых он может проверить. Команды этой страницы выполняются на хосте установки: от root в Linux или от администратора в Windows. Консоль и HTTP API не умеют устанавливать модули и доверять ключам, поэтому украденная учётная запись администратора консоли не позволит запустить код на сервере.

Службы заново проверяют установленные модули и загружают их при каждом запуске. Модуль работает только после того, как вы его включите.

## Установить пакет {#install}

1. Скопируйте файл пакета `arkvory-module-<id>-<version>.tgz` на хост.
2. Проверьте его и прочитайте условия:

   ```bash
   sudo arkvory module install /root/arkvory-module-sample-1.0.0.tgz --root /opt/proanima-arkvory
   ```

   Команда показывает модуль, его роли, данные, которые он хранит, ключ подписи и SHA-256 пакета, а затем условия модуля. Пока ничего не меняется.

3. Установите его:

   ```bash
   sudo arkvory module install /root/arkvory-module-sample-1.0.0.tgz --root /opt/proanima-arkvory --yes
   ```

Arkvory отклоняет пакет, если:

| Причина                                                                                        | Код в сообщении                                                |
| ---------------------------------------------------------------------------------------------- | -------------------------------------------------------------- |
| Подпись сделана не ключом модулей ProAnimaStudio, или манифест изменён                         | `unknown_key`, `wrong_key_class`, `signature_invalid`          |
| Файла нет, он изменён или не указан в манифесте                                                | `file_missing`, `file_mismatch`, `file_unlisted`               |
| В архиве есть ссылки, устройства, пути за пределами пакета или имена, различные лишь регистром | `link_entry`, `special_entry`, `unsafe_path`, `case_collision` |
| В архиве есть нативное дополнение (`.node`)                                                    | `native_addon`                                                 |
| Модулю нужна другая версия Arkvory                                                             | `module_incompatible`                                          |
| ProAnimaStudio отозвала эту версию                                                             | `module_revoked` и версия-замена                               |
| Нет действующего списка отзыва (см. ниже)                                                      | `stale_revocations`                                            |

Ограничения: 1 ГиБ на пакет, 256 МиБ на файл, 4096 файлов. Пакет больше отклоняется до чтения его данных.

Версия, уже установленная с теми же байтами, остаётся как есть. Та же версия с другими байтами отклоняется.

## Включить и загрузить модуль {#load}

Установленный модуль выключен, пока вы его не включите. Службы загружают модули только при запуске.

1. Добавьте модуль в файл модулей (`ARKVORY_MODULES_FILE`, см. [Переменные окружения](../reference/environment#core)). Настройки модуля указываются в `config`:

   ```json
   { "format": 1, "modules": { "sample": { "enabled": true } } }
   ```

2. Перезапустите службы, как описано в разделе [Применить изменение](../install/configuration#apply-change).
3. Проверьте модуль от имени глобального администратора: `GET /api/v1/system/modules` показывает его с `running: true` и `health.status` `ok` в API и на каждом шлюзе чтения.

Модули выполняют API и шлюзы чтения. Worker проверяет те же модули, но не выполняет ни одного. Этот выпуск отклоняет модули, которые работают в worker или в агенте резервного копирования (`role_unsupported`), и модули со своими маршрутами (`routes_unsupported`). Установки Docker Compose модули пока не загружают.

Прежде чем служба импортирует хоть какой-то код модуля, она снова проверяет пакет:

1. Изменять каталог установки, `modules/`, набор модулей, список отзыва и его каталог может только root (в Windows — SYSTEM и Administrators) или владелец каталога установки. Установка так и настраивает права. Файл, который может изменить другая учётная запись, и ссылка внутри пакета отклоняются (`access_unsafe`, `access_link`).
2. Подпись, каждый файл и версия Arkvory — так же, как их проверяет `module install`.
3. Список отзыва. Отозванная версия никогда не загружается. Истёкший список или его отсутствие модуль не останавливают.

Модуль, который не прошёл проверку, не загружается; остальные модули и Arkvory продолжают работу. `GET /api/v1/system/modules` показывает его с `running: false`:

| `health.status` | Значение                                                    | Коды                                                                                                              |
| --------------- | ----------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| `failed`        | Пакет отклонён, или его код не загрузился или не запустился | `file_mismatch`, `unknown_key`, `module_incompatible`, `access_unsafe`, `config_invalid`, `start_failed` и другие |
| `revoked`       | ProAnimaStudio отозвала эту версию                          | причина из списка отзыва                                                                                          |
| `unavailable`   | Каталога пакета нет на хосте                                | `module_unavailable`                                                                                              |

Упавший модуль снимает Arkvory с готовности (`/health/ready` отвечает 503 с `module_failed`), только если он нужен другому включённому модулю. Модуль, который хранит байты опубликованных файлов (данные `layout`), не снимает никогда: Arkvory продолжает отдавать его данные и пишет новые загрузки в своё хранилище вместо хранилища модуля. Журнал записывает `module.refused` и `module.failed` с кодом в `errorCode`.

Чтобы восстановить изменённый или пропавший пакет, установите его заново. Все службы установки должны видеть одни и те же модули, включённые и выключенные: шлюз чтения или worker с другими модулями не готов (`module_plan_mismatch`). Установите те же пакеты на хосте каждого шлюза чтения.

## Обновить, закрепить, понизить версию {#versions}

Установите файл новой версии с `--yes`. Предыдущий пакет остаётся на хосте до следующего изменения модулей.

| Задача                         | Команда                                                         |
| ------------------------------ | --------------------------------------------------------------- |
| Оставить установленную версию  | `sudo arkvory module pin sample 1.0.0 --root …`                 |
| Снова разрешить другие версии  | `sudo arkvory module pin sample --unpin --root …`               |
| Установить более старую версию | `sudo arkvory module install <file> --downgrade --yes --root …` |

Закреплённый модуль отклоняет любую другую версию, пока вы не снимете закрепление. Версия старше установленной или удалённой, пакет которой ещё лежит на хосте, требует `--downgrade`.

## Проверить установленные модули {#list}

```bash
sudo arkvory module list --root /opt/proanima-arkvory
```

Команда заново проверяет каждый установленный пакет так же, как это делают службы перед загрузкой: подпись, каждый файл и архив. У каждого модуля одно состояние:

| Состояние            | Что значит                                                                                                |
| -------------------- | --------------------------------------------------------------------------------------------------------- |
| `ok`                 | Пакет цел                                                                                                 |
| `refused: <code>`    | Файл изменён, добавлен или заменён ссылкой (`file_mismatch`, `file_unlisted`, `link_entry` и другие)      |
| `revoked (<reason>)` | ProAnimaStudio отозвала эту версию. `read path only` значит, что её данные остаются доступными для чтения |

Отклонённый пакет никогда не используется. Чтобы восстановить его, установите файл пакета ещё раз.

## Удалить модуль {#remove}

```bash
sudo arkvory module remove sample --root /opt/proanima-arkvory
```

Модуль уходит из установки, а его пакет остаётся на хосте до следующего изменения модулей. Модуль, который хранит байты опубликованных файлов (данные `layout`), удалить нельзя: Arkvory отказывает с `module_owns_data`, чтобы его данные не стали нечитаемыми.

## Список отзыва {#revocations}

ProAnimaStudio публикует подписанный список отозванных версий модулей. У каждого списка есть номер, и Arkvory никогда не принимает список с номером меньше, чем у сохранённого. Пакет модуля может нести более новый список: Arkvory сохраняет его при установке пакета. На хосте без доступа к хабу сохраните файл списка сами:

```bash
sudo arkvory module revocations /root/module-revocations.json --root /opt/proanima-arkvory
```

Каждый список подписан со сроком действия: по умолчанию 90 дней, не больше 180. `module install` и `module pin <id> <version>` требуют действующего списка; с истёкшим списком или без списка они отказывают с `stale_revocations`. Пакет, который несёт действующий список, тоже подходит. Чтобы продолжить всё равно, добавьте `--allow-stale-revocations`: Arkvory выведет предупреждение и запишет решение в `modules/audit.jsonl`. Истёкший список никогда не останавливает установленные модули: они продолжают работать, их данные остаются читаемыми; версию останавливает только запись об отзыве. Список с большим номером всегда заменяет сохранённый, даже если он уже истёк.

Когда ProAnimaStudio меняет ключ подписи модулей, один релиз содержит оба ключа, а следующий список подписывается новым ключом; старый ключ убирает только более поздний релиз. Обновление до этого релиза отклоняется, пока хост хранит список, подписанный старым ключом: сначала сохраните действующий список. `sudo arkvory module check-revocations --root …` показывает, доверяет ли этот релиз ключу сохранённого списка.

## Доверять автору плагинов {#trust}

Плагины вашей команды или другого автора подписаны ключом автора. Добавьте ключ в список доверия хоста до установки таких плагинов. Список доверия принадлежит хосту: службы читают его, но не могут изменить.

1. Получите у автора файл открытого ключа (`.pub`, формат minisign), а его отпечаток — по другому каналу.
2. Покажите ключ и сверьте отпечаток:

   ```bash
   sudo arkvory module trust add /root/acme.pub --label "Acme platform team" --plugins "op-acme-*" --root /opt/proanima-arkvory
   ```

3. Добавьте его с `--yes`.

| Параметр             | Что значит                                                                                                   |
| -------------------- | ------------------------------------------------------------------------------------------------------------ |
| `--label`            | Чей это ключ; обязателен                                                                                     |
| `--plugins`          | Id плагинов, которые ключ может подписывать, через запятую: точный id или префикс с `*`. По умолчанию `op-*` |
| `--expires`          | Время UTC, например `2027-01-31T00:00:00Z`. После него ключ не принимается для новых установок               |
| `--allow-in-process` | Разрешает плагинам этого ключа работать внутри процесса Arkvory. Такой код получает все права службы         |

Id плагинов всегда начинаются с `op-`. Ключ плагинов никогда не подписывает модули ProAnimaStudio, а ключи ProAnimaStudio никогда не подписывают плагины `op-`. Ключ, который хост уже знает под другим id или как ключ другого вида, отклоняется (`duplicate_key`). Подписи должны быть с предварительным хешированием, как по умолчанию в текущих версиях minisign; старые подписи отклоняются с `signature_algorithm`.

`sudo arkvory module trust list --root …` показывает ключи, которым вы доверяете. `sudo arkvory module trust remove <key id> --root …` удаляет ключ.

Этот выпуск ведёт список доверия; плагины устанавливает следующий выпуск.

## После прерывания {#recover}

Каждое изменение набора модулей записывается в журнал обновлений. Если команда остановилась на полпути, следующая команда развёртывания отказывает с `Interrupted deployment`. Выполните `sudo arkvory recover --root …`: она вернёт прежний набор модулей. До этого отказывает каждая команда модулей, которая что-то меняет, включая `module trust` и `module revocations`.
