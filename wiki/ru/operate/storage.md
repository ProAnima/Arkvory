# Хранение

Arkvory хранит каждый опубликованный файл один раз, без изменений, в каталоге хранилища файлов на локальном диске сервера. На этой странице объясняется, что занимает место на диске, как ограничить его квотами и политиками хранения, как удалённые файлы уходят с диска и что делать, когда диск заполнен.

## Где лежит содержимое {#location}

Каталог хранилища файлов задаёт переменная `ARKVORY_DATA_DIR`. Установщики используют такие расположения:

| Установка      | Хранилище файлов                            |
| -------------- | ------------------------------------------- |
| Windows        | `data\` в `C:\ProgramData\ProAnima\Arkvory` |
| Linux          | `data/` в `/opt/proanima-arkvory`           |
| Docker Compose | Том Docker `proanima-arkvory_storage`       |

Внутри каталога `blobs/` содержит готовые файлы, `staging/` и `parts/` — загрузки в процессе, а файл `storage-id` связывает каталог с базой данных. Сведения каталога — все имена, метки, версии и права — находятся в PostgreSQL. Файлы и база данных принадлежат друг другу.

- Используйте локальную файловую систему с поддержкой жёстких ссылок. Не размещайте хранилище файлов на сетевом ресурсе.
- Не добавляйте, не изменяйте и не удаляйте файлы в каталоге вручную. Arkvory удаляет файлы сам, как описано ниже.
- Опубликованный файл никогда не меняется. Новое содержимое — это новый файл с новым ID.

## Спланируйте диск {#disk}

Место на томе хранилища файлов занимает следующее:

| Что                                  | Примечания                                                                                                                                |
| ------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------- |
| Опубликованные файлы                 | Все версии, которые вы храните                                                                                                            |
| Загрузки в процессе                  | Части и промежуточные файлы, пока загрузка не завершится                                                                                  |
| Файлы завершённых загрузок по частям | Временные части остаются рядом с готовым файлом, пока их не удалит проход физической очистки. См. [Физическая очистка](#physical-cleanup) |
| Удалённые файлы                      | Остаются на диске, пока не закончится защитный срок и проход очистки не удалит их                                                         |
| Копии зеркал                         | Часть в `mirror-staging`, пока зеркало копирует файл. См. [Зеркала](./mirrors)                                                            |

Помимо хранилища файлов, по возможности размещайте базу данных PostgreSQL, журналы и хранилище копий на отдельных томах. См. [Резервные копии](./backups).

Arkvory держит на томе хранилища файлов **резерв** свободного места. По умолчанию это 1 ГиБ (`ARKVORY_STORAGE_RESERVE_BYTES`). Загрузка, которая заняла бы резерв, отклоняется с HTTP 507 и причиной `storage_full`. Скачивания продолжают работать. Пока для новых данных нет места, `GET /health/ready` показывает `writable: false`.

Два предела действуют независимо от диска:

- `ARKVORY_CAPACITY_BYTES` ограничивает всё зарезервированное содержимое установки. По умолчанию — 10 ТиБ. Это логический предел, а не проверка диска. Когда он достигнут, загрузки завершаются неудачей с HTTP 507 и причиной `catalog_limit`.
- `ARKVORY_MAX_OBJECT_BYTES` ограничивает размер одного файла.

См. [Переменные окружения](../reference/environment#storage-and-limits). В Arkvory нет метрики свободного места хранилища файлов или базы данных. Следите за томами средствами операционной системы или с помощью node exporter.

## Кто может управлять хранением {#permissions}

Настройки хранения не входят в обычные права на чтение и запись. Ключу сервиса нужны явные действия в репозитории:

| Действие           | Что позволяет                                                                         |
| ------------------ | ------------------------------------------------------------------------------------- |
| `storage.read`     | Видеть политику, использование и настройки очистки                                    |
| `storage.manage`   | Менять политику, квоту и настройки очистки и запрашивать пакет очистки                |
| `artifact.delete`  | Просматривать удаления, удалять артефакты и включать автоматическую политику хранения |
| `diagnostics.read` | Читать события хранилища                                                              |

Учётные записи с паролем и ключ восстановления сами по себе этих прав не имеют. Чтобы управлять хранением в консоли:

1. Создайте сервисную учётную запись с политикой для репозитория, включающей эти четыре действия. См. [Учётные записи и доступ](../use/accounts).
2. Выпустите и активируйте для неё ключ.
3. В консоли откройте [[ui:keySignIn]], вставьте ключ и нажмите [[ui:connect]].
4. Откройте [[ui:repositories]] и на карточке репозитория нажмите [[ui:repositoryStorage]].

Над каталогом появится панель [[ui:storageTitle]]. Без этих прав панель остаётся скрытой.

Включённая политика хранения привязана к **ключу, который её включил**. Каждый автоматический запуск заново проверяет, что этот ключ ещё активен, не истёк и по-прежнему имеет `storage.manage` и `artifact.delete`. Если вы отзовёте ключ или сократите его права, удаление остановится и появится событие `retention.failed`. После ротации ключа сохраните политику снова с новым ключом.

## Квоты и пороги предупреждений {#quotas}

У репозитория может быть квота. Без квоты действует только общий предел.

| Параметр             | Поле в консоли                | Значение                                                                                                                                                | По умолчанию    |
| -------------------- | ----------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------- |
| Квота                | [[ui:storageQuota]]           | Наибольший объём, который может занять репозиторий. API принимает точное число байт от 1 до 9 007 199 254 740 991, а `null` означает отсутствие предела | Без ограничения |
| Порог предупреждения | [[ui:storageWarningPercent]]  | Доля квоты, при которой появляется предупреждение. 1–98                                                                                                 | 80              |
| Критический порог    | [[ui:storageCriticalPercent]] | Доля, при которой появляется ошибка. 2–99, больше порога предупреждения                                                                                 | 95              |

В использование, которое учитывается в квоте, входит размер всех файлов репозитория, ещё не удалённых с диска: опубликованных файлов, незавершённых загрузок и удалённых файлов, ожидающих очистки. Поэтому удалённый файл продолжает занимать квоту, пока его не удалит проход очистки.

- **Проверка.** Сервер проверяет квоту при начале загрузки. Новая загрузка, которая превысила бы квоту, завершается неудачей с HTTP 507 и причиной `storage_quota`. Повтор с тем же ключом идемпотентности не резервирует место дважды.
- **Уменьшение.** Квоту можно задать ниже текущего использования. Выполняющиеся загрузки могут завершиться. Новые загрузки сверх предела отклоняются.
- **Нет автоматического освобождения.** Квота никогда не вызывает удаление. Правила хранения не удаляют лишние сборки, чтобы уложиться в квоту.
- **Состояния.** Состояние бывает `unlimited`, `normal`, `warning`, `critical` или `exceeded`. Смена состояния один раз записывается как событие хранилища.
- **Наблюдение.** Сервер каждую минуту заново проверяет состояния не более чем 20 репозиториев, в том числе когда автоматическое удаление выключено.

Эти числа — логические резервирования, а не свободное место на диске. Репозиторий может быть в пределах квоты, а диск при этом заполнен, потому что на диске есть ещё промежуточные файлы и другие репозитории.

## Политика хранения {#retention}

Политика хранения автоматически удаляет старые **зарегистрированные сборки UPack** и оставляет последние N из них. Другие файлы она не удаляет: обычные файлы по пути, образы контейнеров, объекты Git LFS и пакеты npm в её область не входят. Без политики ничего не удаляется автоматически.

### Параметры {#retention-settings}

| Параметр            | Поле в консоли          | Значение                                                                                                                    | По умолчанию                          |
| ------------------- | ----------------------- | --------------------------------------------------------------------------------------------------------------------------- | ------------------------------------- |
| Включить            | [[ui:storageEnabled]]   | Включает автоматическое удаление                                                                                            | Выключено                             |
| Группировка         | [[ui:storageGrouping]]  | Единица, по которой ведётся счёт: [[ui:storagePerChannel]], [[ui:storagePerPackage]] или [[ui:storageGlobal]]               | Пакет и канал                         |
| Последних N         | [[ui:storageKeep]]      | Сколько сборок хранить для каждого счётчика, 1–100 000                                                                      | 10                                    |
| Каналы              | [[ui:storageChannels]]  | Собственное N для метки в виде `метка=N`, по одной на строку, до 32. Используется только при группировке по пакету и каналу | `test=10`, `staging=10`, `release=10` |
| Минимальный возраст | [[ui:storageAge]]       | Сборка моложе этого возраста сохраняется; в часах, 0–87 600                                                                 | 24                                    |
| Защищённые метки    | [[ui:storageProtected]] | Сборки с одной из этих меток никогда не удаляются, до 32, через запятую                                                     | `bse`, `release`                      |
| Интервал            | [[ui:storageInterval]]  | Минуты между запусками, 1–10 080                                                                                            | 60                                    |

Метка состоит из 1–64 букв, цифр или символов `_ . : -`.

### Как выбираются сборки {#retention-rules}

1. Сервер ранжирует сборки каждого счётчика по **времени публикации**, от самой новой. Порядок не совпадает с порядком версий SemVer.
2. Счётчик зависит от группировки. При группировке по пакету и каналу сборка учитывается отдельно для каждой настроенной метки канала, которую она несёт, по каждому пакету (`group/name`). Сборка без настроенной метки попадает в один общий счётчик пакета с N по умолчанию. При группировке по пакету у каждого пакета один счётчик. При группировке по всему репозиторию у всех сборок один общий счётчик. Имена пакетов не зависят от регистра, метки зависят.
3. Сборка остаётся, если она входит в последние N **любого** счётчика, к которому относится.
4. Сборка моложе минимального возраста остаётся.
5. Сборка с защищённой меткой остаётся. Её метки берутся из текущей аннотации или из загрузки, если аннотации нет. Защищённые сборки всё равно участвуют в ранжировании, поэтому число сохранённых сборок может быть больше N.

Сборка никогда не удаляется, пока она кому-то нужна:

- Внешний сервис держит на неё ссылку.
- Её использует путь к файлу, текущий или из истории.
- Другая сборка перечисляет её как вложение, сейчас или в истории.
- Она продвинута в стадию. Сначала снимите стадию.
- Её использует образ контейнера, запись Git LFS или npm.

Удаление сборки логическое: она исчезает из списков, а новые скачивания завершаются ответом 404. Байты уходят с диска позже, при [физической очистке](#physical-cleanup). Версия пакета остаётся зарезервированной, поэтому ту же версию нельзя опубликовать снова с другим содержимым.

### Включите политику безопасно {#retention-enable}

Сначала просмотрите, потом включайте. Просмотр показывает, что удалила бы сохранённая политика, и ничего не удаляет.

1. Подключитесь с ключом, у которого есть эти четыре действия, и откройте панель хранения репозитория.
2. Задайте поля и оставьте [[ui:storageEnabled]] выключенным. Нажмите [[ui:storageSave]].
3. Нажмите [[ui:storagePreview]]. В списке до 100 сборок, которые сохранённая политика удалила бы за один пакет. Если кандидатов остаётся больше, консоль сообщает об этом.
4. Если список верный, установите флажок [[ui:storageEnabled]] и флажок подтверждения [[ui:storageAcknowledge]], затем сохраните снова. Для этого нужно `artifact.delete`.

Примечания:

- Просмотр показывает один момент времени. Когда политика запускается, она ранжирует сборки и проверяет зависимости заново.
- Политика сохраняется вместе с номером версии. Если её изменил кто-то другой, перезагрузите страницу и сохраните снова.
- [[ui:storageRefresh]] перезагружает настройки и использование.

### Как выполняется политика {#retention-run}

Пишущий процесс API (не шлюз чтения) проверяет политики каждые 60 секунд и обрабатывает до 20 политик, срок которых наступил. Один пакет удаляет не более 100 сборок. Если остаются кандидаты, следующий пакет начинается через минуту. Иначе следующий запуск наступит через интервал. Расписание хранится в базе данных и переживает перезапуск.

Один пакет можно запустить и самому с помощью операции API [runStoragePolicy](../api/reference/storage#runStoragePolicy). Использование, просмотр и события имеют операции в том же [справочнике API по хранению](../api/reference/storage).

## Физическая очистка {#physical-cleanup}

Удаление артефакта, человеком или политикой, лишь убирает его из каталога. **Физическая очистка** удаляет его байты с диска в фоне, не останавливая API, обработчик и шлюзы чтения. Кроме того, она:

- Отменяет загрузки, срок которых истёк без завершения, и удаляет их части.
- Удаляет временные части завершённых загрузок.

Она не выбирает сборки для удаления. Она убирает только то, что уже удалено или отменено.

**Физическая очистка по умолчанию выключена, и она настраивается для каждого репозитория отдельно.** Включите её в каждом используемом репозитории. Пока она выключена, удалённые файлы, истёкшие загрузки и части завершённых загрузок остаются на диске, а квота учитывает удалённые файлы.

### Параметры очистки {#cleanup-settings}

В панели репозитория откройте [[ui:cleanupTitle]]:

| Параметр      | Поле в консоли         | Значение                                            | По умолчанию | Диапазон |
| ------------- | ---------------------- | --------------------------------------------------- | ------------ | -------- |
| Включить      | [[ui:cleanupEnabled]]  | Включает фоновую очистку                            | Выключено    |          |
| Защитный срок | [[ui:cleanupGrace]]    | Как долго удалённый файл остаётся на диске, в часах | 24           | 0–8760   |
| Пакет         | [[ui:cleanupBatch]]    | Сколько файлов обрабатывается за один пакет         | 25           | 1–100    |
| Интервал      | [[ui:cleanupInterval]] | Секунды между пакетами                              | 60           | 5–86 400 |
| Пауза         | [[ui:cleanupDelay]]    | Миллисекунды паузы между файлами                    | 50           | 0–1000   |

Нажмите [[ui:cleanupSave]], чтобы применить настройки. Изменение действует сразу. Если вы выключите очистку, она остановится после текущего файла. Кнопка [[ui:cleanupRun]] запрашивает пакет в ближайшее время, а не удаляет сразу. Нажмите [[ui:cleanupRefresh]], чтобы увидеть результат последнего пакета.

Защитный срок — это не корзина. При значении 0 файл может быть удалён сразу после удаления, если его не читает ни один клиент. Arkvory не умеет восстанавливать удалённый артефакт.

### Что очистка делает и что пропускает {#cleanup-rules}

- Она удаляет только отменённые или удалённые файлы, у которых прошёл защитный срок. Она ещё раз проверяет, что их ничто не использует: ни ссылка, ни история пути к файлу, ни история вложений.
- Открытое скачивание, записываемая загрузка и файл, который нужен выполняющейся резервной копии, заставляют очистку **пропустить** этот файл. Следующий пакет попробует снова. Последний результат показывает, сколько файлов обработано, пропущено и завершилось ошибкой и сколько байт освобождено.
- Квота и логическая ёмкость освобождаются только после удаления файлов с диска.
- Пакет ограничен размером пакета и паузой, что снижает нагрузку на диск. Это не гарантирует строгую пропускную способность диска и не обещает нулевого влияния на задержку других запросов.
- Очистка выполняется в пишущем процессе API, один раз на базу данных. Раз в 5 секунд он проверяет один репозиторий, срок которого наступил. Без работающего пишущего процесса ничего не очищается.
- Включайте очистку только после обновления всех процессов Arkvory, включая шлюзы и обработчик. Старый процесс без протокола очистки заставляет очистку откладывать работу.

## Удалите артефакт {#delete-artifacts}

Один опубликованный артефакт можно удалить вручную. Для этого нужно `artifact.delete` в репозитории.

1. Откройте артефакт в разделе [[ui:metadata]] и найдите [[ui:deletionTitle]].
2. Нажмите [[ui:deletionInspect]]. Консоль покажет, что ещё использует артефакт. Если что-то блокирует удаление, сначала уберите эту зависимость.
3. Вставьте ID артефакта для подтверждения и нажмите [[ui:deletionSubmit]].

Такое удаление не проверяет защищённые метки, потому что вы сами выбираете объект. Зависимости проверяются всегда. После удаления:

- Артефакт исчезает из списков и поиска. Новое скачивание завершается ответом 404. Уже идущее скачивание может завершиться.
- Версия пакета остаётся зарезервированной.
- Байты остаются на диске, пока [физическая очистка](#physical-cleanup) не удалит их после защитного срока.
- Отменить удаление в консоли или через API нельзя.

Для удаления многих артефактов в API есть [previewRetention](../api/reference/storage#previewRetention) и [applyRetention](../api/reference/storage#applyRetention). Просмотр перечисляет кандидатов, опубликованных до заданной даты, с причинами блокировки. Применение удаляет только переданные вами ID, до 100 за вызов, и возвращает результат для каждого ID: `deleted`, `already_deleted`, `protected`, `changed`, `not_eligible` или `not_found`. Проверяйте каждый результат, а не только статус HTTP.

## Диагностика и события хранилища {#diagnostics}

Раздел [[ui:storageEvents]] перечисляет, что происходило в репозитории, от старых к новым, по 100 на страницу. Нажмите [[ui:storageMore]], чтобы открыть следующую страницу. Чтобы читать его, нужно `diagnostics.read`. Операция API — [getStorageEvents](../api/reference/storage#getStorageEvents), с фильтром по уровню (`info`, `warning`, `error`).

| Событие                                                                                               | Уровень                 | Значение                                                                                                         |
| ----------------------------------------------------------------------------------------------------- | ----------------------- | ---------------------------------------------------------------------------------------------------------------- |
| `storage.policy_updated`                                                                              | info                    | Политика хранения сохранена                                                                                      |
| `retention.completed`                                                                                 | info                    | Пакет удалил сборки. В событии указано число                                                                     |
| `retention.failed`                                                                                    | error                   | Автоматическое удаление остановлено, например потому, что отозван разрешивший его ключ                           |
| `cleanup.configured`                                                                                  | info                    | Настройки очистки сохранены                                                                                      |
| `cleanup.completed`                                                                                   | info или error          | Пакет очистки обработал файлы, пропустил их или завершился по ним ошибкой. В событии числа и освобождённые байты |
| `capacity.normal`, `capacity.warning`, `capacity.critical`, `capacity.exceeded`, `capacity.unlimited` | info, warning или error | Состояние квоты изменилось                                                                                       |
| Коды ошибок HTTP                                                                                      | warning или error       | Запрос управляемого ключа к этому репозиторию завершился ошибкой. Событие хранит ID запроса, маршрут и статус    |

История ограничена: 1000 событий на репозиторий и 20 000 всего, самые старые отбрасываются. Это диагностика по возможности, а не журнал с гарантированной доставкой. Вовремя экспортируйте то, что вам нужно, а для долгосрочных свидетельств используйте журнал сервера. См. [Мониторинг](./monitoring).

Панель показывает и использование: опубликованные байты, незавершённые загрузки, байты, ожидающие очистки, и итог относительно квоты. Операция API — [getStorageUsage](../api/reference/storage#getStorageUsage).

## Когда диск заполнен {#disk-full}

Признаки: загрузки завершаются неудачей с HTTP 507 и причиной `storage_full`, `GET /health/ready` показывает `writable: false` или операционная система сообщает, что свободного места нет. Скачивания продолжают работать. Клиенты могут продолжить свои загрузки после того, как вы освободите место.

1. **Найдите причину.** Проверьте свободное место на томах хранилища файлов, базы данных и хранилища копий. Сравните цифры использования в панели хранения. Большие значения «ожидает очистки» означают, что удалённые данные ещё на диске. Большое значение «незавершённые загрузки» означает брошенные загрузки.
2. **Запустите очистку.** Если очистка выключена, включите её в каждом репозитории с коротким защитным сроком, например 0, если вы согласны, что удалённые файлы уходят сразу. Нажмите [[ui:cleanupRun]]. Она также удаляет временные части завершённых загрузок и истёкшие загрузки. Дождитесь пакетов и прочитайте последний результат. Очистка пропускает используемые файлы, поэтому повторите её.
3. **Удалите ненужное.** Примените политику хранения или удалите артефакты. Место освободится только после того, как очистка удалит байты.
4. **Добавьте места.** Расширьте том или диск. Если хранилище копий или другие данные лежат на том же томе, перенесите их.
5. **Проверьте восстановление.** Когда место освободится, `writable` вернётся в `true`, и загрузки снова заработают.

Не удаляйте файлы в `blobs/`, `staging/` и `parts/` вручную: это нарушает связь между базой данных и диском. Если резерва мало для журналов и базы данных на том же томе, увеличьте `ARKVORY_STORAGE_RESERVE_BYTES`.

Если загрузка завершается неудачей с причиной `storage_quota` или `catalog_limit`, дело не в диске. Увеличьте квоту или общий предел либо удалите данные.

## Ограничения {#limits}

- Политика хранения работает только с зарегистрированными сборками UPack. Другие файлы она никогда не удаляет.
- Порядок хранения определяет время публикации, а не номер версии.
- Для хранения, квот и очистки нужны явные действия ключа сервиса. У учётных записей с паролем и у ключа восстановления их нет.
- Физическая очистка по умолчанию выключена и настраивается для каждого репозитория.
- Удалённый артефакт восстановить нельзя. Восстанавливайте данные из резервной копии. См. [Резервные копии](./backups).
- В зеркалируемых репозиториях политики хранения не выполняются. См. [Зеркала](./mirrors).
- Хранилище файлов должно быть на локальной файловой системе. Сетевые ресурсы и несколько хранилищ не поддерживаются.
