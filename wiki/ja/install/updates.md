# 更新

ProAnimaStudioは、Arkvoryの安定版リリースをハブ経由で告知します。サーバーは、インストール可能なバージョンをハブに問い合わせ、リリースをダウンロードし、署名を確認してインストールします。自分で開始するか、自動更新を有効にしない限り、インストールは行いません。既定では自動更新は無効です。

更新はローリングアップデートではありません。サービスが短時間停止し、実行中の転送は中断します。再開に対応するクライアントは転送を続行します。メンテナンス時間帯に更新してください。

## 更新の仕組み {#how-it-works}

- **リリース。** 公開済みで、バージョンが`x.y.z`の安定版リリースだけをインストールします。プレリリース、ブランチ、任意のアドレス、古いバージョンは拒否します。
- **ハブによる決定。** サーバーは6時間ごとに、自身に承認されたバージョンをハブに問い合わせます。ハブは新しいバージョンの提供を保留したり、段階的に提供したりします。ファイル自体は、ハブが発行する有効期間の短いリンクでGitHubから取得します。これにサーバーのGitHubトークンは不要です。
- **署名。** 各リリースのマニフェストにはProAnimaStudioの署名があります。サーバーは、インストール済みプログラムに組み込まれた公開キーで署名を確認し、その後アーカイブのSHA-256を確認します。署名のないリリースや改変されたリリースは、ハブからでもGitHubからでもインストールしません。完全性の保証をハブに委ねることはありません。
- **ホストの更新ツール。** サーバーのタイマー（Linuxでは`arkvory-update.timer`、Windowsではタスク`ProAnimaArkvoryUpdate`）が毎分更新ツールを実行します。コンソールからのリクエストを取り込み、前回の確認から6時間が経過したらリリースを確認し、設定された時間帯に自動更新を開始します。自動インストールが無効でも、確認は実行します。

### 更新が行う処理 {#what-an-update-does}

1. サービスを実行したまま、リリースをダウンロードし、署名とSHA-256を確認して、インストールルート内の`releases/<version>/`にファイルを展開します。Composeの場合は、新しいイメージをビルドします。
2. リリースがデータベーススキーマを変更する場合は、先に新しいバックアップを作成して検証します。[更新前のバックアップ](#backup)を参照してください。
3. バックアップエージェント、ワーカー、APIを停止します。それぞれに終了まで最大120秒の猶予を与えます。
4. インストールを新しいバージョンに切り替えます。スキーマ変更がある場合は、この時点でマイグレーションを実行します。
5. APIとワーカーを起動し、APIが3回連続で準備完了を報告するまで待ちます。その後、バックアップエージェントを起動します。エージェントはこのチェックの対象ではありません。約90秒以内に報告しなければ、更新は警告を表示し、適用されたままになります。
6. 統計情報が有効な場合は、匿名の`updated`イベントをハブに送信します。ここで失敗しても更新を取り消すことはありません。

古いバージョンは`releases/`に残ります。すべてのデータ、キー、設定はそのままです。

## 更新を確認する {#check}

管理者としてコンソールにサインインし、[[ui:updates]]を開きます。ページには[[ui:updateCurrent]]、[[ui:updateLatest]]、[[ui:updateChecked]]が表示されます。今すぐハブに問い合わせるには、[[ui:updateCheck]]を選びます。サインイン後、新しいリリースがある場合は、[[ui:updateOpen]]を含むバナーで通知します。

ネットワークにアクセスできないなどの理由で確認に失敗すると、ページは最後に見つかったリリースを保持し、古い可能性があると表示します。6時間後、または[[ui:updateCheck]]を選んだときに再確認します。

サーバー上では、`arkvory status --root <root>`がインストール済みのバージョン、自動更新の設定、バージョンの固定を表示します。

ホストの更新ツールが接続されていないとページに表示されたら、`arkvory updates-connect --root <root>`を実行します。古いリリースから更新したインストールの、コンソールと更新タイマーを接続します。更新ツールからの報告が途絶えたと表示された場合は、タイマーまたはタスクが5分間実行されていません。[トラブルシューティング](#troubleshooting)を参照してください。

## 手動でインストールする {#manual}

### コンソールで {#manual-console}

1. [[ui:updates]]を開き、[[ui:updateLatest]]に目的のバージョンが表示されていることを確認します。
2. [[ui:updateInstall]]を選びます。ダイアログにバージョンを表示し、転送が中断する可能性を警告します。
3. [[ui:updateConfirmButton]]を選びます。コンソールは、画面で確認したバージョンとSHA-256を送信します。その後に公開されたバイト列が変わっていた場合、リクエストは拒否されます。
4. 待ちます。リクエストはすぐに受け付けられ、ホストの更新ツールが1分以内に取り込みます。サービスの再起動中にページの接続が切れる場合がありますが、自動で再接続します。2つ目のリクエストは送らないでください。

バージョンが固定されている場合、コンソールはインストールを拒否します。[バージョンを固定する](#pin)を参照してください。

### コマンドで {#manual-command}

```bash
sudo arkvory update --root /opt/proanima-arkvory
sudo arkvory update --root /opt/proanima-arkvory --version 1.2.3
```

`--version`を指定しなければ、ハブがこのサーバーに承認したバージョンをインストールします。`--version`を指定すると、その安定版バージョンを正確にインストールします。インストール済みのバージョンより新しい必要があります。更新に失敗すると、コマンドはエラーコードで終了します。各プラットフォームでの実行方法は、[設定](./configuration#lifecycle-commands)を参照してください。

## 自動更新 {#automatic}

次の3つの方法のいずれかで自動更新を有効にします。

- コンソールで[[ui:updates]]を開き、[[ui:updateSettings]]の[[ui:updateAutomatic]]を選択し、[[ui:updateHour]]を選んで、[[ui:updateSave]]を選びます。
- サーバー上で実行：`arkvory configure --root <root> --enable-updates`。
- スクリプトでインストールするときに指定：`install.sh`には`--automatic`、`install.ps1`には`-AutomaticUpdates`。

無効にするには、コンソールまたは`arkvory configure --root <root> --disable-updates`を使います。

| ルール           | 値                                                                                            |
| ---------------- | --------------------------------------------------------------------------------------------- |
| 時間帯           | 選択したUTCの1時間。既定はUTC 03:00～03:59。時間を設定できるのはコンソールだけです            |
| 試行             | 成功・失敗に関係なく、UTCの1日あたり最大1回。時間帯を逃しても、その日の後の時間には補いません |
| スキップする条件 | バージョンが固定されている、前回の確認に失敗した、または新しいリリースが見つかっていない場合  |
| リリース         | 前回の確認時にハブが承認した最新のリリース                                                    |

バックアップは更新の時間帯を避けてスケジュールしてください。更新はバックアップエージェントを停止し、実行中のバックアップは中断して再びキューに入ります。

## 更新前のバックアップ {#backup}

データベーススキーマを変更しない更新は、バックアップを作成しません。定期バックアップを利用してください。

データベーススキーマを変更するリリースは、新しく作成して検証したバックアップがある場合にのみインストールします。更新ツールは、サービスが動作している間に次を行います。

1. バックアップエージェントに新しいバックアップを要求し、作成と検証が終わるまで待ちます。最大6時間待ちます。この間、コンソールにはリリースのインストール中と表示されます。
2. その後にのみ、サービスを停止し、データベースをマイグレーションして、新しいバージョンを起動します。

バックアップには3つの条件があります。接続済みのバックアップの保管庫が利用可能であること、バックアップエージェントがオンラインであること、過去に完了したバックアップが少なくとも1つあることです。テラバイト単位の初回フルバックアップは、計画して実施する作業であり、更新の付随処理としては行いません。いずれかの条件を満たさないと、**何も変更する前に更新を拒否します**。サービスは動作を続け、コンソールはインストールが拒否されたと表示し、自動更新は翌日に再試行します。保管庫を接続し、初回バックアップを実行してください。[バックアップ](../operate/backups)を参照してください。

スナップショットの後、サービスが停止するまでに到着した変更は、そのバックアップに含まれません。このバックアップが必要になるのは、新しいバージョンがマイグレーション後に失敗した場合だけです。[ロールバックと復旧](#rollback)を参照してください。

### 自分で用意したバックアップで更新する {#manual-upgrade}

内蔵の保管庫を使わない場合は、データベースとストレージ全体のバックアップを自分で作成して検証し、その記録ファイルを更新ツールに渡します。

```bash
sudo arkvory upgrade --root /opt/proanima-arkvory --version 1.2.3 --backup-record /secure/backup-record.txt
```

ファイルは自分で記した記録です。更新ツールは存在することだけを確認し、バックアップの完全性を証明しません。ジャーナルとロールバックは`update`と同じです。このコマンドは新しいバージョンへの更新だけに使え、別のバージョンに固定されている場合は拒否されます。

## ロールバックと復旧 {#rollback}

### 自動ロールバック {#automatic-rollback}

- **スキーマ変更なし。** 新しいバージョンが準備完了にならない場合、更新ツールは停止して以前のリリースを復元し、準備完了を待って、`Update failed; previous release restored`と報告します。
- **スキーマ変更あり、マイグレーション失敗。** マイグレーションは1つのトランザクションで実行します。失敗したマイグレーションはロールバックし、以前のリリースが変更されていないスキーマで再起動します。
- **スキーマ変更あり、マイグレーション後に新しいバージョンが起動しない。** 以前のリリースは新しいスキーマを読めないため、自動で戻す方法はありません。更新ツールはジャーナルを`maintenance-required`にし、復元ポイントを示します。原因を修正して`recover`を実行すると、更新を完了します。または、`journal.json`に記載された復元ポイントを復元し、以前のバージョンを実行します。

Arkvoryにはダウングレードコマンドがありません。コマンドは古いバージョンを拒否します。以前のバージョンは、自動ロールバックのためだけに`releases/`に残ります。

### 中断した更新を復旧する {#recover-update}

更新中に異常終了や停電が起きると、インストールルートにロック`operation.lock`と記録`journal.json`が残ります。復旧するまで、新しい更新とほとんどのコマンドは実行を拒否します。状態が分かる前にロックを削除しないでください。

更新が進行中ではなく（ジャーナルが完了済みか存在しない）、ロックを保持していたプロセスがもう実行されていない場合、次のコマンドが自動でロックを取り除き、警告を記録します。たとえば、停止した更新確認や、[クラスター](../operate/cluster)でフェンシングされたサーバー上で取得したロックが該当します。

1. 新しい実行が始まらないように、更新タイマーを停止します。Linux：`sudo systemctl stop arkvory-update.timer`。Windows：`Disable-ScheduledTask -TaskName ProAnimaArkvoryUpdate`。タイマーのないComposeインストールでは、自分でスケジュールしたジョブを停止します。
2. 更新ツールのプロセスが動作していないことを確認します。`journal.json`とログを保存します。
3. その後にのみ、`operation.lock`を削除します。
4. `arkvory recover --root <root>`を実行します。ジャーナルが許す方向に進みます。
   - スキーマ変更のない更新、またはマイグレーション開始前であれば、以前のバージョンに戻します。
   - マイグレーション開始後であれば、先に進みます。安全に繰り返せるマイグレーションを再実行し、新しいバージョンを起動します。
5. サービスが準備完了になり、テスト用のダウンロードが成功することを確認します。タイマーを再開します：`sudo systemctl start arkvory-update.timer`、または`Enable-ScheduledTask -TaskName ProAnimaArkvoryUpdate`。

更新を開始したコンソールのリクエストがまだ保存されている場合は、`arkvory updates-reset --root <root>`で取り除けます。状態を確認してから実行してください。ロックは取り除きません。

## バージョンを固定する {#pin}

バージョンを固定すると、他のバージョンへのすべての更新を止められます。

```bash
sudo arkvory configure --root <root> --pin                  # インストール済みのバージョンを固定
sudo arkvory configure --root <root> --pin --version 1.2.3  # 別の安定版バージョンを固定
sudo arkvory configure --root <root> --unpin
```

バージョンの固定中は、次のようになります。

- 自動更新は何も行いません。
- コンソールはリリースのインストールを拒否し、サーバー上で固定を解除するよう求めます。
- `arkvory update`は固定されたバージョンをインストールし、別の`--version`を拒否します。
- 確認は続くため、コンソールには引き続き新しいリリースが表示されます。

古いバージョンを固定した後で新しいバージョンをインストールするには、新しいバージョンを固定して`arkvory update`を実行します。スクリプトによるインストール時に固定することもできます。`install.sh`には`--pin`、`install.ps1`には`-Pin`を指定します。

## ハブ、チャネル、統計情報 {#hub}

### サーバーがハブに送るもの {#hub-data}

| タイミング                           | 送信するもの                                                                                                                                                                                                                                                                 |
| ------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 6時間ごと、または要求時の更新確認    | プロジェクト`arkvory`の更新リクエスト。インストール済みのバージョン、オペレーティングシステム（`linux`または`windows`）、プロセッサ（`x86_64`または`aarch64`）、チャネルを含みます。統計情報が有効な場合は、ランダムなインストールIDを持つ`X-Install-Id`ヘッダーを追加します |
| 統計情報が有効で、更新が完了したとき | インストールID、新しいバージョン、オペレーティングシステム、プロセッサ、チャネルを含む1件の`updated`イベント                                                                                                                                                                 |
| リリースのダウンロード               | ハブはGitHubへのリンクを返します。ファイルはそこから取得します                                                                                                                                                                                                               |

キー、アカウント、ホスト名、保存されたコンテンツは送信しません。認証情報がハブに渡ることもありません。インストールIDは、そのインストールだけを識別するランダムな値です。プロジェクトの説明によれば、ハブはIPアドレス、名前、コンテンツを保存しません。ハブは、ユーザーがコンソールから送信したフィードバックも受け取ります。これはユーザーによる別の操作です。

統計情報が無効な場合、サーバーはインストールIDもイベントも送信しません。この場合、ハブはすべてのインストールにリリースしたバージョンだけを提供します。

### オプション {#hub-options}

| 設定           | 既定値                     | 変更方法                                                                                                            |
| -------------- | -------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| 統計情報       | 有効                       | コンソール：[[ui:updateSettings]]の[[ui:updateStatistics]]。コマンド：`--statistics off`または`--statistics on`     |
| チャネル       | `stable`                   | ProAnimaStudioが先行提供するバージョンを受け取るには`--update-channel beta`、戻すには`--update-channel stable`      |
| ハブのアドレス | `https://hub.proanima.net` | 独自のハブには`--hub-url https://hub.example`、GitHubだけを使うには`--hub-off`。アドレスはHTTPSである必要があります |

すべて`arkvory configure --root <root>`のオプションで、再起動なしで反映されます。設定は`config/hub.json`に保存します。ハブのアドレスを変更すると、コンソールがフィードバックを送信する先も変わります。こちらは次回のサービス再起動後に反映されます。

### ハブに接続できない場合 {#hub-unreachable}

ハブが応答しない場合（ネットワーク障害、タイムアウト、サーバーエラー）、更新ツールは代わりにGitHubの最新安定版リリースを読み取り、警告を記録します。署名とSHA-256の確認は同じように行います。ハブによる拒否（ステータス4xx）、ファイルの欠落、不正な署名はエラーであり、代替先には切り替えません。

GitHub上のリリースに認証が必要な場合は、リポジトリの内容を読めるトークンを入れた`github-token.txt`をインストールルートに作成します。ファイルを読めるのは管理者だけにしてください。更新ツールが使用し、サービスは使いません。コマンドオプションとして渡すこともありません。`--hub-off`を指定すると、更新ツールは常にGitHubを使います。

サーバーは、`hub.proanima.net`、`api.github.com`、`github.com`、GitHubのダウンロードホストにHTTPSでアクセスできる必要があります。

## オフライン環境のインストール {#offline}

インターネットにアクセスできないサーバーは、リリースを確認できません。[[ui:updates]]ページには、確認に失敗したと表示されます。サービスには影響しません。代わりにファイルから更新します。

1. インターネットにアクセスできるコンピューターで、サーバーのプラットフォーム用キット（`Arkvory-Linux.tar.gz`または`Arkvory-Windows.zip`）をダウンロードします。SHA-256を、そのリリースの`release-checksums.json`と比較します。
2. キットをサーバーにコピーし、展開します。ディレクトリには`arkvory-release.json`、`arkvory-runtime.zip`、`arkvory-setup.mjs`が入っています。キットに署名ファイルはありません。同じリリースページから`arkvory-release.json.sig`をダウンロードし、`arkvory-release.json`と同じ場所に置いてください。これにより、更新ツールは署名も検証します。
3. ディレクトリの絶対パスを指定して更新を実行します。

   ```bash
   sudo arkvory update --root /opt/proanima-arkvory --artifact /media/release
   ```

   ```powershell
   & 'C:\Program Files\ProAnima\Arkvory\arkvory.ps1' update --root C:\ProgramData\ProAnima\Arkvory --artifact D:\release
   ```

更新ツールは、アーカイブのSHA-256をマニフェストと照合します。署名を確認するのは、マニフェストと同じ場所に`arkvory-release.json.sig`がある場合だけです。ローカルディレクトリの選択は自身が行うため、更新に署名は必須ではありません。署名がない場合、手順1でのキットと`release-checksums.json`の比較が、出所を確認する唯一の手段です。スキーマ変更のルールは同じです。先に検証済みのバックアップが必要です。

ネイティブパッケージと`Arkvory-Setup-x64.exe`はリリースを内包しており、インターネットアクセスは不要です。Composeの更新はホスト上でイメージをビルドします。ベースイメージ`node:24.22.3-bookworm-slim`がまだホストにない場合にのみ、Docker Hubが必要です。

## プラットフォーム別の更新 {#platforms}

### Windows {#platform-windows}

新しい`Arkvory-Setup-x64.exe`を、インストール済みのものに上書きして実行します。セットアップはデータを検出し、所有者を再度尋ねません。コンソールからの更新と同じ方法で、プログラム、サービス、データベースのリリースを更新します。古いバージョンのセットアップは拒否され、同じバージョンのセットアップはサービスを修復します。更新中にセットアップを開始しないでください。インストーラーは英語とロシア語のみです。コンソールまたはコマンドから更新することもできます。

### Linuxパッケージ {#platform-linux}

リリースページから新しいパッケージをダウンロードし、初回と同じようにインストールします：`sudo apt install ./Arkvory-amd64.deb`または`sudo dnf install ./Arkvory-x86_64.rpm`。aptやdnfのリポジトリはないため、`apt upgrade`と`dnf upgrade`では新しいバージョンを見つけられません。パッケージの設定手順は、パッケージ内のリリースを使い、コマンドと同じ更新を実行します。実行中のサービスは、切り替えまでリクエストへの応答を続けます。

スキーマ変更に必要なバックアップがないなどの理由で更新を拒否した場合、古いバージョンは動作を続け、設定手順は失敗します。原因を修正してから、DebianとUbuntuでは`sudo dpkg --configure -a`、RPMシステムでは同じパッケージの再インストールで、この手順を再実行してください。

コンソールから更新した後、パッケージマネージャーの表示するバージョンが、実行中のバージョンより古い場合があります。実行中のバージョンより古いパッケージは拒否されます。

### スクリプトインストール {#platform-script}

スクリプトでインストールした場合、`arkvory`コマンドはありません。コンソールから更新するか、インストールのNode.jsで`manage.mjs update`を実行します。[設定](./configuration#lifecycle-commands)を参照してください。

### Docker Compose {#platform-compose}

コンソールまたは`manage.mjs update`で更新します。更新ツールは新しいバージョンのイメージをビルドし、`backup`、`worker`、`api`コンテナーを置き換え、ボリュームは保持します。`root`を使わないComposeのインストールでは、`updates-poll`のスケジュールが必要です。[Docker Compose](./docker#updates-compose)を参照してください。

## 更新後 {#after}

- `arkvory status --root <root>`を確認し、コンソールにサインインします。
- 不要になったバージョンを`releases/`から削除します。現在のバージョンと、`journal.json`に記載された直前のバージョンを残してください。更新ツールは、古いバージョン、ダウンロードファイル、ステージング領域を削除しません。
- 更新は、スクリプトインストールのNode.js、PostgreSQLのプログラム、オペレーティングシステム、コンテナーエンジンを更新しません。それぞれ別に更新してください。PostgreSQLのメジャーバージョン変更は、それ自体がマイグレーションです。先にバックアップしてください。

## トラブルシューティング {#troubleshooting}

| 表示される内容                                                           | 対処                                                                                                                                                                                                                               |
| ------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ホストの更新ツールが接続されていないとページに表示される                 | メンテナンス時間帯に`arkvory updates-connect --root <root>`を実行してください                                                                                                                                                      |
| 更新ツールからの報告が途絶えたとページに表示される                       | タイマーまたはタスクを確認します。Linux：`systemctl status arkvory-update.timer`と`journalctl -u arkvory-update`。Windows：タスク`ProAnimaArkvoryUpdate`と`logs\updater.log`。`operation.lock`が残っていないことを確認してください |
| リリースの確認に失敗した                                                 | サーバーからハブとGitHubへのアクセスを確認してください。サービスには影響しません                                                                                                                                                   |
| バックアップが必要なためインストールが拒否された                         | 保管庫を接続し、初回バックアップを待ち、状態を再確認します。[更新前のバックアップ](#backup)を参照してください                                                                                                                      |
| 更新に失敗した                                                           | 再試行する前に、`journal.json`、更新ツールのログ、サービスのログを読んでください                                                                                                                                                   |
| 手動の復旧が必要                                                         | [中断した更新を復旧する](#recover-update)の手順に従ってください                                                                                                                                                                    |
| リクエストの待機中に設定が変わった                                       | ページを再読み込みし、リクエストを再送信してください                                                                                                                                                                               |
| `Installation is locked`                                                 | 別の操作が実行中か、異常終了しました。[中断した更新を復旧する](#recover-update)を参照してください                                                                                                                                  |
| `Interrupted deployment; use recover after inspecting journal.json`      | 以前の更新が完了していません。先に復旧してください                                                                                                                                                                                 |
| `Downgrades are forbidden`                                               | 指定したバージョンがインストール済みのものより新しくありません                                                                                                                                                                     |
| `Version is pinned`                                                      | 固定を解除するか、固定されたバージョンをインストールしてください                                                                                                                                                                   |
| `Interrupted update request; inspect installation and use updates-reset` | コンソールのリクエストが受け付けられましたが、完了していません。状態を確認してから`updates-reset`を実行してください                                                                                                                |

その他のヒントは、[トラブルシューティング](../operate/troubleshooting)と[自己修復](../operate/self-healing)を参照してください。

既存のデータベースを PostgreSQL 18.7 に更新する前に、[提供元の更新後の要件](https://www.postgresql.org/about/news/postgresql-187-1712-1616-1520-1425-and-19-rc-2-released-3442/)を確認してください。
