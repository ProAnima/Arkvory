# インストール方法の選択

Arkvoryは1台のサーバーで動作します。どのインストールにも、同じ部品があります。

- **API**：HTTP APIとWebコンソール。
- **ワーカー**：アップロードの完了処理とバックグラウンドジョブを実行します。
- **バックアップエージェント**：スケジュールされたバックアップを、バックアップの保管庫に作成します。
- **PostgreSQL**：カタログのデータベース。

ファイルのコンテンツは、サーバーのローカルディスクに保存されます。この構成は高可用性システムではありません。更新やサーバー障害の際には短い中断が発生し、クライアントは転送を再開します。

## インストールオプション {#installation-options}

| オプション                                                                                              | プラットフォーム                               | サインインなしで再起動後に起動                                                                 | データベース                                                                   | インストール後の自動更新                        | 推奨される用途                                                                |
| ------------------------------------------------------------------------------------------------------- | ---------------------------------------------- | ---------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------ | ----------------------------------------------- | ----------------------------------------------------------------------------- |
| [グラフィカルインストーラー](./windows) `Arkvory-Setup-x64.exe`                                         | Windows x64                                    | はい（Windowsサービス）                                                                        | 同梱のPostgreSQL 18.4（Arkvoryが管理）                                         | オフ                                            | Windowsのサーバーとワークステーション、インターネット接続なしでのインストール |
| [Linuxパッケージ](./linux) `Arkvory-amd64.deb`、`Arkvory-x86_64.rpm`                                    | systemdを使うLinux x64                         | はい（systemdユニット）                                                                        | ディストリビューションが提供する専用のPostgreSQLクラスター（バージョン16〜19） | オフ                                            | Debian、Ubuntu、RPM系のサーバー                                               |
| スクリプト、ネイティブサービス：`install.sh`（[Linux](./linux)）、`install.ps1`（[Windows](./windows)） | systemdを使うLinux x64またはarm64、Windows x64 | はい                                                                                           | 既存のPostgreSQLサーバー                                                       | オフ。`--automatic` / `-AutomaticUpdates`でオン | 自動化、既存のPostgreSQLサーバー、Linux arm64                                 |
| [Docker Compose](./docker)                                                                              | Docker EngineのあるLinux                       | はい（コンテナーエンジンが起動時に開始する場合）                                               | PostgreSQL 18.4コンテナー                                                      | オフ。`--automatic`でオン                       | コンテナーホスト                                                              |
| [Docker Desktop](./docker)                                                                              | Windows x64                                    | いいえ。コンテナーが実行されるのは、ユーザーがサインインしてDocker Desktopが起動した後だけです | PostgreSQL 18.4コンテナー                                                      | オフ。`-AutomaticUpdates`でオン                 | ワークステーションでの評価                                                    |

どのオプションでも、同じAPI、ワーカー、バックアップエージェントがインストールされます。内蔵のHTTPSを使えるのは、ネイティブインストールだけです。ComposeのインストールでHTTPSを使うには、リバースプロキシが必要です。[HTTPSとリバースプロキシ](./https)を参照してください。

### SSHによるリモートインストール {#remote-installation-over-ssh}

**Arkvory Remote Setup**は、クライアントパッケージに含まれています。管理者のコンピューターで実行し、SSHでサーバーに接続して、ネイティブのLinuxまたはWindowsパッケージをインストールします。その後、所有者アカウントを作成し、プライベートなSSHトンネル経由でコンソールを開きます。

| サーバー    | 要件                                                                                                |
| ----------- | --------------------------------------------------------------------------------------------------- |
| Linux x64   | SSHとSFTP、systemd、`apt-get`または`dnf`、rootまたは`sudo -n`（パスワード入力なし）を使えるユーザー |
| Windows x64 | SFTPに対応したOpenSSH Server、Windows PowerShell、管理者アカウント                                  |

トンネルは、Remote Setupの実行中だけ動作します。Arkvoryを他のコンピューターに公開することはありません。パスワードが必要な`sudo`、SSHエージェント、ジャンプホスト、ARMサーバーには対応していません。

## リリースの内容 {#what-a-release-contains}

リリースは[github.com/ProAnima/Arkvory/releases](https://github.com/ProAnima/Arkvory/releases)で公開されます。

| ファイル                                                                                                                                  | 用途                                                                                                                                          |
| ----------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| `Arkvory-Setup-x64.exe`                                                                                                                   | Windows用のグラフィカルインストーラー。Node.js、PostgreSQL、WinSW、Microsoft Visual C++ランタイムを含みます                                   |
| `Arkvory-amd64.deb`、`Arkvory-x86_64.rpm`                                                                                                 | Linuxパッケージ。Node.jsを含みます                                                                                                            |
| `install.sh`、`install.ps1`                                                                                                               | ネイティブサービスまたはDocker Compose用のコマンドラインインストーラー                                                                        |
| `Arkvory-Linux.tar.gz`、`Arkvory-Windows.zip`                                                                                             | 自動化キット。コマンドラインインストーラーとリリースファイルをまとめたもので、GitHub Releasesにアクセスできない環境でのインストールに使います |
| `Arkvory-CLI-Setup-x64.exe`、`Arkvory-CLI-amd64.deb`、`Arkvory-CLI-x86_64.rpm`                                                            | クライアントパッケージ。コマンドラインクライアント`arkvoryctl`とArkvory Remote Setupを含みます                                                |
| `arkvoryctl.mjs`、`arkvory-remote.mjs`                                                                                                    | 同じクライアントツールを、Node.js 24用の単一ファイルにしたものです                                                                            |
| `arkvory-runtime.zip`、`arkvory-setup.mjs`、`arkvory-release.json`、`arkvory-release.json.sig`、`release-checksums.json`、`native-*.json` | プログラムファイル、マニフェスト、チェックサム、署名。インストーラーと更新ツールがこれらを読み込みます                                        |

## 要件 {#requirements}

| 項目                                | 要件                                                                                                                                             |
| ----------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| Windows、グラフィカルインストーラー | x64、Windowsビルド10.0.17763以降（Windows 10 バージョン1809、Windows Server 2019）。管理者権限                                                   |
| Windows、スクリプト                 | x64、Windows PowerShell。ネイティブサービスには管理者権限が必要                                                                                  |
| Linuxパッケージ                     | x64、systemd、glibc 2.28以降、Python 3。パッケージマネージャーがPostgreSQL 16以降をインストールします                                            |
| Linux、スクリプト                   | x64またはarm64、ネイティブサービスにはsystemd、glibc、Bash、curl、Python 3、tar、xz                                                              |
| Docker Compose                      | Composeプラグインを備えたDocker Engine、またはLinuxコンテナーモードのDocker Desktop。互換性のあるcomposeプロバイダーを備えたPodmanも使用できます |
| PostgreSQL                          | 1つのArkvoryインストールにつき1つのデータベース。2つのインストールを同じデータベースに接続しないでください                                       |
| ファイルストレージ                  | ハードリンクをサポートするローカルファイルシステム。ファイルストレージにネットワーク共有を使用しないでください                                   |
| バックアップの保管庫                | 別のボリューム。サービスの開始前にマウントしておきます。[バックアップ](../operate/backups)を参照してください                                     |

Arkvoryは、プロセッサとメモリの最小要件を固定では定めていません。ファイル、データベース、バックアップの保管庫に必要なディスク容量を見込んでおいてください。既定では、Arkvoryはストレージボリュームの空き容量1 GiBを確保し、最大10 TiBの予約済みアップロードを受け付けます。どちらの上限も変更できます。[設定](./configuration)を参照してください。

### インストールと更新時のネットワークアクセス {#network-access-during-installation-and-updates}

グラフィカルインストーラーは、インターネット接続なしで動作します。それ以外のオプションでは、HTTPSでファイルをダウンロードします。

| ホスト                                                     | 使用元                                                                                   |
| ---------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| `nodejs.org`                                               | `install.sh`と`install.ps1`が、Node.js 24.21.0をダウンロードし、SHA-256を確認します      |
| `api.github.com`、`github.com`、GitHubのダウンロードホスト | スクリプトインストーラー、および更新ハブに接続できないときの更新                         |
| `hub.proanima.net`                                         | 更新の確認とダウンロード。[更新](./updates)を参照してください                            |
| Docker Hub                                                 | Composeは`node:24.21.0-bookworm-slim`からイメージをビルドし、`postgres:18.4`を実行します |

インターネット接続がない環境では、リリースのローカルコピーからインストールと更新を行います。[更新](./updates)を参照してください。

## ポート {#ports}

| ポート    | サービス                                                        | 既定の公開範囲                                                                                                                            |
| --------- | --------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| 8080/TCP  | APIとコンソール（HTTP。内蔵TLSを使う場合はHTTPS）               | `127.0.0.1`のみ。ネイティブインストールは、HTTPSを設定した後は他のアドレスでも待ち受けられます。Composeは常に`127.0.0.1:8080`で公開します |
| 54329/TCP | グラフィカルインストーラーとLinuxパッケージが管理するPostgreSQL | `127.0.0.1`のみ                                                                                                                           |
| 5432/TCP  | ComposeインストールのPostgreSQLコンテナー                       | 公開されません。Composeネットワークの内部からのみ到達できます                                                                             |

クライアントのネットワークに開放するのは、HTTPSのポートだけにしてください。データベースのポートは開放しないでください。

## インストールディレクトリ {#installation-directory}

インストールルートは、Windowsでは`C:\ProgramData\ProAnima\Arkvory`、Linuxでは`/opt/proanima-arkvory`です。ホームディレクトリやユーザープロファイルの外にある、専用の空のディレクトリを使ってください。

| ルート内のパス                   | 内容                                                                               |
| -------------------------------- | ---------------------------------------------------------------------------------- |
| `installation.json`              | インストール済みのバージョン、インストールモード、自動更新の設定、バージョンの固定 |
| `journal.json`、`operation.lock` | 最後の更新の状態と、実行中の操作のロック                                           |
| `launcher.mjs`、`manage.mjs`     | サービスを起動するものと、管理コマンド                                             |
| `releases/<version>/`            | インストール済みの各バージョンのプログラムコード。サービスはここに書き込みません   |
| `runtime/`                       | Node.js。グラフィカルインストーラーは、PostgreSQLとWinSWもここに配置します         |
| `config/`                        | 設定、キー、回復キー。[設定](./configuration)を参照してください                    |
| `data/`                          | ネイティブインストールのファイルストレージ                                         |
| `database/`                      | 管理対象のPostgreSQLクラスター。Windowsではそのログも含みます                      |
| `logs/`                          | Windowsサービスのログと、Windowsの更新ツールのログ                                 |
| `service/`                       | Windowsサービスのラッパー                                                          |
| `updates/`                       | コンソールからの更新リクエストと、更新ツールの状態                                 |

Composeのインストールでは、データは`data/`ではなく、Dockerボリューム`proanima-arkvory_storage`（ファイル）と`proanima-arkvory_catalog`（データベース）に保存されます。

`releases/`内の古いバージョンは、自動では削除されません。更新が成功した後で、使っていないバージョンを削除できます。現在のバージョンと、`journal.json`に記載されている直前のバージョンは残してください。

## 回復キー {#recovery-key}

インストーラーは`config/bootstrap-token.txt`を作成します。このファイルには**回復キー**が入っています。管理者権限を持つキーです。読み取れるのは、rootまたはAdministratorsグループだけです。

- インストーラーが所有者アカウントを作成しなかった場合に、最初の所有者アカウントを作成するときに一度だけ使います。コンソールは初回起動時にこのキーを求めます。
- インストール用のツールは、サーバー上でこのキーを読み取ります。所有者の作成、`arkvory configure --backup-vault`、更新後のバックアップの確認、データベーススキーマを変更する前のバックアップです。**このファイルを削除しないでください**。
- クライアント、CIシステム、スクリプトにはコピーしないでください。日常の作業には、権限を限定したユーザーアカウントとサービスキーを作成します。[アカウントとアクセス](../use/accounts)を参照してください。

回復キーを置き換えるには、[設定](./configuration)を参照してください。

## 次のステップ {#next-steps}

1. お使いのプラットフォームのページに従ってインストールします：[Windows](./windows)、[Linux](./linux)、[Docker Compose](./docker)。
2. サインインして、最初のファイルを公開します。[クイックスタート](../guide/quick-start)を参照してください。
3. 他のコンピューターからクライアントが接続する前に、[HTTPS](./https)を設定します。
4. バックアップの保管庫を接続し、最初のバックアップを実行します。[バックアップ](../operate/backups)を参照してください。
5. [更新ポリシー](./updates)を選びます。
