# ライセンス

無料のArkvoryコアは、有料モジュールのライセンスなしで動作します。ライセンスは、[Arkvory Pro](modules#pro)を含むProAnimaStudioの有料機能を有効にします。期限切れになっても既存のProデータが読めなくなることはありません。有料機能を利用できない場合、新規アップロードはコアのストレージと通常の転送を使用します。ライセンスを有効化するまでは、Arkvoryがライセンスに関する情報を外部へ送ることはありません。

このページのコマンドは、インストール先ホストで、Linuxではroot、Windowsでは管理者として実行します。Docker Composeのインストールではモジュールを読み込まないため、これらのコマンドを拒否します。

## オンラインでの有効化 {#activate}

1. ProAnimaStudioのサイトで入手したライセンスキーを、`/root/arkvory.key`など、自分だけが読めるファイルに保存します。
2. 有効化します。

   ```bash
   sudo arkvory license activate --key-file /root/arkvory.key --root /opt/proanima-arkvory
   ```

3. 有効化後、ローカルのキーファイルを削除します。復旧時に再び必要になる場合があるため、アカウントからライセンスキーを取得できる状態を維持してください。

Arkvoryは、証明書を検証するHTTPSで、インストールのハブ（`config/hub.json`のアドレス。更新時と同じ）にリクエストを送信します。そのインストールとリクエストに対する、ProAnimaStudioのライセンス鍵で署名した応答だけを受け入れます。入力ミスのあるキーは、送信前に拒否します。同じインストールを同じキーで再度有効化しても、ライセンスの利用枠を追加で消費しません。

### 送信する情報 {#sent}

| リクエスト | 内容                                                                                                                |
| ---------- | ------------------------------------------------------------------------------------------------------------------- |
| 有効化     | ライセンスキー、インストールID、ランダム値、Arkvoryバージョン、インストール済み有料モジュールのIDとバージョン、時刻 |
| 更新       | 有効化IDとその秘密情報、ランダム値、シーケンス番号、バージョン                                                      |

ライセンシー名、人名、住所、マシンの詳細、データ量、リポジトリ名、コンテンツ、メタデータ、利用統計を送信することはありません。統計を無効にしても、ここで送る情報は増減しません。ハブを無効にしている場合（`--hub-off`）は、[オフライン有効化](#offline)を使用してください。

### 保存する情報 {#kept}

- トークン：ハブの署名付き文書を、データベースとバックアップに保存します。
- 有効化の秘密情報：`config/licenses/`内のファイルに保存し、サービスのアカウントだけが読み取れます。データベース、ログ、バックアップには含みません。
- ライセンスキー：どこにも保存しません。

## 状態の確認 {#status}

```bash
sudo arkvory license status --root /opt/proanima-arkvory
```

スクリプト用には`--json`を追加します。グローバル管理者は、`GET /api/v1/system/license`（[リファレンス](../api/reference/system#getSystemLicense)）で同じ情報を確認できます。Arkvoryは保存済み文書を毎回再検証します。ProAnimaStudioが署名していない文書は`invalid`になり、何の機能も有効にしません。

| 状態            | 意味                                                                             | 有料機能の書き込み           |
| --------------- | -------------------------------------------------------------------------------- | ---------------------------- |
| `valid`         | ライセンスが有効。ハブがしばらく応答していなければ`refreshFailing`               | モジュールの方式             |
| `offline-grace` | 1日超更新していない。トークンは`offlineGraceUntil`まで有効                       | モジュールの方式             |
| `grace`         | ライセンス期間が終了。`graceUntil`まで更新の猶予期間                             | モジュールの方式             |
| `mismatch`      | トークンが別のインストールに属する（別の場所への復元）。`graceUntil`まで猶予期間 | その時点までモジュールの方式 |
| `expired`       | `trial_expired`、`licence_expired`、または`activation_stale`（トークン期限切れ） | コアの形式                   |
| `revoked`       | 署名付きの取り消し。理由を表示                                                   | コアの形式                   |
| `invalid`       | 保存済み文書の検証に失敗                                                         | コアの形式                   |

どの状態でも、データの読み取り、バックアップ、復元は利用でき、ライセンスを理由に公開が失敗することはありません。ライセンスがなければ、有料モジュールは無料コアの形式で新しいデータを書き込みます。更新に成功すると、モジュールの方式による書き込みを自動で再開します。

## 更新とオフライン期間 {#refresh}

ワーカーは、各有効化をおよそ1日1回、および起動時に更新します。更新ごとに新しいトークンと秘密情報を取得し、以前の秘密情報は使えなくなります。

ハブに接続できない場合、ワーカーは15分後に再試行し、その後は毎回待ち時間を増やして最大6時間にします。ライセンスは`valid`を維持し、更新なしで1日経過すると`offline-grace`になります。トークンが期限切れになると（オフライン期間：デフォルト30日、試用版は7日）、`activation_stale`を伴う`expired`になります。`licence_expired`や`activation_suspended`など、ハブによる拒否は再試行しません。問題を解決してから、次を実行してください。

```bash
sudo arkvory license refresh --root /opt/proanima-arkvory
```

時計を戻しても期間は延びません。Arkvoryは、それまでに確認した最新の時刻で判断します。データベースの時計がその時刻より1日超遅れると、`clockRollback`を表示します。

更新リクエストがハブに届いた可能性があり、応答を失った場合、Arkvoryは再起動後も含め、10分間の期間内で1回だけ再送を許可します。結果が不明のまま、再送枠を使い切った、期間が終了した、または返されたトークンが無効な場合、`activation_recovery_required`によりそれ以降の更新を停止します。現在のトークンは有効期限まで有効です。キーを取得し、`license activate --key-file <file>`を再実行してください。`license refresh`ではこの状態を解消できません。

### コピーと復元 {#copies}

仮想マシンのクローンなど、インストールのコピーは同じ秘密情報を保持します。両方が更新すると、ハブは有効化を一時停止します（`activation_secret_reused`）。残すインストールで、キーを使って再度有効化してください。

別のインストールにバックアップを復元すると、古いインストールに属するトークンを引き継ぐため、猶予期間付きの`mismatch`になります。キーで新しいインストールを有効化してから、古いインストールを無効化してください。

オフライン期間に加えてさらに30日間更新していない有効化は失効し、利用枠を解放します。次の更新では、空き枠があれば再取得し、なければ`activation_lapsed`で拒否します。別のインストールを無効化してから更新してください。

## 無効化 {#deactivate}

```bash
sudo arkvory license deactivate lic_0123456789ABCDEFGHJKMNPQRS --root /opt/proanima-arkvory
```

ライセンスまたは1つの有効化を指定します。ハブが利用枠を解放し、Arkvoryが秘密情報を削除します。

## オフライン有効化 {#offline}

ハブに接続できないホストでは：

1. リクエストファイルを書き出します。

   ```bash
   sudo arkvory license request --key-file /root/arkvory.key --out /root/request.json --root /opt/proanima-arkvory
   ```

   ファイルに含むのはキーのSHA-256だけで、キー自体は含みません。Arkvoryは、この処理でネットワークに接続しません。

2. ProAnimaStudioアカウントでファイルをアップロードし、応答をダウンロードします。
3. 応答をインストールします。

   ```bash
   sudo arkvory license install /root/answer.json --root /opt/proanima-arkvory
   ```

応答は、このインストールのリクエストに対応している必要があります。オフライン有効化は自動更新しません。有効期限まで、最長365日間有効で、新しいリクエストで更新します。このようなホストへの取り消しの反映は、同じ方法でインストールするライセンス失効リストを通じてのみ行います。

## エラー {#errors}

| コード                                              | 意味                                                                                   |
| --------------------------------------------------- | -------------------------------------------------------------------------------------- |
| `licence_key_invalid`                               | ハブにキーが登録されていない                                                           |
| `activation_limit_reached`                          | ライセンスの全利用枠が埋まっている。別のインストールを無効化する                       |
| `answer_invalid`                                    | ProAnimaStudioの署名がない、または別のインストール・リクエストへの応答。何も保存しない |
| `installation_mismatch`、`nonce_unknown`            | オフライン応答が別のインストールに属する、または待機中のリクエストに対応しない         |
| `seq_replayed`                                      | 保存済みのものより古い文書のため拒否                                                   |
| `revocation_rollback`                               | 保存済みのものより古い失効リスト                                                       |
| `unreachable`、`timeout`、`tls_failed`、`hub_error` | ハブに接続できなかった。ワーカーが再試行する                                           |
