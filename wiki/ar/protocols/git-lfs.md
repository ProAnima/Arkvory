# Git LFS

كل مستودع Arkvory هو خادم Git LFS. يبقى مستودع git في موضعه، مثل GitHub أو GitLab أو Gitea. لا تنتقل إلى Arkvory إلا الملفات الكبيرة التي يتتبعها Git LFS وأقفال الملفات. كائنات LFS مُخرَجات عادية، لذلك تنطبق عليها أذونات المستودع وحصص التخزين وفحوص SHA-256 والنسخ الاحتياطية والمرايا.

## إعداد مستودع git {#set-up}

تحتاج إلى عنوان الخادم عبر HTTPS (راجع [HTTPS](../install/https))، ومستودع Arkvory مثل `games`، ومفتاح (راجع [الحسابات والمفاتيح](../use/accounts)).

1. ثبّت Git LFS على كل جهاز يستخدم المستودع، وشغّل `git lfs install` مرة واحدة لكل مستخدم.
2. أنشئ الملف `.lfsconfig` في جذر مستودع git وأدرجه في إيداع. يجعل الفريق بأكمله يستخدم Arkvory:

```ini
[lfs]
	url = https://arkvory.example/lfs/games
```

3. تتبّع أنماط الملفات. يكتب ذلك `.gitattributes` الذي تدرجه في إيداع أيضًا:

```bash
git lfs track "*.psd" "*.fbx" "*.wav" "*.uasset" "*.umap"
git add .gitattributes .lfsconfig
```

4. نفّذ الإيداع والدفع كالمعتاد. يطلب الطلب الأول بيانات الاعتماد: راجع [تسجيل الدخول](#sign-in).

عنوان LFS للمستودع هو دائمًا `https://<host>/lfs/<repository>`.

لنقل ملفات موجودة أصلًا في LFS على خادم آخر، نزّل جميع الكائنات من الخادم القديم أولًا، ثم غيّر `lfs.url` وارفعها:

```bash
git lfs fetch --all origin
git config lfs.url https://arkvory.example/lfs/games
git lfs push --all origin
```

## تسجيل الدخول {#sign-in}

يقبل Arkvory مفتاحه بوصفه كلمة مرور لمصادقة HTTP Basic. لا يُفحص اسم المستخدم: استخدم أي اسم. يمكن أن يأتي المفتاح أيضًا كرمز Bearer.

يطلب Git اسم المستخدم وكلمة المرور عبر مساعد بيانات الاعتماد في أول مرة يستجيب فيها الخادم بالحالة `401`. يحفظهما المساعد: Git Credential Manager على Windows وmacOS، و`credential.helper store` أو `cache` على Linux.

| المستخدم        | المفتاح                                                                                 |
| --------------- | --------------------------------------------------------------------------------------- |
| المطوّر          | رمز وصول شخصي. النطاق `read-write` للدفع والأقفال، والنطاق `read` للاستنساخ والسحب فقط. |
| خادم البناء، CI | مفتاح خدمة بالإجراءات المذكورة في [الأذونات](#permissions)                              |

يحتفظ Git ببيانات اعتماد لكل مضيف. لا يستبدل مفتاح Arkvory بيانات اعتماد المضيف الذي يضم مستودع git، مثل GitHub.

على مشغّل CI بلا مساعد بيانات اعتماد، ضع المفتاح في الإعدادات المحلية لنسخة المستودع المسحوبة. يوجد المفتاح حينها فقط في `.git/config` لمساحة العمل تلك، ولا يوضع أبدًا في `.lfsconfig`:

```bash
git config lfs.url "https://ci:${ARKVORY_KEY}@arkvory.example/lfs/games"
```

لا تُدرج مفتاحًا في إيداع. لا تطبعه في السجلات. أزِل مساحة العمل بعد المهمة.

## العمل اليومي {#daily-work}

يعمل Git LFS كما يعمل مع أي خادم LFS. الأوامر التي تستخدمها:

| الأمر                                   | ما يفعله                                                                 |
| --------------------------------------- | ------------------------------------------------------------------------ |
| `git push`                              | يرفع كائنات LFS الجديدة إلى Arkvory قبل دفع الإيداعات                    |
| `git clone`، `git pull`، `git checkout` | تنزّل الكائنات التي تحتاجها شجرة العمل                                    |
| `git lfs fetch --all`                   | ينزّل كائنات جميع الفروع                                                  |
| `git lfs ls-files`                      | يسرد الملفات المتتبَّعة ومعرّفاتها المختصرة                                 |
| `git lfs push --all origin`             | يرفع جميع الكائنات المحلية مجددًا. لا تُرسل الكائنات الموجودة لدى Arkvory. |

لا يُرسل مجددًا كائن موجود أصلًا لدى Arkvory بالمعرّف والحجم نفسيهما. لا يرسل الدفع المكرر بعد انقطاع إلا ما هو مفقود.

## قفل الملفات {#locks}

لا يمكن دمج الأصول الثنائية. يُعلِم القفل الفريق بأن شخصًا واحدًا يحرّر ملفًا. تنتمي الأقفال إلى مستودع Arkvory، لا إلى فرع.

```bash
git lfs lock Content/Maps/Level01.umap
git lfs locks
git lfs unlock Content/Maps/Level01.umap
```

- يفشل `git lfs lock` ثانٍ على المسار نفسه بالرسالة "already created lock" ويذكر المالك.
- يُعرض المالك باسم المستخدم أو حساب الخدمة وقت إنشاء القفل. ويُعرض معرّف مفتاح الملف إذا استُخدم مفتاح ملف.
- لا يفتح قفل الملف إلا مالكه. يحتاج `git lfs unlock --force` على قفل شخص آخر إلى مفتاح خدمة بالإجراء `artifact.delete` في المستودع. لا تستطيع الرموز الشخصية كسر الأقفال.
- مسار القفل مسار داخل مستودع git: حتى 1024 محرفًا، مع `/` بين المجلدات، ومن دون مقاطع فارغة أو `.` أو `..` أو شرطة مائلة عكسية أو نقطتين رأسيتين.
- يعرض `git lfs locks` عددًا قدره 100 قفل في كل صفحة.

فعّل الفحص قبل الدفع، لكي يرفض git دفع تغييرات إلى ملفات قفلها آخرون. الإعداد خاص بكل عنوان خادم:

```bash
git config lfs.https://arkvory.example/lfs/games.locksverify true
```

حدّد أنواع الملفات التي يجب قفلها قبل التحرير. يبقيها Git LFS عندئذ للقراءة فقط حتى تقفلها:

```bash
git lfs track --lockable "*.umap" "*.uasset"
```

يتطلب فحص الأقفال عند الدفع حق الكتابة، لذلك لا يستطيع رمز للقراءة فقط استخدامه. استخدم `git lfs locks` لسرد الأقفال، وهو ما يسمح به حق القراءة.

## نصائح لـUnity وUnreal {#game-engines}

- Unity: أبقِ الأصول النصية (`.unity` و`.prefab` و`.asset`) في git، واضبط تسلسل الأصول على Force Text. تتبّع الملفات الثنائية الكبيرة في LFS، مثل `*.png` و`*.psd` و`*.fbx` و`*.wav` و`*.mp4` و`*.exr`. تُقبل أيضًا الملفات النصية التي تتتبّعها في LFS.
- Unreal Engine: تتبّع `*.uasset` و`*.umap` والملفات المصدرية الكبيرة، وحدّد `*.uasset` و`*.umap` كملفات قابلة للقفل.
- تستخدم تكاملات المحرّر التي تستدعي أوامر قفل LFS بروتوكول قفل الملفات القياسي لـGit LFS. يُختبر Arkvory باستخدام عميلي سطر الأوامر `git` و`git-lfs`.
- لا تضع مخرجات بناء متغيّرة بحجم عشرات الغيغابايت في LFS. ارفعها كمُخرَجات أو [ملفات خام](./raw-files) باستخدام [`arkvoryctl`](./cli). لا تُحذف كائنات LFS بسياسة الاحتفاظ أبدًا، لذلك تبقى إلى الأبد.
- تُخدَم الشيفرة أو الأدوات الكبيرة القابلة لإعادة الاستخدام والتي تشترك فيها مشروعات Unity بصورة أفضل عبر [حزم Unity](./unity-npm).

## ما الذي يُخزَّن {#what-is-stored}

- كائن LFS مُخرَج في مستودع Arkvory. اسمه وهويته هما SHA-256 لمحتواه (`oid` في LFS)، ويحمل التسمية `lfs`. ترى هذه المُخرَجات في وحدة التحكم ضمن [[ui:catalog]].
- يتحقق Arkvory من الحجم وSHA-256 أثناء تلقي الكائن. إذا اختلفا عن `oid`، يفشل الرفع بالحالة `422` ولا يُخزَّن شيء.
- ينتمي الكائن إلى المستودع. يحتفظ مستودعا Arkvory بنسختين خاصتين بهما من الملف نفسه.
- لا تحذف سياسة الاحتفاظ كائنات LFS أبدًا، لأن الخادم لا يستطيع معرفة الإيداعات التي لا تزال تحتاج إليها. لا يوجد أمر لحذف كائن LFS. خطّط لحصة تخزين المستودع بما يكفي لكامل محفوظات الأصول.
- الأقفال صفوف في قاعدة البيانات. تشملها النسخ الاحتياطية.

## الأذونات {#permissions}

تحصل الرموز الشخصية ومفاتيح الملفات على حق القراءة أو الكتابة في المستودع. وتحصل مفاتيح الخدمة على إجراءات محددة.

| العملية                                    | إجراءات مفتاح الخدمة | الرمز الشخصي أو مفتاح الملف          |
| ------------------------------------------ | -------------------- | ------------------------------------ |
| التنزيل (`clone` و`fetch` و`pull`)         | `content.read`       | حق القراءة                           |
| الرفع (`push`)                             | `upload.create`      | حق الكتابة، ونطاق الرمز `read-write` |
| سرد الأقفال                                | `artifact.list`      | حق القراءة                           |
| إنشاء الأقفال الخاصة والتحقق منها وتحريرها | `upload.create`      | حق الكتابة، ونطاق الرمز `read-write` |
| تحرير قفل شخص آخر (`--force`)              | `artifact.delete`    | غير ممكن                             |

تحتاج مهمة CI التي تدفع وتسحب إلى `content.read` و`upload.create` و`artifact.list`. يظل المفتاح الذي لا يُسمح له إلا بالدفع قادرًا على معرفة وجود كائن، لكي لا يرفعه مرتين.

يستطيع الرمز الشخصي للقراءة فقط الاستنساخ والسحب، مع أن طلب قائمة التنزيل من نوع `POST`. ولا يستطيع الدفع أو القفل. تُشرح المرآة وبوابة القراءة في [المرايا وبوابات القراءة](#mirrors-and-read-gateways).

## كيفية عمل النقل {#how-it-works}

لا تحتاج إلى هذه التفاصيل للعمل اليومي. وهي تساعد عند تشخيص وكيل أو جدار ناري.

1. يرسل Git LFS طلب `POST /lfs/<repository>/objects/batch` واحدًا مع العملية (`download` أو `upload`) وقائمة الكائنات. حتى 1000 كائن في الطلب. يرسل Git LFS ما لا يزيد على 100 افتراضيًا.
2. يستجيب Arkvory برابط لكل كائن يجب نقله، صالح لمدة ساعة واحدة. وللرفع، يُسقط الكائنات الموجودة لديه أصلًا.
3. يرسل Git LFS كل كائن باستخدام `PUT` أو ينزّله باستخدام `GET`، إلى `/lfs/<repository>/objects/<oid>`. يحمل الطلب المفتاح نفسه المستخدم في طلب الدفعة.
4. يحتاج `PUT` إلى ترويسة `Content-Length`. يُرفض الرفع بترميز النقل المجزّأ بالحالة `422`.

الميزات المدعومة:

| العنصر           | القيمة                                                                                   |
| ---------------- | ---------------------------------------------------------------------------------------- |
| محوّل النقل       | `basic` فقط                                                                              |
| خوارزمية التجزئة | `sha256` فقط. يحصل العميل الذي يطلب غيرها على `409`.                                     |
| المصادقة         | Basic (المفتاح كلمة مرور) أو Bearer                                                      |
| التنزيل          | `GET` و`HEAD` مع طلبات `Range`                                                           |
| نوع الوسائط      | `application/vnd.git-lfs+json` لطلبات JSON. تُخزَّن أجسام الكائنات من أي نوع وسائط كبايتات. |

الأخطاء مستندات JSON تحتوي على `message` و`request_id`. اذكر `request_id` عند طلب المساعدة من المسؤول.

تشير الروابط إلى العنوان الذي استخدمه العميل للوصول إلى الخادم. عندما ينهي وكيل عكسي اتصال HTTPS، يجب أن يمرّر الترويسة `Host` ويرسل `X-Forwarded-Proto: https`، كما في مثال nginx في تعليمات التثبيت، لكي تستخدم الروابط `https`. لا يضع Arkvory المفتاح في رابط إلا عندما يكون الرابط `https` أو يشير إلى الحاسوب المحلي. عبر HTTP غير مشفّر إلى مضيف آخر، لا يستطيع git إرسال المفتاح مع الكائن ويفشل النقل.

## الملفات الكبيرة والاستئناف {#large-files}

- يرسل Git LFS كل كائن في طلب `PUT` واحد. بعد فشل، يبدأ الكائن مجددًا من البايت الأول. محوّل `tus`، الذي يستأنف داخل الكائن، غير مدعوم.
- يجب أن ينتهي طلب الرفع خلال 30 دقيقة، وألا يتوقف مؤقتًا لأكثر من 30 ثانية (`ARKVORY_UPLOAD_DEADLINE_MS` و`ARKVORY_UPLOAD_IDLE_TIMEOUT_MS`). يحتاج ملف بحجم عدة غيغابايتات إلى شبكة سريعة ومستقرة. للملفات الأكبر، استخدم [`arkvoryctl`](./cli) الذي يرفع في أجزاء.
- تقبل التنزيلات طلبات `Range`.
- يمكن أن يبلغ حجم الكائن الحد الأقصى لحجم الكائن في التثبيت (`ARKVORY_MAX_OBJECT_BYTES`، نحو 10 TiB افتراضيًا). يُرفض الكائن الأكبر في استجابة الدفعة بالحالة `422`.

يسمح الخادم افتراضيًا بعدد 8 من عمليات الرفع المتزامنة و4 لكل مفتاح (`ARKVORY_MAX_UPLOADS` و`ARKVORY_MAX_UPLOADS_PER_PRINCIPAL`). يرسل Git LFS عددًا قدره 8 كائنات في الوقت نفسه افتراضيًا. تنتظر عمليات الرفع الأخرى فتحة متاحة وتتوقف عن الانتظار بعد 20 ثانية (`ARKVORY_TRANSFER_QUEUE_TIMEOUT_MS`) بالحالة `503`. يعيد Git LFS محاولة الكائن الفاشل عدة مرات، لكن دفع الملفات الكبيرة يكون أكثر موثوقية مع عمليات نقل متوازية أقل:

```bash
git config lfs.concurrenttransfers 1
```

يمكنك أيضًا أن تطلب من المسؤول رفع الحدود. تُشرح في [متغيرات البيئة](../reference/environment#transfers-and-bandwidth).

## المرايا وبوابات القراءة {#mirrors-and-read-gateways}

| الموضع                                  | الاستنساخ والجلب                                              | الدفع والأقفال                                                       |
| --------------------------------------- | ------------------------------------------------------------- | -------------------------------------------------------------------- |
| الخادم الرئيسي                          | نعم                                                           | نعم                                                                  |
| [مرآة](../operate/mirrors)              | نعم. تحتوي المرآة على كائنات مصدرها، لذا وجّه `lfs.url` إليها. | مرفوضة (`409`، والسبب `mirror_read_only`). لا تُنسخ الأقفال إلى مرآة. |
| [بوابة قراءة](../operate/read-gateways) | لا. قائمة التنزيل طلب `POST` لا تقبله بوابة القراءة.          | لا                                                                   |

وجّه `lfs.url` دائمًا إلى الخادم الرئيسي، أو إلى مرآة للأجهزة المخصصة للقراءة فقط.

## استكشاف الأخطاء وإصلاحها {#troubleshooting}

| الرسالة أو العَرَض                                       | السبب                                                                    | الإجراء                                                                                                                                                                                      |
| ------------------------------------------------------ | ------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `401` أو خطأ تفويض                                     | مفتاح مفقود أو غير صحيح، أو رمز منتهي أو مُبطل                            | أزِل بيانات الاعتماد المحفوظة في مدير بيانات الاعتماد وادفع مجددًا بمفتاح صالح                                                                                                                 |
| `403` مع "Read-only personal access token"             | نطاق الرمز هو `read`                                                     | أنشئ رمزًا بالنطاق `read-write`                                                                                                                                                               |
| `403`                                                  | يفتقر المفتاح إلى حق الوصول لهذه العملية، أو لم يُمنح الوصول إلى المستودع | أضف الإجراءات من [الأذونات](#permissions)                                                                                                                                                    |
| `Lock failed: already created lock`                    | هناك من يمسك القفل                                                       | اطلب من المالك فتح القفل، أو من مسؤول استخدام `--force`                                                                                                                                      |
| `422` مع "Object exceeds the maximum size"             | الكائن أكبر من حد التثبيت                                                | ينطبق الحد نفسه على `arkvoryctl`. استخدم كائناً أصغر، أو إذا كان حد التثبيت أقل، فاطلب من المسؤول زيادة `ARKVORY_MAX_OBJECT_BYTES` (بالبايت)، دون تجاوز الحد الأقصى الثابت البالغ 10,000 GiB. |
| `422` عند الرفع                                        | المحتوى لا يطابق `oid`؛ تغيّر الملف أثناء الدفع                           | شغّل `git lfs push` مجددًا                                                                                                                                                                     |
| `503` أو `Retry-After`                                 | عدد كبير جدًا من عمليات النقل المتزامنة                                   | خفّض `lfs.concurrenttransfers` وأعد المحاولة                                                                                                                                                  |
| `507`                                                  | بُلغت حصة تخزين المستودع أو سعة التثبيت                                   | حرّر مساحة أو اطلب حصة تخزين أكبر                                                                                                                                                             |
| `409` عند الرفع                                        | المستودع مرآة                                                            | ادفع إلى الخادم الرئيسي                                                                                                                                                                      |
| الملفات في شجرة العمل ملفات نصية صغيرة تحتوي على `oid` | لم تُنزَّل الكائنات، أو لم يُشغَّل `git lfs install`                           | شغّل `git lfs install` ثم `git lfs pull`                                                                                                                                                      |
| `x509: certificate signed by unknown authority`        | لا يثق العميل بالشهادة                                                   | أضف جهة إصدار الشهادة إلى مخزن الثقة في النظام، أو اضبط `http.sslCAInfo`                                                                                                                     |

لا توقف التحقق من TLS ‏(`GIT_SSL_NO_VERIFY`): يُرسل المفتاح مع كل طلب.
