# خطافات الويب

يُعلِم خطاف الويب نظامك بأن شيئًا قد تغيّر في مستودع، لكي لا يضطر إلى الاستقصاء الدوري. يرسل عامل Arkvory طلب HTTP من نوع `POST` إلى عنوان URL الخاص بك لكل حدث في [تغذية تغييرات](../api/reference/artifacts#listCatalogChanges) المستودع. استخدمه لبدء نشر عند نشر نسخة بناء، أو لتحديث ذاكرة تخزين مؤقت عندما يحصل مسار على إصدار جديد.

يضبط المسؤول الاشتراكات في ملف. لا توجد لها API أو صفحة في وحدة التحكم بعد. يمكنك أيضًا قراءة التغذية بنفسك باستخدام `GET /api/v1/repositories/<repository>/changes`.

## كيفية عمل التسليم {#how-it-works}

- **يتابع الاشتراك الواحد مستودعًا واحدًا** ويرسل إلى عنوان URL واحد.
- **تأتي الأحداث بالترتيب، حدثًا واحدًا في كل مرة.** ينتظر الحدث التالي حتى يستجيب المستقبِل بحالة `2xx`.
- **يحدث التسليم مرة واحدة على الأقل.** بعد تعطل أو فقدان استجابة، قد يصل الحدث نفسه مجددًا. لكل حدث `id` ثابت: استخدمه لمنع معالجة النسخ المكررة.
- **يتلقى الاشتراك الجديد الأحداث الجديدة فقط.** لا تُرسل الأحداث التي سبقت إنشاءه.
- **لا يؤخّر المستقبِل المتوقف إلا اشتراكه الخاص.** ينتظر الحدث. يعيد Arkvory المحاولة بعد 12 ثانية، ويضاعف الانتظار حتى ساعة واحدة، ويرسل الأحداث بالترتيب عندما يستجيب المستقبِل مجددًا. لا تنتظر عمليات الرفع والتنزيل خطاف ويب أبدًا.

## إعداد اشتراك {#set-up}

تحتاج إلى الوصول إلى ملفات الخادم والحق في إعادة تشغيل العامل. راجع [الإعدادات](../install/configuration).

1. أنشئ ملفًا يحتوي على سر التوقيع: 16 محرفًا عشوائيًا قابلًا للطباعة على الأقل، مثل `/root/ci.secret`. يحتاج المستقبِل إلى السر نفسه.
2. شغّل `configure` مع الاشتراك. يتحقق الأمر من مدخلاتك، وينسخ السر تحت `config/webhooks`، ويكتب ملف الاشتراكات والإعداد، ويعيد تشغيل الخدمات، ويستعيد الإعدادات السابقة إذا لم تصبح جاهزة. لا يتصل بالمستقبِل.

```bash
sudo arkvory configure --root /opt/proanima-arkvory \
  --webhook ci --webhook-repository releases \
  --webhook-url https://ci.example.com/hooks/arkvory \
  --webhook-secret-file /root/ci.secret \
  --webhook-actions artifact.publish
```

3. ابحث عن `webhook.started` في سجل العامل، وانشر ملفًا وراقب المستقبِل.

يكتب الأمر `config/webhooks/webhooks.json`، ويمكنك أيضًا كتابته يدويًا وتحديد مساره في `ARKVORY_WEBHOOKS_FILE`. شغّل الأمر مجددًا بالاسم نفسه لتغيير اشتراك. يزيله `--webhook-detach ci`: تُحذف ملفاته ويُنسى موضعه. يغيّر الاستدعاء الواحد اشتراكًا واحدًا ولا يمكن مزجه مع خيارات `configure` الأخرى.

يحتوي الملف على هذه الحقول:

```json
{
  "webhooks": [
    {
      "id": "ci",
      "repository": "releases",
      "url": "https://ci.example.com/hooks/arkvory",
      "secretFile": "/opt/proanima-arkvory/config/webhooks/ci.secret",
      "actions": ["artifact.publish"]
    }
  ]
}
```

| الحقل            | المعنى                                                                                                                                                                  |
| ---------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `id`             | اسم الاشتراك: من 1 إلى 64 محرفًا من `a-z` و`0-9` و`_` و`-`. يُحفظ تقدمه تحت هذا الاسم.                                                                                    |
| `repository`     | المستودع الذي تُرسل تغذيته.                                                                                                                                              |
| `url`            | المستقبِل. عنوان HTTPS بلا اسم مستخدم أو استعلام أو جزء، وبحد أقصى 2048 محرفًا. لا يُسمح بـHTTP غير المشفّر إلا مع `localhost` و`127.0.0.1` و`[::1]`.                       |
| `secretFile`     | المسار المطلق للملف الذي يحتوي على سر التوقيع.                                                                                                                          |
| `nextSecretFile` | سر ثانٍ اختياري من أجل [التدوير](#rotate-the-secret).                                                                                                                    |
| `actions`        | قائمة اختيارية بإجراءات التغذية المطلوب إرسالها، مثل `artifact.publish` و`artifact.delete` و`asset.replace` و`stage.added` و`package.register`. من دونها يُرسل كل إجراء. |

يوقف الملف غير الصحيح العامل عند بدء التشغيل مع `worker.unavailable`. يُسمح بما يصل إلى 16 اشتراكًا. في تثبيت Compose، يركّب الأمر أيضًا `config/webhooks` داخل حاوية العامل.

## الطلب {#request}

| الترويسة              | القيمة                                                       |
| --------------------- | ------------------------------------------------------------ |
| `Content-Type`        | `application/json`                                           |
| `X-Arkvory-Delivery`  | معرّف الحدث `id`. يبقى نفسه في كل إعادة للحدث.                |
| `X-Arkvory-Event`     | إجراء التغذية، مثل `artifact.publish`.                       |
| `X-Arkvory-Timestamp` | توقيت Unix بالثواني عند توقيع الطلب.                         |
| `X-Arkvory-Signature` | `sha256=<hex>`. أثناء التدوير توجد قيمتان تفصل بينهما فاصلة. |

الجسم بصيغة JSON:

```json
{
  "id": "releases:128",
  "repository": "releases",
  "sequence": "128",
  "action": "artifact.publish",
  "artifactId": "00000000-0000-4000-8000-000000000001",
  "detail": null
}
```

يمثل `sequence` الموضع في التغذية، كسلسلة عشرية. ويكون `detail` مسار الملف أو المرحلة للإجراءات التي تتضمن أحدهما. لا يحتوي الجسم على صاحب التغيير أو محتوى الملفات أو بيانات التعريف: استخدم `artifactId` لقراءة الحالة الحالية عبر [API](../api/index).

استجب بأي حالة `2xx` خلال 10 ثوانٍ. تُعد الحالة `3xx` (لا تُتبع عمليات إعادة التوجيه) أو `4xx` أو `5xx` أو خطأ اتصال أو انتهاء المهلة فشلًا. يقرأ Arkvory ما لا يزيد على 4 KiB من الاستجابة ويتجاهله.

## التحقق من التوقيع {#verify}

التوقيع هو HMAC-SHA256 باستخدام سرك على النص `<timestamp>.<body>`، ويُكتب بصيغة `sha256=` متبوعة بالملخص الست عشري. تحقق منه قبل الوثوق بطلب:

1. اقرأ الجسم الخام قبل أي تحليل لـJSON.
2. ارفض الطلب عندما يختلف الطابع الزمني عن ساعتك بأكثر من 5 دقائق.
3. احسب التوقيع وقارنه بدالة ثابتة الزمن. إذا احتوت الترويسة على قيمتين، فاقبل أيًا منهما.

Node.js:

```js
import { createHmac, timingSafeEqual } from 'node:crypto';

export function verify(secret, headers, rawBody) {
  const timestamp = headers['x-arkvory-timestamp'];
  if (!/^\d{1,12}$/.test(timestamp ?? '')) return false;
  if (Math.abs(Date.now() / 1000 - Number(timestamp)) > 300) return false;
  const expected = Buffer.from(
    'sha256=' + createHmac('sha256', secret).update(`${timestamp}.${rawBody}`).digest('hex'),
  );
  return String(headers['x-arkvory-signature'] ?? '')
    .split(',')
    .some((given) => {
      const actual = Buffer.from(given.trim());
      return actual.length === expected.length && timingSafeEqual(actual, expected);
    });
}
```

Python:

```python
import hashlib, hmac, time

def verify(secret: bytes, headers, raw_body: bytes) -> bool:
    timestamp = headers.get("X-Arkvory-Timestamp", "")
    if not timestamp.isdigit() or abs(time.time() - int(timestamp)) > 300:
        return False
    digest = hmac.new(secret, timestamp.encode() + b"." + raw_body, hashlib.sha256).hexdigest()
    expected = "sha256=" + digest
    given = headers.get("X-Arkvory-Signature", "").split(",")
    return any(hmac.compare_digest(part.strip(), expected) for part in given)
```

## التعامل مع عمليات التسليم المتكررة {#repeats}

- خزّن `id` لكل حدث عالجته وتجاهل تكراره.
- استجب بسرعة: ضع العمل في طابور وأرجع `204`. يؤخّر المستقبِل البطيء كل حدث لاحق في اشتراكه.
- لا يعني التكرار أن العملية حدثت مرتين. تعامل مع الحدث بوصفه إشارة واقرأ الحالة الحالية من API.

## تدوير السر {#rotate-the-secret}

1. شغّل الأمر نفسه مع `--webhook-secret-file` للسر الحالي و`--webhook-next-secret-file` للجديد. يحمل كل طلب الآن توقيعين.
2. انقل المستقبِل إلى السر الجديد. يواصل المستقبِل الذي يقبل أيًا من التوقيعين العمل خلال ذلك.
3. شغّل الأمر مجددًا مع ملف السر الجديد في `--webhook-secret-file` ومن دون `--webhook-next-secret-file`.

## المستقبِلون الخاصون والشهادات {#private-receivers}

- يرفض Arkvory المستقبِلين على عناوين الاسترجاع المحلي والعناوين الخاصة والمحلية للرابط وعناوين بيانات التعريف السحابية، وكذلك الأسماء التي تُحلّ إلى هذه العناوين. يمنع هذا استخدام الخادم للوصول إلى خدمات داخلية.
- للإرسال إلى مستقبِل في شبكتك، أضف الشبكة باستخدام `--webhook-allow-private`، مثل `--webhook-allow-private 10.20.0.0/16` ‏(`ARKVORY_WEBHOOKS_ALLOW_PRIVATE`). يبقى هذا السماح حتى إزالة آخر اشتراك.
- لمستقبِل شهادته صادرة عن جهة إصدار خاصة بك، أضف ملف PEM لهذه الجهة بواسطة `--webhook-ca-file` ‏(`ARKVORY_WEBHOOKS_CA_FILE`). يجري التحقق من الشهادة دائمًا.

## مراقبة خطافات الويب {#monitor}

يكتب العامل `webhook.step_failed` مع `errorCode` عند فشل التسليم، و`webhook.recovered` عندما ينجح مجددًا. تُشرح المقاييس `arkvory_webhook_failing` و`arkvory_webhook_last_success_timestamp_seconds` والتنبيه `ArkvoryWebhookFailing` في [المراقبة](../operate/monitoring). يشير `webhook.stopped` إلى نهاية حلقة اشتراك، عند إيقاف التشغيل أو عندما يفقد العامل ملكية التخزين. يعني `webhook.prune_failed` أن العامل لم يستطع نسيان الاشتراكات المُزالة عند البدء؛ ويحاول مجددًا عند البدء التالي. لا يظهر الرمزان `unavailable` و`internal` إلا في السجل، ولا يظهران في `arkvory_webhook_failing`.

## اشتراك لا يتقدم {#stuck}

لا يتخطى Arkvory حدثًا أبدًا: وهذا ما يجعل التسليم موثوقًا. لذلك يوقف المستقبِل الذي يستمر في رفض حدث واحد، مثلًا بحالة `400` لأنه لا يستطيع تحليله، اشتراكه بأكمله. لا يُرسل أي حدث لاحق من ذلك الاشتراك؛ وتواصل الاشتراكات الأخرى العمل. يكتب العامل `webhook.step_failed` مع `http_4xx` ويعيد المحاولة بفاصل يصل إلى ساعة واحدة، وتصبح قيمة `arkvory_webhook_failing` هي `1`، وينطلق التنبيه `ArkvoryWebhookFailing` بعد 15 دقيقة.

1. أصلح المستقبِل ليستجيب للحدث بحالة `2xx`. يرسله Arkvory في المحاولة التالية، بعد نحو ساعة على الأكثر، ثم يرسل جميع الأحداث المنتظرة بالترتيب. يحتفظ تشغيل `configure` مجددًا بالاسم والمستودع نفسيهما بالموضع.
2. إذا كان قبول الحدث مستحيلًا، فأزِل الاشتراك باستخدام `--webhook-detach` وأضفه مجددًا. يبدأ من نهاية التغذية: **لا** تُرسل الأحداث المنتظرة. اقرأها من [تغذية التغييرات](../api/reference/artifacts#listCatalogChanges) بعد آخر `sequence` عالجه المستقبِل.

## استكشاف الأخطاء وإصلاحها {#troubleshooting}

| `errorCode`   | السبب والإجراء                                                                                                                                        |
| ------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| `blocked`     | عنوان المستقبِل غير مسموح (استرجاع محلي أو خاص أو محلي للرابط أو بيانات تعريف). استخدم عنوانًا عامًا أو أضف الشبكة إلى `ARKVORY_WEBHOOKS_ALLOW_PRIVATE`. |
| `timeout`     | لا استجابة خلال 10 ثوانٍ. استجب بسرعة أكبر وضع العمل في طابور.                                                                                         |
| `network`     | رُفض الاتصال أو لم يُعثر على الاسم أو أُعيد ضبط الاتصال. تحقق من URL وDNS والجدار الناري من الخادم.                                                      |
| `tls`         | الشهادة غير موثوقة أو منتهية أو تحمل اسمًا خاطئًا. أصلحها أو اضبط `ARKVORY_WEBHOOKS_CA_FILE`.                                                           |
| `redirect`    | استجاب المستقبِل بحالة `3xx`. لا تُتبع عمليات إعادة التوجيه: استخدم عنوان URL النهائي.                                                                  |
| `http_4xx`    | رفض المستقبِل الطلب. تحقق من فحص التوقيع لديه ومساره ومفتاحه.                                                                                          |
| `http_5xx`    | فشل المستقبِل. يواصل Arkvory إعادة المحاولة بفاصل يصل إلى ساعة واحدة.                                                                                  |
| `secret`      | ملف السر مفقود أو غير قابل للقراءة أو أقصر من 16 بايت.                                                                                                |
| `unavailable` | لم يستطع العامل قراءة التغذية أو حالة الاشتراك من قاعدة البيانات. لم يُرسل شيء؛ ويحاول مجددًا بعد 5 ثوانٍ. تحقق من قاعدة البيانات.                       |
| `internal`    | خطأ غير متوقع في العامل. لم يُرسل شيء؛ ويحاول مجددًا بعد 5 ثوانٍ. أبلغ عنه مع سجل العامل.                                                                |

لا يصل شيء؟ تحقق من وجود `webhook.started` في سجل العامل، ومن ضبط `ARKVORY_WEBHOOKS_FILE`، ومن اسم المستودع ومرشح `actions`. لا يرسل الاشتراك الجديد إلا الأحداث التي تلي خطوته الأولى.
