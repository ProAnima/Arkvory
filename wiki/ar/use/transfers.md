# الرفع والتنزيل

تُرسل الملفات إلى Arkvory على أجزاء مهما كان حجمها، ويمكن لعملية النقل المتوقفة أن تستأنف من حيث توقفت. توضح هذه الصفحة الطريقة في وحدة التحكم وباستخدام `arkvoryctl` وSDK وHTTP API.

يحتاج الرفع إلى الإجراءات `upload.create` و`upload.read` و`upload.write` و`upload.complete`. وبمستويات المجموعات، يحتاج إلى إذن الكتابة. ويحتاج التنزيل إلى `content.read`. راجع [الأذونات](./accounts#permissions).

## رفع ملف {#upload}

تتبع كل عملية رفع الخطوات نفسها. يحسب العميل SHA-256 للملف كاملًا، ويبدأ جلسة رفع باسم الملف وحجمه ومجموعه الاختباري. ثم يرسل الملف على أجزاء. وعند وصول جميع الأجزاء، يجمعها الخادم ويتحقق من المجموع الاختباري وينشر الملف بوصفه مُخرَجًا غير قابل للتغيير.

### في وحدة التحكم {#upload-console}

1. اختر [[ui:upload]] في الشريط الجانبي، أو [[ui:uploadFile]] في الشريط العلوي.
2. اختر الملف تحت [[ui:chooseFile]]. تقرأ وحدة التحكم الملف كاملًا مرة واحدة لحساب مجموعه الاختباري ([[ui:hashing]]). إذا كان حجمه عشرات الغيغابايت، يستغرق ذلك بعض الوقت قبل إرسال أول بايت.
3. اختر [[ui:startUpload]]. يعرض الشريط تحت [[ui:transferTitle]] مدى التقدم.
4. عند نشر الملف، يظهر معرّفه. افتح [[ui:catalog]] لعرضه.

يوقف [[ui:pause]] النقل ويحتفظ بالأجزاء التي وصلت. يحذّرك المتصفح قبل مغادرة الصفحة أثناء الرفع. لا ترسل وحدة التحكم تسميات أو بيانات تعريف مع الملف. أضفها بعد ذلك في [[ui:metadata]]؛ راجع [الملفات حسب المسار](./files#labels).

### باستخدام arkvoryctl {#upload-cli}

```bash
arkvoryctl upload ./Build/Game.zip --label test
arkvoryctl upload ./Build/Game.zip --file metadata.json --state ./job-state/game.json
arkvoryctl uploads status 3b0c0b8e-6a4e-4f5f-9d3b-5a6c1c9b0f11
arkvoryctl uploads cancel 3b0c0b8e-6a4e-4f5f-9d3b-5a6c1c9b0f11
```

يطبع `upload` المُخرَج عند نشره. يضيف `--label` تسمية واحدة. ويشير `--file` إلى ملف JSON يحتوي على `labels` و`metadata`، وله الأولوية. لتخزين الملف تحت مسار، استخدم `put`؛ ولنشر UPack، استخدم `packages publish`. راجع [سطر الأوامر](../protocols/cli#transfers).

### باستخدام SDK {#upload-sdk}

```typescript
const session = await releases.uploads.create(idempotencyKey, {
  name: 'Game.zip',
  size: String(file.size),
  sha256,
  labels: ['test'],
  metadata: { commit: 'abc123' },
});
const artifact = await releases.uploads.resume(session.id, file, {
  onProgress: (bytes) => console.log(bytes),
});
```

يرسل `resume` الأجزاء غير الموجودة على الخادم ويكمل الرفع. يوجد المثال الكامل، مع حساب المجموع الاختباري في Node.js، في [SDK لـTypeScript](../protocols/sdk#upload-a-large-file-with-resume-node-js).

### باستخدام HTTP API {#upload-http}

```bash
curl -X POST "$ARKVORY/api/v1/repositories/releases/uploads" \
  -H "Authorization: Bearer $ARKVORY_KEY" -H "Idempotency-Key: game-1234" \
  -H "Content-Type: application/json" \
  -d '{"name":"Game.zip","size":"73400320","sha256":"<64 hex digits>"}'

curl "$ARKVORY/api/v1/repositories/releases/uploads/$ID/parts" -H "Authorization: Bearer $ARKVORY_KEY"

curl -X PUT "$ARKVORY/api/v1/repositories/releases/uploads/$ID/parts/0" \
  -H "Authorization: Bearer $ARKVORY_KEY" -H "Content-Type: application/octet-stream" \
  -H "X-Content-SHA256: <64 hex digits of this part>" --data-binary @part-0.bin

curl -X POST "$ARKVORY/api/v1/repositories/releases/uploads/$ID/complete" \
  -H "Authorization: Bearer $ARKVORY_KEY"
```

الحجم سلسلة نصية عشرية. يتكون `Idempotency-Key` من 1 إلى 128 حرفًا أو رقمًا أو من الرموز `.` أو `_` أو `:` أو `-`. تتضمن استجابة الاستدعاء الأول `id` لعملية الرفع و`expiresAt`. ويعيد الاستدعاء الثاني حجم الجزء `partBytes` والأجزاء المخزّنة بالفعل. يكون كل جزء بهذا الحجم تمامًا، باستثناء الأخير. العمليات هي `createUpload` و`listUploadParts` و`putUploadPart` و`completeUpload` ([عمليات الرفع](../api/reference/uploads)).

للملف الصغير، يمكنك استخدام طريقتين أبسط. يرسل `PUT /uploads/{id}/content` الملف كاملًا في طلب واحد. وينشئ `PUT /raw/<path>` الجلسة ويرسل البايتات ويخزّنها في مسار بطلب واحد، كما يفعل `curl -T`. يجب أن يكتمل كل من الطلبين خلال 30 دقيقة. استخدم الأجزاء لكل نقل كبير أو بطيء. راجع [الملفات الخام](../protocols/raw-files). يُرسل الملف الفارغ في طلب واحد.

## الحد الأقصى لحجم الملف {#limits}

| الحد                  | القيمة                                                                                                                               |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| حجم الجزء             | 8 MiB للملفات حتى نحو 78 GiB. تستخدم الملفات الأكبر 16 ثم 32 ثم 64 MiB وهكذا، حتى 1 GiB، بحيث لا يحتاج الملف إلى أكثر من 10 000 جزء. |
| الأجزاء لكل عملية رفع | 10 000 (الفهارس من 0 إلى 9999)                                                                                                       |
| أكبر ملف              | 10 000 جزء بحجم 1 GiB، أي نحو 10 TiB                                                                                                 |
| سقف أقل               | يمكن للمسؤول تعيينه باستخدام `ARKVORY_MAX_OBJECT_BYTES`                                                                              |
| اسم الملف             | من 1 إلى 240 حرفًا، دون `/` أو `\` أو محارف تحكم                                                                                      |

يختار الخادم حجم الجزء عند إنشاء الرفع، ويُبقي عليه طوال العملية. يعرض `GET /api/v1/capabilities` القيم `maxObjectBytes` و`partBytes` و`maxPartBytes` و`maxParts`. ترفض وحدة التحكم الملف الذي يتجاوز حد الخادم قبل البدء.

يحتفظ العميل بجزء واحد في الذاكرة أثناء حساب مجموعه الاختباري وإرساله. للملفات التي تتجاوز 78 GiB، يكبر الجزء، ومعه الذاكرة المستخدمة، حتى 1 GiB.

يجب أن تتسع المساحة الحرة على قرص الخادم للأجزاء والملف المجمّع لفترة من الوقت. إذا امتلأ القرص، يرفض الخادم الرفع مع `507 storage_full`.

## استئناف الرفع {#resume}

تحتفظ جلسة الرفع بأجزائها بعد حدوث فشل. للاستئناف، أعطِ العميل الملف نفسه والجلسة نفسها.

**وحدة التحكم.** في علامة التبويب المفتوحة، اختر [[ui:startUpload]] مجددًا بعد [[ui:pause]]. احتفظ بمعرّف الرفع لاستخدامه بعد إغلاق علامة التبويب. وسّع [[ui:resumeTitle]]: يعرض الحقل [[ui:uploadId]] المعرّف أثناء الرفع. لاحقًا، اختر الملف نفسه، وأدخل المعرّف هناك ثم اختر [[ui:startUpload]]. تقارن وحدة التحكم الأجزاء بملفك. إذا اختلف الملف، تتوقف وتخبرك. يمسح [[ui:newUpload]] الحقلين ويبدأ رفعًا جديدًا.

الحقل [[ui:idempotency]] طريقة أخرى للعودة. تملؤه وحدة التحكم تلقائيًا. يعيد المفتاح نفسه مع الملف نفسه الجلسة نفسها بدلًا من إنشاء جلسة ثانية.

**arkvoryctl.** شغّل الأمر نفسه بالخيارات نفسها. حفظ العميل نقطة تحقق في `<file>.arkvory-upload.json` بجانب الملف المصدر، أو في الملف الذي حددته في `--state`، قبل أول طلب. لنشر البايتات نفسها بوصفها مُخرَجًا جديدًا، استخدم `--state` جديدًا. في CI، احتفظ بالملف المصدر ومجلد الحالة بين محاولات الإعادة. يؤدي تغيير الملف أو الخادم أو المستودع أو الخيارات إلى `checkpoint_mismatch` (رمز الخروج 6).

**SDK.** استدعِ `resume` مجددًا بمعرّف الجلسة المحفوظ والملف نفسه. للاسترداد حتى عند فقدان استجابة `create`، استدعِ `create` بمفتاح منع التكرار نفسه وواصف الملف نفسه: ستعيد الجلسة نفسها.

**HTTP.** اقرأ الأجزاء المخزّنة باستخدام `listUploadParts`، ثم أرسل الفهارس الناقصة. إعادة إرسال جزء بالبايتات نفسها آمنة. وتُرفض البايتات المختلفة لفهرس مخزّن مع `409 upload_state`.

يعيد العملاء الطلب تلقائيًا أيضًا بعد فشل الشبكة أو بعد `408` و`429` و`502` و`503` و`504`: حتى 20 مرة للعملية الواحدة، مع انتظار يتزايد من 0.5 إلى 60 ثانية ويراعي `Retry-After`. يوفر `arkvoryctl` الخيارين `--retries` و`--attempt-timeout` للاتصالات البطيئة.

لا يستطيع استئناف الرفع إلا الحساب أو المفتاح الذي أنشأه. وبالنسبة إلى أي طرف آخر، فهو غير موجود. يحافظ تدوير مفتاح الخدمة على الحساب، لذا يستطيع المفتاح الجديد استئناف الرفع.

## المجاميع الاختبارية {#checksums}

- **قبل الرفع.** تحسب وحدة التحكم وCLI وSDK قيمة SHA-256 للملف وترسلها في الجلسة.
- **كل جزء.** يحتوي الرأس `X-Content-SHA256` على المجموع الاختباري للجزء. يُرفض الجزء الذي لا تطابق بايتاته المجموع مع `422 integrity_mismatch` ولا يُخزَّن.
- **عند الانتهاء.** يتحقق الخادم من حجم الملف المجمّع وSHA-256 الخاص به مقابل الجلسة قبل النشر. ينتج عن عدم التطابق `422 integrity_mismatch`؛ ويخرج CLI بالرمز 5. ولا يظهر المُخرَج.
- **التنزيلات.** تتحقق وحدة التحكم وCLI وSDK من SHA-256 للملف كاملًا قبل تسليمه. ولا يظهر الملف النهائي إلا بعد نجاح التحقق.

قيمة ETag للملف هي مجموعه الاختباري: `"sha256:<64 hex digits>"`. تعرض تفاصيل المُخرَج قيمة SHA-256 وينسخها [[ui:copyHash]].

## مهمة الإكمال {#completion}

يستغرق تجميع ملف كبير وقتًا. للملفات الأصغر من 16 GiB، تجمعها `completeUpload` داخل الطلب، وقد يستغرق ذلك حتى 30 دقيقة. بدءًا من 16 GiB، تطلب SDK، ومن ثم وحدة التحكم وCLI، من العامل إكماله: تعيد `enqueueCompletion` الاستجابة `202` مع مهمة، ويستعلم العميل دوريًا باستخدام `getCompletionJob` حتى تصبح الحالة `completed` أو `failed`. تحتوي المهمة الفاشلة على رمز خطأ، مثل `integrity_mismatch`.

يجب تشغيل خدمة العامل لتنفيذ المهام. تحاول المهمة حتى 5 مرات مع انتظار متزايد، وتتوقف فورًا عند أخطاء لا تصلحها الإعادة. يعيد استدعاء `enqueueCompletion` المكرر المهمة نفسها. إذا أُعيد تشغيل الخادم، تتابع المهمة عملها. ولا تحتاج إلى بدء الرفع مجددًا.

## انتهاء صلاحية الرفع {#expiry}

تنتهي صلاحية جلسة الرفع غير المكتملة بعد 7 أيام من إنشائها. يرد الوقت في `expiresAt`، ولا يُمدَّد ولا يتغير عند إرسال الأجزاء. بعده، تُرفض الأجزاء و`complete` مع `409 upload_expired`. ابدأ رفعًا جديدًا. لا تنتهي صلاحية الملفات المنشورة مطلقًا.

يزيل الخادم الجلسات المنتهية وأجزاءها في الخلفية. للتخلي عن جلسة قبل ذلك، استخدم `arkvoryctl uploads cancel ID` أو `cancelUpload`. الإلغاء يختلف عن الإيقاف المؤقت: تُحذف الأجزاء.

## تنزيل ملف {#download}

### في وحدة التحكم {#download-console}

اختر [[ui:download]] بجانب ملف في [[ui:catalog]] أو في تفاصيل المُخرَج. يسأل المتصفح أين تريد حفظ الملف. ينتقل الملف إلى قائمة الانتظار في [[ui:downloads]]. تكتب القائمة البيانات في نسخة مؤقتة، وتتحقق من SHA-256، ثم تستبدل الملف الهدف بعد ذلك فقط.

تحتاج قائمة الانتظار إلى Chrome أو Edge عبر HTTPS أو على الحاسوب المحلي، لأنها تكتب ملفًا كبيرًا عبر وصول المتصفح إلى نظام الملفات. في المتصفحات الأخرى، استخدم CLI أو SDK.

حالات التنزيل هي [[ui:downloadQueued]] و[[ui:downloadRunning]] و[[ui:downloadRetrying]] و[[ui:downloadPaused]] و[[ui:downloadSaving]] و[[ui:downloadCompleted]] و[[ui:downloadFailed]] و[[ui:downloadCancelled]]. الأزرار هي:

| الزر                                           | التأثير                                                      |
| ---------------------------------------------- | ------------------------------------------------------------ |
| [[ui:downloadResume]]                          | استئناف تنزيل متوقف مؤقتًا أو فاشل بدءًا من الجزء المحفوظ      |
| [[ui:downloadCancel]]                          | إلغاء تنزيل واحد وحذف نسخته المؤقتة                          |
| [[ui:downloadsPause]] / [[ui:downloadsResume]] | إيقاف قائمة الانتظار كلها مؤقتًا واستئنافها                   |
| [[ui:downloadsClearWaiting]]                   | إلغاء التنزيلات المنتظرة                                     |
| [[ui:downloadsCancel]]                         | إلغاء جميع التنزيلات                                         |
| [[ui:downloadsClearFinished]]                  | إزالة الصفوف المنتهية لإتاحة مكان (تستوعب القائمة 64 تنزيلًا) |
| [[ui:downloadRestore]]                         | استرجاع التنزيلات غير المكتملة بعد إعادة تحميل الصفحة        |

يحتوي [[ui:downloadSettings]] على [[ui:downloadConcurrency]] (من 1 إلى 8، والافتراضي 2)، و[[ui:downloadInterval]] (من 0 إلى 60 000 مللي ثانية، والافتراضي 250)، و[[ui:downloadWait]] (من 1 إلى 1800 ثانية، والافتراضي 300). اختر [[ui:downloadApply]] لاستخدامها. وهي لا ترفع حدود الخادم.

بعد إعادة التحميل أو إغلاق علامة التبويب، سجّل الدخول مجددًا إلى الخادم نفسه بالحساب نفسه، وافتح [[ui:downloads]] ثم اختر [[ui:downloadRestore]]. تنتظر التنزيلات المسترجعة في وضع الإيقاف المؤقت. اختر [[ui:downloadResume]] لكل منها واختر الملف الهدف مجددًا. يحتاج المتصفح إلى مساحة حرة للنسخة المؤقتة.

### باستخدام arkvoryctl {#download-cli}

```bash
arkvoryctl download 3b0c0b8e-6a4e-4f5f-9d3b-5a6c1c9b0f11 ./Game.zip
arkvoryctl get builds/game/1.4/Game.zip ./Game.zip
arkvoryctl packages download app ./app.upack --range ^1.4 --stage release
```

أثناء التنزيل، يبقى `<output>.arkvory-part` و`<output>.arkvory-download.json` بجانب الملف الهدف. شغّل الأمر نفسه مجددًا بعد الانقطاع. لا يظهر الملف النهائي إلا بعد التحقق من SHA-256. ولا يُستبدل أي ملف هدف موجود مطلقًا (`destination_exists`، رمز الخروج 6).

### باستخدام HTTP: النطاقات وETag {#download-http}

تعيد `downloadArtifact` بايتات المُخرَج. ويعيد `HEAD` الرؤوس فقط.

```bash
curl -fL -H "Authorization: Bearer $ARKVORY_KEY" -C - -o Game.zip \
  "$ARKVORY/api/v1/repositories/releases/artifacts/$ID/content"
```

- `Accept-Ranges: bytes`. أرسل `Range: bytes=1048576-` أو `bytes=0-1023` أو `bytes=-500` لنطاق واحد. الاستجابة هي `206` مع `Content-Range`. لا تُدعَم عدة نطاقات في الوقت نفسه: يرسل الخادم الملف كاملًا. إذا كانت البداية بعد نهاية الملف، تكون الاستجابة `416`.
- قيمة `ETag` هي `"sha256:<hex>"`. ينتج عن إرسالها في `If-None-Match` الاستجابة `304`. ويستأنف `If-Range` معها نطاقًا فقط إذا بقي الملف نفسه؛ وإلا يصل الملف كاملًا.
- يستأنف `curl -C -` التنزيل. تُحدِّد العناوين المعتمدة على الاسم الملف في كل طلب، مثل `packages/content?name=app&range=^1.4`، لذا قد يتغير الملف بين استدعاءين. لاستئنافه بأمان، أرسل قيمة ETag التي حصلت عليها في `If-Range`، أو حدّد الاسم أولًا ثم نزّل باستخدام معرّف المُخرَج.

تقرأ SDK المحتوى بنطاقات من 8 MiB وتتحقق من كل منها. راجع [SDK لـTypeScript](../protocols/sdk#download-with-verification).

## روابط لمن لا يملك مفتاحًا {#links}

يتيح رابط التنزيل لشخص جلب ملف واحد دون أي مفتاح: مختبِر أو عميل أو جهاز بناء لا يحمل بيانات اعتماد. يتيح الرابط الوصول إلى ذلك المُخرَج وحده، للطلبين `GET` و`HEAD`، حتى تنتهي صلاحيته. ويعمل مع `curl -C -` ومع النطاقات.

في وحدة التحكم، افتح المُخرَج في [[ui:metadata]] واختر [[ui:downloadLink]]. تنسخ وحدة التحكم الرابط وتعرضه مع وقت انتهاء صلاحيته. يستمر الرابط ساعة واحدة. ولا يظهر الزر إلا إذا كان يُسمح لك بتنزيل الملف.

```bash
arkvoryctl link 3b0c0b8e-6a4e-4f5f-9d3b-5a6c1c9b0f11 --ttl 900
```

```bash
curl -X POST "$ARKVORY/api/v1/repositories/releases/artifacts/$ID/links" \
  -H "Authorization: Bearer $ARKVORY_KEY" -H "Content-Type: application/json" \
  -d '{"ttlSeconds":900}'
```

تتراوح مدة الصلاحية من 60 ثانية إلى 24 ساعة (86 400 ثانية)، والافتراضي ساعة واحدة. تتضمن الاستجابة `token` يبدأ بـ`dtl_`، و`url` و`expiresAt`. تطبع CLI وSDK عنوان URL كاملًا. وتعيد API المسار الذي تضيفه إلى عنوان الخادم.

الرابط سر. كل من يملكه يستطيع تنزيل الملف. لا يمكنك إبطال الرابط قبل انتهاء صلاحيته، لذا اجعل مدته قصيرة. عامل عنوان URL كمفتاح: أبقه بعيدًا عن غرف الدردشة والسجلات العامة. قد تسجّله سجلات الوكيل ومحفوظات المتصفح. راجع [روابط التنزيل](../api/reference/links).

## الحدود وقوائم الانتظار {#queues}

يضبط المسؤول عدد عمليات النقل التي يشغّلها الخادم معًا وسرعتها. افتراضيًا، يشغّل الخادم عمليتي رفع و16 تنزيلًا في الوقت نفسه، ويشغّل الحساب الواحد عملية رفع واحدة و4 تنزيلات. تنتظر العمليات الإضافية في قائمة لمدة تصل إلى 20 ثانية. إذا امتلأت القائمة أو انتهت مدة الانتظار، يعيد الخادم `503` مع `Retry-After`، وينتظر العملاء ويعيدون المحاولة. عند ضبط ميزانية بايتات في الثانية، تصبح عمليات النقل أبطأ لكنها لا تتوقف. لا يستطيع المستخدمون عرض هذه الميزانيات أو تغييرها. القيم مذكورة في [متغيرات البيئة](../reference/environment#transfers-and-bandwidth).

## الأخطاء {#errors}

| الاستجابة                  | السبب                                                         | الإجراء المطلوب                                |
| -------------------------- | ------------------------------------------------------------- | ---------------------------------------------- |
| `409 upload_expired`       | مضى على الجلسة أكثر من 7 أيام                                 | ابدأ رفعًا جديدًا                                |
| `409 upload_state`         | نُشر الرفع أو أُلغي بالفعل، أو يحتوي جزء مخزّن على بايتات مختلفة | ابدأ رفعًا جديدًا، أو تحقّق من استخدام الملف نفسه |
| `409 parts_incomplete`     | لم تصل بعض الأجزاء                                            | استأنف الرفع                                   |
| `409 part_mismatch`        | لا تطابق الأجزاء الحجم أو الفهارس المخططة لها                 | خذ حجم الجزء من `listUploadParts` واستأنف      |
| `409 idempotency_mismatch` | استُخدم المفتاح لملف آخر                                       | استخدم مفتاحًا جديدًا                            |
| `422 integrity_mismatch`   | لا يتطابق مجموع اختباري                                       | أعد إرسال الملف الأصلي                         |
| `507 storage_quota`        | استُنفدت حصة المستودع                                          | احذف نسخ بناء قديمة أو اطلب حصة أكبر           |
| `507 storage_full`         | قرص الخادم ممتلئ                                              | اتصل بالمسؤول                                  |
| `503` مع `Retry-After`     | الخادم مشغول                                                  | انتظر، يعيد العملاء المحاولة تلقائيًا           |

توجد القائمة الكاملة في [الأخطاء](../api/errors).
