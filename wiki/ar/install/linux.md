# Linux

توجد طريقتان لتشغيل Arkvory على Linux:

- **حزمة** `Arkvory-amd64.deb` أو `Arkvory-x86_64.rpm`. موصى بها. تثبّت خدمات systemd وعنقود PostgreSQL مخصصًا يديره Arkvory. يوفّر مدير الحزم برامج PostgreSQL.
- **النص البرمجي** `install.sh`. يثبّت الخدمات نفسها، لكنه يستخدم خادم PostgreSQL موجودًا. ويدعم arm64 أيضًا. راجع [استخدام PostgreSQL موجود](#existing-postgresql).

لاستخدام Docker، راجع [Docker Compose](./docker). ولجولة أولى في وحدة التحكم، راجع [البدء السريع](../guide/quick-start).

## المتطلبات {#requirements}

| العنصر             | المتطلب                                                                                                                                                                                                                      |
| ------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| المعالج            | x64 للحزم. لا توجد حزم arm64: استخدم `install.sh` على arm64                                                                                                                                                                  |
| نظام التهيئة       | systemd. لا تُدعم OpenRC أو runit أو أنظمة التهيئة الأخرى                                                                                                                                                                     |
| مكتبة C            | glibc 2.28 أو أحدث. لا يُدعم Alpine Linux ‏(musl)                                                                                                                                                                             |
| التوزيعات المختبرة | Ubuntu 24.04 لحزمة `.deb` وFedora 44 لحزمة `.rpm`. لم تُختبر توزيعات systemd الأخرى التي تستوفي الاعتماديات أدناه                                                                                                             |
| اعتماديات `.deb`   | `postgresql` 16 أو أحدث، و`systemd`، و`python3`، و`ca-certificates`، و`libc6` 2.28 أو أحدث، و`libstdc++6`، و`libgcc-s1`، و`libatomic1`                                                                                       |
| اعتماديات `.rpm`   | `postgresql-server` 16 أو أحدث، و`systemd`، و`python3`، و`ca-certificates`، و`glibc` 2.28 أو أحدث، و`libstdc++`، و`libatomic`                                                                                                |
| برامج PostgreSQL   | الإصدار 16 إلى 19. تبحث خطوة التثبيت في `/usr/lib/postgresql/*/bin` و`/usr/pgsql-*/bin` و`/usr/bin` و`/usr/lib/pgsql/bin` وتختار أعلى إصدار تجده. إذا كانت توزيعتك لا توفّر إلا إصدارًا أقدم، فأضف مستودع PostgreSQL أحدث أولًا |
| الحساب             | `root` أو مستخدم يستطيع تشغيل `sudo`                                                                                                                                                                                         |
| المنافذ المتاحة    | 8080، و54329 أو أحد المنافذ 45329-45348، على `127.0.0.1`                                                                                                                                                                     |
| تخزين الملفات      | نظام ملفات محلي يدعم الروابط الصلبة. لا تستخدم مشاركة شبكية                                                                                                                                                                  |

تتضمن الحزمة Node.js 24. لا يحتاج تثبيتها إلى إنترنت إلا بقدر ما يستخدمه مدير الحزم للحصول على الاعتماديات.

لا تغيّر الحزمة أي عنقود أو خدمة PostgreSQL موجودة. يشغّل Arkvory عنقوده الخاص باستخدام برامج PostgreSQL.

## تثبيت الحزمة {#install-package}

1. نزّل حزمة توزيعتك من [إصدارات GitHub](https://github.com/ProAnima/Arkvory/releases)، مع `native-linux.json` من الإصدار نفسه.
2. قارن SHA-256 للحزمة بالقيمة في `native-linux.json`. الحزم غير موقّعة بمفتاح الناشر، لذا فهذا التحقق هو الدليل الوحيد على ما نزّلته.
3. ثبّت الحزمة. أبقِ `./` قبل اسم الملف: فهي تخبر مدير الحزم بأن الملف محلي. على Debian وUbuntu:

```bash
sudo apt install ./Arkvory-amd64.deb
```

على Fedora والأنظمة المتوافقة مع RPM:

```bash
sudo dnf install ./Arkvory-x86_64.rpm
```

يثبّت مدير الحزم الاعتماديات، ثم يُهيّئ Arkvory نفسه. وهو:

1. ينسخ Node.js إلى `/opt/proanima-arkvory/runtime/node`،
2. ينشئ حسابَي الخدمة والإعدادات والمفاتيح ومفتاح الاسترداد،
3. ينشئ عنقود PostgreSQL ويشغّله وينفّذ ترحيلات قاعدة البيانات،
4. يسجّل الخدمات ومؤقّت التحديث ويشغّلها،
5. ينتظر حتى تستجيب API لفحص الجاهزية ثلاث مرات متتالية.

في النهاية يطبع عنوان وحدة التحكم ومسار مفتاح الاسترداد. إذا فشلت خطوة، يتوقف التثبيت مع خطأ. راجع [استكشاف الأخطاء وإصلاحها](#troubleshooting).

التحديثات التلقائية متوقفة بعد التثبيت. لتفعيلها، راجع [التحديثات](./updates).

## ما الذي تنشئه الحزمة {#what-package-creates}

### الملفات والأدلة {#files}

| المسار                                                          | المحتوى                                                                                                                            |
| --------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| `/usr/lib/proanima-arkvory/`                                    | محتويات الحزمة: Node.js وملفات الإصدار وبرنامج التثبيت. تديرها الحزمة                                                              |
| `/usr/bin/arkvory`                                              | أمر الإدارة. راجع [أمر arkvory](#arkvory-command)                                                                                  |
| `/usr/share/applications/arkvory.desktop`                       | عنصر قائمة يفتح وحدة التحكم على سطح المكتب. لا يستخدمه خادم بلا سطح مكتب                                                           |
| `/opt/proanima-arkvory/`                                        | جذر التثبيت: الإعدادات والبيانات وقاعدة البيانات وشيفرة كل إصدار. يُشرح تنظيمه في [اختيار طريقة التثبيت](./#installation-directory) |
| `/etc/systemd/system/arkvory-*.service`، `arkvory-update.timer` | وحدات الخدمات ومؤقّت التحديث                                                                                                        |

ملكية الجذر هي `root:arkvory` ووضع أذوناته `0711`. داخله، تكون ملكية `config/` هي `root:arkvory` ووضعه `0750`، ويملك `arkvory` الدليلين `data/` و`logs/`، ويملك `arkvory-db` الدليل `database/` بوضع `0700`. لا يستطيع قراءة مفتاح الاسترداد وملفات كلمة مرور قاعدة البيانات إلا `root`.

### الحسابات {#accounts}

| الحساب       | ما يشغّله                          | ملاحظات                                                                         |
| ------------ | --------------------------------- | ------------------------------------------------------------------------------- |
| `arkvory`    | API والعامل ووكيل النسخ الاحتياطي | حساب نظام بلا صدفة لتسجيل الدخول، ودليله الرئيسي `/opt/proanima-arkvory/data`   |
| `arkvory-db` | قاعدة البيانات                    | حساب نظام بلا صدفة لتسجيل الدخول. لا يستطيع حساب API قراءة ملفات قاعدة البيانات |

### الخدمات {#services}

| الوحدة                 | حساب التشغيل                               | سياسة إعادة التشغيل                                |
| ---------------------- | ------------------------------------------ | -------------------------------------------------- |
| `arkvory-database`     | `arkvory-db`                               | `on-failure`، بعد 10 ثوانٍ                          |
| `arkvory-api`          | `arkvory`                                  | `always`، بعد 10 ثوانٍ                              |
| `arkvory-worker`       | `arkvory`                                  | `always`، بعد 10 ثوانٍ                              |
| `arkvory-backup`       | `arkvory`                                  | `always`، بعد 10 ثوانٍ                              |
| `arkvory-update.timer` | يشغّل `arkvory-update.service` بحساب `root` | كل دقيقة. تتحقق المهمة من طلبات التحديث والإصدارات |

تبدأ جميع الوحدات عند الإقلاع (`multi-user.target`). وتُمنح 120 ثانية للتوقف. تعمل مع `NoNewPrivileges` و`/tmp` خاص ونظام ملفات للقراءة فقط خارج أدلتها، ومن دون وصول إلى `/home`. لا تستطيع API والعامل الكتابة إلا في `data/` و`logs/` و`updates/inbox/` ضمن الجذر. يقرأ وكيل النسخ الاحتياطي التخزين ولا يكتب إلا في مخزن النسخ الاحتياطية. ولأن `/home` مخفي عن الوحدات، فلا تضع الشهادات أو مخازن النسخ الاحتياطية أو دليل البيانات تحت أي دليل رئيسي لمستخدم.

الخدمة التي تتوقف من دون طلبك تبدأ مجددًا بعد 10 ثوانٍ. والعملية التي يتعطل خيطها الرئيسي لمدة 60 ثانية تنهي نفسها وتبدأ مجددًا. فشل فحص الجاهزية وحده لا يعيد تشغيل الخدمة. راجع [الإصلاح الذاتي](../operate/self-healing).

### المنافذ {#ports}

| المنفذ    | الاستخدام               | الإتاحة                                                                                                                      |
| --------- | ----------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| 8080/TCP  | API ووحدة التحكم        | على `127.0.0.1` فقط، حتى تضبط [HTTPS](./https)                                                                               |
| 54329/TCP | عنقود PostgreSQL المُدار | على `127.0.0.1` فقط. إذا كان 54329 مشغولًا عند التثبيت، يُختار أول منفذ متاح من 45329-45348؛ ويُحفظ في `database/settings.json` |

## التشغيل الأول والخطوات الأولى {#first-start}

1. تحقق من تشغيل الخدمات:

   ```bash
   systemctl status arkvory-database arkvory-api arkvory-worker arkvory-backup
   ```

2. اقرأ مفتاح الاسترداد. لا يستطيع قراءته إلا `root`.

   ```bash
   sudo cat /opt/proanima-arkvory/config/bootstrap-token.txt
   ```

3. افتح `http://127.0.0.1:8080/console/#onboarding`. على خادم بعيد، مرّر المنفذ أولًا وافتح العنوان على حاسوبك:

   ```bash
   ssh -L 8080:127.0.0.1:8080 admin@arkvory.example
   ```

4. في وحدة التحكم، افتح [[ui:navStart]] ووسّع [[ui:welcomeOwner]]. ألصق المفتاح في [[ui:welcomeRecovery]]، وأدخل اسم المالك وكلمة مرور لا تقل عن 12 حرفًا، واختر [[ui:welcomeCreate]]. يتألف الاسم من 3 إلى 64 حرفًا: أحرف لاتينية أو أرقام أو نقطة أو شرطة أو شرطة سفلية.
5. سجّل الدخول بالاسم وكلمة المرور الجديدين.

المالك هو المسؤول الأول. يبقى مفتاح الاسترداد على الخادم: لا تحذف الملف ولا تنسخه إلى العملاء أو أنظمة CI. تقرؤه أدوات التثبيت. للعمل اليومي، أنشئ حسابات ومفاتيح خدمة. راجع [الحسابات والوصول](../use/accounts) و[الأمان](../operate/security).

قبل اتصال العملاء من حواسيب أخرى، اضبط [HTTPS](./https). ثم صِل مخزن نسخ احتياطية ونفّذ أول نسخة احتياطية: راجع [النسخ الاحتياطي](../operate/backups).

للتثبيت على خادم من حاسوبك، يمكنك استخدام Arkvory Remote Setup بدلًا من ذلك. راجع [اختيار طريقة التثبيت](./#remote-installation-over-ssh).

## أمر arkvory {#arkvory-command}

تثبّت الحزمة `/usr/bin/arkvory`. يسرد `arkvory help` جميع الأوامر ولا يحتاج إلى حقوق خاصة. يحتاج كل أمر آخر إلى `root` وجذر التثبيت:

```bash
sudo arkvory status --root /opt/proanima-arkvory
```

يطبع `status` نمط التثبيت والإصدار المثبّت وإعداد التحديث التلقائي وتثبيت الإصدار.

| الأمر             | الاستخدام                                                                                       |
| ----------------- | ----------------------------------------------------------------------------------------------- |
| `status`          | عرض الإصدار المثبّت وسياسة التحديث                                                               |
| `update`          | تثبيت إصدار مستقر أحدث الآن. راجع [التحديثات](./updates)                                        |
| `configure`       | HTTPS ومخزن النسخ الاحتياطية والمرايا وسياسة التحديث والمركز. راجع [الإعدادات](./configuration) |
| `recover`         | إكمال تحديث انقطع. راجع [التحديثات](./updates#recover-update)                                   |
| `finish-install`  | متابعة تثبيت انقطع                                                                              |
| `updates-connect` | ربط وحدة التحكم بمؤقّت التحديث لتثبيت حُدّث من إصدار قديم                                          |

## السجلات {#logs}

تكتب الخدمات في سجل النظام. وتكتب API والعامل سجل JSON واحدًا في كل سطر.

```bash
sudo journalctl -u arkvory-api -u arkvory-worker -u arkvory-backup -u arkvory-database
sudo journalctl -u arkvory-api -f
sudo journalctl -u arkvory-update --since today
```

يحتوي `arkvory-update` على مخرجات مؤقّت التحديث. حجم سجل النظام والاحتفاظ به من إعدادات نظام التشغيل. لحقول السجلات والمقاييس، راجع [المراقبة](../operate/monitoring). تطبع أوامر النشر أسطرًا بالصيغة `<ISO-8601 time> INFO|WARN|ERROR <text>`. وتُزال الأسرار منها.

## الترقية {#upgrade}

ثبّت حزمة أحدث فوق القديمة، أو حدّث من وحدة التحكم أو باستخدام `arkvory update`. تواصل الخدمات العمل حتى ينتقل التحديث إلى الشيفرة الجديدة. راجع [التحديثات](./updates) لمعرفة السياسات والنسخة الاحتياطية التي تسبق تغيير مخطط قاعدة البيانات وخطوات الاسترداد.

لا يوجد مستودع apt أو dnf لـArkvory. نزّل كل حزمة جديدة من صفحة الإصدارات.

## الإزالة {#remove}

### إزالة الحزمة مع الاحتفاظ بالبيانات {#remove-package}

على Debian وUbuntu:

```bash
sudo apt remove proanima-arkvory
```

على Fedora والأنظمة المتوافقة مع RPM:

```bash
sudo dnf remove proanima-arkvory
```

توقف الإزالة الخدمات ومؤقّت التحديث وتعطّلها. وتحذف `/usr/lib/proanima-arkvory` و`/usr/bin/arkvory` وعنصر القائمة. وهي **تحتفظ** عمدًا بما يلي:

- `/opt/proanima-arkvory`: قاعدة البيانات وجميع الملفات والإعدادات ومفتاح الاسترداد،
- ملفات الوحدات في `/etc/systemd/system` والحسابين `arkvory` و`arkvory-db`،
- مخزن النسخ الاحتياطية وملف إعداد systemd الإضافي الخاص به. لا تمس المخزن أبدًا.

لا يزيل `apt purge` أكثر مما يزيله `apt remove`. إذا ثبّت الحزمة مرة أخرى، تتابع باستخدام البيانات المحتفَظ بها وتبدأ الخدمات.

### إزالة كل شيء {#remove-all}

يحذف هذا جميع الملفات المخزّنة والفهرس. أنشئ نسخة احتياطية أولًا واحتفظ بمخزن النسخ الاحتياطية.

```bash
sudo systemctl disable --now arkvory-update.timer arkvory-backup arkvory-worker arkvory-api arkvory-database
sudo rm -rf /opt/proanima-arkvory
sudo rm -f /etc/systemd/system/arkvory-*.service /etc/systemd/system/arkvory-update.timer
sudo rm -rf /etc/systemd/system/arkvory-backup.service.d
sudo systemctl daemon-reload
sudo userdel arkvory
sudo userdel arkvory-db
```

أزِل الحزمة أولًا كما هو موضح أعلاه. بعد التثبيت بنص برمجي لا توجد حزمة: يوقف الأمر الأول الخدمات، وتُبلغ الأوامر التي تذكر `arkvory-database` و`arkvory-db` بأنهما غير موجودين.

## استخدام PostgreSQL موجود {#existing-postgresql}

تنشئ الحزمة عنقودها الخاص دائمًا. لاستخدام خادم PostgreSQL تديره مؤسستك، ثبّت بواسطة `install.sh`. ينشئ الخدمات الثلاث نفسها ومؤقّت التحديث، لكنه لا ينشئ وحدة `arkvory-database` ولا أمر `/usr/bin/arkvory`.

استخدم إصدار PostgreSQL من 16 إلى 19. خصّص قاعدة بيانات واحدة لكل تثبيت Arkvory. لا تربط تثبيتين بقاعدة البيانات نفسها أبدًا.

1. اطلب من مسؤول قاعدة البيانات قاعدة بيانات فارغة ودورًا يملكها. ينفّذ Arkvory ترحيلاته باستخدام هذا الدور.
2. نزّل `install.sh` من الإصدار واقرأه. يحتاج إلى `bash` و`curl` و`python3` و`tar` و`xz`، وإلى systemd و`root`.
3. شغّله. يسأل النص البرمجي عن عنوان URL للاتصال؛ ويكون الإدخال مخفيًا.

   ```bash
   sudo bash ./install.sh --automatic
   ```

   لتمرير العنوان في ملف بدلًا من ذلك، أنشئ ملفًا لا يستطيع قراءته إلا `root`:

   ```json
   { "ARKVORY_DATABASE_URL": "postgresql://arkvory:<password>@db.example:5432/arkvory" }
   ```

   ```bash
   sudo bash ./install.sh --config /root/arkvory.json
   ```

4. احذف دليل العمل المؤقت `/opt/proanima-arkvory/bootstrap.*` عند اكتمال التثبيت. إذا أدخلت العنوان عند المطالبة، فسيحتوي عليه الدليل في `native.json`.
5. أنشئ المالك كما هو موضح في [التشغيل الأول والخطوات الأولى](#first-start).

ينزّل النص البرمجي Node.js 24.22.3 من `nodejs.org` ويتحقق من SHA-256 الخاص به ويثبّت أحدث إصدار مستقر. احذف `--automatic` من الأمر لإبقاء التحديثات التلقائية متوقفة. تغيّر متغيرات البيئة القيم الافتراضية:

| المتغير                   | المعنى                                                   | القيمة الافتراضية       |
| ------------------------- | -------------------------------------------------------- | ----------------------- |
| `ARKVORY_INSTALL_ROOT`    | جذر التثبيت. استخدم دليلًا فارغًا ومخصصًا خارج `/home`      | `/opt/proanima-arkvory` |
| `ARKVORY_RELEASE_VERSION` | تثبيت هذا الإصدار المستقر بدلًا من الأحدث                 | أحدث إصدار مستقر        |
| `ARKVORY_ARTIFACT_DIR`    | التثبيت من `Arkvory-Linux.tar.gz` بعد فكّه بدلًا من GitHub | غير معيّن                |

مرّرها عبر `sudo env`، مثل `sudo env ARKVORY_INSTALL_ROOT=/srv/arkvory bash ./install.sh`.

عند عدم وجود أمر `arkvory`، استدعِ برنامج الإدارة باستخدام Node.js الذي ثبّته النص البرمجي. استخدم `linux-arm64` على arm64:

```bash
root=/opt/proanima-arkvory
sudo "$root/runtime/node-v24.22.3-linux-x64/bin/node" "$root/manage.mjs" status --root "$root"
```

تتولى بنفسك نسخ خادم PostgreSQL احتياطيًا وصيانته. ينسخ وكيل النسخ الاحتياطي في Arkvory محتوى قاعدة البيانات إلى مخزن النسخ الاحتياطية عبر عنوان URL للاتصال. راجع [النسخ الاحتياطي](../operate/backups).

## استكشاف الأخطاء وإصلاحها {#troubleshooting}

| المشكلة                                                          | الإجراء                                                                                                                                                                                                                                                                                                 |
| ---------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `PostgreSQL 16–19 server binaries are required`                  | برامج PostgreSQL مفقودة أو قديمة جدًا. ثبّت خادم PostgreSQL بإصدار من 16 إلى 19 وثبّت الحزمة مجددًا                                                                                                                                                                                                         |
| `Use a dedicated empty installation directory`                   | يحتوي `/opt/proanima-arkvory` على ملفات من تثبيت أول توقف قبل حفظ `installation.json`. لا يستبدل برنامج التثبيت الإعدادات أبدًا. اقرأ السجل ومخرجات مدير الحزم وأصلح السبب. يمكن نقل دليل لا يحتوي بيانات بعد إلى مكان آخر لتستطيع التثبيت مجددًا. لا تحذف `config/` أو `database/` من تثبيت يحتوي بيانات |
| `Installation is locked`                                         | هناك عملية قيد التشغيل أو عملية تعطلت. أوقف مؤقّت التحديث واقرأ `journal.json` في الجذر، ولا تحذف `operation.lock` قبل معرفة الحالة. راجع [التحديثات](./updates#recover-update)                                                                                                                          |
| وجود `database/bootstrap-started` مع غياب `database/initialized` | انقطع إنشاء قاعدة البيانات. لا تحذف العنقود ولا تكرّر SQL يدويًا. أصلح السبب وشغّل `sudo arkvory finish-install --root /opt/proanima-arkvory`                                                                                                                                                              |
| خدمة لا تبدأ                                                     | `journalctl -u arkvory-api -n 100`. يطبع فشل البدء سجل JSON واحدًا يحتوي `reason` يذكر اسم الإعداد، ولا يذكر قيمته أبدًا                                                                                                                                                                                  |
| المنفذ 8080 مشغول                                                | يستخدمه برنامج آخر. حرّر المنفذ أو اضبط `ARKVORY_PORT` في `config/runtime.json`. راجع [الإعدادات](./configuration#address-and-port). منفذ قاعدة البيانات هو الذي اختير عند التثبيت (54329 أو 45329-45348)؛ ولا يتغيّر تلقائيًا                                                                             |

إذا توقف التثبيت بعد كتابة `installation.json`، فيمكنك أيضًا تكرار خطوة تهيئة الحزمة: `sudo dpkg --configure -a` على Debian وUbuntu، أو تثبيت الحزمة نفسها مجددًا على أنظمة RPM.

للمزيد من الإرشادات، راجع [استكشاف الأخطاء وإصلاحها](../operate/troubleshooting).
