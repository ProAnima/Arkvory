# الإعدادات

يحتوي Arkvory على نوعين من الإعدادات:

- **إعدادات الخادم** هي متغيرات `ARKVORY_*` في ملف `config/runtime.json`. تضبط العنوان والحدود والتخزين وما شابه ذلك. تقرؤها API والعامل ووكيل النسخ الاحتياطي عند بدء التشغيل.
- **سياسة التثبيت** تشمل سياسة التحديث وملفات HTTPS ومخزن النسخ الاحتياطية والمرايا. تغيّرها بأمر `arkvory configure`. يتحقق الأمر من التغيير ويعيد تشغيل ما يلزم ويستعيد الحالة القديمة إذا لم تبدأ الخدمات.

توضح هذه الصفحة مواقع الملفات والأوامر المتاحة وكيفية عمل الإعدادات الرئيسية. توجد القائمة الكاملة للمتغيرات، مع القيم الافتراضية والنطاقات، في [متغيرات البيئة](../reference/environment).

## موقع الإعدادات {#where-it-lives}

يحتوي جذر التثبيت على كل شيء. وهو `C:\ProgramData\ProAnima\Arkvory` على Windows و`/opt/proanima-arkvory` على Linux. يستخدم تثبيت Compose الجذر نفسه على المضيف. المسارات أدناه نسبية إلى الجذر.

| الملف                                                                          | المحتوى                                                                                             | كيفية تغييره                                             |
| ------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------- | -------------------------------------------------------- |
| `config/runtime.json`                                                          | إعدادات الخادم. تبدأ المفاتيح بـ`ARKVORY_`، وكل قيمة سلسلة نصية. يحتوي على كلمة مرور قاعدة البيانات | يدويًا أو باستخدام `configure`                            |
| `config/keys.json`                                                             | تجزئات SHA-256 لمفتاح الاسترداد ومفتاح الجاهزية. لا يحتوي على مفتاح أبدًا                            | فقط عند [استبدال مفتاح الاسترداد](#replace-recovery-key) |
| `config/bootstrap-token.txt`                                                   | مفتاح الاسترداد                                                                                     | فقط لاستبداله                                            |
| `config/health-token.txt`                                                      | المفتاح الذي تستخدمه أدوات التثبيت لفحص الجاهزية                                                    | لا تغيّره                                                 |
| `config/hub.json`                                                              | عنوان المركز وقناة التحديث وإعداد الإحصاءات                                                         | باستخدام `configure`                                     |
| `config/install-id`                                                            | معرّف تثبيت عشوائي، لا يُرسل إلى المركز إلا عند تفعيل الإحصاءات                                       | لا تغيّره                                                 |
| `config/mirrors/`                                                              | قائمة المرايا والمفاتيح التي يستخدمها العامل للمصادر                                                | باستخدام `configure --mirror`                            |
| `config/webhooks/`                                                             | قائمة الاشتراكات وأسرار التوقيع وشهادات جهات الإصدار الموثوقة للمستقبِلين التي يستخدمها العامل       | باستخدام `configure --webhook`                           |
| `installation.json`                                                            | النمط والمحرّك وإعداد التحديث التلقائي وتثبيت الإصدار والإصدار المثبّت                                | بالأوامر فقط                                             |
| `github-token.txt`                                                             | رمز GitHub اختياري لتنزيل الإصدارات. راجع [التحديثات](./updates#hub-unreachable)                    | يدويًا                                                    |
| `config/compose.env`، `config/compose.vault.yml`، `config/compose.mirrors.yml` | في Compose فقط: الصورة وتركيب مخزن النسخ الاحتياطية وتركيب المرايا                                  | بالأوامر فقط                                             |

في تثبيت Linux الأصلي، تكون ملكية `runtime.json` و`keys.json` هي `root:arkvory` ووضعهما `0640`، ولا يستطيع قراءة ملفات بيانات الاعتماد في `config/` إلا `root`. يستخدم تثبيت Compose الوضع `0644` للملفات التي تقرؤها الحاويات: راجع [Docker Compose](./docker#owners). احتفظ بالمالكين وأوضاع الأذونات التي ضبطها برنامج التثبيت.

## أوامر دورة الحياة {#lifecycle-commands}

لأوامر إدارة تثبيت موجود، حدّد جذر التثبيت باستخدام `--root`. يتطلب تغيير الخدمات الأصلية صلاحيات المسؤول. مع Compose، استخدم حسابًا يملك الوصول إلى جذر التثبيت ومحرّك الحاويات. تُشرح استثناءات `help` و`volume-init` أدناه.

| التثبيت                         | كيفية تشغيل أمر                                                                                                                                               |
| ------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| حزمة Linux                      | `sudo arkvory <command> --root /opt/proanima-arkvory`                                                                                                         |
| Windows، برنامج التثبيت الرسومي | في PowerShell بحقوق مرتفعة: `& 'C:\Program Files\ProAnima\Arkvory\arkvory.ps1' <command> --root C:\ProgramData\ProAnima\Arkvory`                              |
| التثبيت بنص برمجي، Compose      | `sudo <root>/runtime/node-v24.22.3-linux-x64/bin/node <root>/manage.mjs <command> --root <root>`. على Windows استخدم `runtime\node-v24.22.3-win-x64\node.exe` |

يسرد `arkvory help` الأوامر من دون حقوق خاصة. تستخدم أمثلة هذا الموقع الصيغة المختصرة `arkvory <command>`.

| الأمر                                            | الاستخدام                                                                                                                    |
| ------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------- |
| `status`                                         | يعرض نمط التثبيت والمحرّك وإعداد التحديث التلقائي والتثبيت والإصدار المثبّت                                                    |
| `configure`                                      | يغيّر سياسة. راجع [أمر configure](#configure-command)                                                                         |
| `update`                                         | يثبّت إصدارًا مستقرًا أحدث الآن. راجع [التحديثات](./updates)                                                                    |
| `upgrade`                                        | يثبّت إصدارًا يغيّر مخطط قاعدة البيانات مع سجل نسخة احتياطية أعددته بنفسك. راجع [التحديثات](./updates#manual-upgrade)           |
| `recover`                                        | يُكمل تحديثًا انقطع. راجع [التحديثات](./updates#recover-update)                                                                |
| `finish-install`                                 | يتابع تثبيتًا أول انقطع                                                                                                       |
| `updates-connect`                                | يربط وحدة التحكم بمؤقّت التحديث، ويسجّل الخدمات التي يفتقر إليها تثبيت قديم                                                    |
| `updates-poll`، `updates-reset`، `changes-reset` | يستخدمها مؤقّت التحديث وتُستخدم للاسترداد. راجع [التحديثات](./updates#recover-update)                                          |
| `volume-init`                                    | يضع علامة على دليل فارغ بوصفه وحدة تخزين جديدة. لا يحتاج إلى `--root`. راجع [وحدات تخزين متعددة](../operate/storage#volumes) |

يعمل أمر واحد فقط في كل مرة. يتوقف الأمر الثاني بالرسالة `Installation is locked`. لا تضع مفتاحًا أو كلمة مرور في خيار أمر أبدًا: استخدم الملفات.

### أمر configure {#configure-command}

يغيّر كل استدعاء نوعًا واحدًا من الإعدادات. لا يمكن مزج الأنواع الستة في استدعاء واحد.

| النوع                 | الخيارات                                                                                                                                                                                                                                                                                | الأثر                                                                                                                       |
| --------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| HTTPS                 | `--tls-cert FILE --tls-key FILE [--listen-host ADDRESS]`، أو `--tls-off [--listen-host ADDRESS]`                                                                                                                                                                                        | يفعّل HTTPS المدمج أو يوقفه. يعيد تشغيل الخدمات ويتحقق من الجاهزية. راجع [HTTPS](./https)                                    |
| مخزن النسخ الاحتياطية | `--backup-vault DIRECTORY [--vault-key-file FILE \| --init-vault --vault-no-encryption]`، أو `--backup-vault-off`                                                                                                                                                                       | يصل المخزن أو يفصله. يعيد تشغيل وكيل النسخ الاحتياطي فقط. راجع [النسخ الاحتياطي](../operate/backups)                        |
| المرايا               | `--mirror REPOSITORY --mirror-upstream URL --mirror-token-file FILE [--mirror-source REPOSITORY] [--mirror-stages LIST] [--mirror-ca-file FILE]`، أو `--mirror REPOSITORY --mirror-token-file FILE` لمفتاح جديد، أو `--mirror-detach REPOSITORY[,REPOSITORY…]` أو `--mirror-detach all` | يجعل المستودع مرآة أو هدف استيراد، أو يعيده إلى مستودع عادي. راجع [المرايا](../operate/mirrors)                             |
| خطافات الويب          | `--webhook ID --webhook-repository REPOSITORY --webhook-url URL --webhook-secret-file FILE [--webhook-next-secret-file FILE] [--webhook-actions LIST] [--webhook-allow-private LIST] [--webhook-ca-file FILE]`، أو `--webhook-detach ID`                                                | يضيف اشتراك خطاف ويب أو يستبدله أو يزيله. يعيد تشغيل الخدمات ويتحقق من الجاهزية. راجع [خطافات الويب](../protocols/webhooks) |
| العنقود               | `--cluster ha-2` أو `ha-3` `[--cluster-resource NAME]`                                                                                                                                                                                                                                  | على العقدة الأساسية لوحدة تخزين منسوخة: يفعّل نمط العنقود. راجع [عنقود التوافر العالي](../operate/cluster#build)             |
| التحديثات             | `--enable-updates`، `--disable-updates`، `--pin [--version X.Y.Z]`، `--unpin`، `--update-channel stable` أو `beta`، `--statistics on` أو `off`، `--hub-url URL`، `--hub-off`                                                                                                            | يغيّر سياسة التحديث. راجع [التحديثات](./updates)                                                                             |

تعيد تغييرات HTTPS والمخزن والمرايا تشغيل الخدمات وتستعيد الإعدادات السابقة عندما لا يعمل التغيير. تكتفي خيارات التحديث بإعادة كتابة `installation.json` و`hub.json`؛ ولا تعيد تشغيل شيء. مسارات الملفات مطلقة.

## الإعدادات حسب المهمة {#settings-by-task}

### العنوان والمنفذ {#address-and-port}

| المتغير        | القيمة الافتراضية | المعنى                      |
| -------------- | ----------------- | --------------------------- |
| `ARKVORY_HOST` | `127.0.0.1`       | العنوان الذي تستمع عليه API |
| `ARKVORY_PORT` | `8080`            | منفذ TCP                    |

بالإعداد الافتراضي، لا تستطيع الاتصال إلا البرامج على الخادم. لقبول حواسيب أخرى، اختر إحدى طريقتين:

- **HTTPS المدمج.** `arkvory configure --tls-cert … --tls-key … --listen-host 0.0.0.0`. راجع [HTTPS](./https#built-in-tls).
- **وكيل عكسي على حاسوب آخر.** اضبط `ARKVORY_HOST` على عنوان واجهة الشبكة الخاصة بالوكيل، وأدرج الوكيل في `ARKVORY_TRUSTED_PROXIES`. عدّل `runtime.json` أو شغّل `arkvory configure --tls-off --listen-host <address>`. اقصر الوصول إلى المنفذ على الوكيل باستخدام جدار ناري.

يُرفض `--listen-host` وحده: استخدمه مع ملفات TLS أو مع `--tls-off`. بعد `--tls-off`، أضف `--listen-host 127.0.0.1` للعودة إلى عنوان الاسترجاع المحلي، وإلا فستواصل API الاستماع على العنوان المضبوط.

عندما تستمع API على عنوان غير عنوان الاسترجاع المحلي، ومن دون TLS ووكيل موثوق، تسجّل التحذير `http.plaintext_exposed` عند البدء. لا ترسل المفاتيح عبر HTTP غير مشفّر بين الحواسيب أبدًا.

على Linux، تعمل الخدمات بحساب بلا امتيازات، ولا يمكنه عادةً الاستماع على منفذ أقل من 1024. تستمر اختصارات وحدة التحكم (قائمة ابدأ وعنصر القائمة) في الإشارة إلى المنفذ 8080. تتبع أوامر دورة الحياة العنوان والمنفذ في `runtime.json`. في تثبيت Compose يكون العنوان والمنفذ ثابتين: راجع [Docker Compose](./docker#ports).

### العنوان العام والترويسات الممرّرة {#public-address}

لا يوجد إعداد لعنوان URL عام. يبني الخادم الروابط المطلقة، مثل الروابط في استجابات Git LFS وnpm، من الطلب: يكون المخطط `https` عندما يكون الاتصال عبر TLS أو عندما يرسل الوكيل `X-Forwarded-Proto: https`، ويُؤخذ المضيف من الترويسة `Host`. يستطيع الوكيل المدرج في `ARKVORY_TRUSTED_PROXIES` ضبط المضيف أيضًا بواسطة `X-Forwarded-Host`. لذلك يجب أن يمرّر وكيلك الاسم العام. راجع [HTTPS](./https#reverse-proxy).

يقبل `ARKVORY_TRUSTED_PROXIES` حتى 32 عنوانًا أو نطاق CIDR، مفصولة بفواصل. هذه الأطراف وحدها تستطيع تعيين عنوان العميل بواسطة `X-Forwarded-For` ومعرّف الطلب بواسطة `X-Request-Id`. من دون القائمة، يظهر كل عميل كأنه قادم من عنوان الوكيل، ويحسبهم حد تسجيل الدخول عميلًا واحدًا.

### المتصفحات على عنوان آخر {#browsers}

يسرد `ARKVORY_CORS_ORIGINS` ما يصل إلى 16 أصلًا لوحدة تحكم أو تطبيق ويب آخر يعمل على عنوان مختلف، مفصولة بفواصل. يتألف كل أصل من مخطط ومضيف ومنفذ اختياري، ومن دون مسار. يجب أن يستخدم HTTPS؛ ولا يُقبل HTTP غير المشفّر إلا مع `localhost` و`127.0.0.1` و`[::1]`. راجع [HTTPS](./https#console-api-address). يتيح `ARKVORY_ALLOW_REGISTRATION=true` للأشخاص إنشاء حساباتهم على صفحة تسجيل الدخول؛ وهو متوقف افتراضيًا.

### قاعدة البيانات {#database}

| المتغير                      | القيمة الافتراضية    | المعنى                                                                                                        |
| ---------------------------- | -------------------- | ------------------------------------------------------------------------------------------------------------- |
| `ARKVORY_DATABASE_URL`       | يضبطه برنامج التثبيت | عنوان URL لاتصال PostgreSQL. تستمع قاعدة البيانات المُدارة على `127.0.0.1` على المنفذ الذي اختير أثناء التثبيت |
| `ARKVORY_DATABASE_POOL_SIZE` | `20`                 | حجم مجموعة اتصالات استعلامات API، من 4 إلى 200                                                                |

لا توجّه تثبيتًا إلى قاعدة بيانات أخرى. تنتمي الملفات المخزّنة والفهرس إلى مجموعة واحدة. الانتقال إلى قاعدة بيانات جديدة هو استعادة من نسخة احتياطية: راجع [النسخ الاحتياطي](../operate/backups).

لخادم PostgreSQL خارجي، احسب `max_connections` بناءً على مجموع الحدود العليا لمجموعات الاتصالات في جميع العمليات. لكل عملية API، بما في ذلك كل بوابة قراءة، مجموعات منفصلة: حتى `ARKVORY_DATABASE_POOL_SIZE` اتصالًا للاستعلامات (20 افتراضيًا)، و8 اتصالات للجلسات طويلة الأمد، وحتى `ARKVORY_MAX_UPLOADS` اتصالًا لأقفال كتابة عمليات الرفع (8 افتراضيًا). للعامل مجموعات منفصلة تضم 5 اتصالات للاستعلامات، و8 للجلسات، و`2 + min(N, 16)` لأقفال الكتابة، حيث N هو عدد المرايا المضبوطة. ولكل عملية API وللعامل أيضًا مجموعة تضم حتى 16 اتصالًا لقرّاء ذاكرات التخزين المؤقت للوحدات، ولا تُفتح إلا أثناء قراءة وحدة من ذاكرتها المؤقتة. لوكيل النسخ الاحتياطي مجموعته الخاصة من 6 اتصالات، ويفتح مجموعة أخرى من 6 اتصالات أثناء التقاط نسخة احتياطية. هذه حدود عليا وليست اتصالات مشغولة باستمرار. اترك سعة إضافية لأدوات الترخيص والصيانة وإدارة قاعدة البيانات.

### دليل التخزين والمساحة المتاحة {#storage}

| المتغير                         | القيمة الافتراضية | المعنى                                                                      |
| ------------------------------- | ----------------- | --------------------------------------------------------------------------- |
| `ARKVORY_DATA_DIR`              | `<root>/data`     | موضع تخزين محتوى الملفات. يضبطه برنامج التثبيت. استخدم قرصًا محليًا           |
| `ARKVORY_CAPACITY_BYTES`        | 10 TiB            | أقصى ما يمكن أن يستخدمه كل المحتوى المحجوز. هو حد للحجوزات وليس قياسًا للقرص |
| `ARKVORY_STORAGE_RESERVE_BYTES` | 1 GiB             | مساحة متاحة لا تستخدمها عمليات الرفع أبدًا. يوقف `0` الاحتياطي               |
| `ARKVORY_MAX_OBJECT_BYTES`      | نحو 10 TiB        | أكبر كائن منفرد. اضبط قيمة أقل لتقييد حجم الملف                             |

أبقِ `ARKVORY_DATA_DIR` في الموضع الذي حدّده برنامج التثبيت. لا تستطيع وحدات Linux الكتابة إلا في `data/` و`logs/` و`updates/inbox/` ضمن الجذر، لذا يكون أي مسار آخر للقراءة فقط بالنسبة إليها. لاستخدام قرص أكبر، أوقف الخدمات وانسخ المحتوى إلى القرص الجديد، ثم ركّب القرص في `data/` مع المالك `arkvory`، وابدأ الخدمات. على Windows وLinux يمكنك أيضًا اختيار الجذر نفسه عند التثبيت بنص برمجي (`-Root` و`ARKVORY_INSTALL_ROOT`). راجع [التخزين](../operate/storage).

### حدود النقل {#limits}

تخص الحدود عملية API واحدة. المعدّل `0` يعني عدم وجود حد.

| المتغير                               | القيمة الافتراضية               | المعنى                                                                                                    |
| ------------------------------------- | ------------------------------- | --------------------------------------------------------------------------------------------------------- |
| `ARKVORY_MAX_UPLOADS`                 | `8`                             | عمليات الرفع المتزامنة، من 1 إلى 32                                                                       |
| `ARKVORY_MAX_DOWNLOADS`               | `16`                            | عمليات التنزيل المتزامنة، من 1 إلى 256                                                                    |
| `ARKVORY_MAX_UPLOADS_PER_PRINCIPAL`   | `min(4, ARKVORY_MAX_UPLOADS)`   | عمليات الرفع المتزامنة لحساب أو مفتاح واحد                                                                |
| `ARKVORY_MAX_DOWNLOADS_PER_PRINCIPAL` | `min(4, ARKVORY_MAX_DOWNLOADS)` | عمليات التنزيل المتزامنة لحساب أو مفتاح واحد                                                              |
| `ARKVORY_DOWNLOAD_STRATEGY`           | `ordered`                       | ترتيب طابور التنزيل: `ordered` (فئات وأدوار)، أو `smallest-first`، أو `shared` (بلا طابور، كما في السابق) |
| `ARKVORY_UPLOAD_BYTES_PER_SECOND`     | `0`                             | معدّل الرفع الإجمالي بالبايت في الثانية                                                                    |
| `ARKVORY_DOWNLOAD_BYTES_PER_SECOND`   | `0`                             | معدّل التنزيل الإجمالي بالبايت في الثانية                                                                  |
| `ARKVORY_UPLOAD_DEADLINE_MS`          | `1800000`                       | أطول مدة لطلب رفع واحد، 30 دقيقة                                                                          |
| `ARKVORY_UPLOAD_IDLE_TIMEOUT_MS`      | `30000`                         | يتوقف طلب الرفع إذا لم يرسل بيانات طوال هذه المدة                                                         |

يجب أن يسمح الوكيل أمام API بطلب لا تقل مدته عن `ARKVORY_UPLOAD_DEADLINE_MS`. راجع [HTTPS](./https#reverse-proxy). توجد الحدود الأخرى، مثل طابور الانتظار ومعدّلات كل حساب، في [متغيرات البيئة](../reference/environment#transfers-and-bandwidth).

يمكن تغيير قيم طابور التنزيل (الاستراتيجية وعدد التنزيلات المتزامنة والاحتياطي والأوزان وغيرها) أيضًا من دون إعادة تشغيل: [[ui:fleet]] ← [[ui:fleetThisSettings]]، أو `PUT /api/v1/system/downloads/settings`. تتقدم القيم المحفوظة على هذه المتغيرات في عملية الكتابة؛ راجع [المواقع](../operate/sites#site-settings).

### النسخ الاحتياطي والمرايا {#backups-mirrors}

استخدم `configure` لكليهما. يكتب `--backup-vault` المتغير `ARKVORY_BACKUP_VAULT`، ويمنح حساب الخدمة حق الوصول إلى الدليل، ويعيد تشغيل وكيل النسخ الاحتياطي وحده، ولا يحتفظ بالتغيير إلا عندما يبلّغ الوكيل بأن المخزن متاح. يجب أن يكون المخزن خارج جذر التثبيت وخارج التخزين. يكتب `--mirror` المتغير `ARKVORY_MIRRORS_FILE` وملفات المفاتيح، ويعيد تشغيل API والعامل، ويتحقق من المصدر باستخدام مفتاحك قبل تغيير أي شيء.

### التحديثات والمركز {#updates-and-hub}

توجد سياسة التحديث في `installation.json` و`config/hub.json`. توجد الخيارات في [أمر configure](#configure-command)، ومعانيها في [التحديثات](./updates). المتغير `ARKVORY_HUB_URL` في `runtime.json` منفصل: فهو يضبط وجهة إرسال ملاحظات وحدة التحكم. يغيّر `configure --hub-url` أو `--hub-off` الاثنين معًا، ويتغيّر عنوان الملاحظات بعد إعادة تشغيل الخدمات التالية.

### السجلات وإيقاف التشغيل {#logs-and-shutdown}

| المتغير                    | القيمة الافتراضية | المعنى                                                                                       |
| -------------------------- | ----------------- | -------------------------------------------------------------------------------------------- |
| `ARKVORY_LOG_LEVEL`        | `info`            | `debug` أو `info` أو `warning` أو `error`. يخفي المستويان `warning` و`error` سجل الوصول أيضًا |
| `ARKVORY_ACCESS_LOG`       | `true`            | سجل JSON واحد لكل طلب HTTP. لا تُكتب سلسلة الاستعلام أبدًا                                     |
| `ARKVORY_DRAIN_TIMEOUT_MS` | `30000`           | الوقت الممنوح للطلبات الجارية كي تنتهي بعد طلب التوقف                                        |

تمنح برامج الإشراف الخدمة 120 ثانية للتوقف. إذا ضبطت مهلة إنهاء الطلبات على أكثر من نحو 90 ثانية، فارفع أيضًا مهلة التوقف في مدير الخدمات: `TimeoutStopSec` في وحدات systemd، ومهلة توقف خدمات Windows، و`stop_grace_period` في Compose. راجع [المراقبة](../operate/monitoring).

## تطبيق تغيير {#apply-change}

يطبّق `configure` تغييره بنفسه. لكل تعديل تجريه في `config/runtime.json`:

1. أنشئ نسخة من الملف، مثل `sudo cp -p /opt/proanima-arkvory/config/runtime.json /root/runtime.json.bak`. يحتوي على كلمة مرور قاعدة البيانات: أبقِ النسخة خاصة.
2. عدّل الملف في موضعه. حافظ على JSON صالح، وعلى أن تكون كل قيمة سلسلة نصية.
3. تحقق من المالك ووضع الأذونات. على Linux يجب أن يبقيا `root:arkvory` و`0640`. أصلحهما بواسطة `sudo chown root:arkvory runtime.json` و`sudo chmod 0640 runtime.json`.
4. أعد تشغيل الخدمات. لا تُقرأ الإعدادات إلا عند البدء.

   ```bash
   sudo systemctl restart arkvory-api arkvory-worker arkvory-backup
   ```

   ```powershell
   Restart-Service Arkvoryapi, Arkvoryworker, Arkvorybackup
   ```

   في تثبيت Compose، أوقف الحاويات وابدأها بأمر `compose` من [Docker Compose](./docker#manage):

   ```bash
   "${compose[@]}" stop --timeout 120 backup worker api
   "${compose[@]}" up -d --wait api worker
   "${compose[@]}" up -d backup
   ```

5. تحقق من النتيجة. توقف القيمة الخارجة عن نطاقها العملية عند البدء برسالة تذكر اسم المتغير، ولا تذكر قيمته أبدًا. على Linux، اقرأها بواسطة `journalctl -u arkvory-api -n 50`. لا يعود Arkvory إلى قيمة افتراضية في هذه الحالة.

تقطع إعادة التشغيل عمليات النقل الجارية. يستأنفها العملاء.

## استبدال مفتاح الاسترداد {#replace-recovery-key}

استبدل مفتاح الاسترداد إذا اشتبهت في أن شخصًا قد قرأ `config/bootstrap-token.txt`. يُخزَّن المفتاح في موضعين يجب تغييرهما معًا: يحتوي ملف `bootstrap-token.txt` على المفتاح، ويحتوي الإدخال `bootstrap-owner` في `keys.json` على SHA-256 الخاص به. أبقِ الإدخال `deployment-health` كما هو.

1. أنشئ نسخة من `config/keys.json`.
2. احفظ هذا النص البرمجي باسم `replace-recovery-key.mjs`:

   ```js
   import { createHash, randomBytes } from 'node:crypto';
   import { readFileSync, writeFileSync } from 'node:fs';

   const directory = process.argv[2];
   const token = randomBytes(32).toString('hex');
   const keys = JSON.parse(readFileSync(`${directory}/keys.json`, 'utf8'));
   const owner = keys.find((key) => key.id === 'bootstrap-owner');
   if (!owner) throw new Error('No bootstrap-owner entry');
   owner.sha256 = createHash('sha256').update(token).digest('hex');
   writeFileSync(`${directory}/keys.json`, JSON.stringify(keys, null, 2));
   writeFileSync(`${directory}/bootstrap-token.txt`, token);
   ```

3. شغّله بحساب `root` أو مسؤول باستخدام Node.js الخاص بالتثبيت. يكتب النص البرمجي في الملفات الموجودة، لذلك تبقى الملكية وقواعد الوصول كما هي.

   ```bash
   sudo /opt/proanima-arkvory/runtime/node ./replace-recovery-key.mjs /opt/proanima-arkvory/config
   ```

   ```powershell
   & 'C:\ProgramData\ProAnima\Arkvory\runtime\node.exe' .\replace-recovery-key.mjs 'C:\ProgramData\ProAnima\Arkvory\config'
   ```

   بعد التثبيت بنص برمجي، استخدم Node.js تحت `runtime\node-v24.22.3-…` بدلًا من ذلك.

4. أعد تشغيل الخدمات كما هو موضح في [تطبيق تغيير](#apply-change).
5. اقرأ المفتاح الجديد من `config/bootstrap-token.txt`، واحذف النص البرمجي ونسخة `keys.json`.

لا تتأثر الحسابات والرموز الشخصية ومفاتيح الخدمة. فهي موجودة في قاعدة البيانات.
