# المصادقة

يحتاج كل استدعاء إلى `/api/v1` إلى بيانات اعتماد، باستثناء فحوص الصحة العامة وخيارات تسجيل الدخول وتسجيل الدخول والتسجيل. تسرد هذه الصفحة أنواع بيانات الاعتماد، وكيفية الحصول على كل منها وإرسالها، ومعنى قواعد الوصول في [مرجع API](./index#reference-pages). لقواعد الأشخاص الذين يديرون الوصول، انظر [الحسابات والوصول](../use/accounts).

## نظرة سريعة على بيانات الاعتماد {#credentials}

| بيانات الاعتماد  | شكلها                | كيفية الحصول عليها                                    | مدة الصلاحية                    | الاستخدام                                         |
| ---------------- | -------------------- | ----------------------------------------------------- | ------------------------------- | ------------------------------------------------- |
| جلسة وحدة التحكم | `dps_…`              | تسجيل الدخول باسم وكلمة مرور                          | 12 ساعة                         | شخص في وحدة التحكم أو برنامج نصي يسجل الدخول      |
| رمز وصول شخصي    | `pat_…`              | إنشاؤه من جلسة                                        | 90 يوماً افتراضياً، و365 كحد أقصى | البرامج النصية والأدوات لشخص واحد                 |
| مفتاح خدمة       | `arkvory_…`          | إصداره لحساب خدمة ثم تفعيله                           | 90 يوماً افتراضياً، و365 كحد أقصى | ‏CI/CD ووكلاء النشر والأنظمة الأخرى               |
| مفتاح الاسترداد  | 64 رقماً سداسياً عشرياً | يكتبه برنامج التثبيت إلى `config/bootstrap-token.txt` | لا تنتهي صلاحيته                | إنشاء المالك وإدارة حسابات الخدمة واسترداد الوصول |
| رابط تنزيل       | `dtl_…`              | إنشاؤه لمُخرَج واحد                                     | من 60 ثانية إلى 24 ساعة         | إعطاء مُخرَج واحد لشخص دون مفتاح                    |

استخدم مفتاح خدمة للأتمتة ورمز وصول شخصياً لأدوات شخص. لا تستخدم مفتاح الاسترداد للعمل اليومي.

## صيغ الترويسات {#headers}

تقبل `/api/v1` بيانات اعتماد في ترويسة واحدة:

```http
Authorization: Bearer <credential>
```

- يبلغ طول بيانات الاعتماد من 32 إلى 512 محرفاً. أي طول آخر يؤدي فوراً إلى `credential_invalid`.
- يقبل سجل الحاويات (`/v2`) وGit LFS ‏(`/lfs`) وسجل npm ‏(`/npm`) أيضاً HTTP Basic، لأن `docker login` وgit وnpm ترسل بيانات الاعتماد بهذه الطريقة. لا يُفحص اسم المستخدم؛ كلمة المرور هي بيانات الاعتماد. انظر [العملاء والبروتوكولات](../protocols/index#credentials).
- يوضع رابط التنزيل في سلسلة الاستعلام بصيغة `?token=dtl_…`، ويعمل فقط على مسار محتوى مُخرَج واحد. انظر [روابط التنزيل](#download-links). تتقدم ترويسة `Authorization` دائماً على الاستعلام.
- يتلقى الطلب الذي لا يحمل بيانات اعتماد صالحة الاستجابة `401` مع `WWW-Authenticate: Bearer` وسبب: `credential_missing` أو `credential_invalid` أو `session_expired` أو `token_expired`. لا يعرف أن بيانات الاعتماد انتهت صلاحيتها إلا حامل سرها المطابق تماماً.
- **بلا ملفات تعريف ارتباط.** لا يضبط Arkvory أياً منها ولا يقرأ أياً منها، لذلك لا يرفق المتصفح بيانات اعتماد تلقائياً أبداً، ولا يوجد تزوير طلبات عبر المواقع يلزم التصدي له. يرسل البرنامج النصي الترويسة في كل استدعاء. تحتفظ وحدة التحكم برمز جلستها في ذاكرة علامة تبويب المتصفح وتنساه عند إغلاقها.
- **الأصول الأخرى.** لا تحتاج صفحة على عنوان Arkvory نفسه إلى شيء. تُرفض صفحة على عنوان آخر بالاستجابة `403` والسبب `origin_not_allowed` ما لم يُدرج المسؤول أصلها في `ARKVORY_CORS_ORIGINS`، حتى مع بيانات اعتماد صالحة. استخدم HTTPS: يمكن قراءة بيانات الاعتماد المرسلة عبر HTTP غير المشفر على الشبكة. انظر [HTTPS](../install/https).

تحقق من هوية بيانات الاعتماد وما تتيحه:

```bash
curl -fsS -H "Authorization: Bearer $ARKVORY_KEY" "$ARKVORY_URL/api/v1/auth/me"
curl -fsS -H "Authorization: Bearer $ARKVORY_KEY" "$ARKVORY_URL/api/v1/auth/permissions"
```

## جلسات تسجيل الدخول إلى وحدة التحكم {#sessions}

يسجل الشخص الدخول باسم وكلمة مرور ويتلقى جلسة. تفعل وحدة التحكم ذلك نيابة عنك؛ ويمكن لبرنامج نصي فعل الشيء نفسه.

1. ضع الاسم وكلمة المرور في ملف خاص `login.json` كي لا يظهرا أبداً في سطر أوامر أو قائمة عمليات:

   ```json
   { "name": "alice", "password": "a long password of 12 to 128 characters" }
   ```

2. استدعِ `login`:

   ```bash
   curl -fsS -X POST "$ARKVORY_URL/api/v1/auth/login" \
     -H "Content-Type: application/json" -d @login.json
   ```

3. تحتوي الاستجابة على رمز الجلسة ووقت انتهائها:

   ```json
   {
     "token": "dps_…",
     "expiresAt": "2026-10-05T21:30:00.000Z",
     "account": { "id": "…", "name": "alice", "administrator": false, "enabled": true }
   }
   ```

4. أرسل الرمز بصيغة `Authorization: Bearer dps_…`.

قواعد الجلسة:

- تدوم 12 ساعة ولا تتمدد. بعد ذلك، يعيد كل استدعاء الاستجابة `401` بالسبب `session_expired`. سجّل الدخول مجدداً.
- للحساب 32 جلسة كحد أقصى. ينهي تسجيل دخول جديد أقدم الجلسات التي تتجاوز ذلك العدد.
- تنهي `POST /api/v1/auth/logout` الجلسة. يؤدي تغيير كلمة مرورك أو إعادة تعيينها بواسطة مسؤول إلى إنهاء جميع جلسات الحساب ورموزه الشخصية. ويوقفها تعطيل الحساب.
- تحمل الجلسة كامل صلاحيات الحساب، بما فيها علم المسؤول. الجلسة وحدها تستطيع إنشاء الرموز الشخصية وإبطالها وتغيير كلمة مرور الحساب نفسه.
- تُقارن الأسماء دون مراعاة حالة الأحرف. يعطي الاسم الخاطئ وكلمة المرور الخاطئة والحساب المعطّل الاستجابة `401` نفسها بالسبب `invalid_credentials`.
- لا تسجل بوابة القراءة دخول أي شخص؛ استخدم الكاتب.

### التسجيل الذاتي {#self-registration}

نقطة النهاية `GET /api/v1/auth/options` عامة وتخبرك بما إذا كان يجوز للأشخاص إنشاء حساباتهم. التسجيل الذاتي معطّل ما لم يضبط المسؤول `ARKVORY_ALLOW_REGISTRATION=true`؛ عندئذٍ تنشئ `POST /api/v1/auth/register` بالجسم نفسه المستخدم لتسجيل الدخول حساباً عادياً (ليس مسؤولاً، ودون وصول إلى أي مستودع)، وتعيد جلسة بالاستجابة `201`. وإلا تجيب بـ`403` والسبب `registration_disabled`. يتوقف التسجيل الذاتي عند 900 حساب، كي يظل بإمكان المسؤولين إنشاء حسابات حتى حد 1,000.

## رموز الوصول الشخصية {#personal-tokens}

يتيح رمز الوصول الشخصي لبرنامج نصي العمل بهويتك دون كلمة مرورك. لا تستطيع إنشاءه إلا جلسة مسجّل دخولها.

```bash
curl -fsS -X POST "$ARKVORY_URL/api/v1/auth/tokens" \
  -H "Authorization: Bearer $SESSION" -H "Content-Type: application/json" \
  -d '{"name":"laptop-cli","scope":"read-write","expiresAt":"2026-12-31T00:00:00Z"}'
```

في وحدة التحكم، افتح [[ui:personalAccessTokens]] في بطاقة [[ui:connection]]، وأدخل [[ui:tokenName]]، واختر [[ui:tokenScope]] و[[ui:tokenExpiry]]، ثم اختر [[ui:generateToken]].

| الحقل       | القاعدة                                                                                                          |
| ----------- | ---------------------------------------------------------------------------------------------------------------- |
| `name`      | من 1 إلى 64 محرفاً.                                                                                               |
| `scope`     | ‏`read` أو `read-write`. تستخدم واجهة API ‏`read-write` عند حذفه؛ وتقترح وحدة التحكم [[ui:tokenScopeRead]] أولاً. |
| `expiresAt` | وقت مستقبلي وفق RFC 3339، لا يبعد أكثر من 365 يوماً. الافتراضي 90 يوماً. لا توجد رموز بلا نهاية.                   |

تتضمن استجابة `201` الرمز مرة واحدة باسم `token`. احفظه حينها: يحتفظ الخادم بالتجزئة فقط، وتعرض القائمة بادئة قصيرة. وبعد ذلك:

- يملك الرمز وصول حسابه إلى المستودعات ولا شيء إضافياً. لا يحمل علم المسؤول أبداً، فلا يستطيع إدارة الحسابات أو المجموعات أو التحديثات أو النسخ الاحتياطية.
- لا يستطيع رمز `read` إلا القراءة. يُرفض أي طلب يغيّر شيئاً، باستثناء `logout`، بالاستجابة `403` والسبب `read_only_token` قبل تشغيل العملية.
- لا يستطيع الرمز إنشاء رموز أو تغيير كلمة مرور؛ يتطلب ذلك جلسة.
- للحساب 50 رمزاً نشطاً كحد أقصى. تسردها `GET /api/v1/auth/tokens` مع بادئتها ونطاقها ونهايتها وآخر استخدام لها. تبطل `DELETE /api/v1/auth/tokens/{id}` أحدها فوراً ([[ui:revokeToken]] في وحدة التحكم). يستطيع المسؤول سرد رموز أي حساب وإبطالها.
- يعيد الرمز المنتهي الصلاحية الاستجابة `401` بالسبب `token_expired`.

## حسابات الخدمة والمفاتيح {#service-accounts}

**حساب الخدمة** هوية لأداة، مثل وكيل بناء. له **سياسة**: قائمة **روابط**، يسمي كل منها مستودعاً واحداً و**الإجراءات** المحددة المسموح بها فيه (انظر [إجراءات المستودع](#repository-actions)). للسياسة 64 ربطاً كحد أقصى. يملك الحساب عمليات الرفع والمهام التي تبدأها مفاتيحه، لذلك لا يُفقد شيء عند تدوير مفتاح. للخادم 1,000 حساب خدمة كحد أقصى.

لا ينشئ حساب الخدمة إلا [مفتاح الاسترداد](#recovery-key). ويغيّر الحسابات الموجودة هو أو مشغّل لديه [تفويض](#delegation). في وحدة التحكم، استخدم [[ui:services]]: ‏[[ui:serviceCreate]] ثم اضبط [[ui:servicePolicy]]. يملأ [[ui:bindingRead]] إجراءات القراءة السبعة، ويضيف [[ui:bindingPublish]] الإجراءات اللازمة لرفع الحزم وتسجيلها.

```bash
curl -fsS -X POST "$ARKVORY_URL/api/v1/service-accounts" \
  -H "Authorization: Bearer $RECOVERY_KEY" -H "Content-Type: application/json" \
  -d '{"name":"ci-release","bindings":[{"resource":{"kind":"repository","id":"releases"},
       "actions":["repository.read","artifact.read","upload.create","upload.read","upload.write",
                  "upload.complete","upload.cancel","job.read","package.publish"]}]}'
```

تستخدم الأسماء من 3 إلى 64 محرفاً من الأحرف والأرقام و`_` و`.` و`-`. لتغيير السياسة، أرسل `PUT /api/v1/service-accounts/{id}/policy` مع `expectedRevision` التي قرأتها ([المقارنة والاستبدال](./index#revisions)). لتعطيل الحساب، أرسل `PATCH /api/v1/service-accounts/{id}` مع `{"expectedRevision": n, "enabled": false}`؛ تتوقف جميع مفاتيحه عن العمل حتى تعيد تمكينه.

### مفاتيح الخدمة {#service-keys}

المفتاح هو السر الذي يسجل حساب الخدمة دخوله به. شكله `arkvory_<uuid>.<secret>`. يمر المفتاح بثلاث حالات: `pending` و`active` و`revoked`.

1. **الإصدار.** أرسل `POST /api/v1/service-accounts/{id}/keys` مع `Idempotency-Key` و`name` و`bindings` المسموح للمفتاح استخدامها، ومع `expiresAt` إن أردت (بتوقيت UTC، خلال 365 يوماً؛ والافتراضي 90). يجب أن تقع روابط المفتاح ضمن سياسة الحساب. تتضمن الاستجابة `201` بيانات تعريف المفتاح و`secret` الخاص به، لهذه المرة فقط. يعيد التكرار بمفتاح منع التكرار نفسه الاستجابة `200` مع بيانات التعريف ودون السر.
2. **التفعيل.** يكون المفتاح الجديد `pending` وغير قابل للاستخدام إلا لاستدعاء واحد هو `POST /api/v1/auth/activate-key`، مع السر الجديد بصفته بيانات الاعتماد. الاستجابة `204`. افعل ذلك خلال 15 دقيقة؛ وبعدها تنتهي صلاحية المفتاح دون استخدامه. في وحدة التحكم، انسخ السر، واختر [[ui:keySaved]] ثم [[ui:keyActivate]]. لا يسبب التفعيل مجدداً ضرراً.
3. **الاستخدام.** يعمل المفتاح حتى `expiresAt` أو حتى إبطاله أو تعطيل حسابه.

```bash
curl -fsS -X POST "$ARKVORY_URL/api/v1/service-accounts/$ACCOUNT/keys" \
  -H "Authorization: Bearer $RECOVERY_KEY" -H "Idempotency-Key: ci-release-2026-10" \
  -H "Content-Type: application/json" \
  -d '{"name":"ci-release-2026-10","bindings":[{"resource":{"kind":"repository","id":"releases"},
       "actions":["upload.create","upload.read","upload.write","upload.complete","job.read"]}]}'
curl -fsS -X POST "$ARKVORY_URL/api/v1/auth/activate-key" -H "Authorization: Bearer $NEW_SECRET"
```

الحدود: للحساب 3 مفاتيح نشطة و2 معلّقان كحد أقصى في الوقت نفسه (`507` بالسبب `key_limit`).

**التدوير.** تصدر `POST /api/v1/api-keys/{id}/rotate` مفتاحاً جديداً معلّقاً للحساب نفسه، بالجسم نفسه المستخدم للإصدار ومع `Idempotency-Key`. يجب أن تقع روابطه ضمن روابط المفتاح القديم. عند تفعيل المفتاح الجديد، تُقصّر نهاية صلاحية المفتاح القديم إلى 24 ساعة كحد أقصى من تلك اللحظة. انقل أدواتك إلى المفتاح الجديد، ثم أبطل القديم. في وحدة التحكم: [[ui:keyRotate]].

**الإبطال.** تنهي `POST /api/v1/api-keys/{id}/revoke` المفتاح نهائياً؛ ولا يسبب تكرارها ضرراً. في وحدة التحكم: [[ui:keyRevoke]]. لا يوقف إبطال مفتاح عملية نقل بدأت بالفعل. هل فقدت سر مفتاح معلّق؟ أبطله وأصدر آخر بمفتاح منع تكرار جديد.

### التفويض {#delegation}

يمكن لمفتاح الاسترداد تسليم جزء من الإدارة إلى **مشغّل**: حساب خدمة يجوز لمفتاحه إدارة حسابات خدمة أخرى. يسمي **التفويض** مفتاح المشغّل والحساب الهدف و**الإجراءات الإدارية** التي يجوز له استخدامها عليه و**سقف الصلاحيات**، أي إجراءات المستودع التي يجوز له منحها. الإجراءات الإدارية السبعة هي:

| الإجراء                  | ما يسمح به                            |
| ------------------------ | ------------------------------------- |
| `service-account.read`   | رؤية الحساب في القوائم وقراءة بطاقته. |
| `service-account.manage` | تمكين الحساب أو تعطيله.               |
| `policy.read`            | قراءة سياسة الحساب.                   |
| `policy.manage`          | استبدال سياسة الحساب.                 |
| `credential.read`        | سرد مفاتيح الحساب وقراءة مفتاح.       |
| `credential.manage`      | إصدار المفاتيح وتدويرها وإبطالها.     |
| `service-audit.read`     | قراءة محفوظات مفاتيح الحساب.          |

القواعد: يجب أن يكون مفتاح المشغّل صادراً من مفتاح الاسترداد؛ ولا يدير المشغّل حسابه الخاص أبداً؛ ولا يستطيع منح شيء خارج سقف صلاحياته أو يتجاوز سياسة الحساب؛ ولا يجوز أن تدوم صلاحية مفتاح يصدره أكثر من مفتاحه؛ ولا يؤدي إنهاء تفويض إلى إبطال مفاتيح فُعّلت بالفعل. لا ينشئ الحسابات ويضبط التفويضات إلا مفتاح الاسترداد (`PUT` و`DELETE /api/v1/api-keys/{id}/delegations/{accountId}`). يمكن لمفتاح مشغّل واحد امتلاك حتى 64 تفويضاً. في وحدة التحكم، استخدم [[ui:delegations]]. يتلقى المشغّل الذي يحتاج إلى شيء خارج تفويضه الاستجابة `404` لحساب لا يديره، أو `403`.

## مفتاح الاسترداد {#recovery-key}

ينشئ برنامج التثبيت **مفتاح الاسترداد** مرة واحدة ويكتبه إلى `config/bootstrap-token.txt` في [جذر التثبيت](../install/index#installation-directory). لا يستطيع قراءة الملف إلا مجموعة المسؤولين على Windows أو root على Linux. توجد تجزئته في ملف مفاتيح الخادم (`ARKVORY_KEYS_FILE`) تحت الاسم `bootstrap-owner`. ينشئ برنامج التثبيت أيضاً `config/health-token.txt`، وهو مفتاح ثانٍ بلا أي حقوق على المستودعات، يستطيع استدعاء فحوص الصحة التي تتطلب المصادقة والمقاييس.

ما يستطيع مفتاح الاسترداد فعله:

- إنشاء الحساب الأول وكل حساب بعده، وإعادة تعيين كلمات المرور، وتعطيل الحسابات، وإدارة المجموعات ومنح وصولها إلى المستودعات.
- قراءة التدقيق الأمني وإبطال الرموز الشخصية لأي حساب.
- إنشاء حسابات الخدمة وضبط سياساتها وإصدار مفاتيحها وإبطالها وضبط التفويضات.
- قراءة النسخ الاحتياطية والتحديثات وطلبها، وتنزيل سجل الخادم للملاحظات.
- قراءة المستودع `releases` والكتابة إليه كعضو في مجموعة بوصول [[ui:write]].

ما لا يستطيع فعله: لا يملك وصولاً إلى مستودعات غير `releases`، ولا يستطيع حذف المُخرَجات أو إدارة سياسات التخزين (فهذه الإجراءات موجودة لمفاتيح الخدمة فقط)، وليس جلسة، فلا يستطيع إنشاء رموز شخصية أو تغيير كلمة مرور. احتفظ به على الخادم. تقرؤه أدوات التثبيت هناك. لا تضعه في CI ولا تلصقه في الأدوات؛ أنشئ مفتاح خدمة بدلاً من ذلك. لاستبداله، انظر [الإعدادات](../install/configuration).

يستخدم نموذج [[ui:welcomeOwner]] في وحدة التحكم (تحت [[ui:navStart]]) مفتاح الاسترداد لإنشاء المالك الأول. ولا يعمل إلا ما دام لا يوجد أي حساب. لإعادة تعيين كلمة مرور حساب موجود دون جلسة، اعثر على معرّفه باستخدام `GET /api/v1/users`، وضع كلمة المرور الجديدة (من 12 إلى 128 محرفاً) في ملف خاص وأرسلها بمفتاح الاسترداد. تنهي إعادة التعيين جميع جلسات ذلك الحساب ورموزه.

```bash
echo '{"password": "a new password of 12 to 128 characters"}' > reset.json
curl -fsS -X PATCH "$ARKVORY_URL/api/v1/users/$USER_ID" \
  -H "Authorization: Bearer $RECOVERY_KEY" -H "Content-Type: application/json" -d @reset.json
rm reset.json
```

يمكن للمسؤول إضافة مفاتيح ملفات أخرى في ملف المفاتيح. لكل إدخال `id` و`sha256` للسر و`repositories` و`permissions` ‏(`read` و`write`) التي يحصل عليها، واختيارياً العلمان `administrator` و`serviceAdministrator`. يُقرأ الملف عند بدء التشغيل، لذا أعد تشغيل واجهة API والعامل بعد أي تغيير.

## روابط التنزيل {#download-links}

تعيد `POST /api/v1/repositories/{repository}/artifacts/{id}/links` رمز `token` ‏(`dtl_…`) ورابط `url` لمُخرَج واحد. اطلب مدة صلاحية باستخدام `ttlSeconds`: من 60 إلى 86,400، و3,600 افتراضياً. يحتاج المستدعي إلى `content.read`.

لا يعمل الرابط إلا بطلب `GET` أو `HEAD` إلى `/api/v1/repositories/{repository}/artifacts/{id}/content?token=…`، لذلك المُخرَج في ذلك المستودع، وللقراءة فقط. إنه سر. لا يستطيع الخادم إبطاله قبل انتهاء صلاحيته، ولا يظهر في السجلات. أنشئ الروابط بأقصر مدة تحتاج إليها.

## معنى قاعدة الوصول {#access-rules}

لكل عملية في المرجع سطر **الوصول**. هذه أنواع القواعد:

| القاعدة في المرجع                           | ما تتطلبه                                                                                                                                                                             |
| ------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| أي شخص دون مفتاح                            | لا شيء. حيوية العملية وحالة الجاهزية وخيارات تسجيل الدخول وتسجيل الدخول والتسجيل.                                                                                                     |
| أي مفتاح أو جلسة صالحين                     | أي بيانات اعتماد صالحة. أمثلة: الإمكانات وقائمة العمليات وهويتك وتفاصيل الجاهزية والمقاييس.                                                                                           |
| جلسة حساب مسجّل دخوله (وليست مفتاحاً)         | جلسة شخص. تُرفض الرموز الشخصية والمفاتيح (`session_required`). أمثلة: إنشاء رموزك وإبطالها وتغيير كلمة مرورك.                                                                          |
| مسؤول                                       | جلسة حساب مسؤول أو مفتاح ملف بعلم المسؤول، مثل مفتاح الاسترداد. تُرفض الرموز الشخصية ومفاتيح الخدمة (`administrator_required`). أمثلة: الحسابات والمجموعات والتدقيق الأمني والتحديثات. |
| مفتاح التهيئة (مفتاح استرداد التثبيت)       | مفتاح ملف بعلم إدارة الخدمات. يملكه مفتاح الاسترداد. أمثلة: إنشاء حسابات الخدمة وضبط التفويضات.                                                                                       |
| مفتاح التهيئة أو المفتاح نفسه               | مفتاح الاسترداد أو المفتاح الذي تُسرد تفويضاته.                                                                                                                                        |
| المفتاح الصادر قبل التفعيل أو بعده          | العملية الوحيدة التي تقبل مفتاحاً معلّقاً: التفعيل.                                                                                                                                      |
| المستودعات التي يجوز للمستدعي رؤيتها        | الإجراء `repository.read` على ذلك المستودع، أو أي وصول إليه لجلسة أو مفتاح ملف. يُستبعد المستودع الذي لا يستطيع المستدعي رؤيته من القوائم ويجيب بالاستجابة `404`.                      |
| إذن النظام `backup.read` أو `backup.manage` | تملكه جلسات المسؤولين ومفاتيح الملفات ذات علم المسؤول. ولا تملكه مفاتيح الخدمة والرموز الشخصية أبداً. يتضمن `backup.manage` الإذن `backup.read`.                                       |
| إذن إدارة الخدمات                           | أحد [الإجراءات الإدارية](#delegation) السبعة على الحساب الهدف من تفويض، أو مفتاح الاسترداد.                                                                                           |
| إذن المستودع                                | **كل** إجراءات المستودع المدرجة على المستودع المسمى في المسار. تضيف عدة قواعد وصول شروطاً: يجب أن تكون عملية الرفع أو المهمة أو المرجع ملكاً للمستدعي.                                  |

الجزء الثاني من سطر المستودع، مثل «مفاتيح الملفات: `read` و`write`»، هو المنحة العامة التي يحتاج إليها الأشخاص ومفاتيح الملفات بدلاً من الإجراءات المحددة. انظر [منح المجموعات](#group-grants).

إلى جانب قاعدة الوصول، يرفض الخادم أيضاً التغيير في مستودع مرآة (`409` و`mirror_read_only`)، وترفض بوابة القراءة كل تغيير (`405` و`read_only`).

## أذونات المستودعات {#repository-permissions}

### منح المجموعات {#group-grants}

يحصل الأشخاص على وصول إلى المستودعات عبر **المجموعات**. يمنح المسؤول مجموعة `read` أو `write` (يُعرض بوصفه «قراءة وكتابة») على مستودع ويضيف الحسابات إلى المجموعة. في وحدة التحكم: [[ui:administration]] ثم [[ui:manageGrants]] و[[ui:saveGrant]]. استدعاءات API هي `PUT /api/v1/access-groups/{id}/grants/{repository}` مع `{"access": "read"}` أو `{"access": "write"}`، و`PUT /api/v1/access-groups/{id}/members/{userId}`. تُعاد حساب الحقوق في كل طلب، فيسري التغيير فوراً.

تمنح `read` الإجراءات التالية: `repository.read` و`artifact.read` و`artifact.list` و`content.read` و`package.read` و`asset.read` و`annotation.read`. وتضيف `write` الإجراءات `upload.create` و`upload.read` و`upload.write` و`upload.complete` و`upload.cancel` و`job.read` و`package.publish` و`asset.write` و`asset.restore` و`annotation.write` و`reference.write` و`artifact.promote` و`audit.read`. لا يمكن الحصول على الإجراءات `artifact.delete` و`storage.read` و`storage.manage` و`diagnostics.read` من مجموعة: لا يملكها إلا مفتاح خدمة.

### إجراءات المستودع {#repository-actions}

يحمل مفتاح الخدمة إجراءات محددة، لكل مستودع على حدة. عددها 24:

| الإجراء            | ما يسمح به                                                                                             |
| ------------------ | ------------------------------------------------------------------------------------------------------ |
| `repository.read`  | رؤية المستودع وحالة مرآته.                                                                             |
| `artifact.read`    | قراءة تفاصيل المُخرَج ومراحله وترقياته. ويلزم أيضاً مع كل تغيير على مُخرَج.                                 |
| `artifact.list`    | سرد المُخرَجات والبحث فيها، وسرد المُخرَجات ذات المراحل، وقراءة سجل الترقية وتدفق التغييرات.               |
| `artifact.promote` | تعيين المراحل وإزالتها، والترقية (بالنسخ أو النقل) إلى مستودع آخر.                                     |
| `artifact.delete`  | حذف المُخرَجات، ومعاينة الاحتفاظ وتطبيقه، وإزالة صور الحاويات، وإلغاء قفل ملفات Git LFS قسرياً.           |
| `content.read`     | تنزيل البايتات حسب المعرّف أو الحزمة أو المسار، وإنشاء روابط تنزيل.                                     |
| `upload.create`    | إنشاء جلسات رفع. يستخدمه الدفع إلى السجلات وGit LFS.                                                   |
| `upload.read`      | قراءة جلسات الرفع الخاصة بك وأجزائها.                                                                  |
| `upload.write`     | إرسال الأجزاء أو المحتوى الكامل لعملية رفعك.                                                           |
| `upload.complete`  | إكمال عملية رفعك أو وضع إكمالها في الطابور.                                                            |
| `upload.cancel`    | إلغاء عملية رفعك المعلّقة.                                                                              |
| `job.read`         | قراءة مهام الإكمال الخاصة بك.                                                                          |
| `package.read`     | سرد الحزم وتحديد الإصدارات وتنزيل الحزم.                                                               |
| `package.publish`  | تسجيل أرشيف UPack كحزمة.                                                                               |
| `asset.read`       | سرد الملفات حسب المسار وقراءة مؤشراتها ومحفوظاتها ومراجعاتها. يحتاج تنزيل البايتات إلى `content.read`. |
| `asset.write`      | توجيه مسار إلى مُخرَج أو تخزين ملف خام.                                                                  |
| `asset.restore`    | استعادة مراجعة سابقة لمسار.                                                                            |
| `annotation.read`  | قراءة التسميات وبيانات التعريف والتجميعات والمرفقات.                                                   |
| `annotation.write` | استبدال التسميات وبيانات التعريف والتجميعات والمرفقات.                                                 |
| `reference.write`  | إضافة المراجع التي تحمي مُخرَجاً وإزالتها.                                                                |
| `audit.read`       | قراءة تدقيق فهرس المستودع.                                                                             |
| `storage.read`     | قراءة الحصة والاستخدام وسياسة التخزين وإعدادات التنظيف.                                                |
| `storage.manage`   | تغيير سياسة التخزين وإعدادات التنظيف وتشغيل التنظيف.                                                   |
| `diagnostics.read` | قراءة أحداث التخزين.                                                                                   |

ترد المجموعة الدقيقة التي تحتاج إليها العملية في سطرها في المرجع، مثل `upload.write` و`upload.complete` للعملية `putUploadContent`. يحتاج تغيير مستودع إلى إجراء `read` الموافق أيضاً، مثل `artifact.read` مع `annotation.write`.

تنطبق شروط المالك على عمليات الرفع والمهام: لا تتعامل إلا مع جلسات الرفع ومهام الإكمال التي أنشأها حسابك. تُعد جميع مفاتيح حساب خدمة واحد وجميع جلسات ورموز شخص واحد المالك نفسه. لذلك تُفصل الخدمات المتعددة في مستودع واحد بالحسابات والمستودعات، وليس ببادئات المسار.

### أذونات الإدارة والنظام {#administration-permissions}

يوجد نوعان آخران من الأذونات ليسا إجراءات مستودع. تُسرد الإجراءات الإدارية السبعة تحت [التفويض](#delegation). ولا يملك إذني النظام `backup.read` و`backup.manage` إلا المسؤولون ومفتاح الاسترداد.

## حدود تسجيل الدخول {#sign-in-limits}

يبطئ الخادم تخمين كلمات المرور قبل فحص أي كلمة مرور. تُحفظ العدّادات الخاصة بالعناوين وعدّاد التسجيلات الإجمالي للخادم في ذاكرة كل عملية API وتبدأ مجدداً بعد إعادة التشغيل. تنطبق الحدود الخاصة بالعناوين لكل عنوان عميل، ويُحتسب عنوان IPv6 بحسب بادئته /64. يُخزَّن رصيد كلمات المرور الخاطئة وحالة القفل لكل حساب في PostgreSQL، وتتشاطرهما جميع عمليات API ويستمران بعد إعادة التشغيل. خلف وكيل عكسي، اضبط `ARKVORY_TRUSTED_PROXIES`، وإلا يظهر كل عميل بوصفه الوكيل.

| الحد                           | القيمة                                                                                                                                                                                                                                                                                                        |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| محاولات تسجيل الدخول لكل عنوان | دفعة من 10، ثم محاولة إضافية كل 15 ثانية. لا يستهلك تسجيل الدخول الناجح محاولة.                                                                                                                                                                                                                               |
| كلمات المرور الفاشلة لكل حساب  | تضيف كل كلمة مرور خاطئة 1 إلى رصيد ينخفض بمقدار 1 كل 6 ثوانٍ. فوق 20، يرفض الحساب المحاولات لمدة 1 ثانية، تتضاعف مع كل فشل إضافي حتى 2 دقيقة؛ وخلال ذلك تتلقى حتى كلمة المرور الصحيحة `429`. يُمسح الرصيد عند نجاح تسجيل الدخول أو نجاح المستخدم في تغيير كلمة مروره أو إعادة تعيين كلمة المرور بواسطة المسؤول. |
| التسجيلات لكل عنوان            | ‏3، ثم تسجيل إضافي كل 20 دقيقة.                                                                                                                                                                                                                                                                               |
| التسجيلات لكل خادم             | ‏20، ثم تسجيل إضافي كل 3 دقائق.                                                                                                                                                                                                                                                                               |
| طلبات تسجيل الدخول الجارية     | ‏16 لكل عملية API، وللجسم 10 ثوانٍ للوصول. يعيد التجاوز `503` بالرمز `busy`.                                                                                                                                                                                                                                   |

تعيد المحاولة المرفوضة الاستجابة `429` بالرمز `rate_limited` والسبب `login_attempts` أو `registration_attempts` أو `password_attempts`، و`Retry-After` بالثواني. انتظر تلك المدة؛ ولا تكرر في حلقة. خارج فترة القفل المؤقت، يؤدي إدخال كلمة المرور الحالية بشكل خاطئ عند تغيير المستخدم كلمة مروره إلى زيادة الرصيد نفسه الخاص بالحساب، ويعيد `401` بالسبب `current_password_invalid`. أثناء القفل المؤقت، يعيد تغيير كلمة المرور `429` بالسبب `password_attempts`. تُصفّر إعادة تعيين كلمة المرور بواسطة المسؤول هذا الرصيد. ميزانية المحاولات لكل عنوان مستقلة عن رصيد الحساب. تُكتب جميع عمليات تسجيل الدخول والتسجيل وتغيير كلمات المرور وتغيير الرموز في التدقيق الأمني (`GET /api/v1/security/audit`، للمسؤولين فقط)، الذي يحتفظ بـ365 يوماً.
