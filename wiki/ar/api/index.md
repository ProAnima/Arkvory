# نظرة عامة على HTTP API

واجهة HTTP API هي الواجهة التي تستخدمها وحدة تحكم الويب وعميل سطر الأوامر وحزمة SDK. يمكن لتكاملك تنفيذ كل ما تنفذه بأي لغة. تشرح هذه الصفحة القواعد التي تسري على كل عملية. تسرد الصفحات ضمن [صفحات المرجع](#reference-pages) كل عملية مع قاعدة الوصول إليها وقاعدة إعادة المحاولة ومعلماتها واستجاباتها، وتُولّد من العقد الذي يفرضه الخادم.

## الأساسيات {#basics}

- **المسار الأساسي.** تقع كل عملية تحت `/api/v1`، مثل `https://arkvory.example/api/v1/repositories`. الاستثناء الوحيد هو فحوص الصحة تحت `/health`.
- **الصيغة.** الطلبات والاستجابات بصيغة JSON ‏(`application/json`). يقتصر جسم JSON على 64 KiB، ويتلقى الطلب الذي يرسل نوع محتوى آخر لعملية JSON الاستجابة `415`. تُرسل بايتات الملفات بصيغة `application/octet-stream`.
- **الحقول المجهولة.** ترفض معظم العمليات طلباً يحتوي على حقل لا تعرّفه (`400`، مع الحقل في `details`). في الاستجابات، تجاهل الحقول التي لا تعرفها.
- **الأوقات** طوابع زمنية وفق RFC 3339 بتوقيت UTC. **معرّفات** المُخرَجات وعمليات الرفع والمهام والحسابات والمفاتيح من نوع UUID.
- **الأسماء.** يطابق اسم المستودع النمط `[a-z0-9][a-z0-9_-]{0,63}`. يتكون اسم الملف (اسم المُخرَج) من 240 محرفاً كحد أقصى ولا يتضمن `/` أو `\`. يصل المسار في المستودع إلى 1,024 محرفاً.
- **التخزين المؤقت.** تحمل الاستجابات `Cache-Control: private, no-store`.
- **البروتوكولات الأخرى.** تتبع المسارات `/v2` (الحاويات) و`/lfs` ‏(Git LFS) و`/npm` مواصفات عملائها وتستخدم صيغ أخطاء خاصة بها. وليست جزءاً من مستند OpenAPI. انظر [العملاء والبروتوكولات](../protocols/index).

### الأحجام والأعداد {#sizes}

لا يستطيع رقم JSON تمثيل كل قيمة من 64 بت. لذلك يرسل Arkvory **الأحجام وعدّادات البايتات كسلاسل نصية عشرية**: `"size": "1048576"`. وينطبق الأمر نفسه على الحجم الذي تعلنه عند إنشاء عملية رفع. ليس للحجم إشارة أو أصفار بادئة، ولا يتجاوز 16 رقماً. الأعداد والمراجعات والحدود وفهارس الأجزاء أعداد صحيحة عادية في JSON.

أكبر كائن هو 10,000 GiB ‏(10 737 418 240 000 بايت)، ما لم يضبط المسؤول قيمة أقل لـ`ARKVORY_MAX_OBJECT_BYTES`. يُرفض الحجم المعلن الأكبر بالاستجابة `400`.

## المصادقة {#authentication}

تحتاج كل عملية، باستثناء تسجيل الدخول والتسجيل الذاتي وفحوص الصحة العامة وخيارات تسجيل الدخول، إلى بيانات اعتماد في الترويسة `Authorization: Bearer <credential>`. لا يحتاج التسجيل الذاتي (`POST /api/v1/auth/register`، `registerAccount`) إلى بيانات اعتماد، ولا يمكن أن ينجح إلا عندما يضبط المسؤول `ARKVORY_ALLOW_REGISTRATION=true`؛ وإذا كان معطّلاً فإنه يعيد `403` والسبب `registration_disabled`. قد تكون بيانات الاعتماد جلسة وحدة تحكم أو رمز وصول شخصياً أو مفتاح خدمة أو مفتاح الاسترداد. يعتمد ما تستطيع فعله على نوعها وعلى **قاعدة الوصول** لكل عملية. اقرأ [المصادقة](./authentication) قبل تصميم التكامل، وامنح الأتمتة مفتاح خدمة بالإجراءات التي تحتاج إليها فقط.

## الاكتشاف {#discovery}

يمكن للعميل سؤال الخادم عما يدعمه بدلاً من التخمين. تتطلب جميع الطلبات التالية بيانات اعتماد.

| الطلب                          | الاستجابة                                                                                                                                                                                                                                                                                               |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET /api/v1/capabilities`     | إصدارات API ‏(`v1`)، ودور البوابة (`api` أو `reader`)، وأعلام الميزات وحدود هذا الخادم: `maxObjectBytes` و`partBytes` (أصغر جزء، 8 MiB) و`maxPartBytes` ‏(1 GiB) و`maxParts` ‏(10,000) و`maxPageSize` ‏(100).                                                                                           |
| `GET /api/v1/operations`       | العمليات التي يُرجح أن بيانات الاعتماد هذه تستطيع استدعاءها، ولكل منها `operationId` والطريقة والمسار و`surface` وفئة `retry` والإجراءات المطلوبة والشروط المتبقية. رشّح باستخدام `repository` و`surface` و`after` و`limit` (من 1 إلى 100، و50 افتراضياً). القائمة استرشادية: الطلب الفعلي وحده هو الحاسم. |
| `GET /api/v1/openapi.json`     | مستند OpenAPI 3.0.3 لواجهة API الكاتبة. أضف `?surface=<name>` للحصول على مجال واحد فقط.                                                                                                                                                                                                                 |
| `GET /api/v1/auth/permissions` | إجراءات بيانات الاعتماد المستدعية لكل مستودع.                                                                                                                                                                                                                                                           |
| `GET /api/v1/auth/me`          | هوية بيانات الاعتماد ونوعها ومنحها العامة `read`/`write`.                                                                                                                                                                                                                                               |
| `GET /api/v1/repositories`     | المستودعات التي يجوز لبيانات الاعتماد رؤيتها.                                                                                                                                                                                                                                                           |

استخدم `capabilities` لقراءة الحدود بدلاً من تثبيتها في التعليمات البرمجية. عامل علم الميزة الذي لا تعرفه بوصفه `false`.

### المجالات {#surfaces}

تُجمع العمليات في ستة **مجالات**. هي تسميات في العقد وليست خدمات منفصلة؛ ولا تتغير عناوين URL.

| المجال           | ما يشمله                                                                             |
| ---------------- | ------------------------------------------------------------------------------------ |
| `discovery`      | الإمكانات وفهرس العمليات وOpenAPI والمستودعات                                        |
| `identity`       | تسجيل الدخول وهوية المستدعي نفسه والرموز وتفعيل المفاتيح                             |
| `catalog`        | المُخرَجات والتعليقات الوصفية والحزم والملفات حسب المسار والمراحل والترقية والمرفقات   |
| `transfers`      | جلسات الرفع والأجزاء ومهام الإكمال والتنزيلات                                        |
| `administration` | الحسابات والمجموعات وحسابات الخدمة والمفاتيح والتفويضات والتحديثات والنسخ الاحتياطية |
| `operations`     | حيوية العملية والجاهزية والمقاييس والملاحظات                                         |

فحوص الصحة هي `GET /health/live` (العملية تعمل) و`GET /health/status` (عام؛ `{"status":"ready"}` أو `unavailable`) دون بيانات اعتماد، و`GET /health/ready` و`GET /health/metrics` مع بيانات اعتماد. لا تستخدم ميزانية الطلبات، لذلك لا يجعل الحمل موازن الأحمال يستبعد الخادم.

## ترقيم الصفحات {#pagination}

تُعاد القائمة صفحة تلو الأخرى. تحتوي الاستجابة على `items` و`next`. عندما لا تكون `next` بقيمة `null`، أعد إرسالها دون تغيير في معلمة الاستعلام `after` لقراءة الصفحة التالية؛ وعندما تكون `null`، تكون القائمة مكتملة. عامل المؤشر كسلسلة نصية معتمة ولا تبنِ مؤشراً بنفسك.

يضبط `limit` حجم الصفحة، من 1 إلى 100. تعيد معظم القوائم 50 عنصراً عند حذفه. الصفحات ليست لقطة ثابتة: قد تظهر العناصر التي تصل أثناء القراءة وقد لا تظهر. يجب إبقاء المرشحات وترتيب الفرز كما هما أثناء تتبع `next`.

## المراجعات والمقارنة والاستبدال {#revisions}

للأشياء التي يحررها الأشخاص **مراجعة** يبدأ ترقيمها من 1: تسميات المُخرَج وبيانات تعريفه وتجميعاته، ومرفقات نسخة البناء، ومسار الملف، وسياسة التخزين، وخطة النسخ الاحتياطي، وإعدادات حساب الخدمة. يحدد التغيير المراجعة التي يتوقعها في جسم الطلب باسم `expectedRevision`:

```json
{ "expectedRevision": 3, "value": { "labels": ["tested"], "metadata": {}, "collections": [] } }
```

إذا لم تكن المراجعة الحالية 3، لا يتغير شيء ويجيب الخادم بالاستجابة `409` والسبب `revision_mismatch`. هذه هي **المقارنة والاستبدال**. اقرأ الحالة مجدداً، وطبّق تغييرك عليها، وأرسل المراجعة الجديدة. لا تكرر المحاولة أبداً برقم أكبر لفرض الكتابة. استخدم `0` لشيء لم يوجد بعد، مثل مسار جديد. لا تستخدم واجهة API الترويسة `If-Match`.

**للمُخرَج المنزّل** مدقق مختلف هو `ETag`. انظر [تنزيلات النطاق وETag](#range-downloads).

## مفاتيح منع التكرار {#idempotency}

تجعل الترويسة `Idempotency-Key` الطلب المكرر يُحدث أثره مرة واحدة. استخدم قيمة من 1 إلى 128 محرفاً من الأحرف والأرقام و`_ . : -`، واحفظها مع حالة المهمة قبل الطلب الأول، كي تكرر المهمة المعاد تشغيلها المفتاح نفسه. تتطلب عمليات الكتابة التالية مفتاحاً:

| العملية                                                             | التكرار بالمفتاح نفسه والجسم نفسه                                                          |
| ------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| `createUpload`                                                      | يعيد جلسة الرفع نفسها.                                                                     |
| `issueServiceKey` و`rotateServiceKey`                               | يعيد بيانات تعريف المفتاح بالاستجابة `200` دون السر. أبطل المفتاح وأصدر آخر إذا فقدت السر. |
| `requestBackupRun` و`requestBackupVerify` و`requestBackupRetention` | يعيد الطلب نفسه بدلاً من إضافة طلب آخر إلى الطابور.                                         |

يُرفض المفتاح نفسه مع جسم مختلف بالاستجابة `409` والسبب `idempotency_mismatch`. نطاق المفتاح هو المستدعي والهدف، لذلك يمكن لمستدعيين استخدام القيمة نفسها.

يمكن تكرار عمليات الكتابة الأخرى بأمان لسبب آخر: فهي تضبط حالة (تعيين مرحلة أو تسجيل حزمة أو إبطال مفتاح)، أو تستخدم المقارنة والاستبدال. يوضح القسم التالي ذلك لكل فئة.

## قواعد إعادة المحاولة {#retry-rules}

لكل عملية **فئة إعادة محاولة**. تحدد الفئة ما يجب على العميل فعله إذا لم يتلق الاستجابة. يعرضها المرجع باسم «إعادة المحاولة» لكل عملية.

| الفئة              | المعنى                         | الإجراء                                                                                                                                               |
| ------------------ | ------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| `read`             | لا تغيّر القراءة شيئاً.          | كرر مع تأخير متزايد.                                                                                                                                  |
| `idempotent`       | للطلب نفسه الأثر نفسه.         | كرر. قد تختلف الاستجابة في التفاصيل: قد يُبلغ الحذف للمرة الثانية بأن الكائن لم يعد موجوداً.                                                            |
| `idempotency-key`  | آمنة فقط مع مفتاح.             | كرر باستخدام `Idempotency-Key` نفسه والجسم نفسه.                                                                                                      |
| `compare-and-swap` | تغيير يعتمد على مراجعة.        | اقرأ الحالة، واتخذ القرار مجدداً، وكرر بالمراجعة التي قرأتها. لا ترفع `expectedRevision` أبداً لتجاوز `409`.                                            |
| `reconcile-upload` | خطوة من جلسة رفع.              | اقرأ عملية الرفع وأجزاءها أولاً (`getUpload` و`listUploadParts`)، ثم أرسل المفقود. لا يمكن متابعة `PUT` لملف كامل من منتصفه: يبدأ مجدداً من البايت صفر. |
| `reconcile-job`    | وضع مهمة إكمال في الطابور.     | اقرأ المهمة (`getCompletionJob`) أولاً. يمكن إعادة وضع مهمة فاشلة في الطابور.                                                                          |
| `never-automatic`  | قد ينفّذ التكرار الإجراء مرتين. | لا تكرر تلقائياً. افحص النتيجة ثم قرر. أمثلة: إنشاء حساب أو رمز أو رابط تنزيل، أو تشغيل سياسة تخزين، أو إرسال ملاحظات.                                 |

عطل الشبكة والحالات `408` و`429` و`502` و`503` و`504` مؤقتة: كرر وفق الفئة، وانتظر مدة لا تقل عما تحدده `Retry-After`، وأضف تأخيراً أُسّياً متزايداً مع حد لعدد المحاولات. لا تكرر `401` و`403` واستجابات `4xx` الأخرى دون تغيير الطلب. لا تكرر `500` عشوائياً؛ أعطِ معرّف الطلب للدعم. بعد `503` على تغيير، تكون النتيجة مجهولة، لذا استخدم الفئة لمعرفة ما حدث. تطبق حزمة SDK وعميل سطر الأوامر هذه القواعد.

## تنزيلات النطاق وETag {#range-downloads}

تعيد `GET` و`HEAD` للمسار `…/artifacts/{id}/content` البايتات الأصلية مع `ETag` قوي بالصيغة `"sha256:<hex>"` و`Accept-Ranges: bytes`. ينطبق الأمر نفسه على التنزيل حسب الحزمة (`…/packages/content`) وحسب مسار الملف (`…/asset/content` و`…/raw/{path}`). تبحث هذه الطلبات عن المُخرَج الحالي في كل مرة؛ ويسمي `packages/content` و`raw` المُخرَج المختار في `X-Arkvory-Artifact-Id`، كي تستطيع تثبيته للاستئناف.

- تعيد `Range: bytes=0-1023` و`bytes=1024-` و`bytes=-1024` الاستجابة `206` مع `Content-Range`. يقدم الخادم نطاقاً واحداً؛ ويجيب عن قائمة نطاقات بالملف الكامل.
- تعيد بداية تتجاوز نهاية الملف الاستجابة `416` والرمز `invalid_input` والسبب `range_not_satisfiable` و`Content-Range: bytes */<size>`.
- للاستئناف، أرسل `Range` مع `If-Range: "<the ETag you saw>"`. إذا تغيّر المحتوى خلف الاسم، تختلف `ETag` وتتلقى الملف الجديد كاملاً بدلاً من ملف مختلط.
- تعيد `If-None-Match` مع `ETag` الاستجابة `304` دون جسم.
- تحقق من SHA-256 لما حفظته. تحمله ETag.

يعمل رابط التنزيل (`?token=`) على مسار محتوى مُخرَج واحد. انظر [المصادقة](./authentication#download-links).

## الأخطاء {#errors}

لكل فشل غلاف JSON نفسه: `code` و`message` و`requestId`، وعندما تتوفر تفاصيل إضافية، `reason` و`details` و`retryAfterSeconds`. اتخذ القرار بناءً على `code` و`reason`، وليس `message` أبداً. تُعامل الأسباب المجهولة كأنها غائبة، ويُعالج `code` المجهول وفق حالة HTTP. انظر [الأخطاء](./errors).

## حدود المعدل والخوادم المشغولة {#rate-limits}

لا يحتسب Arkvory استدعاءات API لكل دقيقة. بل يحدّ مقدار ما ينفذه في الوقت نفسه، ويحدّ محاولات تخمين كلمة المرور:

- **الانشغال.** يقبل الخادم عدداً ثابتاً من الطلبات وعمليات النقل في الوقت نفسه (`ARKVORY_MAX_REQUESTS`، افتراضياً 128؛ و2 رفع و16 تنزيلاً افتراضياً). قد تنتظر عملية النقل في طابور محدود حتى 20 ثانية. عند عدم وجود موضع، تكون الاستجابة `503` بالرمز `busy`. كرر بعد `Retry-After`.
- **السعة.** يعيد استنفاد احتياطي القرص أو بلوغ حصة أو حد لعدد الكائنات الاستجابة `507`، ولا يتحسن ذلك بالانتظار.
- **المحاولات.** يعيد تكرار محاولات تسجيل الدخول أو التسجيل أو كلمات المرور أو الملاحظات أكثر من المسموح الاستجابة `429` بالرمز `rate_limited`. انظر [المصادقة](./authentication#sign-in-limits).

تحمل كل من `429` و`503` الترويسة `Retry-After` بالثواني (2 عندما لا يملك الخادم تقديراً)، والعدد نفسه في `retryAfterSeconds`. إذا مر الطلب عبر وكيل، فقد يضيف الوكيل حدوده الخاصة.

## معرّفات الطلبات {#request-ids}

لكل استجابة ترويسة `X-Request-Id`، ويحمل كل خطأ القيمة نفسها في `requestId`. سجّلها مع مهمتك واذكرها للدعم. لا يُستخدم معرّف الطلب الذي ترسله إلا إذا وصل عبر وكيل مُدرج في `ARKVORY_TRUSTED_PROXIES` وتكوّن من 8 إلى 128 محرفاً آمناً؛ وإلا ينشئ الخادم معرّفاً جديداً. لا تُسجل ترويسة W3C ‏`traceparent` إلا في سجل وصول الخادم.

## المتصفحات وCORS {#cors}

تعمل صفحة الويب على عنوان Arkvory نفسه دون أي إعداد. ولا تعمل صفحة على عنوان آخر إلا إذا أدرج المسؤول أصلها المطابق تماماً في `ARKVORY_CORS_ORIGINS` (حتى 16، باستخدام HTTPS أو HTTP للحلقة المحلية). يتلقى أصل آخر الاستجابة `403` بالسبب `origin_not_allowed`، حتى عندما يكون المفتاح صالحاً. لا تستخدم الطلبات ملفات تعريف الارتباط أبداً: أرسل المفتاح في الترويسة `Authorization` واحتفظ به في الذاكرة. انظر [متغيرات البيئة](../reference/environment).

## ضمان التوافق {#evolution}

لا تتغير `/api/v1` إلا بالإضافة: عمليات جديدة، وحقول طلب اختيارية جديدة، وحقول استجابة جديدة، وأسباب أخطاء جديدة، وأعلام ميزات جديدة. يحصل التغيير الذي سيكسر توافق العميل، مثل معنى مختلف أو حقل إلزامي جديد أو حالة مختلفة أو ترقيم صفحات مختلف، على إصدار API جديد وفترة يعمل فيها الإصداران معاً. في المقابل، يجب أن يفعل عميلك ما يلي:

- تجاهل حقول الاستجابة التي لا يعرفها؛
- معاملة `reason` المجهول كأنه غائب، ومعالجة `code` المجهول وفق حالة HTTP؛
- أخذ الحدود من `capabilities`؛
- إرسال الحقول التي تعرّفها العملية فقط.

قيم `operationId` أسماء ثابتة. استخدمها عند ربط العمليات بتعليماتك البرمجية.

## مثال: رفع ملف واحد وتنزيله {#example}

يرفع هذا التسلسل ملفاً في طلب واحد. للملفات الأكبر من بضعة غيغابايت أو الروابط غير الموثوقة، استخدم [`arkvoryctl`](../protocols/cli) أو [حزمة SDK](../protocols/sdk): يرسلان الأجزاء ويتابعان بعد الفشل. يستخدم المثال `jq` لقراءة JSON.

أولاً، اضبط العنوان والمفتاح، واحسب حجم الملف وSHA-256 الخاص به:

```bash
export ARKVORY_URL=https://arkvory.example
export ARKVORY_KEY="$(cat ~/.arkvory/key)"
FILE=./Setup.exe
SIZE=$(stat -c %s "$FILE")
SHA=$(sha256sum "$FILE" | cut -d ' ' -f 1)
```

**الخطوة 1. حجز الرفع.** يعيد `Idempotency-Key` نفسه الجلسة نفسها، لذلك يمكنك تكرار هذا الاستدعاء بأمان.

```bash
ID=$(curl -fsS -X POST "$ARKVORY_URL/api/v1/repositories/releases/uploads" \
  -H "Authorization: Bearer $ARKVORY_KEY" \
  -H "Idempotency-Key: build-1042-setup" \
  -H "Content-Type: application/json" \
  -d "{\"name\":\"Setup.exe\",\"size\":\"$SIZE\",\"sha256\":\"$SHA\",\"labels\":[\"nightly\"]}" \
  | jq -r .id)
```

**الخطوة 2. إرسال البايتات.** ينشر الخادم المُخرَج عندما يتطابق الحجم وSHA-256.

```bash
curl -fsS -X PUT "$ARKVORY_URL/api/v1/repositories/releases/uploads/$ID/content" \
  -H "Authorization: Bearer $ARKVORY_KEY" \
  -H "Content-Type: application/octet-stream" \
  -T "$FILE" | jq '{id, status}'
```

**الخطوة 3. تنزيله.** معرّف المُخرَج هو معرّف الرفع.

```bash
curl -fL -o Setup-copy.exe \
  -H "Authorization: Bearer $ARKVORY_KEY" \
  "$ARKVORY_URL/api/v1/repositories/releases/artifacts/$ID/content"
sha256sum Setup-copy.exe
```

تجيب الخطوة 2 بـ`{"id": "…", "status": "available"}`. إذا انقطع الاتصال أثناء الخطوة 2، فاقرأ عملية الرفع باستخدام `GET …/uploads/$ID`: ما دامت حالتها `pending`، أرسل الملف مجدداً من البداية. تعيش جلسة الرفع 7 أيام. يحتاج المفتاح إلى الإجراءات `upload.create` و`upload.write` و`upload.complete` و`content.read` على `releases`. انظر [الرفع](./reference/uploads) و[عمليات النقل](../use/transfers).
