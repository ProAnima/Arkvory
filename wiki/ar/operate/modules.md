# الوحدات

تضيف حزمة الوحدة ميزة إلى Arkvory. لا يثبّت Arkvory إلا الحزم التي يستطيع التحقق من توقيعها. تُنفّذ أوامر هذه الصفحة على مضيف التثبيت، بصلاحيات root على Linux أو مسؤول على Windows. لا تستطيع وحدة التحكم وواجهة HTTP API تثبيت وحدات أو الوثوق بمفاتيح، لذلك لا يتيح الاستيلاء على حساب مسؤول في وحدة التحكم تشغيل تعليمات برمجية على الخادم.

تفحص الخدمات الوحدات المثبّتة مجدداً وتحمّلها في كل مرة تبدأ فيها. لا تعمل الوحدة إلا بعد تفعيلها.

## Arkvory Pro {#pro}

‏Arkvory Pro مجموعة اختيارية من وحدات ProAnimaStudio المدفوعة والموقّعة لنواة Arkvory المجانية. يعمل Pro 0.1.1 مع Arkvory من 0.6.3 إلى 0.7.0 (واجهة الإضافات 0.13) على Windows/Linux x64. احصل على حزم الوحدات والترخيص من ProAnimaStudio؛ وتُثبّت منفصلة عن النواة. انظر [التثبيت](#install) و[التراخيص](licenses).

- **إزالة التكرار** تخزّن المقاطع المشتركة مرة واحدة وتعيد استخدامها عبر الكائنات. ينسّق الفهرس المشترك جمع البيانات غير المستخدمة مع النشر والقرّاء والنسخ الاحتياطية.
- **عمليات النقل التفاضلية** تعيد استخدام المحتوى المتاح بالفعل لعميل متوافق وتنقل البيانات أو التصحيحات المفقودة. تتضمن الحزمة وحدات تخزين ونقل للخادم ووحدة عميل تفاضلي. يعتمد التوفير على البيانات والعميل؛ ولا تصبح تنزيلات HTTP العادية عمليات نقل تفاضلية تلقائياً.
- **الترخيص** يتحكم في الكتابة المدفوعة والتحسينات. تبقى البيانات الموجودة قابلة للقراءة عند انتهاء صلاحية الترخيص أو عدم توفره؛ وترجع عمليات الرفع الجديدة إلى تخزين النواة وعمليات النقل العادية. تحتسب حصة Pro بيانات Pro المنطقية، بما فيها عمليات الرفع المقبولة غير المكتملة، دون تخفيض مقابل إزالة التكرار. يحد حقل updatesUntil في الترخيص أهلية استخدام نسخ بناء أحدث للوحدات.

تُحمّل الوحدات عند بدء الخدمات؛ ولا تحمّلها تثبيتات Docker Compose. انسخ بيانات التعريف وبيانات الوحدات احتياطياً قبل الترقية. عند اعتماد الفهرس المشترك لأول مرة، أوقف عمليات API/worker الكاتبة الأقدم؛ فالكتابة المختلطة من الإصدارات القديمة والجديدة غير مدعومة. استعد البيانات وحالة الترخيص معاً، وانتظر الاسترداد، وتحقق من عملية رفع Pro جديدة قبل استئناف الكتابة العادية.

قد يستغرق استرداد فهرس كبير وقتاً: على بيئة القبول، أصبحت 4 ملايين من المقاطع ذات فهرس مشترك مستعاد بالفعل قابلة للكتابة بعد 32 دقيقة و43 ثانية، دون إعادة تشغيل. هذا ليس ضماناً لمدة الاستعادة ولا قياساً لإنتاجية 4 TB. لا يحل قبول التوافر العالي على مضيف مادي واحد محل فحوص العزل القسري ونطاقات الأعطال في موقعك. لا يغيّر Pro شروط ترخيص النواة.

## إمكانات الوحدات وإضافات الجهات الخارجية {#module-capabilities}

يمكن لوحدات ProAnimaStudio الموقّعة إضافة التخزين وبروتوكولات النقل ومسارات HTTP، مع خدمات للعمل في الخلفية والحوسبة المحدودة والتنظيف المنسق للبيانات وفق أدوارها. لا تحتاج الوحدات المجانية إلى ترخيص ميزات مدفوعة؛ وتعلن الوحدات المدفوعة متطلبات ترخيصها. يجب أن تطابق كل حزمة واجهة الامتدادات في النواة وتجتاز فحوص التوقيع والسلامة.

لا يتوفر تثبيت إضافات الجهات الخارجية وتشغيلها في هذا الإصدار. يمكنك إدارة [مفاتيح المؤلفين الموثوقين](#trust)، لكن إضافة مفتاح لا تمكّن تثبيت الإضافات. لا تعتبر واجهة الوحدات بيئة عزل لتعليمات برمجية عشوائية.

## تثبيت حزمة {#install}

1. انسخ ملف الحزمة `arkvory-module-<id>-<version>.tgz` إلى المضيف.
2. افحصه واقرأ شروطه:

   ```bash
   sudo arkvory module install /root/arkvory-module-sample-1.0.0.tgz --root /opt/proanima-arkvory
   ```

   يعرض الأمر الوحدة وأدوارها والبيانات التي تحتفظ بها ومفتاح التوقيع وSHA-256 للحزمة، ثم شروط الوحدة. لا يتغير شيء بعد.

3. ثبّتها:

   ```bash
   sudo arkvory module install /root/arkvory-module-sample-1.0.0.tgz --root /opt/proanima-arkvory --yes
   ```

يرفض Arkvory الحزمة في الحالات التالية:

| السبب                                                                                 | الرمز في الرسالة                                               |
| ------------------------------------------------------------------------------------- | -------------------------------------------------------------- |
| التوقيع ليس من مفتاح وحدات ProAnimaStudio أو تغيّر بيان الحزمة                         | `unknown_key` و`wrong_key_class` و`signature_invalid`          |
| ملف مفقود أو تغيّر أو ليس مدرجاً في البيان                                              | `file_missing` و`file_mismatch` و`file_unlisted`               |
| يحتوي الأرشيف على روابط أو أجهزة أو مسارات خارج الحزمة أو أسماء تتعارض في حالة الأحرف | `link_entry` و`special_entry` و`unsafe_path` و`case_collision` |
| يحتوي الأرشيف على إضافة أصلية (`.node`)                                               | `native_addon`                                                 |
| تحتاج الوحدة إلى إصدار آخر من Arkvory                                                 | `module_incompatible`                                          |
| أبطلت ProAnimaStudio هذا الإصدار                                                      | `module_revoked`، مع الإصدار البديل                            |
| لا توجد قائمة إبطال سارية (انظر أدناه)                                                | `stale_revocations`                                            |

الحدود: 1 GiB لكل حزمة، و256 MiB لكل ملف، و4096 ملفاً. تُرفض الحزمة الأكبر قبل قراءة بياناتها.

يُترك الإصدار المثبّت بالفعل بالبايتات نفسها كما هو. ويُرفض الإصدار نفسه ببايتات مختلفة.

## تفعيل وحدة وتحميلها {#load}

تبقى الوحدة المثبّتة معطّلة حتى تفعّلها. لا تحمّل الخدمات الوحدات إلا عند بدء تشغيلها.

1. أضف الوحدة إلى ملف الوحدات (`ARKVORY_MODULES_FILE`، انظر [متغيرات البيئة](../reference/environment#core)). توضع إعدادات الوحدة في `config`:

   ```json
   { "format": 1, "modules": { "sample": { "enabled": true } } }
   ```

2. إذا كانت الوحدة تحتفظ بملفات، فاعتمد حجم دليل بياناتها باستخدام `resources`، مثلاً `"resources": { "dataMiB": 512, "dataFiles": 10000 }` بجانب `enabled`. يحل ذلك محل الحجم الذي تطلبه الحزمة. انظر [دليل بيانات الوحدة](#data).
3. أعد تشغيل الخدمات كما في [تطبيق تغيير](../install/configuration#apply-change).
4. افحص الوحدة بصفتك مسؤولاً عاماً: تسردها `GET /api/v1/system/modules` مع `running: true` و`health.status` بقيمة `ok` على واجهة API وكل بوابة قراءة.

تعمل الوحدات الموقّعة في واجهة API وبوابات القراءة والعامل ووكيل النسخ الاحتياطي وفق أدوارها المعلنة. لا تمنح كل عملية الوحدة إلا الخدمات المتاحة لذلك الدور والمعلنة في `uses`. وما زالت بادئات المسارات تتطلب خدمة `routes` ‏(`routes_unsupported`). لا تحمّل تثبيتات Docker Compose الوحدات بعد.

يسجل تخزين الوحدة مثيلات باسم `<module>.<name>`. يمكن لسياسات توزيع التخزين اختيار هذه المثيلات لعمليات الرفع الجديدة؛ وعندما يتوقف مثيل عن قبول الكتابة، ترجع العمليات الجديدة إلى `default`. تفحص النواة البايتات كاملة قبل نشر كائن مركب من أجزاء مخزّنة. ينتظر تنظيف بيانات الوحدة ما دام أي قارئ محتوى أو تثبيت نسخة احتياطية أو حاجز التقاط يحمي التثبيت. تُنفّذ العمليات الحسابية في خيوط محدودة؛ ولا تقر اشتراكات الخلفية الأحداث إلا بعد نجاح المعالج، وقد تعيد تسليمها بعد فشل.

قبل أن تستورد خدمة أي تعليمات برمجية لوحدة، تفحص الحزمة مجدداً:

1. لا يجوز تغيير دليل التثبيت و`modules/` ومجموعة الوحدات وقائمة الإبطال ودليلها إلا لـroot (على Windows: ‏SYSTEM والمسؤولون) أو مالك دليل التثبيت. يضبط التثبيت ذلك. يُرفض الملف الذي يستطيع حساب آخر تغييره، أو الرابط داخل حزمة (`access_unsafe` و`access_link`).
2. التوقيع وكل ملف وإصدار Arkvory، كما يفحصها `module install`.
3. قائمة الإبطال. لا يُحمّل إصدار مُبطل أبداً. ولا توقف قائمة منتهية أو غائبة الوحدة.

لا تُحمّل الوحدة التي تفشل في فحص؛ وتواصل الوحدات الأخرى وArkvory العمل. تعرضها `GET /api/v1/system/modules` مع `running: false`:

| `health.status` | المعنى                                            | الرموز                                                                                                          |
| --------------- | ------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| `failed`        | رُفضت الحزمة أو لم تُحمّل تعليماتها البرمجية أو تبدأ | `file_mismatch` و`unknown_key` و`module_incompatible` و`access_unsafe` و`config_invalid` و`start_failed` وغيرها |
| `revoked`       | أبطلت ProAnimaStudio هذا الإصدار                  | السبب من قائمة الإبطال                                                                                          |
| `unavailable`   | دليل الحزمة مفقود من المضيف                       | `module_unavailable`                                                                                            |

لا تسلب الوحدة الفاشلة جاهزية Arkvory (تجيب `/health/ready` بالاستجابة 503 مع `module_failed`) إلا عندما تحتاج إليها وحدة مفعّلة أخرى. ولا تفعل ذلك أبداً وحدة تخزّن بايتات الملفات المنشورة (`layout` للبيانات): يواصل Arkvory تقديم بياناتها ويكتب عمليات الرفع الجديدة إلى تخزينه الخاص بدلاً من تخزين الوحدة. يسجل السجل `module.refused` و`module.failed` مع الرمز في `errorCode`.

ثبّت الحزمة مجدداً لإصلاح حزمة متغيرة أو مفقودة. يجب أن ترى كل خدمة في التثبيت الوحدات نفسها، مفعّلة كانت أم لا: لا تكون بوابة قراءة أو عامل بوحدات مختلفة جاهزين (`module_plan_mismatch`). ثبّت الحزم نفسها على مضيف كل بوابة قراءة.

### دليل بيانات الوحدة {#data}

تحصل الوحدة التي تحتفظ بفهارس أو بيانات مخبئية أو حالة خاصة بها على دليل في وحدة البيانات: `module-data/<id>/` في دليل تخزين `default`. قسم `data` مخصص للنسخ الاحتياطية، وقسم `cache` ليس كذلك. يحتسب Arkvory كل كتابة ضمن الحجم المعتمد، بوحدات MiB وبعدد الملفات، للقسمين معاً. تُرفض الكتابة التي تتجاوزه (`module_quota_exceeded`) وتستمر الوحدة في العمل. من دون حجم معتمد، لا تستطيع الوحدة إلا القراءة. ويسري أيضاً [احتياطي الوحدة](./storage#disk). على بوابة القراءة، تقرأ الوحدة الملفات نفسها ولا تستطيع تغييرها.

تلتقط النسخ الاحتياطية المنطقية بايتات الكائنات المنشورة عبر الوحدة المثبّتة بدور النسخ الاحتياطي؛ ولا تنسخ دليل الوحدة أو بيانات التخزين المؤقت أو حالة التنسيق الخاصة كصورة لنظام الملفات. أبقِ وحدات المصدر مثبّتة وقابلة للقراءة حتى ينتهي الالتقاط. تستطيع الاستعادة باستخدام [--to-default-storage](backups#restore-default-storage) استرداد هذه الكائنات كملفات blobs عادية للنواة دون الوحدة الأصلية أو ترخيص مدفوع؛ احجز حجمها المنطقي الكامل. احفظ أسرار التثبيت منفصلة واتبع إجراء استرداد الترخيص قبل تفعيل الكتابة المدفوعة مجدداً. لا تؤدي إزالة وحدة إلى حذف دليل بياناتها؛ لا تحذف ملفات ما زالت الكائنات المنشورة تشير إليها.

قبل الترقية إلى واجهة الامتدادات 0.7.0، أوقف جميع عمليات API والعامل الأقدم التي تكتب بيانات الوحدات. تتشارك جميع عمليات الكتابة الجديدة احتساب الحصص عبر منسّق PostgreSQL للتثبيت؛ وتُحتسب الملفات المؤقتة أيضاً ضمن الحصة. الكتابة المختلطة من الإصدارات القديمة والجديدة غير مدعومة. بعد انهيار، يعيد Arkvory بناء الاحتساب عند الحاجة، ولا يستعيد مساحة الأدلة المؤقتة للبروتوكول الجديد إلا بعد الاستحواذ على قفل قاعدة بيانات المالك السابق. لا تُزال الملفات المؤقتة القديمة تلقائياً وتواصل استهلاك الحصة؛ راجعها منفصلة مع إيقاف الكاتبين. لعمليات النسخ الاحتياطي وصول للقراءة فقط.

## مسارات الوحدات {#routes}

يجوز للوحدة إضافة مسارات HTTP تحت بادئتها الخاصة `/api/ext/<id>/v<major>/`، مثل `/api/ext/sample/v1/`. يفحص Arkvory كل طلب قبل تشغيل أي تعليمات برمجية للوحدة:

| الفحص           | كما في `/api/v1`                                                                                                                                         |
| --------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| بيانات الاعتماد | المفاتيح والجلسات والرموز نفسها؛ يكون المسار متاحاً لكل مستدعٍ مسجّل دخوله أو للمسؤول العام فقط                                                             |
| الإذن           | الإذن الذي يحدده المسار على المستودع في مساره، مثل `content.read` أو `upload.create`: يحتاج إليه مفتاح الخدمة، ويحتاج الحساب إلى منحة القراءة أو الكتابة |
| جسم الطلب       | حد حجم المسار وحدود الرفع والمواعيد القصوى وعرض النطاق للخادم                                                                                            |
| الملفات         | يرسلها Arkvory نفسه: ‏ETag وRange و`If-Range` و304 وطابور التنزيل وعرض نطاق التنزيل                                                                      |

للأخطاء صيغة أخطاء API. لا ترى الوحدة بيانات الاعتماد أو الترويسات الأخرى أبداً. تقدم بوابة القراءة مسارات القراءة للوحدة وتجيب عن الباقي بـ`read_only`.

تصف كل وحدة مساراتها في مستند OpenAPI، ويقارن Arkvory بينهما عند بدء الوحدة. لا تبدأ وحدة تخالف مساراتها القواعد ولا تقدم شيئاً؛ ويواصل Arkvory العمل. تعرضها `GET /api/v1/system/modules` مع `running: false` و`health.status` بقيمة `failed`:

| الرمز                    | المعنى                                                                            |
| ------------------------ | --------------------------------------------------------------------------------- |
| `routes_invalid`         | يخالف مسار القواعد، مثل مسار خارج بادئة الوحدة أو تغيير متاح لكل مستدعٍ مسجّل دخوله |
| `openapi_invalid`        | مستند OpenAPI مفقود أو غير صالح                                                   |
| `openapi_route_mismatch` | لا توجد عملية لمسار في المستند أو لا يوجد مسار لعملية                             |
| `transfer_invalid`       | تقترح الوحدة بروتوكول نقل لا يجوز لها اقتراحه                                     |

مستندات المسارات:

| العنوان                                                                                     | من يستطيع قراءته    | المحتوى                                                                              |
| ------------------------------------------------------------------------------------------- | ------------------- | ------------------------------------------------------------------------------------ |
| `GET /api/ext/openapi.json`                                                                 | كل مستدعٍ مسجّل دخوله | مسارات جميع الوحدات التي تشغّلها هذه الخدمة، مع العمليات التي يجوز للمستدعي استدعاؤها |
| [`GET /api/v1/system/modules/{id}/openapi`](../api/reference/system#getSystemModuleOpenApi) | المسؤول العام       | مسارات وحدة واحدة                                                                    |

لا تسرد `/api/v1/openapi.json` مسارات الوحدات أبداً. يجوز لوحدة من النوع `transfer` اقتراح طريقة أخرى لنقل الملفات: تسردها `GET /api/v1/capabilities` في `transfer`. لا يستخدمها العميل إلا مع امتداد مطابق؛ وإلا ينقل الملفات كالمعتاد.

## التحديث والتثبيت على إصدار والرجوع إلى إصدار أقدم {#versions}

ثبّت ملف الإصدار الجديد باستخدام `--yes`. تبقى الحزمة السابقة على المضيف حتى التغيير التالي للوحدات.

| المهمة                         | الأمر                                                           |
| ------------------------------ | --------------------------------------------------------------- |
| الاحتفاظ بالإصدار المثبّت       | `sudo arkvory module pin sample 1.0.0 --root …`                 |
| السماح بالإصدارات الأخرى مجدداً | `sudo arkvory module pin sample --unpin --root …`               |
| تثبيت إصدار أقدم               | `sudo arkvory module install <file> --downgrade --yes --root …` |

ترفض الوحدة المثبّتة على إصدار كل إصدار آخر حتى تلغي ذلك التثبيت. يتطلب الإصدار الأقدم من المثبّت، أو من إصدار أُزيل وما زالت حزمته على المضيف، استخدام `--downgrade`.

## فحص الوحدات المثبّتة {#list}

```bash
sudo arkvory module list --root /opt/proanima-arkvory
```

يتحقق الأمر مجدداً من كل حزمة مثبّتة، كما تفعل الخدمات قبل تحميلها: التوقيع وكل ملف والأرشيف. تعرض كل وحدة حالة واحدة:

| الحالة               | المعنى                                                                                   |
| -------------------- | ---------------------------------------------------------------------------------------- |
| `ok`                 | الحزمة سليمة                                                                             |
| `refused: <code>`    | تغيّر ملف أو أُضيف أو استُبدل برابط (`file_mismatch` و`file_unlisted` و`link_entry` وغيرها) |
| `revoked (<reason>)` | أبطلت ProAnimaStudio هذا الإصدار. تعني `read path only` أن بياناته تبقى قابلة للقراءة    |

لا تُستخدم الحزمة المرفوضة أبداً. ثبّت ملف الحزمة مجدداً لإصلاحها.

### في وحدة التحكم {#console}

يجد المسؤول العام [[ui:modules]] في قائمة وحدة التحكم. تعرض الصفحة كل وحدة مع إصدارها ونقطة الإضافة ومصدرها وحالتها في العملية التي أجابت، والتراخيص مع حالتها ومدتها. إنها للقراءة فقط: ثبّت الوحدات وفعّلها وأزلها بأوامر هذه الصفحة.

## إزالة وحدة {#remove}

```bash
sudo arkvory module remove sample --root /opt/proanima-arkvory
```

تغادر الوحدة التثبيت، وتبقى حزمتها على المضيف حتى التغيير التالي للوحدات. لا يمكن إزالة وحدة تخزّن بايتات الملفات المنشورة (`layout` للبيانات): يرفض Arkvory بالرمز `module_owns_data`، كي لا تصبح بياناتها غير قابلة للقراءة أبداً.

## قائمة الإبطال {#revocations}

تنشر ProAnimaStudio قائمة موقّعة بإصدارات الوحدات المُبطلة. لكل قائمة رقم، ولا يقبل Arkvory أبداً قائمة برقم أقل مما لديه. قد تحمل حزمة وحدة قائمة أحدث: يحتفظ بها Arkvory عند تثبيت الحزمة. على مضيف لا يصل إلى المركز، خزّن ملف قائمة بنفسك:

```bash
sudo arkvory module revocations /root/module-revocations.json --root /opt/proanima-arkvory
```

تُوقّع كل قائمة بموعد انتهاء: 90 يوماً افتراضياً، ولا يتجاوز 180 أبداً. يحتاج `module install` و`module pin <id> <version>` إلى قائمة سارية؛ ويرفضان مع قائمة منتهية أو غائبة بالرمز `stale_revocations`. تُحتسب الحزمة التي تحمل قائمة سارية. للمتابعة رغم ذلك، أضف `--allow-stale-revocations`: يطبع Arkvory تحذيراً ويسجل القرار في `modules/audit.jsonl`. لا توقف القائمة المنتهية الوحدات المثبّتة أبداً: تواصل العمل وتبقى بياناتها قابلة للقراءة؛ وحده إدخال الإبطال يوقف إصداراً. تحل القائمة ذات الرقم الأعلى دائماً محل المخزّنة، حتى إذا انتهت صلاحيتها.

عندما تستبدل ProAnimaStudio مفتاح توقيع وحداتها، يحمل إصدار واحد المفتاحين وتُوقّع القائمة التالية بالمفتاح الجديد؛ ولا يُزال القديم إلا في إصدار لاحق. تُرفض الترقية إلى ذلك الإصدار ما دام المضيف يخزّن قائمة موقّعة بالمفتاح القديم: خزّن قائمة سارية أولاً. يعرض `sudo arkvory module check-revocations --root …` ما إذا كان هذا الإصدار يثق بمفتاح القائمة المخزّنة.

## الوثوق بمؤلف إضافة {#trust}

تُوقّع إضافات فريقك أو مؤلف آخر بمفتاح المؤلف. أضف المفتاح إلى قائمة ثقة المضيف قبل تثبيت تلك الإضافات. تخص قائمة الثقة المضيف: تستطيع الخدمات قراءتها ولا تستطيع تغييرها.

1. احصل على ملف المفتاح العام (`.pub`، بصيغة minisign) من المؤلف، وعلى بصمته عبر قناة أخرى.
2. اعرض المفتاح وقارن البصمة:

   ```bash
   sudo arkvory module trust add /root/acme.pub --label "Acme platform team" --plugins "op-acme-*" --root /opt/proanima-arkvory
   ```

3. أضفه باستخدام `--yes`.

| الخيار               | المعنى                                                                                                 |
| -------------------- | ------------------------------------------------------------------------------------------------------ |
| `--label`            | صاحب المفتاح؛ مطلوب                                                                                    |
| `--plugins`          | معرّفات الإضافات التي يجوز للمفتاح توقيعها، مفصولة بفواصل: معرّف مطابق أو بادئة مع `*`. الافتراضي `op-*` |
| `--expires`          | وقت UTC مثل `2027-01-31T00:00:00Z`. بعده، لا يقبل المفتاح تثبيتاً جديداً                                 |
| `--allow-in-process` | يسمح لإضافات المفتاح بالعمل داخل عملية Arkvory. تحصل هذه التعليمات البرمجية على جميع حقوق الخدمة       |

تبدأ معرّفات الإضافات دائماً بـ`op-`. لا يوقّع مفتاح إضافة وحدات ProAnimaStudio أبداً، ولا توقّع مفاتيح ProAnimaStudio إضافات `op-` أبداً. يُرفض المفتاح الذي يعرفه المضيف بالفعل بمعرّف آخر أو كمفتاح من نوع آخر (`duplicate_key`). يجب أن تكون التوقيعات مسبقة التجزئة، وهو الافتراضي في إصدارات minisign الحالية؛ وتُرفض التوقيعات القديمة بالرمز `signature_algorithm`.

يعرض `sudo arkvory module trust list --root …` المفاتيح الموثوقة. ويزيل `sudo arkvory module trust remove <key id> --root …` أحدها.

يحتفظ هذا الإصدار بقائمة الثقة؛ ويُتاح تثبيت الإضافات في إصدار لاحق.

## بعد انقطاع {#recover}

يُسجل كل تغيير لمجموعة الوحدات في دفتر التحديث. إذا توقف أمر في منتصفه، يرفض أمر النشر التالي بالرسالة `Interrupted deployment`. شغّل `sudo arkvory recover --root …`: يعيد مجموعة الوحدات السابقة. وحتى ذلك الحين، يرفض كل أمر وحدات يغيّر شيئاً، بما فيه `module trust` و`module revocations`.

## مدة طلب الوحدة {#request-scope}

يستخدم مسار الوحدة أذونات المستدعي حتى انتهاء استجابته، بما في ذلك البث. يسحب الإلغاء أو الإكمال هذه الأذونات ويغلق موارد القراءة. تقرأ خدمة `upload-read` الأجزاء المقبولة لعمليات الرفع غير المكتملة بعد فحص الملكية و`upload.read` والنطاق والإلغاء. تستطيع الوحدات سحب عروض النقل أثناء عملها. تحذفها استعلامات الإمكانات اللاحقة؛ وتبقى المسارات وعمليات النقل النشطة. قد يخزّن العملاء عروضاً قديمة مؤقتاً، لذلك يجب أن تفحص المسارات كل عملية.

## استرداد الذاكرة المخبئية المشتقة {#derived-cache}

يجوز للوحدات الموقّعة إعلان `derived-cache` (واجهة الامتدادات 0.9.0). تبني عمليات API والعامل أجيالاً غير قابلة للتغيير وتقرؤها؛ والقرّاء يقرؤون فقط؛ ولا تتلقى عمليات النسخ الاحتياطي هذه الخدمة. يجب مع ذلك فحص أذونات المصدر لكل طلب. تشمل ميزانية موارد الوحدة المعتمدة كلاً من البيانات والتخزين المؤقت القديمين والأجيال المشتقة المحتفظ بها. يتطلب غياب عنصر من الذاكرة المخبئية إعادة توليده أو استخدام بديل.

لا يثبت فقدان جلسة PostgreSQL أن إدخال/إخراج الملفات قد توقف. تظل حجوزات المالك غير المؤكدة ومراجع القرّاء المحفوظة محتسبة. طبّق أولاً ترحيلات قاعدة البيانات لإصدار النواة هذا. قبل الاسترداد، أوقف جميع المضيفين المشاركين وتحقق من انتهاء عملياتهم والإدخال/الإخراج لديهم، أو أثبت أن النسخة المحددة من عملية المالك انتهت ولا يمكنها الاستئناف؛ واعزل المضيفين غير القابلين للوصول قسرياً. احصل على UUID الدقيق للمالك من التشخيصات وسجّل الأدلة. لا تستنتج انتهاء العملية أبداً من PID أو مهلة أو غياب قفل قاعدة بيانات.

على المضيف الموثوق، مع ضبط `ARKVORY_DATABASE_URL`، شغّل الأمر أدناه باستخدام حزم مبنية من إصدار النواة هذا. يقر العلم بالإيقاف الفعلي؛ ويظل الاسترداد يرفض وجود قفل مالك نشط. لا تأكيد يعني لا إجراء. استأنف التسوية بعدها وتحقق من استعادة المساحة؛ فالتأكيد وحده لا يحرر الحصة فوراً. هذه صيانة مضيف وليست إذناً للوحدة أو لسطر الأوامر البعيد.

```sh
node scripts/recover-derived-cache.mjs --owner UUID --confirm-owner-stopped
```

## حالة تنسيق الوحدة {#module-state}

تضيف واجهة الامتدادات 0.10.0 سجلاً ذرياً محدوداً للحالة للوحدات الموقّعة. يبقى بعد تجاوز فشل التوافر العالي، لكنه لا يُدرج في النسخ الاحتياطية المنطقية القابلة للنقل. بعد الاستعادة، اتبع إجراء إعادة التهيئة الصريح للوحدة؛ ويجب أن تبقى قراءة الكائنات المخزّنة واستعادتها متاحتين. هذه الحالة منفصلة عن تخزين الكائنات ولا تُصفّر بإعادة تثبيت وحدة.

تستطيع وحدة نقل سحب بروتوكولها مؤقتاً وإعادته بعد نجاح فحوص السياسة، دون إعادة تشغيل Arkvory. يظل كل طلب خاضعاً لسياسة الوحدة الحالية.

تتيح واجهة الامتدادات 0.12.0 لوحدة تخزين موقّعة ضبط حد منطقي للبايتات. تحتسب النواة أحجام الكائنات كاملة وعمليات الرفع المقبولة غير المكتملة عبر المستودعات دون تخفيض مقابل إزالة التكرار. عند بلوغ الحد، تستخدم عمليات الرفع الجديدة التخزين الافتراضي؛ وتحتفظ العمليات المقبولة بوجهتها وتبقى الكائنات المخزّنة قابلة للقراءة. لا تغادر البايتات العدّاد إلا بعد التنظيف.

## فهرس الموارد المشترك {#resource-catalog}

توفر واجهة الامتدادات 0.13.0 فهرس موارد مشتركاً للوحدات الموقّعة. تبقى الملفات محمية ما دامت عمليات الرفع أو الموارد التابعة تشير إليها. وحده تنظيف النواة يحرر ملكية الرفع. ينتظر الجمع الفعلي القرّاء والنسخ الاحتياطية؛ وتحتفظ عمليات الحذف الفاشلة بالتبعيات لإعادة المحاولة.

قبل أول ترقية إلى وحدة تستخدم هذا الفهرس، أوقف جميع عمليات API والعامل الأقدم. لا تخلط الكاتبين القدامى والجدد. بعد الاستعادة المنطقية، يبقى الجمع معطّلاً حتى تفحص الوحدة جميع وصفات تركيب البيانات والملفات والتبعيات بنجاح. أصلح البيانات المفقودة أو التالفة قبل استئناف الجمع.
