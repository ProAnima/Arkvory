# इंस्टॉलेशन चुनें

Arkvory एक सर्वर पर चलता है। हर इंस्टॉलेशन में एक जैसे हिस्से होते हैं:

- **API**: HTTP API और वेब कंसोल।
- **वर्कर**: अपलोड पूरे करता है और पृष्ठभूमि के काम चलाता है।
- **बैकअप एजेंट**: बैकअप स्टोरेज में निर्धारित बैकअप बनाता है।
- **PostgreSQL**: कैटलॉग का डेटाबेस।

फ़ाइलों की सामग्री सर्वर की स्थानीय डिस्क पर सहेजी जाती है। एक अकेला सर्वर उच्च उपलब्धता (high availability) वाला सिस्टम नहीं है: अपडेट या सर्वर की विफलता से थोड़ी देर का व्यवधान होता है, और क्लाइंट अपने ट्रांसफ़र जारी रखते हैं। दो या तीन Linux सर्वर के लिए, जो सिंक्रोनस कॉपी रखते हैं और एक-दूसरे का काम संभाल लेते हैं, [उच्च उपलब्धता क्लस्टर](../operate/cluster) देखें।

सभी विकल्प एक ही API, वर्कर और बैकअप एजेंट इंस्टॉल करते हैं। बिल्ट-इन HTTPS केवल नेटिव इंस्टॉलेशन के लिए उपलब्ध है। Compose इंस्टॉलेशन में HTTPS के लिए रिवर्स प्रॉक्सी चाहिए। [HTTPS और रिवर्स प्रॉक्सी](./https) देखें।

### SSH से रिमोट इंस्टॉलेशन {#remote-installation-over-ssh}

**Arkvory Remote Setup** क्लाइंट पैकेजों का हिस्सा है। यह व्यवस्थापक के कंप्यूटर पर चलता है, SSH से सर्वर से जुड़ता है और वहाँ नेटिव Linux या Windows पैकेज इंस्टॉल करता है। फिर यह स्वामी खाता बनाता है और निजी SSH टनल के ज़रिए कंसोल खोलता है।

| सर्वर       | आवश्यकताएँ                                                                                                   |
| ----------- | ------------------------------------------------------------------------------------------------------------ |
| Linux x64   | SSH और SFTP, systemd, `apt-get` या `dnf`, root या ऐसा उपयोगकर्ता जिसके पास `sudo -n` हो (पासवर्ड माँगे बिना) |
| Windows x64 | SFTP के साथ OpenSSH Server, Windows PowerShell, एक व्यवस्थापक खाता                                           |

टनल केवल तब तक काम करती है जब तक Remote Setup चल रहा है। यह Arkvory को दूसरे कंप्यूटरों के लिए प्रकाशित नहीं करती। पासवर्ड से सुरक्षित `sudo`, SSH एजेंट, जंप होस्ट और ARM सर्वर समर्थित नहीं हैं।

| मद                          | आवश्यकता                                                                                                                     |
| --------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |

| Windows, स्क्रिप्ट          | x64, Windows PowerShell। नेटिव सेवाओं के लिए व्यवस्थापक अधिकार                                                               |
| Linux पैकेज                 | x64, systemd, glibc 2.28 या उसके बाद का, Python 3। पैकेज मैनेजर PostgreSQL 16 या उसके बाद का संस्करण इंस्टॉल करता है         |
| Linux, स्क्रिप्ट            | x64 या arm64, नेटिव सेवाओं के लिए systemd, glibc, Bash, curl, Python 3, tar और xz                                            |
| Docker Compose              | Compose प्लगइन के साथ Docker Engine, या Linux कंटेनर मोड में Docker Desktop। संगत compose प्रोवाइडर के साथ Podman भी संभव है |

| फ़ाइल स्टोरेज               | हार्ड लिंक का समर्थन करने वाला स्थानीय फ़ाइल सिस्टम। फ़ाइल स्टोरेज के लिए नेटवर्क शेयर इस्तेमाल न करें                       |
| बैकअप स्टोरेज (vault)       | अलग वॉल्यूम, जो सेवाएँ शुरू होने से पहले माउंट हो चुका हो। [बैकअप](../operate/backups) देखें                                 |

Arkvory प्रोसेसर या मेमोरी की कोई निश्चित न्यूनतम सीमा तय नहीं करता। डिस्क स्पेस की योजना अपनी फ़ाइलों, डेटाबेस और बैकअप स्टोरेज के हिसाब से बनाएँ। डिफ़ॉल्ट रूप से Arkvory स्टोरेज वॉल्यूम पर 1 GiB खाली जगह रखता है और 10 TiB तक के आरक्षित अपलोड स्वीकार करता है। आप दोनों सीमाएँ बदल सकते हैं। [कॉन्फ़िगरेशन](./configuration) देखें।

### इंस्टॉलेशन और अपडेट के दौरान नेटवर्क एक्सेस {#network-access-during-installation-and-updates}

ग्राफ़िकल इंस्टॉलर इंटरनेट एक्सेस के बिना काम करता है। बाकी विकल्प HTTPS से फ़ाइलें डाउनलोड करते हैं:

| होस्ट                                                     | कौन इस्तेमाल करता है                                                                      |
| --------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| `nodejs.org`                                              | `install.sh` और `install.ps1` Node.js 24.21.0 डाउनलोड करते हैं और उसका SHA-256 जाँचते हैं |
| `api.github.com`, `github.com` और GitHub के डाउनलोड होस्ट | स्क्रिप्ट इंस्टॉलर, और अपडेट तब जब अपडेट हब तक पहुँचा न जा सके                            |
| `hub.proanima.net`                                        | अपडेट की जाँच और डाउनलोड। [अपडेट](./updates) देखें                                        |
| Docker Hub                                                | Compose अपनी इमेज `node:24.21.0-bookworm-slim` से बनाता है और `postgres:18.4` चलाता है    |

इंटरनेट एक्सेस के बिना रिलीज़ की स्थानीय प्रति से इंस्टॉल और अपडेट करें। [अपडेट](./updates) देखें।

## इंस्टॉलेशन डायरेक्टरी {#installation-directory}

इंस्टॉलेशन रूट Windows पर `C:\ProgramData\ProAnima\Arkvory` और Linux पर `/opt/proanima-arkvory` है। होम डायरेक्टरी और उपयोगकर्ता प्रोफ़ाइल के बाहर एक समर्पित, खाली डायरेक्टरी इस्तेमाल करें।

| रूट में पथ                       | सामग्री                                                                           |
| -------------------------------- | --------------------------------------------------------------------------------- |
| `installation.json`              | इंस्टॉल किया गया संस्करण, इंस्टॉलेशन मोड, स्वचालित अपडेट की सेटिंग और संस्करण पिन |
| `journal.json`, `operation.lock` | पिछले अपडेट की स्थिति, और चल रहे ऑपरेशन का लॉक                                    |
| `launcher.mjs`, `manage.mjs`     | सेवाएँ शुरू करते हैं और प्रबंधन कमांड चलाते हैं                                   |
| `releases/<version>/`            | हर इंस्टॉल किए गए संस्करण का प्रोग्राम कोड। सेवाएँ यहाँ नहीं लिखतीं               |
| `runtime/`                       | Node.js। ग्राफ़िकल इंस्टॉलर यहीं PostgreSQL और WinSW भी रखता है                   |
| `config/`                        | सेटिंग्स, कुंजियाँ और पुनर्प्राप्ति कुंजी। [कॉन्फ़िगरेशन](./configuration) देखें  |
| `data/`                          | नेटिव इंस्टॉलेशन का फ़ाइल स्टोरेज                                                 |
| `database/`                      | प्रबंधित PostgreSQL क्लस्टर। Windows पर उसके लॉग भी                               |
| `logs/`                          | Windows सेवाओं के लॉग और Windows अपडेटर का लॉग                                    |
| `service/`                       | Windows सेवा रैपर                                                                 |
| `updates/`                       | कंसोल से आए अपडेट अनुरोध और अपडेटर की स्थिति                                      |

Compose इंस्टॉलेशन अपना डेटा `data/` में नहीं, Docker वॉल्यूम `proanima-arkvory_storage` (फ़ाइलें) और `proanima-arkvory_catalog` (डेटाबेस) में रखता है।

`releases/` के पुराने संस्करण अपने-आप नहीं हटाए जाते। सफल अपडेट के बाद आप अनुपयोगी संस्करण हटा सकते हैं। वर्तमान संस्करण और `journal.json` में बताया गया पिछला संस्करण रखें।

## पुनर्प्राप्ति कुंजी {#recovery-key}

इंस्टॉलर `config/bootstrap-token.txt` बनाता है। इस फ़ाइल में **पुनर्प्राप्ति कुंजी** होती है: व्यवस्थापक अधिकारों वाली कुंजी। इसे केवल root या Administrators समूह पढ़ सकता है।

- अगर इंस्टॉलर ने पहला स्वामी खाता नहीं बनाया, तो उसे बनाने के लिए इसे एक बार इस्तेमाल करें। पहली बार शुरू करने पर कंसोल इसे माँगता है।
- इंस्टॉलेशन टूल इसे सर्वर पर पढ़ते हैं: स्वामी बनाना, `arkvory configure --backup-vault`, अपडेट के बाद बैकअप की जाँच, और डेटाबेस स्कीमा बदलने से पहले बैकअप। **इस फ़ाइल को न हटाएँ।**
- इसे क्लाइंट, CI सिस्टम या स्क्रिप्ट में कॉपी न करें। रोज़ के काम के लिए सीमित अधिकारों वाले उपयोगकर्ता खाते और सेवा कुंजियाँ बनाएँ। [खाते और एक्सेस](../use/accounts) देखें।

पुनर्प्राप्ति कुंजी बदलने के लिए [कॉन्फ़िगरेशन](./configuration) देखें।

## अगले कदम {#next-steps}

1. अपने प्लेटफ़ॉर्म के पेज से इंस्टॉल करें: [Windows](./windows), [Linux](./linux) या [Docker Compose](./docker)।
2. साइन इन करें और पहली फ़ाइल प्रकाशित करें। [त्वरित शुरुआत](../guide/quick-start) देखें।
3. दूसरे कंप्यूटरों से क्लाइंट जुड़ने से पहले [HTTPS](./https) कॉन्फ़िगर करें।
4. बैकअप स्टोरेज जोड़ें और पहला बैकअप चलाएँ। [बैकअप](../operate/backups) देखें।
5. [अपडेट नीति](./updates) चुनें।
