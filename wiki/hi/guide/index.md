# अवलोकन

ProAnima Arkvory बिल्ड आर्टिफ़ैक्ट और फ़ाइलों के लिए एक सेल्फ़-होस्टेड रिपॉज़िटरी है। आप इसे अपने सर्वर पर इंस्टॉल करते हैं। आपके बिल्ड जो फ़ाइलें बनाते हैं, यह उन्हें सहेजता है और उन लोगों व सिस्टम तक पहुँचाता है जिन्हें उनकी ज़रूरत है: डिप्लॉयमेंट एजेंट, CI/CD पाइपलाइन, टेस्ट मशीनें और डेवलपर।

Arkvory सभी के लिए मुफ़्त है, कंपनियों के लिए भी। इसका सोर्स कोड पढ़ने के लिए खुला है, लेकिन यह ओपन सोर्स नहीं है। आप इसे अपने संगठन के भीतर इस्तेमाल और संशोधित कर सकते हैं। आप इसकी प्रतियाँ वितरित नहीं कर सकते, इसे बेच नहीं सकते और इसे सेवा के रूप में नहीं दे सकते। [लाइसेंस](https://github.com/ProAnima/Arkvory/blob/main/LICENSE.md) देखें।

## यह किसके लिए है {#who-it-is-for}

- **CI/CD इंजीनियर**, जिन्हें बिल्ड प्रकाशित करने, संस्करण या स्टेज से बिल्ड खोजने और डिप्लॉयमेंट जॉब में उसे डाउनलोड करने के लिए एक ही जगह चाहिए।
- **व्यवस्थापक**, जो ऐसी स्टोरेज सेवा चाहते हैं जो एक ही सर्वर पर चले, अपने-आप फिर से शुरू हो जाए, अपने बैकअप खुद बनाए और खुद को अपडेट करे।
- **गेम स्टूडियो**, जो Unity या Unreal Engine के साथ काम करते हैं। Arkvory बड़ी बाइनरी एसेट Git LFS के ज़रिए, Unity पैकेज npm रजिस्ट्री के ज़रिए और दसियों गीगाबाइट के बिल्ड आउटपुट सहेजता है।
- **कई साइटों वाली टीमें**, जो किसी रिपॉज़िटरी की रीड-ओनली प्रति उन लोगों के पास रखना चाहती हैं जो उससे डाउनलोड करते हैं।

## यह क्या सहेजता है {#what-it-stores}

सब कुछ **रिपॉज़िटरी** में रखा जाता है। एक रिपॉज़िटरी में एक ही समय पर कई प्रकार की सामग्री हो सकती है:

| सामग्री                    | आप इसके साथ कैसे काम करते हैं                                                                                                                          |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| आर्टिफ़ैक्ट (कोई भी फ़ाइल) | कंसोल, [कमांड-लाइन क्लाइंट](../protocols/cli), [SDK](../protocols/sdk) या HTTP API से अपलोड करें                                                       |
| UPack पैकेज                | समूह, नाम और SemVer संस्करण वाले संस्करणित पैकेज। [पैकेज](../use/packages) देखें।                                                                      |
| पथ वाली फ़ाइलें            | `builds/game/1.4/Setup.exe` जैसा पथ, जो हर पिछला संस्करण सँभालकर रखता है। [फ़ाइलें और पथ](../use/files) और [रॉ फ़ाइलें](../protocols/raw-files) देखें। |
| कंटेनर इमेज                | Docker, Podman, Helm और ORAS के लिए OCI रजिस्ट्री। [कंटेनर इमेज](../protocols/containers) देखें।                                                       |
| Git LFS ऑब्जेक्ट           | फ़ाइल लॉकिंग वाला Git LFS सर्वर। [Git LFS](../protocols/git-lfs) देखें।                                                                                |
| npm और Unity पैकेज         | npm रजिस्ट्री, जिसे Unity Package Manager इस्तेमाल कर सकता है। [Unity और npm](../protocols/unity-npm) देखें।                                           |

सहेजी गई हर फ़ाइल SHA-256 चेकसम वाला एक अपरिवर्तनीय **आर्टिफ़ैक्ट** है। नई सामग्री पुराने बाइट कभी नहीं बदलती; वह एक नया आर्टिफ़ैक्ट बनाती है। [अवधारणाएँ](./concepts) देखें।

## मुख्य क्षमताएँ {#main-capabilities}

- **बड़ी फ़ाइलें।** अपलोड भागों में भेजे जाते हैं और नेटवर्क विफलता या रीस्टार्ट के बाद जारी रह सकते हैं। एक ऑब्जेक्ट लगभग 10 TiB तक का हो सकता है। डाउनलोड HTTP रेंज का समर्थन करते हैं, इसलिए वे भी जारी रह सकते हैं।
- **एक्सेस नियंत्रण।** उपयोगकर्ता खाते, समूह, व्यक्तिगत एक्सेस टोकन और कुंजियों वाले सेवा खाते। हर कुंजी को केवल वही रिपॉज़िटरी कार्रवाइयाँ मिलती हैं जिनकी उसे ज़रूरत है।
- **स्टेज और प्रमोशन।** बिल्ड को `qa`, `release` या `prod` चिह्नित करें, या उसे दोबारा अपलोड किए बिना किसी दूसरी रिपॉज़िटरी में प्रकाशित करें। डिप्लॉयमेंट एजेंट "`^1.4` श्रेणी का सबसे नया `release` बिल्ड" माँग सकता है।
- **मेटाडेटा।** लेबल, टेक्स्ट मेटाडेटा, संग्रह और संलग्न फ़ाइलें, जैसे मैनिफ़ेस्ट, SBOM और हस्ताक्षर।
- **प्रतिधारण।** हर पैकेज के अंतिम N बिल्ड रखें, कोटा तय करें और पुरानी सामग्री को पृष्ठभूमि में हटाएँ।
- **बैकअप।** बैकअप एजेंट रोज़ के शेड्यूल पर डेटाबेस और सारी सामग्री को किसी दूसरी डिस्क या NAS पर बने बैकअप स्टोरेज (vault) में कॉपी करता है और कॉपियों की जाँच करता है।
- **मिरर।** दूसरा इंस्टॉलेशन किसी रिपॉज़िटरी की रीड-ओनली प्रति रख सकता है और मुख्य सर्वर उपलब्ध न होने पर उसे परोस सकता है।
- **रीड गेटवे।** उसी साझा स्टोरेज पर चलने वाले अतिरिक्त डाउनलोड प्रोसेस एक ही डाउनलोड बजट साझा करते हैं।
- **स्वतः पुनर्प्राप्ति।** क्रैश या हैंग के बाद सेवाएँ फिर से शुरू हो जाती हैं। लंबे ट्रांसफ़र रीस्टार्ट के बाद जारी रह सकते हैं।
- **अपडेट।** सर्वर हब में जाँचता है कि ProAnimaStudio ने कौन-से हस्ताक्षरित स्थिर रिलीज़ स्वीकृत किए हैं। आप उन्हें हाथ से या रखरखाव के घंटे में अपने-आप इंस्टॉल करवा सकते हैं, और पिछले संस्करण पर लौट भी सकते हैं।
- **वेब कंसोल।** लाइट और डार्क थीम, ग्यारह भाषाओं में: अंग्रेज़ी, रूसी, स्पेनिश, फ़्रेंच, जर्मन, पुर्तगाली, चीनी, जापानी, कोरियाई, हिंदी और अरबी (दाएँ से बाएँ)। यह दस्तावेज़ीकरण भी इन्हीं भाषाओं में है। [वेब कंसोल](./console) देखें।

## यह कैसे चलता है {#how-it-runs}

Arkvory एक सर्वर पर चलता है। कैटलॉग के लिए यह PostgreSQL और सामग्री के लिए एक स्थानीय डायरेक्टरी इस्तेमाल करता है। तीन सेवाएँ मिलकर काम करती हैं:

| सेवा        | उद्देश्य                                                                           |
| ----------- | ---------------------------------------------------------------------------------- |
| API         | HTTP सर्वर: API, कंसोल और रजिस्ट्रियाँ। यह प्रतिधारण और भौतिक क्लीनअप भी चलाता है। |
| वर्कर       | पृष्ठभूमि के काम: बड़े अपलोड पूरे करना और मिरर सिंक्रनाइज़ करना                    |
| बैकअप एजेंट | बैकअप स्टोरेज में निर्धारित बैकअप                                                  |

आप इसे तीन तरीकों से इंस्टॉल कर सकते हैं:

| प्लेटफ़ॉर्म                   | इंस्टॉलर                                  | विवरण                                                                                                                                                                                  |
| ----------------------------- | ----------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Windows 10/11, Windows Server | `Arkvory-Setup-x64.exe`                   | सेटअप विज़ार्ड। इसमें Node.js और PostgreSQL शामिल हैं और यह इंटरनेट के बिना काम करता है। सेवाएँ किसी साइन-इन किए हुए उपयोगकर्ता के बिना चलती हैं। [Windows](../install/windows) देखें। |
| Linux                         | `Arkvory-amd64.deb`, `Arkvory-x86_64.rpm` | apt और dnf के पैकेज, systemd सेवाओं के साथ। [Linux](../install/linux) देखें।                                                                                                           |
| Docker                        | Docker Compose                            | API, वर्कर, बैकअप एजेंट और PostgreSQL कंटेनरों में। [Docker](../install/docker) देखें।                                                                                                 |

डिफ़ॉल्ट रूप से सर्वर केवल `127.0.0.1:8080` पर कनेक्शन स्वीकार करता है। दूसरी मशीनें जुड़ें, इससे पहले [HTTPS](../install/https) सेट करें।

एक इंस्टॉलेशन का मतलब एक सर्वर है। यह उच्च उपलब्धता (high availability) वाला क्लस्टर नहीं है: सर्वर रुक जाए तो क्लाइंट उसके लौटने तक प्रतीक्षा करते हैं। [बैकअप](../operate/backups) इस्तेमाल करें और ज़रूरत हो तो दूसरी साइट पर [मिरर](../operate/mirrors) रखें।

2. [अवधारणाएँ](./concepts): वे शब्द जो बाकी दस्तावेज़ीकरण में इस्तेमाल होते हैं।

4. [कमांड-लाइन क्लाइंट](../protocols/cli): स्क्रिप्ट और CI से Arkvory इस्तेमाल करें।
5. [बैकअप](../operate/backups): प्रोडक्शन में जाने से पहले अपने डेटा को सुरक्षित करें।
