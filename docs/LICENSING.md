Основное уведомление: [LICENSE.md](../LICENSE.md). Атрибуция: [NOTICE.md](../NOTICE.md).

## Модель доступа

Проект проприетарный. Общая открытая лицензия не предоставляется. Отдельные компании получают только те права, которые прямо записаны в их письменных соглашениях с Ian Panaev.

Доступ в GitHub и право по договору — разные вещи. Техническое приглашение, разрешённый fork или упоминание компании в документации не заменяют лицензионное соглашение. Форки партнёров должны оставаться приватными в пределах предоставленных им прав.

Для закрытой модели исходный репозиторий должен оставаться Private. Публикация исходников в публичном GitHub-репозитории предоставляет другим пользователям права просмотра и форка внутри GitHub в соответствии с условиями платформы; один запрет в README не отменяет эти условия.

## Что определить в отдельном соглашении

- Полное юридическое наименование лицензиата и уполномоченных подписантов.
- Разрешённое назначение и способы развёртывания, число установок/пользователей при необходимости.
- Право на приватный fork, изменение исходников и доступ сотрудников, подрядчиков и аффилированных лиц.
- Разрешены ли передача исходников, распространение сборок, перепродажа и предоставление сервиса третьим лицам.
- Права на доработки партнёра и условия передачи изменений обратно правообладателю.
- Использование названий, логотипов и бренда.
- Срок, оплата при наличии, поддержка, гарантии, ответственность, прекращение и судьба копий/форков.
- Применимое право и порядок разрешения споров.

Это перечень вопросов для договора, а не готовое соглашение и не предоставление разрешений. Перед выдачей лицензий конкретным компаниям условия следует проверить с юристом для соответствующей юрисдикции. Здесь не создаётся публичный список разрешённых компаний и не выдумываются реквизиты сторон.

## Разработка и зависимости

Сотрудник или подрядчик, вносящий вклад, должен иметь согласованные условия доступа и прав на этот вклад. Публикация pull request сама по себе не заменяет такого соглашения. Не добавляем автоматическое отчуждение прав партнёра без отдельного договора.

Сторонние компоненты сохраняют свои лицензии. Перед выпуском проверяются условия и необходимые уведомления для реально поставляемых компонентов. Собственный LICENSE не перелицензирует зависимости.

Поле `license: "UNLICENSED"` и `private: true` в package.json обозначают отсутствие общей npm-лицензии и запрет случайной публикации пакетов. Права конкретных лицензиатов определяются отдельными соглашениями, а не этим полем.
