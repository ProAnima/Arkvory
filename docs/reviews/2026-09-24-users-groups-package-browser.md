## Что проверялось помимо найденных дефектов

- Репозиторные права групп не образуют декартово произведение разрешений; роль администратора сама по себе не даёт читать содержимое. Следующий запрос учитывает отзыв membership, выключение пользователя и смену пароля. Сессии ограничены по сроку и количеству, токены хранятся в БД в виде хеша.
- Worker заново разрешает principal пользователя перед завершением job; существующие service keys сохраняют прежние scopes. Шлюзы чтения сохраняют запрет изменений и конечные leases раздачи.
- Значения SQL передаются параметрами; порядок и выражения пагинации выбираются из фиксированного набора. SemVer, курсоры и выдача более 1000 версий покрыты PostgreSQL-тестами. Exact/latest legacy lookup возвращает один ID, не загружая весь каталог.
- UI использует textContent для пользовательских значений, хранит токен только в памяти. В браузере проверены обычный вход/выход, отменённый вход, административный экран, RU/EN, тёмная и светлая темы. Новых стилей в ходе исправлений нет; полного нового mobile/accessibility-аудита не проводилось.

## Сохраняющиеся ограничения

Реальные Hub/CI/upack/pgutil, двухсерверная репликация и HA-отказы по-прежнему требуют отложенного стенда. Текущий legacy-адаптер возвращает native 401 при отсутствии/неизвестном ключе, тогда как [Common Packages Download](https://docs.inedo.com/docs/proget/api/packages/download) документирует 403. Матрица совместимости теперь явно указывает это отличие вместо утверждения о сверенных статусах. Полную ProGet-совместимость этот merge не объявляет.

Глубокая пагинация под смешанной нагрузкой, независимый security-аудит, полный административный audit trail и минимальные PostgreSQL runtime roles остаются отдельными задачами. Уже начатый разрешённый поток не обрывается исключительно при отзыве membership; это прежняя зафиксированная граница. Обновление требует согласованного backup, остановки старого кода и завершения `npm run migrate` до запуска новой версии.
