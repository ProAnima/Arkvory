# Аудит архитектуры — 2026-09-25

## Оценка

Основа подходит для дальнейшей разработки: strict TypeScript, изолированное ядро, потребительские порты, адаптеры PostgreSQL/blob-store, отдельные contracts/SDK/compat, потоковые передачи и явные состояния. Главный риск сейчас — концентрация ответственности в отдельных файлах и неполная автоматизация приёмки. Наличие документации само по себе не доказывает реализацию отказоустойчивости.

## Найденный долг

AST-аудит выявил 28 превышений: 7 файлов, 5 классов и 16 функций/методов. Точные размеры и ссылки на регрессии находятся в config/architecture-exceptions.json и генерируемом test-results/architecture.json. Несколько метрик могут относиться к одному исходнику.

Приоритет декомпозиции:

1. SDK transport: файл 984 и класс 921 строк кода. Выделять транспортацию HTTP, обработку ошибок/отмены и группы операций за прежним публичным facade. Сохранить fault/contract tests; не создавать новый универсальный god-service.
2. API composition root: файл 735, createServer 676. Отделить сборку зависимостей, lifecycle/cleanup и регистрацию групп маршрутов. Сохранить порядок авторизации, shutdown и standalone-lock.
3. PostgreSQL browse/service accounts/identity/catalog: отделять чтение, команды и mapping там, где есть независимые причины изменения, сохраняя транзакционные инварианты и проверки конкурентного доступа.
4. UI: build attachments, storage policy, download controller и другие обработчики — отделять состояние, rendering и действия по текущим сценариям; проверять реальные действия через browser gate.
5. messages и operation-policy — декларативные таблицы: дробить по языку/группе операций с проверкой полноты. SQL миграций не переписывать задним числом ради размера; новые миграции выносить в независимые модули с сохранением порядка.

Долг заморожен на фактических размерах до 2026-12-20; новые возможности не должны увеличивать эти декларации. Срок — точка обязательного пересмотра, не обещание автоматического рефакторинга. Это изменения правил разработки, без массового изменения поведения продукта.

## Закрываемые пробелы

Единый реестр пакетов, контроль TS overrides, AST-лимиты и проверяемые исключения; запрет пропущенных/focused тестов; инвентаризация всех тестовых входов; общий runner с тайм-аутами, отменой, эксклюзивной сборкой и отчётами. Браузер и аудит зависимостей входят в обязательную CI-приёмку. Итоговый always-verdict не принимает провал/пропуск обязательного задания.

## Что остаётся за пределами этого изменения

Двухсерверная репликация и split-brain/failover, restore из резервной копии, совместимость с настоящим ProGet/клиентами, долговременные нагрузочные испытания и физический online GC требуют собственных сценариев и стенда. Локальные 5 GiB тесты проверяют конкретные restart/resume/hash/RSS-инварианты и не доказывают HA. Включение S3/нового адаптера требует той же контрактной приёмки порта.

См. [гейты](ENGINEERING_GATES.md), [решение](adr/0027-executable-engineering-gates.md), [архитектуру](ARCHITECTURE.md).
