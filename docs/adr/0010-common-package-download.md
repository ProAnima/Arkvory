# ADR 0010: чтение исходного UPack через Common Packages API

Статус: accepted. Дата: 2026-09-23.

## Контекст

Реализован legacy download через `/upack/{feed}/download/...`. Клиенты ProGet 2023+ могут запрашивать те же байты через `/api/packages/{feed}/download`. Публикация и каталог Common Packages пока не реализованы, а фикстур реального стенда нет.

## Решение

- Добавить GET/HEAD `/api/packages/{feed}/download` для уже зарегистрированного UPack. Принимать только `group`, `name`, `version`; последние два обязательны. Пустая группа подразумевается при отсутствии `group`.
- Требовать точного выбора одной версии с поиском group/name/version без учёта регистра. Неоднозначные и неподдержанные идентификаторы, включая `purl`, отклонять 400. Отсутствующий пакет возвращает 404.
- Использовать существующие сервисные ключи, repository ACL и потоковую выдачу с Range, ETag и admission. Никаких новых копий blob или операций публикации маршрут не создаёт.

## Последствия

Маршрут расширяет только чтение UPack и не означает поддержку остальных видов фидов Common Packages API. Формат ошибки пока native; статус аутентификации и заголовки нужно сверить с выбранной сборкой ProGet и клиентами до переключения hostname. Основание формы URL и статусов — [официальный контракт Inedo](https://docs.inedo.com/docs/proget/api/packages/download).
