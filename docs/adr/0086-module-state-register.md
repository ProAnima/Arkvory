# 0086. Атомарное служебное состояние модулей

Статус: proposed, реализация в отдельном PR. Дата: 2026-10-20. Owner: Ian Panaev.

## Сценарий и границы

Подписанному модулю нужен небольшой устойчивый регистр для контрольных отметок
и координации API/worker. Read/rename файла не даёт compare-and-swap, а данные
layout-модуля нельзя перезаписывать без допуска ядра на очистку. Эти гарантии
не изменяются. Добавляется отдельная служба `module-state` extension-api 0.10.0.

Служба привязана хостом к id модуля и хранит один непрозрачный документ до 8 МиБ
в PostgreSQL. В пределах экземпляра допускаются не более восьми одновременных
операций, дальше `busy`; очередь в модуле не создаётся. API/worker могут читать
и обновлять, reader/backup — только читать. Плагины operator/development службу
не получают. Модуль обязан объявить её в uses.

`read()` возвращает null либо точные байты и десятичную ревизию.
`compareExchange(null, bytes)` создаёт только отсутствующую запись;
`compareExchange(revision, bytes)` заменяет только указанную ревизию. Один SQL
INSERT/UPDATE обеспечивает атомарность между процессами и узлами. Каждая запись
увеличивает bigint-ревизию, даже если байты не изменились; числа за пределами
безопасного Number остаются строками. Нет delete/reset и перехода через максимум.
Неопределённый исход требует перечитывания; exactly-once не обещается. Повторы
конфликтов ограничивает вызывающий модуль и заново вычисляет переход.

Expand-only миграция 50 добавляет arkvory_module_state. Старые процессы таблицу
не используют; новые получают её после штатного обновления схемы. Физическая
репликация БД сохраняет регистр при переключении HA. Обычное удаление или новая
версия модуля не сбрасывают запись.

Это служебное состояние конкретной установки, не единственная копия данных
пользователя и не blob-store. Переносимые логические backup его явно исключают,
как другие привязанные к исходной установке записи. После restore потребитель
обязан явно обработать отсутствие/повторную инициализацию; оно не доказывает,
что внешняя операция никогда не выполнялась. Чтение и восстановление объектов
не могут зависеть от доступности регистра.

LicenseService дополнительно предоставляет installation(): стабильный
идентификатор установки из сохранённого контекста, null до инициализации.
Секреты активации не раскрываются. Сам идентификатор не является разрешением.

## Приёмка

Общий moduleStateContract применяется к PostgreSQL. Проверяются два независимых
адаптера, гонка создания и обновления, stale writer, изоляция пространств,
read-only, граница размера, bigint вне Number и повторное создание адаптера.
Governance требует suite для каждой службы. Миграции и исключение backup
проверяются существующими integration/backup гейтами. Публичный CI и полный
verify остаются обязательными; до результатов реализация не считается принятой.
