# ADR 0085: восстановление логической копии в основное хранилище

Статус: принято к реализации.

## Контекст

ADR 0054 и 0083 сохраняют backend каждого объекта при восстановлении. Это правильно для восстановления прежней топологии, но мешает аварийному переносу, если исходный том или модуль недоступен. Логическая копия уже содержит полные байты объектов, независимо от устройства исходного backend.

## Решение

Добавить явный флаг `restore --to-default-storage`. Без него прежняя проверка наличия всех backend остаётся обязательной. С флагом все опубликованные объекты потоково восстанавливаются в `default` с проверкой размера и SHA-256. Исходный inventory остаётся неизменным; адрес чтения из vault берётся из исходной записи.

После проверки всех байтов загрузка каталога в одной транзакции заменяет `storage_backend` на `default`, очищает `parts_backend` и правила размещения. Незавершённые загрузки отменяются по существующей нормализации. Версия нормализации становится 2. План, отчёт и аудит явно отражают выбранный режим.

Требования пустой БД и пустого хранилища, раздельных путей и подтверждения `--yes` сохраняются. Это восстановление полной копии, а не миграция работающего экземпляра. На целевом носителе нужно место для полных несжатых объектов. Исходные модули и лицензии не нужны для чтения восстановленных байтов.

## Проверки

Интеграционная проверка создаёт объекты в двух хранилищах, снимает настоящую копию и восстанавливает через CLI. Она проверяет отказ обычного режима без второго тома, план без записи, атомарную перепривязку каталога, удаление правил размещения и чтение исходных байтов через API без второго backend. Повторное восстановление в непустую цель запрещено. Существующие проверки повреждений копии и восстановления прежней топологии остаются обязательными.
