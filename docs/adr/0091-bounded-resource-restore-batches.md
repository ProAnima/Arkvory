# 0091. Ограниченные группы восстановления каталога ресурсов

Статус: реализация и приёмка. Дата: 2026-10-23.

## Причина

Восстановление миллионов записей выполняло отдельный durable COMMIT для каждого
файла. На локальном стенде зарегистрированы ожидания WALSync и медленное
продвижение даже после перекрытия независимых файловых чтений.

## Решение и гарантии

Публичный порт restore не меняется. Адаптер одного связанного каталога собирает
поступившие за оборот event loop запросы в группу максимум по восемь. Каждое
обращение сразу занимает место в прежнем общем лимите восьми операций БД,
включая время ожидания группы. Другие операции учитываются в том же лимите.
Входные имена, ключи, sources и metadata проверяются и копируются до ожидания.

Группа исполняется в порядке поступления под прежней advisory xact lock, с
прежними SQL timeout и проверками неизменяемости. Успех всех обещаний наступает
только после COMMIT; synchronous_commit и fsync не отключаются. Конфликт или
ошибка откатывает всю группу и отклоняет все её запросы. Частичный успех не
сообщается; вызывающий может повторить идемпотентное восстановление.

Запросы restore следует дождаться перед initialize, как и прежде. Общая
готовность по-прежнему требует всех файлов источников. До initialize GC закрыт.
Ни пакетная обработка, ни более быстрый файловый обход не разрешают удаление
и не меняют reader pins, квоты, роли либо namespace. Порядок канонического
представления сохраняется; вызывающие параллельные запросы для разных ключей
не должны нарушать порядок вариантов одного ключа.

## Приёмка

PostgreSQL-проверки подтверждают один xmin для группы, общий предел admission,
копирование изменяемого входа, порядок canonical_name и полный rollback при
конфликте. Существующие проверки missing sources, namespace, read-only и GC
остаются обязательными. Масштабная проверка записи после восстановления
выполняется отдельно на настоящем ядре и не заменяется маленьким контрактом.
