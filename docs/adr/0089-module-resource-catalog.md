# ADR 0089: общий каталог ссылок на ресурсы модулей

Статус: в реализации. Дата: 2026-10-21.

## Контекст

Каталог процесса не доказывает отсутствие ссылок других API/worker.
`module-state` ограничен одним документом; `derived-cache` допускает потерю
восстанавливаемых данных. Ни один из них не подходит для очистки исходных файлов.

## Решение

Служба `resource-catalog` API 0.13 предоставляется подписанным модулям.
Namespace задаёт ядро. Reader/backup только читают; API/worker изменяют ссылки.
Схема 52 хранит логические ресурсы, физические файлы, владельцев-загрузки и
рёбра зависимостей. Короткие транзакции сериализуются по namespace. SQL,
произвольные таблицы и код модуля внутри транзакции не предоставляются.

До использования ресурса загрузка получает устойчивую ссылку. До создания файла
резервируются его уникальное имя и зависимости. После durable close файл
публикуется в индексе. Подтверждение с неопределённым результатом повторяется
идемпотентно. Закрытие владельца допускается только внутри core collect после
завершения его I/O и удаления рецепта; закрытый владелец не открывается вновь.
Ссылки не освобождаются по TTL или потере соединения.

Все физические версии логического ресурса сохраняются, пока есть хотя бы одна
ссылка на него. Это консервативно: дубликаты одного содержимого удаляются вместе
после освобождения последнего владельца. Зависимости сохраняются до успешного
unlink всех физических файлов. Grace использует время БД.

GC переводит ресурс в doomed транзакционно с проверкой ссылок. Новые ссылки
на doomed получают busy. Само ядро удаляет зарегистрированные файлы под
ModuleUnlinkAdmission и ModuleRemoval: активное чтение и backup закрывают допуск.
Unlink выполняется вне транзакции. Ошибка оставляет состояние для повтора.
Номер поколения защищает завершение старого GC после повторного использования
логического ключа. Имена физических файлов никогда не переиспользуются.

## Восстановление и обновление

Индекс восстанавливается из файлов и рецептов модуля; он исключён из логической
копии по явному реестру. После restore GC закрыт до полной успешной сверки.
`restore` только добавляет существующие файлы до initialize; отсутствующие
источники запрещают initialize. Модуль обязан валидировать все рецепты и файлы;
повреждение не означает отсутствие ссылок. Reader/backup не выполняют сверку.

Первичное внедрение требует остановки старых процессов модуля перед обновлением.
Rolling-смешение старых писателей без общего каталога с новыми недопустимо.
Это ограничение должно быть проверено процедурой установки до выпуска.

## Критерии приёмки

Роли и namespaces; конкурентные retain/release/GC; ошибки unlink и повтор;
запоздалые владельцы и поколения; reader/backup pins; восстановление индекса;
источники нескольких физических версий; реальный Pro core-e2e и HA.
До их прохождения этот ADR не является доказательством готовности релиза.
