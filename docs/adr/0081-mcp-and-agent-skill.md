# 0081. MCP-сервер в arkvoryctl и навык для агентов

Статус: proposed. Owner: Ian Panaev. Дата: 2026-10-17. MCP-сервер, навык и расширения API этого ADR входят в бесплатное ядро ([ADR 0078](0078-open-core-modules-and-licenses.md)) и не зависят от лицензии. Решение добавляет стороннюю зависимость в клиентский пакет, новую поверхность для ИИ-агентов и аддитивные расширения `/api/v1`. До решения владельца код не пишется. Связано с [ADR 0034](0034-remote-client-cli.md), [ADR 0017](0017-managed-service-keys.md), [ADR 0051](0051-error-contract.md), [ADR 0079](0079-extension-modules.md), [ADR 0080](0080-event-integrations.md).

## Контекст

Агенты развёртывания и ИИ-агенты (Claude Code и другие клиенты Model Context Protocol) уже работают с Arkvory через `arkvoryctl` и его JSON-вывод. Каждый раз агент заново разбирает справку, флаги и коды ошибок, а риск случайной записи ничем не ограничен. Факты кода:

- **Границы CLI.** `apps/cli` зависит только от `packages/sdk` и `packages/contracts` (`config/architecture.json`) и владеет локальными файлами и профилями.
- **Профили и ключ.** Профиль хранится в `~/.config/arkvory/profiles.json` (`ARKVORY_CLI_HOME`), ключ — только по `tokenFile`; переопределения — `ARKVORY_TOKEN`, `ARKVORY_TOKEN_FILE`, `ARKVORY_BASE_URL` (`apps/cli/src/profiles.ts`, `connection()`). При `ARKVORY_BASE_URL` файл ключа профиля не используется. TLS не отключается, HTTPS обязателен, кроме loopback.
- **Журнал запросов.** `--verbose` пишет строку на обмен без заголовков и query (`verboseLine`), так что ключ туда не попадает.
- **Проверенное скачивание.** SDK уже умеет скачивать с проверкой (`packages/sdk/src/verified-download.ts`, `checkpointed-download.ts`): CLI хеширует неизменяемый префикс и проверяет итоговый SHA-256 (`apps/cli/src/download.ts`). Загрузка идёт с чекпойнтами (`upload.ts`, `publish-package.ts`).
- **Ссылки-токены.** Команда `link` выдаёт URL с токеном `dtl_…` — это предъявительский секрет.
- **Поиск.** Работает только внутри репозитория (`GET R/search`, до 100 результатов). Общего поиска по установке и пакетного чтения метаданных нет. Обнаружение есть: `GET /api/v1/repositories`, `GET /api/v1/operations`, `GET /api/v1/capabilities`, `GET /api/v1/auth/permissions`.
- **Поставка.** Клиент распространяется собранным `arkvoryctl.mjs` с приватным Node (`scripts/package-client.mjs`); лицензии встроенных зависимостей копируются рядом.
- **Заголовки SDK.** SDK не передаёт идентификатор клиента: в журнале доступа CLI и консоль неотличимы (`packages/sdk/src/http-transport.ts`).
- **Библиотеки MCP** (данные npm на 2026-10-17):
  - `@modelcontextprotocol/sdk` 1.32.x (MIT) тянет `express`, `hono`, `cors`, `jose`, `express-rate-limit` и другие пакеты для HTTP-транспорта и OAuth;
  - разделённая вторая версия `@modelcontextprotocol/server` 2.x (Apache-2.0) зависит только от `@modelcontextprotocol/core` и `zod` ^4 и экспортирует `./stdio`;
  - последняя версия протокола в SDK — `2025-11-25`, поддерживаются также `2025-06-18`, `2025-03-26` и `2024-11-05`.

## Решение

### 1. Локальный stdio-сервер в CLI

`arkvoryctl mcp [--profile <p>] [--write] [--write-repositories <r1,r2>] [--root <dir>] [--max-output-bytes <n>]` запускается клиентом агента как дочерний процесс и говорит MCP по stdin/stdout.

Инварианты:

- **Нет нового сетевого слушателя:** ни HTTP, ни SSE, ни WebSocket. Значит, нет новой поверхности аутентификации и CORS. Все вызовы идут через SDK к API, и сервер проверяет ACL как обычно. MCP не добавляет серверных маршрутов и прав.
- **Ключ — только из профиля или окружения** по тем же правилам `connection()`. Аргументом инструмента ключ не передаётся. Ключ не появляется в выводе инструментов, ресурсах, ошибках и stderr.
- **По умолчанию только чтение.** Инструменты записи регистрируются только с `--write`. `--write-repositories` дополнительно ограничивает запись списком репозиториев: проверка в CLI до вызова, затем обычная проверка прав на сервере.
- **Локальные пути ограничены корнем** `--root` (по умолчанию — текущий каталог при запуске). Путь разрешается через `realpath`; ссылка, выводящая за корень, устройство, FIFO и путь с `..` после нормализации отклоняются (`path_outside_root`).
- **Набор инструментов зависит от прав ключа.** При запуске CLI читает `GET /api/v1/auth/permissions` и `capabilities` и не регистрирует инструменты, которые ключ заведомо не может выполнить, и протоколы, выключенные модулями (ADR 0079). Это удобство, а не защита.
- **Идентификатор клиента.** SDK получает необязательный параметр `clientName`; CLI передаёт заголовок `Arkvory-Client: arkvoryctl-mcp/<версия>`. Сервер пишет его в журнал доступа (аддитивно, только печатный ASCII до 64 символов). Консоль заголовок не ставит.

### 2. Библиотека и протокол

- **Библиотека.** `@modelcontextprotocol/server` (вторая версия) с `./stdio`. Версия закрепляется точно (`2.3.0` от 2026-10-02 на момент написания; в PR — последняя, опубликованная не меньше 14 дней назад). Зависимость объявляется только в `apps/cli/package.json` и встраивается в `arkvoryctl.mjs`.
  - Тексты лицензий Apache-2.0 (с NOTICE) и MIT (`zod`) копируются в клиентский пакет так же, как `SSH2-LICENSE.txt` в `clientFiles` (`scripts/package-client.mjs`), и проверяются тестом упаковки.
  - `npm run gate -- security` покрывает новые пакеты.
  - Первая версия SDK отклонена: HTTP-сервер и OAuth не нужны stdio-процессу и расширяют поверхность аудита.
- **Схемы и данные.** `zod` используется только в `apps/cli/src/mcp/` для схем входа инструментов. В `contracts` и `sdk` его нет. Ответы API по-прежнему проверяют читатели контракта SDK; входы после `zod` проходят те же проверки CLI (`repositoryName` и другие).
- **Протокол.** `2025-11-25`; нижняя граница — `2025-06-18`, где есть `outputSchema` и `structuredContent`. Подсказки инструментов (`readOnlyHint`, `destructiveHint`, `idempotentHint`, `openWorldHint`) существуют с `2025-03-26`. С клиентом старше `2025-06-18` сервер завершает инициализацию ошибкой с понятным текстом.
- **Код.** `apps/cli/src/mcp/` — по файлу на группу инструментов, в пределах 500/300/100 строк. Для самого MCP allowlist `apps/cli` не меняется и новый workspace не нужен; точка инструментов модулей (п. 3.1) использует `extension-api` по ADR 0079.

### 3. Инструменты

У всех инструментов `openWorldHint: false`: они работают с одной известной установкой.

| Инструмент                | API                                                                                              | Подсказки                                                                                      |
| ------------------------- | ------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------- |
| `arkvory_repositories`    | `GET /api/v1/repositories`                                                                       | readOnly                                                                                       |
| `arkvory_search`          | `GET R/search`; после этапа A1 — `GET /api/v1/search`                                            | readOnly                                                                                       |
| `arkvory_artifacts`       | `GET R/artifacts`                                                                                | readOnly                                                                                       |
| `arkvory_artifact`        | артефакт, аннотации (если есть `annotation.read`), стадии, пакет, вложения                       | readOnly                                                                                       |
| `arkvory_packages`        | `GET R/packages`, разрешение версии                                                              | readOnly                                                                                       |
| `arkvory_files`           | `GET R/assets/page`, `GET R/asset/history`                                                       | readOnly                                                                                       |
| `arkvory_history`         | `GET R/changes`, промоушены; после ADR 0080 — `GET /api/v1/events`                               | readOnly                                                                                       |
| `arkvory_status`          | `/health/status`, `capabilities`, зеркала, очередь скачиваний, резервные копии, `fleet/overview` | readOnly; недоступный раздел — `forbidden`, а не ошибка                                        |
| `arkvory_download`        | проверенное скачивание SDK                                                                       | readOnly: false, destructive: false, idempotent: true                                          |
| `arkvory_upload`          | файл по пути (`raw`) или загрузка артефакта                                                      | только с `--write`; destructive: false (новая ревизия, прежняя сохраняется), idempotent: false |
| `arkvory_publish_package` | публикация UPack                                                                                 | только с `--write`; destructive: false, idempotent: false                                      |
| `arkvory_promote`         | добавление стадии                                                                                | только с `--write`; destructive: false, idempotent: true                                       |
| `arkvory_stage_remove`    | снятие стадии                                                                                    | только с `--write`; destructive: true                                                          |
| `arkvory_annotate`        | метки и metadata с `expectedRevision`                                                            | только с `--write`; destructive: true (заменяет значения), idempotent: true при той же ревизии |

**Чего нет никогда:** удаления артефактов и файлов, восстановления ревизий, ссылок `dtl_`, управления пользователями, группами, ключами, политиками, площадками, обновлениями и резервными копиями. Это задачи человека в консоли или CLI. Подсказки MCP — лишь сигнал клиенту, поэтому граница проводится набором инструментов, а не подсказками.

**`arkvory_download`.** Пишет только внутри корня. Существующий файл заменяется только при `overwrite: true`. Байты идут потоком во временный файл рядом с целью; SHA-256 и размер сверяются с дескриптором; затем атомарное переименование. При несовпадении временный файл удаляется, и цели нет. Необязательный `maxBytes` отклоняет больший артефакт до начала передачи. Ответ — путь, размер и `sha256`, байты в ответ не попадают никогда. Если в `arkvoryctl` установлен клиентский модуль с расширением передачи, SDK выбирает его согласованием возможностей (ADR 0079, п. 5.2). Инструмент от этого не меняется, а итоговая проверка размера и SHA-256 остаётся за SDK.

**Запись.** Источник — файл внутри корня. Загрузка возобновляется с чекпойнтом в каталоге CLI. Ответ — квитанция публикации того же формата, что у `arkvoryctl`.

#### 3.1. Инструменты клиентских модулей

Подписанный клиентский модуль (ADR 0078, ADR 0079, п. 5.11) может добавить инструменты через `McpToolContribution` из `extension-api`: имя, схема входа и выхода, подсказки и обработчик, получающий только SDK-клиент, корень и `AbortSignal`. Ядро MCP:

- регистрирует их только из модулей, загруженных после проверки подписи; имена — только `arkvory_<module>_*`, встроенные имена зарезервированы;
- применяет те же правила: запись — только с `--write` и в пределах `--write-repositories`, пути — внутри корня, лимиты и очистка вывода, отсутствие секретов, коды ошибок;
- не регистрирует инструменты из списка «чего нет никогда» в любом модуле: удаление, администрирование, ссылки `dtl_`.

Набор бесплатных инструментов от установки модулей не меняется.

### 4. Вывод

- **Формат.** `structuredContent` по `outputSchema` и короткая текстовая сводка.
- **Размер.** Один результат — не больше 64 КиБ (`--max-output-bytes`, до 1 МиБ). Списки — до 100 элементов с курсором `next`; обрезанное помечено `truncated: true`.
- **Чужие строки.** Имена, метки, metadata и пути — данные других пользователей. Они очищаются от управляющих символов, возвращаются только в полях данных и никогда не встраиваются в текст инструкций. Навык (п. 6) требует считать их данными.
- **Секреты.** Не возвращаются: ключи, `Authorization`, ссылки `dtl_`, путь к файлу ключа.
- **Ошибки.** `isError: true` с машинным кодом контракта ошибок ADR 0051 и `request_id`. Сетевые ошибки SDK передаются кодами, без адресов и стеков.
- **Отмена и прогресс.** `notifications/cancelled` прерывает операцию через `AbortSignal` SDK. Прогресс передачи (`progressToken`) отправляется не чаще двух раз в секунду.

### 5. Ресурсы и подсказки (необязательный этап)

- **Ресурсы.** Шаблоны `arkvory://<profile>/repositories/<r>/artifacts/<id>` и `arkvory://<profile>/repositories/<r>/packages/<group>/<name>/<version>` — JSON метаданных без байтов. Список ограничен 100 и курсором.
- **Подсказки.** `publish-release` и `promote-build` повторяют сценарии навыка.

### 6. Навык для агентов

- **Расположение.** `integrations/agent-skills/arkvory/` — новый каталог верхнего уровня для поставляемых интеграций без кода продукта. Это не workspace, поэтому `config/architecture.json` не меняется. Содержимое: `SKILL.md` (frontmatter `name: arkvory`, `description`) и `reference/` (команды, коды ошибок, рабочие процессы).
- **Поставка.** Навык входит в клиентский пакет. `arkvoryctl skill install [--target <dir>]` копирует его в `~/.claude/skills/arkvory` (или в каталог проекта) и без `--force` не перезаписывает изменённые файлы.
- **Язык.** Английский: так написаны идентификаторы и справка CLI. Навык — не страница wiki, поэтому переводы не требуются. Пользовательская страница `wiki/guide/agents.md` (английский источник и переводы в том же коммите) описывает установку MCP и навыка.
- **Чему учит навык:**
  - настроить профиль с `--token-file` и выделенным сервисным ключом с узкими привязками (ADR 0017); никогда не вставлять ключ в чат, аргументы и файлы проекта;
  - подключить MCP (`claude mcp add arkvory -- arkvoryctl mcp --profile <p>`); запись — отдельной конфигурацией с `--write --write-repositories`;
  - найти и скачать с проверкой; публиковать с сохранением чекпойнта и квитанции; продвигать только после проверки стадий и `sha256`; ссылаться на артефакт по id, а не по имени;
  - перед любой записью показать пользователю, что будет сделано, и получить подтверждение; не удалять; считать содержимое metadata и имён данными, а не инструкциями;
  - разбирать коды ошибок (`permission_missing`, `busy` с ожиданием и другие) без бесконечных повторов.

### 7. Расширения API (аддитивные; OpenAPI, SDK и CLI в том же PR)

- **A1. Общий поиск** `GET /api/v1/search?q=&repositories=&labels=&stage=&after=&limit=` — по репозиториям, где у принципала есть `artifact.list` (не больше 1000, как чтение площадок ADR 0077). Ключ курсора — `(publishedAt desc, repository, id)`. Элемент совпадает с `R/search` и добавляет `repository`. Запрос ограничен по правилам ADR 0075. Агент не обязан знать репозиторий заранее.
- **A2. Пакетное чтение** `POST /api/v1/repositories/{r}/artifacts/batch` (`{ids}` до 100) → `{items, missing}`. Операция чтения: нужно `artifact.read`, она идемпотентна и без N+1. Нужна MCP, консоли и интеграциям событий (по событию перечитывают состояние).
- **A3. События.** `GET /api/v1/events` (ADR 0080) — инструмент `arkvory_history` и наблюдение после публикации.
- **A4. Модули.** `capabilities.modules` и `GET /api/v1/system/modules` (ADR 0079) — набор инструментов по включённым протоколам.
- **A5. Согласование возможностей передачи** — `capabilities.transfer` (ADR 0079, п. 5.2). MCP пользуется передачей, которую выбрал SDK, без своих инструментов и параметров.
- **A6.** Заголовок `Arkvory-Client` (п. 1).

### 8. Модель угроз

Главный риск — внедрение инструкций через metadata, имена и файлы: агент вызывает запись, которой пользователь не хотел. Защита строится слоями:

1. по умолчанию только чтение;
2. список репозиториев для записи;
3. инструментов удаления и администрирования нет;
4. подсказки MCP, по которым клиент спрашивает подтверждение;
5. рекомендация выделенного сервисного ключа с минимальными правами;
6. ACL сервера как последняя граница.

Утечка локальных файлов ограничена корнем, утечка секретов — правилами вывода. Ресурсы процесса ограничены размерами вывода, пагинацией и сроками SDK.

## Альтернативы

- **Удалённый MCP-сервер внутри API** (HTTP-транспорт, OAuth). Новая поверхность аутентификации на сервере хранения и вторая модель сессий. Отклонено для этого ADR; возможно отдельным решением, если понадобятся агенты без локального CLI.
- **Отдельный пакет `arkvory-mcp`.** Дублирует профили, чекпойнты и поставку; CLI уже владеет ими.
- **Первая версия SDK** — см. п. 2.
- **Только навык без MCP.** Работает и остаётся запасным путём (навык учит и CLI), но без схем, подсказок и ограничений вывода.
- **Навык в `docs/` или `deploy/client/`.** `docs/` — инженерные документы, а `deploy/client/` — сценарии упаковки. Отдельный каталог проще проверять policy-тестом.

## Последствия

- Новые сторонние пакеты в клиенте (`@modelcontextprotocol/server`, `@modelcontextprotocol/core`, `zod`), лицензия Apache-2.0 в списке third-party.
- Общий поиск и пакетное чтение полезны и без MCP (консоль, интеграции).
- Поведение MCP зависит от клиента агента (подтверждения, показ подсказок). Сервер Arkvory это не контролирует, поэтому граница — набор инструментов и ACL.

## Этапы (каждый — отдельный PR)

1. **M1. Чтение.** `arkvoryctl mcp` с инструментами чтения, `arkvory_status` и `arkvory_download`; зависимость, лицензии, `Arkvory-Client`. Гейты: `quick`, `integration`, `native-package`.
2. **M2. Запись.** `--write`, `--write-repositories`, инструменты записи. Гейты: `quick`, `integration`.
3. **M3. Навык.** `integrations/agent-skills/arkvory`, `arkvoryctl skill install`, страница wiki с переводами, упаковка. Гейты: `quick`, `native-package`.
4. **M4. Общий поиск (A1).** Маршрут, SDK, CLI `search --all`, инструмент. Гейты: `quick`, `integration`.
5. **M5. Пакетное чтение (A2)**, ресурсы и подсказки MCP; `arkvory_history` по событиям после этапа E2 ADR 0080. Гейты: `quick`, `integration`.
6. **M6. Инструменты клиентских модулей** (п. 3.1) после этапа X5 ADR 0079. Гейты: `quick`, `integration`.

## Проверка

- **Unit (пара связанных транспортов в одном процессе):**
  - `tools/list` без `--write` не содержит записи, а с `--write` содержит её с правильными подсказками;
  - инструменты, недоступные по правам, скрыты;
  - схемы входа отклоняют лишние поля;
  - вывод больше лимита обрезается с `truncated`;
  - управляющие символы удаляются;
  - путь вне корня, ссылка наружу и FIFO отклоняются.
- **Integration (настоящий `arkvoryctl mcp` как дочерний процесс против API на PostgreSQL):**
  - согласование протокола;
  - поиск и пагинация;
  - скачивание с проверкой: прокси, портящий байт, даёт `checksum_mismatch` и не оставляет цели;
  - отмена прерывает передачу;
  - запись вне `--write-repositories` отклоняется до запроса;
  - 403 сервера передаётся кодом;
  - в stdout и stderr нет значения ключа и `dtl_` (поиск по выводу всего сценария);
  - в журнале доступа есть `Arkvory-Client`.
- **Policy навыка:**
  - frontmatter `SKILL.md` корректен;
  - каждая команда `arkvoryctl …` в навыке существует в списке команд CLI;
  - ссылки ведут на существующие файлы;
  - образцы ключей отсутствуют.
- **Инструменты модулей.** Тестовый подписанный клиентский модуль добавляет инструмент `arkvory_<module>_*`; инструмент записи без `--write` не регистрируется; имя встроенного инструмента и неподписанный модуль отклоняются.
- **Упаковка.** Тексты лицензий новых зависимостей есть в клиентских пакетах Windows и Linux; `arkvoryctl mcp --help` работает в установленном пакете.

## Реализация: этапы M1 и A1 (2026-10-17)

Выполнено по поручению владельца в ветке `feat/mcp-search`; статус ADR меняет владелец.

**A1.** `GET /api/v1/search` (`searchAllRepositories`): application `GlobalSearch` и порт `GlobalSearchStore`, PostgreSQL-адаптер `PostgresGlobalSearch`, маршрут `apps/api/src/search-routes.ts`, SDK `searchAll()`, CLI `search --all`. Права: в политике операций `authenticated`, фильтр делает сценарий — репозитории, где у принципала есть `artifact.list` и которые проходят ту же проверку `authorizeAction`, что и `R/search`; не больше первых 1000 по имени. Нечитаемый или несуществующий репозиторий в `repositories` отбрасывается одинаково, ответ не раскрывает существование. Ограничения: `q` до 240 символов, `repositories` до 100, `labels` до 8 (нужны все), `stage`, `limit` 1–100 (50 по умолчанию). Порядок `(publishedAt desc, repository, id)`; строки без времени публикации сортируются по времени резервирования. Курсор непрозрачный (`<микросекунды>.<репозиторий>.<id>`), сравнение в БД без округления. Один запрос на страницу с `SET LOCAL statement_timeout = 5000` (тайм-аут — 503 `unavailable`); подстрока сканирует перечисленные репозитории, как `R/search` (ADR 0075).

**M1.** `arkvoryctl mcp [--root DIR] [--max-output-bytes N]` в `apps/cli/src/mcp/` и `mcp-command.ts`. Инструменты: `arkvory_repositories`, `arkvory_search`, `arkvory_artifacts`, `arkvory_artifact`, `arkvory_packages`, `arkvory_files`, `arkvory_history`, `arkvory_status`, `arkvory_download`. SDK получил `clientName` (заголовок `Arkvory-Client`, печатный ASCII до 64), журнал доступа — поле `client`. Лицензии встроенного кода — `MCP-LICENSES.txt` в клиентских пакетах.

Отступления и уточнения:

- **Порядок этапов.** A1 (по таблице этапов — M4) сделан вместе с M1, поэтому `arkvory_search` сразу работает через `GET /api/v1/search`, без промежуточного `R/search`. Навык (M3) и запись (M2) не делались.
- **Версии.** `@modelcontextprotocol/server` 2.3.0 (2026-10-02): 2.3.1 вышла 2026-10-05, меньше 14 дней назад. `zod` 4.6.5 (2026-09-13): 4.6.6 и 4.6.7 тоже моложе 14 дней. Обе закреплены точно и объявлены только в `apps/cli`.
- **Встроенный код.** Пакет MCP-сервера содержит скомпилированные в свои файлы `ajv`, `ajv-formats`, `fast-deep-equal`, `fast-uri` (BSD-3-Clause), `json-schema-traverse` и `content-type`; npm их не ставит, но они попадают в `arkvoryctl.mjs`. Их тексты добавлены в `MCP-LICENSES.txt` вместе с Apache-2.0 пакетов MCP и MIT `zod`; текста `content-type` нет в `node_modules`, он хранится в `deploy/client/licenses/`. Файла NOTICE в пакетах MCP нет. Unit-тест собирает CLI и падает, если у собранного или встроенного пакета нет текста лицензии.
- **Текстовый блок.** Кроме сводки он содержит тот же JSON, что `structuredContent`: спецификация MCP рекомендует это для клиентов, читающих только текст. Лимит `--max-output-bytes` (4096–1048576) меряется по сериализованному результату, включая экранирование JSON внутри текста. Элемент, не помещающийся сам, отдаётся со строками до 256 символов; если курсор сохранить нельзя — `output_too_large`. Список, не помещающийся в лимит, обрезается до префикса; `next` продолжает сразу после последнего возвращённого элемента — из ключа элемента или повторным запросом страницы ровно такого размера.
- **Набор инструментов** строится только по `GET /api/v1/auth/permissions`; `capabilities` при запуске не читаются, пока нет модулей ADR 0079 (их читает `arkvory_status`).
- **`arkvory_status`** — разделы `server` (capabilities), `replication`, `mirrors`, `backup`, `fleet`. Отдельного раздела очереди скачиваний нет: API чтения её состояния, кроме агрегатов readiness, пока нет.
- **`arkvory_history`** читает только `R/changes`; журнал промоушенов и события — после ADR 0080. В `arkvory_artifact` нет раздела пакета (API пакета по ID артефакта нет), аннотации и вложения — при `annotation.read`.
- **`arkvory_download`.** Каталог назначения должен существовать (`directory_not_found`), автоматически не создаётся. Существующая цель — обычный файл или ссылка на файл внутри корня; всё остальное — `path_outside_root`. Локальное несовпадение размера или SHA-256 отдаётся кодом ADR 0051 `integrity_mismatch` (в разделе «Проверка» выше назван `checksum_mismatch`, такого кода в ADR 0051 нет). Место проверяется до запроса метаданных, ещё раз перед открытием временного файла, после открытия и перед переименованием (тот же device/inode, каталог разрешается в себя); подмена каталога на ссылку другим локальным процессом даёт `path_outside_root`, остаётся лишь окно между проверкой и `open` (в Node нет `openat`). В Windows имена устройств, потоки и имена с точкой или пробелом в конце — `invalid_path`. История пути в `arkvory_files` продолжается `after` = `next`, как остальные списки.
- **Отмена.** `notifications/cancelled` прерывает вызовы SDK с `AbortSignal`; `list`, `packages` и `annotations` SDK сигнал не принимают и ограничены сроком `--timeout`.
- **Согласование версии.** Более новую ревизию клиента (например, `2026-07-28`) сервер не отклоняет, а отвечает своей последней (`2025-11-25`), как требует спецификация; ошибка -32602 — только для ревизии старше `2025-06-18`, пустой или не в формате даты.
- **Границы A1.** Курсор со временем вне точного диапазона сравнения в SQL (безопасное целое, годы 1684–2255) и `q` с NUL — 400 `invalid_input`, а не 500 из PostgreSQL. Репозитории, названные в `repositories`, проверяются по правам напрямую, поэтому предел в 1000 не скрывает доступный репозиторий.
- **Проверки.** Unit: обработчики с поддельным SDK (лимиты, обрезка и курсор, корень с `realpath` и ссылками, отсутствие ключа и `dtl_` в выводе, коды ошибок), протокол на паре потоков stdio (согласование версии, `tools/list` и подсказки, `tools/call`, лишние поля). Integration: настоящий `arkvoryctl mcp` дочерним процессом против API на PostgreSQL (поиск, скачивание с проверкой, отказ 403 кодом, выход при закрытии stdin, ключа нет в stdout и stderr, `Arkvory-Client` в журнале доступа) и ACL общего поиска. Прокси, портящий байт, и отмена передачи проверены unit-тестами с поддельным SDK, а не через настоящий прокси; гейт `native-package` локально не запускался.

## Реализация: этапы M2 и M3 (2026-10-17)

Выполнено по поручению владельца в ветке `feat/mcp-write`; статус ADR меняет владелец.

**M2.** `arkvoryctl mcp --write [--write-repositories R1,R2]`: `apps/cli/src/mcp/write-tools.ts` (`arkvory_upload`, `arkvory_publish_package`), `stage-tools.ts` (`arkvory_promote`, `arkvory_stage_remove`, `arkvory_annotate`), `source.ts` (источник в корне). Без `--write` инструменты записи не регистрируются; с ним — только при правах ключа (загрузка — все четыре `upload.create`, `upload.read`, `upload.write` и `upload.complete`, без которых сессию нельзя довести до конца; UPack — ещё `package.publish`; стадии — `artifact.promote`; аннотации — `annotation.read` и `annotation.write`). `--write-repositories` проверяется до запроса (`repository_not_allowed`), без `--write` — ошибка запуска. Инструкции сервера с `--write` перечисляют разрешённые репозитории и требуют подтверждения пользователя перед каждой записью.

**M3.** `integrations/agent-skills/arkvory/` (`SKILL.md`, `reference/tools.md`, `workflows.md`, `errors.md`, `cli.md`), копия в клиентских пакетах — `agent-skills/arkvory/` рядом с `arkvoryctl.mjs`, команда `arkvoryctl skill install [--target DIR] [--force]`, страница `wiki/guide/agents.md` с переводами.

Отступления и уточнения:

- **`arkvory_promote`** — добавление стадии, как в таблице п. 3; межрепозиторный `promote` инструментом не стал. Необязательный `sha256` отклоняет продвижение, если у артефакта другие байты (`integrity_mismatch`), — так навык выполняет «продвигать только после проверки `sha256`».
- **Подсказки.** `arkvory_stage_remove` — `destructiveHint: true` и `idempotentHint: true`: снятие отсутствующей стадии сервер принимает (204) и ничего не меняет. `arkvory_annotate` — destructive и idempotent, как в таблице: повтор с той же ревизией сервер отклоняет `conflict`, а не применяет дважды.
- **`arkvory_annotate`** читает текущие аннотации и заменяет только переданные `labels` и/или `metadata`; коллекции и непереданное поле остаются со значениями прочитанной ревизии. Конкурентное изменение отсекает `expectedRevision` на сервере.
- **Источник записи.** Те же правила корня, что у скачивания, плюс проверка открытого дескриптора (тот же device/inode, путь по-прежнему ведёт к нему; в POSIX `O_NOFOLLOW` и `O_NONBLOCK`). Все байты — дайджест, части и тело запроса — читаются через этот дескриптор: `HandleBlob` — подкласс `Blob`, потому что `fetch` (undici) отправляет телом известной длины только настоящий `Blob`, а похожий объект — строкой `[object Blob]`; поведение проверяет unit-тест с локальным HTTP-сервером и интеграционный тест с загрузкой из двух частей. Файл, содержащий ключ в любом месте, не отправляется (`source_contains_credential`): ключ ищется в том же проходе, что считает SHA-256, — в каждом блоке и на стыке двух блоков; сервер сверяет итоговый SHA-256, поэтому сохраняется ровно просмотренное. Закодированная или сжатая копия не находится. Собственные файлы CLI — каталог `ARKVORY_CLI_HOME` (профили, чекпойнты) и файл ключа — не читаются загрузкой и не заменяются скачиванием даже внутри корня (`private_path`): иначе скачивание с `overwrite: true` в `profiles.json` (корень по умолчанию — каталог запуска, часто домашний) перенаправило бы следующую команду с тем же ключом на другой сервер.
- **Чекпойнт** — в `<ARKVORY_CLI_HOME>/mcp-uploads/`, имя — SHA-256 от сервера, репозитория, реального пути, размера, SHA-256 файла, меток и metadata. Повтор того же вызова идёт по тому же ключу идемпотентности; изменённый файл или другие метки — новая загрузка, а не `checkpoint_mismatch`. Чекпойнт загрузки, которая уже не завершится (истекла, отменена, сборка не удалась, части не те), оставшийся от прошлого вызова, удаляется под его блокировкой, и загрузка один раз начинается заново с новым ключом; загрузка, начатая этим же вызовом, не перезапускается. При запуске `mcp --write` удаляются чекпойнты старше 30 дней и сверх 1000 новейших, а также временные файлы старше суток; чекпойнт с файлом блокировки не трогается (чужую блокировку не забираем; после аварии `.lock` удаляет человек, `state_locked`). Удалённая квитанция означает, что повтор того же вызова загрузит файл заново. Ответ — квитанция сервера без пути чекпойнта (он вне корня), плюс `size` и `sha256` прочитанного файла.
- **Проверка квитанции** добавлена в общий `upload()`, то есть и для `arkvoryctl upload`, `put` и `packages publish`: квитанция не `available` или с другими размером и SHA-256 — `integrity_mismatch` (код 5, не `integrity_failed` скачивания), и на ней не строятся регистрация UPack и ревизия пути. Ошибка с `stage: "register"` несёт `artifactId` и в MCP.
- **`skill install`.** `--target` — сам каталог навыка. Изменённость определяется по `.arkvory-skill.json` (SHA-256 установленных файлов): файл, совпадающий с прошлой установкой, обновляется; изменённый без `--force` останавливает установку до записи (`skill_modified`). Файл, которого больше нет в навыке, удаляется, только если не изменён. Ссылка или каталог на месте файла, а также ссылка или junction на месте каталога навыка (`reference`) — `skill_target_not_file` до записи. Имена из манифеста (его может изменить любой с доступом к каталогу) принимаются только как сегменты через `/` без `..`, `.`, пустых сегментов, `\`, `:` и NUL; имя, отличающееся от оставшегося файла только регистром, не удаляется. Отдельный выпускной `arkvoryctl.mjs` навыка не несёт (`skill_not_found`); он есть в клиентских пакетах Windows и Linux и при запуске из репозитория. Установщик Windows теперь копирует подкаталоги полезной нагрузки (`recursesubdirs`) и перед копированием удаляет `{app}\agent-skills` (`[InstallDelete]`), иначе файл, убранный из новой версии навыка, оставался бы после обновления.
- **Wiki.** `guide/agents` на английском и переводах `ru`, `es`, `fr`, `de`, `pt`, `zh`, `ko`, `hi`; `ja` и `ar` — заглушки, как остальные их непереведённые страницы. Раздел `#mcp` страницы `protocols/cli` обновлён во всех языках.
- **Проверки.** Unit с поддельным SDK, протокол на паре потоков (набор инструментов с `--write` и без, подсказки, отказ кодом), policy и упаковка навыка (собранный CLI в раскладке пакета ставит, сохраняет изменённый файл, заменяет с `--force`). Integration: настоящий `arkvoryctl mcp --write` против API на PostgreSQL — публикация из двух частей, повтор, скачивание с проверкой, ревизия пути, UPack, стадии, аннотации и `conflict`, отказ вне списка без запроса к серверу, 403 кодом, ключа нет в выводе. Тест установки клиентского пакета (`tests/deployment/client-install.mjs`) ставит навык из установленного клиента. Гейт `native-package` локально не запускался.
