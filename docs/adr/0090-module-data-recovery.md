# 0090. Чтение файлов модуля во время восстановления учёта

Статус: принято для реализации. Дата: 2026-10-22.

## Причина

Полный пересчёт файлов каталога превышает бюджет запуска подписанного модуля.
Чтение неизменяемых файлов не расходует квоту и не должно ждать этого обхода.

## Решение

Хост открывает файловый порт с отложенным учётом. Проверки путей и запрет
следования ссылкам сохраняются. Читающий хост не пересчитывает дерево при
открытии; явная и периодическая reconciliation по-прежнему доступны.
Пишущий хост запускает подготовку в своей последовательной очереди.
Любая мутация проходит после подготовки через прежние advisory lock,
durable intent, учёт временных файлов и проверку квоты. Новый процесс,
грязный журнал и восстановление мёртвого владельца сохраняют полный пересчёт.

До готовности usage возвращает busy, при ошибке подготовки — unavailable.
Нулевые размеры не подменяют неизвестный расход. Кешированное usage не
разрешает запись: это всегда обязанность устойчивого журнала под блокировкой.

Остановка отменяет ещё идущий первоначальный обход до новых мутаций и
дренирует последовательную очередь. Отмена не публикует частичные счётчики.
Прямые пользователи openModuleData без deferredAccounting сохраняют прежнее
синхронное открытие. Публичные типы и 30-секундный бюджет ModuleRuntime не меняются.

Модуль отвечает за собственное состояние восстановления. Готовность чтения
не даёт разрешения на запись, очистку или использование неполных индексов.
Этот ADR не меняет блокировки удаления, reader pins и правила resource-catalog.

Конкуренция за advisory lock при фоновой подготовке не означает повреждение:
до входа в защищённую работу busy повторяется не более 300 попыток с задержкой
100–1000 мс и отменой при остановке. Очередь мутаций остаётся за подготовкой.
Начатая работа, потеря владения и другие ошибки не повторяются; после
исчерпания попыток запись остаётся закрытой. Обычные мутации сохраняют
прежнее неблокирующее получение блокировки.
