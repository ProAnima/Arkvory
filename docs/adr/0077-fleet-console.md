# 0077. Единая консоль площадок

Статус: proposed (этапы F1 и F2 реализованы). Owner: Ian Panaev. Дата: 2026-10-14.

## Контекст

Установка Arkvory редко одна: основная площадка, зеркала на других площадках (ADR 0058), установки с импортом по стадиям, узлы HA (ADR 0072), шлюзы чтения (ADR 0009). Сейчас каждая установка самостоятельна:

- консоль работает только со своим API (`connect-src 'self'`, один адрес);
- источник не знает своих зеркал; процесс записи не показывает шлюзы чтения; узлы HA видны только через readiness активного узла;
- всё, кроме запроса обновления, настраивается локальной командой `arkvory configure` / `cluster-*` от root на хосте; консоль показывает команды для копирования;
- у каждой площадки свои пользователи и ключи (ADR 0058 намеренно не переносит учётные данные).

Администратору нужно одно место, где видны все площадки, их состояние, содержимое и связи, и откуда их можно настроить.

## Решение

### 1. Управляющая площадка и реестр

Одна установка — управляющая (обычно основная). В её БД хранится реестр площадок: имя, адрес API, закреплённый отпечаток сертификата TLS (SHA-256 SPKI) или CA, ключ управления площадкой (зашифрован AES-256-GCM ключом из `ARKVORY_FLEET_KEY_FILE`, файл 0600 в конфигурации установки), время последнего ответа и последний снимок состояния. Консоль по-прежнему ходит только к своему API; к площадкам ходит сервер управляющей установки. Отдельного сервиса нет.

Пользоваться единой консолью может только глобальный администратор управляющей установки. Ключи площадок в консоль, логи и ответы API не попадают никогда.

### 2. Сопряжение

1. На площадке глобальный администратор создаёт код сопряжения (консоль площадки или `arkvory fleet-pair`): одноразовый, 10 минут, показывается один раз.
2. На управляющей площадке администратор вводит адрес площадки. Сервер получает сертификат и `GET /health/status`, показывает отпечаток и имя площадки для сверки с тем, что показала площадка вместе с кодом.
3. Администратор вводит код. Управляющая площадка по закреплённому TLS вызывает `POST /api/v1/system/fleet/enrollment` с кодом и своим именем и отпечатком. Площадка создаёт учётные данные управления (новый вид credential `fleet-key`) и возвращает ключ один раз.

Площадка знает своего управляющего: имя, отпечаток, время сопряжения; её глобальный администратор видит это в своей консоли и может отозвать доступ. Перевыпуск ключа — повторное сопряжение.

### 3. Права ключа управления

`fleet-key` — не сервисный ключ и не пользователь. Ему разрешён только список маршрутов:

- чтение состояния площадки: `GET /api/v1/system/topology` (новый, глобальный администратор или `fleet-key`): роль, версия, схема, HA (копии, узлы), шлюзы чтения (аренды), зеркала и их курсоры, голова ленты изменений, обновления, резервные копии, очередь скачиваний, readiness;
- чтение каталога: репозитории, артефакты, пакеты, файлы по путям, история, лента изменений — без байтов содержимого (этап F2);
- запросы изменений (п. 5) и их состояние.

Каждый вызов несёт заголовок `Arkvory-Fleet-Actor` с именем администратора управляющей площадки: он пишется в аудит площадки рядом с `fleet-key` и не участвует в авторизации.

### 4. Опрос и состояние

Процесс записи управляющей площадки раз в 30 секунд (с разбросом, не больше 8 запросов одновременно, таймаут 10 с) читает `topology` каждой площадки и хранит последний снимок. Недоступная площадка — состояние `unreachable` с временем последнего ответа; ошибка TLS — `certificate`, отозванный ключ — `revoked`. Отставание зеркала считается на управляющей площадке, когда и источник, и зеркало сопряжены: голова ленты источника против курсора зеркала. Метрики: `arkvory_fleet_site_up`, `arkvory_fleet_site_last_seen_timestamp_seconds`, `arkvory_fleet_mirror_lag_changes`.

### 5. Удалённые изменения

Площадка ничего не выполняет из API: как обновления (ADR 0038), изменение — это запрос в локальный почтовый ящик, который применяет привилегированный агент площадки тем же кодом, что `arkvory configure` и `cluster-*`, с проверками, откатом и readiness. Запрос идемпотентен (`id`), содержит ожидаемую ревизию настроек, состояние читается тем же маршрутом.

- **Зеркала и импорт:** подключить, отключить, сменить ключ источника, стадии импорта, сертификат источника. Ключ источника — секрет: он идёт отдельным файлом 0600 рядом с запросом, читается агентом и удаляется после применения; в самом запросе и состоянии его нет.
- **Обновления:** запрос обновления, окно обслуживания, канал.
- **Очередь скачиваний** (этап 3 ADR 0076): настройки хранятся в БД площадки с ревизией и применяются без перезапуска; переменные окружения остаются значениями по умолчанию.
- **HA:** переключение активного узла и режим одной копии — только с подтверждением: администратор вводит имя целевого узла, площадка проверяет его по своему состоянию; запрос живёт 5 минут. Ограждение и вывод узлов остаются локальными командами.

### 6. Консоль

Новый раздел «Площадки» (только глобальный администратор):

- карта: площадки и связи «источник → зеркало», «импорт», узлы HA и шлюзы внутри площадки, состояние цветом;
- список площадок: роль, версия, доступность, копии HA, шлюзы, зеркала с отставанием, обновления, резервные копии, очередь скачиваний;
- площадка — вкладки «Обзор», «Содержимое» (каталог, пакеты, файлы площадки в той же раскладке, что локальные страницы), «Зеркала», «Обновления», «Очередь скачиваний», «Кластер»; действия — кнопками с подтверждением и состоянием запроса;
- управляющая площадка — первая в списке, тот же вид; локальные страницы остаются.

### 7. Безопасность

- Только HTTPS к площадкам (HTTP — только loopback), без перенаправлений, с закреплённым отпечатком; проверку TLS не отключать.
- Адрес площадки вводит глобальный администратор; разрешены внутренние адреса (площадки внутри сети), запросы идут только на адреса реестра.
- Ключи площадок зашифрованы ключом установки; без файла ключа реестр недоступен, опрос останавливается с понятной ошибкой. Ключ не входит в резервную копию БД; реестр восстанавливается с пометкой «нужно повторное сопряжение».
- Отзыв на площадке действует сразу; компрометация управляющей площадки компрометирует управление всеми площадками — это явный риск выбора серверного реестра, поэтому права `fleet-key` ограничены списком, а удаление данных и пользователей удалённо недоступно.

### 8. Этапы (каждый — отдельный PR)

- F1. `topology` на каждой площадке, коды сопряжения и `fleet-key`, реестр и опрос на управляющей, раздел «Площадки» с обзором (только чтение).
- F2. Содержимое площадок: каталог, пакеты, файлы через сервер управляющей площадки, только метаданные.
- F3. Почтовый ящик изменений: зеркала и импорт, обновления, очередь скачиваний (вместе с этапом 3 ADR 0076), HA с подтверждением.
- F4. Карта связей, отставание зеркал, оповещения и метрики.

## Уточнения реализации (этап F1)

- **Отпечаток** — SHA-256 всего сертификата (как показывают браузеры и `openssl x509 -fingerprint -sha256`), а не открытого ключа: администратор сверяет его где угодно. Площадка со встроенным HTTPS показывает свой отпечаток рядом с кодом сопряжения; за TLS-прокси сверяют с отпечатком, который браузер показывает для адреса площадки.
- **Проверка TLS не отключается.** При знакомстве управляющая площадка один раз читает сертификат без доверия, ничего не отправляя, только чтобы показать отпечаток. Все запросы к площадке идут с закреплённым сертификатом как единственным якорем доверия (`ca` + `allowPartialTrustChain`): цепочка проверяется против него, и отпечаток должен совпасть. Перевыпущенный сертификат — состояние `certificate`, повторное сопряжение.
- **Ключ печати** по умолчанию — `fleet.key` в каталоге данных, создаётся процессом записи при первом запуске (`0600`, исключительное создание). На HA он переезжает с данными; его нет в БД и резервных копиях; установщику и Compose ничего не нужно. `ARKVORY_FLEET_KEY_FILE` переопределяет путь. Шлюзы чтения ключа не создают и площадками не управляют.
- **`fleet-key`** — новый вид учётных данных с белым списком маршрутов (в F1 — только `GET /api/v1/system/topology`); всё остальное — 403 `permission_missing`, даже при флаге администратора. Управлять площадками и создавать коды может только человек — глобальный администратор, не ключ управления.
- **Код** — 60 бит в алфавите Crockford (`XXXX-XXXX-XXXX`), 10 минут, хранится только как SHA-256, обмен — `DELETE … RETURNING`, один раз. Повторное подключение того же адреса отклоняется до траты кода.
- **Опрос**: процесс записи раз в 30 секунд, не больше 8 одновременно, 10 секунд и 1 МиБ на ответ; ответ проверяется по контракту до сохранения. Неудача сохраняет последний известный снимок.
- **Отставание зеркала** считается на самом зеркале: голова источника, которую оно последний раз видело, минус его курсор. Сопрягать источник для этого не нужно.
- Реестр, коды и управляющие — вне резервной копии: доверие устанавливается заново после восстановления.

## Уточнения реализации (этап F2)

- **Один список маршрутов** `fleetReadRoutes` в `contracts`: по нему площадка пускает `fleet-key` (только `GET`), и по нему же управляющая площадка проверяет `path` до запроса. Разойтись они не могут. Маршрутов с байтами (содержимое артефактов и файлов, загрузки) в списке нет; путь — абсолютный, не длиннее 2048 символов, без фрагмента, `..`/`.`, `%2e%2e`, `%2f` и обратной косой черты; иначе 400 до любого сетевого запроса.
- **Права на площадке.** `fleet-key` получает чтение всех репозиториев площадки (список собирается из аудита рекурсивным skip-scan, не больше 1000), но не флаг глобального администратора для других маршрутов: запись, удаление, пользователи, ключи и настройки остаются 403 `permission_missing`. Вторая проверка — на площадке: даже скомпрометированная управляющая площадка не получает байты через `fleet-key`.
- **Прокси без интерпретации.** `GET /api/v1/fleet/sites/{id}/read?path=` возвращает статус и тело ответа площадки как есть (до 16 МиБ, тот же закреплённый TLS и таймаут); SDK `client.fleet.site(id)` даёт те же методы каталога, что локальный клиент, и проверяет ответы теми же читателями контракта. Ошибки транспорта: отозванный ключ → 409, отказ площадки → 403, недоступность и TLS → 503.
- **Консоль**: кнопка «Содержимое» в строке площадки открывает репозитории, поиск артефактов и страницы файлов с пагинацией; данные площадки выводятся только как текст.

## Последствия

- Публичный контракт расширяется аддитивно: `/api/v1/system/topology`, `/api/v1/system/fleet/*`, вид credential `fleet-key`, заголовок `Arkvory-Fleet-Actor`.
- Новые таблицы реестра и сопряжений; ключи площадок вне резервной копии.
- Управляющая площадка становится точкой высокой ценности: её глобальные администраторы и файл ключа должны защищаться так же, как root площадок.
- Площадки без сопряжения работают как прежде; локальная настройка командами остаётся.
