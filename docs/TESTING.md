# Стратегия проверок

## Что уже проверяется

`npm run check`: форматирование, TypeScript каждого workspace, type-aware ESLint, архитектурный граф. Это проверки каркаса. В нём пока нет работающего сервиса и продуктовых тестов; успешный check не означает, что публикация/скачивание реализованы.

## Проверки по уровням

| Уровень          | Проверяемое поведение                                                         |
| ---------------- | ----------------------------------------------------------------------------- |
| Domain           | Идентичность, переходы, версии, политики меток/удаления; без сети и БД        |
| Application      | Оркестрация сценариев, ACL, идемпотентность, реакции на отказ порта           |
| Adapter contract | Одинаковые гарантии Local/Object backend, ошибки и отмена                     |
| Integration      | Реальная PostgreSQL, выбранный blob backend, leases/outbox/reconciliation     |
| HTTP/SDK         | Схемы, авторизация, коды, пагинация, abort, безопасные retry                  |
| ProGet           | Одинаковые сценарии на тестовом ProGet и ProAnima Depot, реальные клиенты     |
| Transfer         | 5 ГБ, bounded memory, Range, backpressure, повтор частей, совместная нагрузка |
| Failure/restore  | Отключение узла, потеря ответа, разделение сети, чистое восстановление        |

Unit-тесты размещаются рядом со сценарием как `*.test.ts`; межпакетные интеграционные/контрактные/нагрузочные сценарии — в `tests/`. Раннер выбирается и подключается вместе с первым сценарием; product test job не может быть зелёным за счёт отсутствия тестов.

Данные больших тестов генерируются потоково; не коммитим архивы 5 ГБ. Fixtures маленькие, обезличенные, с описанием происхождения и версии протокола. Контрактные записи не выполняются на рабочих фидах ProGet.

Часы и случайность контролируемы. Не полагаемся на sleep для гонок: используем управляемые точки синхронизации. Для асинхронных jobs проверяем повторную доставку, истечение lease и устаревшего владельца.

## Приёмка первого сценария

- Приём файла до 5 ГБ не накапливает всё тело в памяти.
- До завершения и проверки файл не доступен как опубликованный.
- GET/HEAD/Range возвращают правильные байты, размер и ETag.
- После перезапуска промежуточная операция корректно продолжается или очищается.
- Потеря ответа завершения не создаёт две публикации.
- Ограничения и фактическая конфигурация стенда записаны в результатах.

Тесты должны защищать поведение и инварианты, а не повторять реализацию или проверять существование пустых экспортов. Процент покрытия сам по себе не является критерием надёжности.
