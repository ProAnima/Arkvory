# Проверка standalone-ядра

Дата: 2026-09-22. Это результаты первого нативного сценария, не сертификация HA и не оценка промышленной нагрузки.

## Стенд

Windows, Node.js 24.13.0, реальная PostgreSQL 18.4 на loopback, локальная файловая система. Для испытаний PostgreSQL запущена отдельным временным процессом: Docker Desktop на стенде не отвечал. Эта вспомогательная установка находится вне исходников и не является зависимостью продукта.

## Функциональные проверки

- Строгая типизация десяти workspaces, type-aware ESLint, Prettier, зависимости слоёв.
- Runtime build: JS + declarations, без runtime TypeScript loader.
- Домен: ограничение размера, SHA-256, безопасное имя, bounded metadata/labels, канонизация идемпотентности и права.
- LocalBlobStore: проверка до публикации, неполное/избыточное/повреждённое содержимое, отмена, неизменяемость, повтор, restart, пустой объект и Range.
- HTTP/PostgreSQL: миграции и повторный запуск, repository/read/write scopes, невидимость pending, идемпотентность, конфликт тела, cancel, GET/HEAD/206/304/416, If-Range и пагинация.
- Конкурентные резервы не превышают ёмкость; одновременные запросы с одним ключом возвращают один ID.
- Сохранённый blob без commit восстанавливается через complete. Занятый upload возвращает 503.
- Принудительное завершение PostgreSQL-соединения владельца upload-lock не позволяет публикацию через другой pool.
- Второй API на той же БД и подключение существующей БД к другому каталогу отклоняются.

## Реальный файл 5 GiB

Скрипт `tests/large-transfer.mjs`: один реальный HTTP-поток upload → публикация → принудительное завершение серверного процесса → новый процесс → suffix Range → полный download с подсчётом хеша.

| Показатель                             | Измерение                        |
| -------------------------------------- | -------------------------------- |
| Bytes                                  | 5 368 709 120                    |
| Upload                                 | 45 829 ms                        |
| Полный download                        | 11 176 ms                        |
| Пик RSS отдельного серверного процесса | 142 442 496 bytes, около 136 MiB |
| SHA-256 до/после                       | Совпадает                        |
| Range после перезапуска                | Точные последние 17 bytes        |
| Одновременные передачи                 | 1                                |

SHA-256 тестового содержимого:

```text
b23228f170c6e7ab93aeee2c5711299da5d561470be1c6842ef063f17bfed415
```

Данные генерируются одним повторно используемым буфером 1 MiB. Сам файл не хранится в Git; тест удаляет собственный временный каталог. Память клиента и серверного процесса разделена. RSS измеряется каждые 100 ms; тест отклоняет пик выше 384 MiB. Показатель не включает page cache ОС и не доказывает ограничение при большом числе клиентов.

Локальный машинный отчёт: `test-results/large-transfer.json` (исключён из Git). Время зависит от диска, кеша ОС, БД и сети; не используйте эти цифры как SLA или прогноз для сети с несколькими шлюзами.

## Пока не подтверждено

Аппаратное отключение питания, отказ диска/узла, HA PostgreSQL/blob-store, межузловая сеть, 4 ТБ миграции, реальные ProGet-клиенты, распаковка payload/CRC всех ZIP entries, mixed-load fairness и ограничение общей полосы. Эти сценарии остаются отдельными этапами; владелец отложил стенд двух серверов.

## Инкремент 0.2

Локально проверены: части после restart, gaps, конфликт индекса/хеша; offline GC и отказ удаления без освобождения квоты; expiry и отозванные права worker; lease generation и реальный worker subprocess; CAS annotations/assets; UPack registration/immutable identity, SemVer/path/symlink validation; SDK по HTTP, legacy original downloads и ACL/Range; dry-run/import/repeat/read-back hash и offline scrub. 13 unit/local tests и 16 PostgreSQL/HTTP integration tests. Browser smoke: страница консоли отображается, обработчик выбора файла работает; полного browser upload/save теста нет.

Реальный 5 GiB multipart: 640 частей по 8 MiB, SIGKILL API после части 319, новый процесс видит 320 подтверждений, продолжение до complete, повторный SIGKILL, Range и полный download. Общий SHA-256 совпал с указанным выше.

| Измерение                 | Значение                                               |
| ------------------------- | ------------------------------------------------------ |
| Upload + restart + сборка | 71 678 ms                                              |
| Полный download           | 13 408 ms                                              |
| Пик RSS API               | 147 103 744 bytes, около 140 MiB                       |
| Bytes                     | 5 368 709 120                                          |
| Отчёт                     | test-results/large-multipart.json (локальный, ignored) |

Первый прогон обнаружил timeout неактивного сокета во время сборки. Для синхронного complete увеличено ожидание до 30 минут при сохранении ограниченного допуска; убран повторный полный hash после уже проверенной потоковой сборки. Повторный прогон прошёл. Reverse proxy должен допускать такую длительность либо клиент использует complete-async и worker. Измерения относятся к одному потоку на локальном диске, не являются сетевым SLA.

## История файлов и восстановление (2026-09-22)

Добавлены 1 unit test runtime-контрактов и 7 PostgreSQL/HTTP integration tests. Полный набор: 14 unit/local и 23 integration tests. Проверяются страницы по 50 с точным окончанием, параллельное добавление ревизий, сохранение прежних байтов после restart, legacy download текущего указателя, конкурирующие restore, повтор с устаревшей ревизией, диапазон PostgreSQL integer, изоляция репозиториев, read/write ACL и отмена SDK-запроса.

Отказы записи воспроизводятся PostgreSQL triggers отдельно в таблице истории и в аудите: HTTP возвращает 503, текущий указатель и число ревизий не меняются. Миграция проверяется на существующей истории схемы 3: старые поля автора/даты остаются null, повторный migrate безопасен, новые записи заполняются.

В браузере на изолированном localhost-профиле проверены загрузка двух ревизий, восстановление первой как третьей, открытие исторического artifact в метаданных и очистка истории/выбора при отключении. Отображение таблицы проверено визуально. Это ручной smoke, не автоматизированная проверка всех browser-сценариев. Потоковые byte paths не менялись; тесты 5 GiB в этом инкременте не повторялись. Стенд двух серверов и реальные ProGet-клиенты остаются отложенными.

## Темы и локализация консоли

Добавлены проверки словарей/параметров, fallback preferences при запрете storage, семантических цветов и контраста текста в обеих темах. HTTP integration проверяет раздачу tokens.css и appearance-init.js с прежней CSP. Полный набор — 17 unit/local и 23 integration tests.

Ручной browser smoke на отдельной тестовой БД: светлая/тёмная темы, RU/EN без reload, перевод уже загруженных ревизий и дат, восстановление, открытие старого файла, ошибка JSON с переключением языка, успешное сохранение метаданных, reload с сохранёнными темой/языком и пустым ключом. Через file chooser загружен небольшой искусственный файл, подтверждены публикация и появление в каталоге, ошибок JavaScript нет. На ширине 390 CSS px проверено отсутствие горизонтального переполнения страницы; навигация и таблицы имеют собственную прокрутку. Эти проверки не являются полным аудитом доступности или всех browser upload/save сценариев.

Новые сценарии: fault proxy с обрывом multipart и потерей ответов после create/part/complete; пустой upload после потери ответа; повтор без дубликатов; CLI продолжает принятую часть и отклоняет изменённый исходник. ## Сетевые бюджеты шлюза (2026-09-22)

Полный набор: **44 unit/local/SDK tests + 30 PostgreSQL/HTTP integration tests**. Проверки типов, ESLint, формат и архитектурные границы проходят. Принудительное завершение PostgreSQL-соединения standalone ownership отдельно проверяет остановку активного throttled download, readiness 503 и сохранность файла после restart.

Реализованы общий и per-principal bucket для каждого направления, предел активных операций клиента, корректное закрытие очередей и агрегаты readiness. Проверки: виртуальное монотонное время, математические границы burst/rate, конкуренция принципалов и ключей, защита больших квантов от потока маленьких, отмена/ограничение очередей/backpressure, реальные параллельные full/multipart uploads и native/legacy/Range downloads. HEAD/304/416 не расходуют byte budget. При выключении API активная раздача прерывается, а опубликованные bytes доступны после restart.

## Шлюзы чтения и аренда долей (2026-09-22)

Текущий набор: **47 unit/local/SDK tests + 34 PostgreSQL/HTTP integration tests**. Добавлены три unit-теста локального окна и расчёта долей, четыре интеграционных сценария; проверки конфигурации и обновления старого каталога расширены для схемы 5.

Проверены writer и два reader в отдельных процессах, сумма скоростей, невозможность увеличить долю локальной настройкой, ACL/405/Range, обрыв при SIGKILL reader и целостность скачивания через writer. Проверены конфликт номера slot/policy, повторный startup до истечения аренды, рост generation, запрет standalone bypass и offline maintenance при живом reader, отсутствие создания storage на reader.

TCP proxy приостанавливает обмен между reader и PostgreSQL во время активного download. Поток завершается до истечения DB reservation благодаря локальному окну; после expiry запускается новый reader с тем же slot. Возвращение DB-связи не оживляет старый процесс. Unit-тесты отдельно моделируют поздний heartbeat и паузу процесса. Условия часов и буферизации изложены в [READ_GATEWAYS](READ_GATEWAYS.md).

Испытания выполнены на Windows, локальном PostgreSQL и одном согласованном storage root. Отказы двух физических серверов, репликация файлов/БД, внешний балансировщик, скачки DB clock и промышленный HA не проверялись.

Повторный standalone regression `--multipart --verified --traffic` с новым кодом: 5 368 709 120 bytes, SIGKILL посреди upload и после публикации, обрыв download, полное совпадение SHA-256 `b23228f170c6e7ab93aeee2c5711299da5d561470be1c6842ef063f17bfed415`. Upload с продолжением и сборкой — 192,364 ms; verified download — 127,989 ms. RSS API — 151,617,536 bytes (около 145 MiB), клиента — 162,799,616 bytes (около 155 MiB), оба ниже assertion 384 MiB. Квоты: 64 MiB/s на шлюз и 48 MiB/s на principal в каждом направлении. Этот большой прогон проверяет standalone regression; несколько readers и потеря PostgreSQL проверены отдельными сценариями выше. Отчёт: ignored `test-results/large-traffic.json`.
