# Проверка standalone-ядра

Дата: 2026-09-22. Это результаты первого нативного сценария, не сертификация HA и не оценка промышленной нагрузки.

## Стенд

Windows, Node.js 24.13.0, реальная PostgreSQL 18.4 на loopback, локальная файловая система. Для испытаний PostgreSQL запущена отдельным временным процессом: Docker Desktop на стенде не отвечал. Эта вспомогательная установка находится вне исходников и не является зависимостью продукта.

## Функциональные проверки

- Строгая типизация десяти workspaces, type-aware ESLint, Prettier, зависимости слоёв.
- Runtime build: JS + declarations, без runtime TypeScript loader.
- Домен: ограничение размера, SHA-256, безопасное имя, bounded metadata/labels, канонизация идемпотентности и права.
- LocalBlobStore: проверка до публикации, неполное/избыточное/повреждённое содержимое, отмена, неизменяемость, повтор, restart, пустой объект и Range.
- HTTP/PostgreSQL: миграции и повторный запуск, repository/read/write scopes, невидимость pending, идемпотентность, конфликт тела, cancel, GET/HEAD/206/304/416, If-Range и пагинация.
- Конкурентные резервы не превышают ёмкость; одновременные запросы с одним ключом возвращают один ID.
- Сохранённый blob без commit восстанавливается через complete. Занятый upload возвращает 503.
- Принудительное завершение PostgreSQL-соединения владельца upload-lock не позволяет публикацию через другой pool.
- Второй API на той же БД и подключение существующей БД к другому каталогу отклоняются.

## Реальный файл 5 GiB

Скрипт `tests/large-transfer.mjs`: один реальный HTTP-поток upload → публикация → принудительное завершение серверного процесса → новый процесс → suffix Range → полный download с подсчётом хеша.

| Показатель                             | Измерение                        |
| -------------------------------------- | -------------------------------- |
| Bytes                                  | 5 368 709 120                    |
| Upload                                 | 45 829 ms                        |
| Полный download                        | 11 176 ms                        |
| Пик RSS отдельного серверного процесса | 142 442 496 bytes, около 136 MiB |
| SHA-256 до/после                       | Совпадает                        |
| Range после перезапуска                | Точные последние 17 bytes        |
| Одновременные передачи                 | 1                                |

SHA-256 тестового содержимого:

```text
b23228f170c6e7ab93aeee2c5711299da5d561470be1c6842ef063f17bfed415
```

Данные генерируются одним повторно используемым буфером 1 MiB. Сам файл не хранится в Git; тест удаляет собственный временный каталог. Память клиента и серверного процесса разделена. RSS измеряется каждые 100 ms; тест отклоняет пик выше 384 MiB. Показатель не включает page cache ОС и не доказывает ограничение при большом числе клиентов.

Локальный машинный отчёт: `test-results/large-transfer.json` (исключён из Git). Время зависит от диска, кеша ОС, БД и сети; не используйте эти цифры как SLA или прогноз для сети с несколькими шлюзами.

## Пока не подтверждено

Аппаратное отключение питания, отказ диска/узла, HA PostgreSQL/blob-store, межузловая сеть, 4 ТБ миграции, ProGet-клиенты, распаковка UPack, прерванный multipart/resume, безопасный GC, справедливость очередей и ограничение общей полосы. Эти сценарии остаются отдельными этапами.
