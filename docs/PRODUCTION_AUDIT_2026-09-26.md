# Аудит готовности к эксплуатации — 2026-09-26

## Область и метод

Проверка исходного состояния `b6aade5`: три независимых прохода по безопасности, хранению/очередям и продуктовым контрактам; отдельно — обновления, поставка и CI. Подтверждённые дефекты исправляются с регрессиями, затем проверяются общими гейтами. Это source review и автоматизированная приёмка standalone-профиля; проверка настоящих серверов, сети площадки и клиентов ProGet не выполнялась.

Чистые зависимости domain/application, отдельные contracts/SDK/адаптеры и composition roots сохраняются. Исправления не добавляют сервисов, не ослабляют strict TypeScript, лимиты размеров или обязательные гейты. Реестр `config/architecture-exceptions.json` остаётся явным техническим долгом, а не доказательством отсутствия будущего рефакторинга.

Дополнительно исправлен P2 в supervision установщика: тайм-аут завершал ожидание до подтверждённой остановки дерева процессов. Откат или следующая команда могли выполняться одновременно с дочерним процессом прежней команды. Теперь ожидается завершение дерева на Windows/POSIX; при неподтверждённой остановке автоматический rollback запрещён, installation lock сохраняется. Регрессии supervision и UpdatePort проверяют обе ветви. Уже принятые внешним service/container daemon задания требуют отдельной проверки.

Повторный review выявил ещё одну границу supervision: readiness loop перехватывал ошибку неподтверждённой остановки worker probe как обычную временную недоступность. Теперь такая ошибка немедленно передаётся updater и владельцу installation lock. `tests/deployment-health.test.mjs` проверяет прямую и обёрнутую ошибку, сохранение lock и штатные повторы безопасно завершившегося probe.

Обозначения P1/P2 — приоритет исправления в этом review, не оценка CVSS. Наличие теста в таблице означает его назначение; результаты прогона фиксируются отдельно ниже.

## Проверенные границы

- Авторизация native/legacy, CORS, серверная фильтрация прав, сессии, managed keys и делегирование; обработка ошибок, download headers и ссылки вложений.
- Multipart/resume, публикация, completion leases/generation, отмена, content pins, online/offline cleanup и связь БД с immutable blobs.
- CLI/SDK transport, ограничение ответов, каталог и свойства сборок; соответствие README/roadmap текущим API и UI.
- Локальный мастер SSH: доверие ключу до отправки credentials, Host/CSRF/cookie/CSP, экранирование команд, туннель и отделение от публичного API.
- Release manifests, проверка архива, переключение/rollback, привилегии workflow, обязательные CI lanes и замороженные архитектурные исключения.

На просмотренной поверхности прямой обход ACL, передача GitHub credential на CDN, shell injection или обход пути не подтверждены. Это ограниченный вывод о выполненном review, а не гарантия отсутствия уязвимостей.

## Проверки

Локально Windows, Node.js 24.13, отдельная PostgreSQL на loopback и Edge через Playwright: `npm run gate -- quick integration browser deployment` завершился успешно. Пройдены policy/format/TypeScript/lint/границы, 162 unit и 127 PostgreSQL/HTTP тестов, три браузерных сценария и проверка переносимой упаковки. Первый static-прогон выявил lint-ошибки в новых обработчиках; они исправлены без отключения правил, повтор прошёл. Аудит зависимостей через `npm run gate -- security`: 0 известных уязвимостей на момент проверки.

После повторного review и исправления readiness выполнен `npm run gate -- quick deployment`: статические проверки, 166 unit-тестов и упаковка прошли. Четыре новых сценария проверяют прохождение ошибки через настоящий readiness loop и installation lock; служба ОС в этих unit-сценариях заменена тестовым probe.

Локальный набор не заменяет `verify`: настоящие Windows/Linux службы, нативная установка и контейнеры проверяются обязательной CI-матрицей PR. Отчёты фиксируют точный commit и dirty state. Проверки 5 GiB и итоговые результаты CI сообщаются отдельно; успешная standalone-приёмка не подтверждает HA или реальную миграцию ProGet.

Повторная read-only проверка настроек GitHub: default workflow permissions = `read`; endpoints branch protection и rulesets возвращают 403 с требованием GitHub Pro для приватного репозитория. Поэтому обязательность merge gate обеспечивается процессом review, а не серверным запретом merge. Публичность репозитория и тариф не менялись. После подключения подходящего тарифа требуется включить required check `Arkvory merge gate` для main.
