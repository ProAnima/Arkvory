# Разработка

## Подготовка

Node.js 24 LTS, npm 11; устанавливайте актуальный безопасный patch в этой линии. Зависимости инструментов зафиксированы точными версиями и `package-lock.json`. Воспроизводимая установка: `npm ci`. Корень — npm workspace; отдельные lock-файлы внутри пакетов не создаются.

TypeScript 5.9.3 выбран как проверяемая совместимая базовая версия с текущими инструментами lint. Обновление major TypeScript выполняется отдельно с проверкой совместимости parser, линтера и сборки, а не автоматически по `latest`.

`npm run check` выполняется локально и в GitHub Actions на Linux и Windows. Основной репозиторий — [ProAnima/Depot](https://github.com/ProAnima/Depot). Workflow проверок находится в `.github/workflows/check.yml`.

Это проприетарный проект Ian Panaev под брендом ProAnimaStudio. Работа с кодом и передачей изменений выполняется в пределах отдельно предоставленных прав; см. [LICENSE.md](LICENSE.md) и [модель лицензирования](docs/LICENSING.md). Публичный fork или отправка PR не заменяют согласование прав на вклад.

## Изменения

Работа начинается с небольшого вертикального сценария из roadmap. Не реализуйте все будущие интерфейсы и классы заранее. Пустой `index.ts` заменяется реальными публичными экспортами при появлении кода. Порты размещаются в `application`, предметные инварианты — в `domain`, I/O — в адаптерах.

Между пакетами используйте имя `@proanima/depot-<package>` и публичный экспорт. В manifests объявляйте реальные workspace-зависимости. Runtime exports указывают на `dist/index.js` и `.d.ts`; условие `depot-source` используется только tooling. `npm run build` собирает workspaces в порядке зависимостей. CI проверяет сборку и тесты из чистого checkout.

Для Node.js используется ESM/NodeNext; относительные импорты исходников указывают ожидаемое расширение `.js`. Browser SDK/UI получают отдельное DOM-окружение. Domain/application/contracts не получают Node.js globals.

## Проверки и review

- Формат: `npm run format`, затем `npm run check`.
- Правила домена — быстрые тесты без БД и сети.
- Адаптеры — интеграционные проверки с реальными зависимостями.
- API/SDK/ProGet — контрактные сценарии, включая ошибки и авторизацию.
- Передачи — проверка backpressure, отмены, повторов, памяти и частичных отказов.
- Запускайте `npm test` и соответствующие PostgreSQL integration tests; нельзя подменять их `passWithNoTests`.
- Результаты значимых замеров записывайте с конфигурацией стенда и версией кода. Нет оснований обещать throughput по одному короткому тесту.

Готовность изменения: нужное поведение работает; ошибки обработаны; новые зависимости обоснованы; проверки проходят; документация/схемы актуальны; секретов нет; известные ограничения перечислены. Шаблон описания: [CHANGE.md](docs/templates/CHANGE.md).

## Зависимости и конфигурация

Новая библиотека должна решать конкретную задачу. Проверяйте поддержку выбранного Node.js/TypeScript, лицензию и способ обновления. Не выполняйте автоматический `audit fix --force` и массовые major-обновления в рамках функциональной задачи.

Переменные окружения читаются и валидируются при запуске composition root; затем передаётся типизированная конфигурация. Нельзя читать `process.env` посреди доменного сценария. Настройки клиента не содержат серверные ключи.
